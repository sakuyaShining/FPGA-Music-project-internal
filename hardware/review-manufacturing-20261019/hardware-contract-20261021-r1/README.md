# 当前载板与86号冻结实验的接口核对 · r1

本目录包含独立候选和真实 Icarus 数字验证，不改动原始86号实验、产品根源码或当前 PCB。不是整机码流、不是模拟验证、未制造放行。

## 已确认的两个具体冲突

1. 当前原生 U8 的 Q0..Q7 分别连接 `ADDR0/1/2/3、MUX_DISABLE、RC_DRIVE、LCD_RESET_N、TP_RESET_N`。冻结 `rc_mux_scan.v` 的每个扫描字高两位固定为 `00`，会使当前载板显示和触摸复位持续有效。`rc_mux_scan_hw.v` 在独立副本增加运行时 `peripheral_reset_n[1:0]` 输入（bit1→触摸复位，bit0→共用显示复位），不再在扫描中覆盖该状态。最终仍须由实际复位/总线控制器正确提供状态，不能把悬空输入当成高。
2. 冻结 `rc_delta_store.v` 的原始节点编号是 `MUX地址×6+通道`，但实验 `instrument_sensor_probe.v` 的示例位置映射使用顺序 `0..77`。当前两份电极 OPTION 表按每组14电极顺序分配，不能直接使用实验示例表。`board-map-25.vh` / `board-map-26.vh` 由当前原生焊盘及接口逐项推导，参考通道14/15不会混入音位。它们只修正物理节点到位置算法的索引，不决定 MIDI 基准音或端点选择。

`node-map-audit.csv` 保留全部75/78音位电极的物理连接和存储节点。该映射表与本板一起使用；修改接线后必须重新生成，不能只改变 MIDI 音高表。

## 实际验证

运行 `D:/anaconda/python.exe check_contract.py`。引擎为 `D:/iverilog/bin/iverilog.exe` / `vvp.exe`。

- 原冻结扫描负对照：复现128个扫描字覆盖屏幕复位，明确 FAIL；完整字长/地址/序列/测量和超时检查不出现其他错误。
- 候选扫描：真实串行595移位/锁存模型，两整帧32行、128个完整字，含三种运行时复位状态、总线授权等待、报告背压和一次整帧卡高超时情景，通过。
- 25与26音位各做原线性映射负对照和新物理映射正对照。位置模块实际读取模拟存储的不同节点值，对每条触摸、失效位和加权位置逐一比对；两负对照失败、两正确映射通过。
- 所有原始输入与测试命令/日志/SHA256 见 `contract-results.json` 和各运行目录；PCB 以及五个冻结86号源文件前后哈希相同。

测试使用加速数字延时，只验证接口语义、计时控制和索引，不证明真实RC范围/采样速率/触摸精度。没有运行最终共同总线控制器、完整产品顶层、Gowin PnR/STA 或板上下载。候选需接入最新实验的实际产品封装后再做这些检查。当前硬件连接可以保留；尚未因这两个软件接口问题改板或改器件。
