## 一、v1 引脚表：已与官方 cst 逐条核对，全部正确

交叉来源：Sipeed `TangNano-20K-example` 的 `audio.cst`、`blink_leds.cst`、`Tang_nano_20K_LCD.cst`。

| 信号 | 91 号声明 | 官方来源 | 结果 |
|---|---|---|---|
| `clk` | 4 | `audio.cst` | 一致 |
| `btn_rst`（高有效） | 87 | `audio.cst` | 一致 |
| `pa_en` / `dac_din` / `dac_ws` / `dac_bck` | 51 / 54 / 55 / 56 | `audio.cst` | 一致 |
| `led[0..5]` | 15–20 | `blink_leds.cst` | 一致 |
| `pad[0..15]` | 27–42 | `Tang_nano_20K_LCD.cst`（LCD_B/G/R 数据线） | 一致 |

**附带的更正（本条已二次推翻，见 §六）**：官方 LCD 示例确实把 27–42 连续 16 个脚分配给 RGB 数据线，但**这 16 个脚并不都在 2.54 mm 排针上**。按 Sipeed 官方引脚框图逐脚核对（§六）：排针上只有 `27,28,29,30,31,41,42` 共 **7** 个；`32–40` 只连到 FPC 座与 HDMI 座，排针上没有。

因此准确表述是：

- **从 FPC 座引线** → 27–42 全 16 路可用，v1 的 16 电极直连物理成立
- **从 2.54 mm 排针引线** → 只有 7 路，16 路不成立

载板是插排针的，所以载板拿不到 16 路直连 —— 这正是载板必须走扫描链的物理原因。

## 二、未验证的一层：`J6` 第 N 脚 ↔ FPGA 第 M 脚

`interface-references/expected-pin-nets.json` 只记录连接器级连接：

```json
"J5": { "5": "SENSE_4", "6": "SENSE_3", "7": "I2S_BCK", "8": "I2S_DIN",
        "10": "SENSE_5", "11": "I2S_LRCK", "15": "GND", "16": "3V3_IO" },
"J6": { "5": "TP_INT", "6": "BUS_MOSI", ... }
```

**不含「该脚对应 FPGA 几号」。** 该层来自 `hardware/system-candidate-20261015/nano-header-candidate.csv`，其 `status` 列自述：

```
candidate_not_for_connection_until_board_and_wrapper_check
```

### 2.1 与官方定义冲突

该 csv 把 15–20 分配给 `BUS_MOSI` / `SCAN_LATCH` / `INPUT_LOAD_N` / `LCD_VIS_CS_N` / `LCD_HARM_CS_N` / `LCD_SHARED_DC`。

但官方 `blink_leds.cst`：

```
IO_LOC "leds[5]" 20;  IO_LOC "leds[4]" 19;  IO_LOC "leds[3]" 18;
IO_LOC "leds[2]" 17;  IO_LOC "leds[1]" 16;  IO_LOC "leds[0]" 15;
```

**15–20 是板载 6 个 LED。** csv 自己的 `existing_load` 列写的就是 `onboard_LED_510ohm`——它知道这些脚挂着 LED，却仍当排针信号使用。

### 2.2 两种可能，后果都严重

| 情况 | 后果 |
|---|---|
| 15–20 引到排针但并着 LED | 做输出：LED 跟着闪，驱动被 510 Ω 分流。做**电极输入**：510 Ω + LED 形成弱上拉，干扰 `PULL_MODE=DOWN` 的放电计数，接触量读数失真 |
| 15–20 未引到排针 | 载板这 6 根线接在空脚或别的信号上，扫描链与屏接口整体错位，板子无法工作 |

### 2.3 唯一的判定方法

**万用表通断档，量「J6 第 6 脚 ↔ FPGA 15 号脚」是否导通。**

- 导通 → csv 映射成立，但 15–20 带 LED 负载，**不能用作电极输入**
- 不导通 → csv 映射错误，载板该组走线需重做

v1 码流已可烧录，板子在手，此测量约 5 分钟。**在此之前不应基于该 csv 继续扩展任何引脚规划。**

## 三、v1 与载板不是同一套输入方案

| | v1（`tdm_ship_owned`） | 载板 `e098c5db` |
|---|---|---|
| 电极输入 | 16 路直连 27–42 | 6 路 `SENSE_0..5` + 扫描链（6×74HC4067 → 84 节点） |
| 扫描链 | 无 | `BUS_SCK` / `BUS_MOSI` / `SCAN_LATCH` / `INPUT_LOAD_N` / `BUS_RETURN` |
| 屏 | 无 | `HARM_CS_N` / `TP_INT` / `J10` 12P |
| I²C | 无 | `I2C_SDA` / `I2C_SCL` |
| AUX | 板载 54/55/56 直出 | 走排针 `I2S_BCK` / `I2S_DIN` / `I2S_LRCK` |
| 供电 | 板载 USB-C | `J13` XH2.5 2P + 受保护电源入口 |

**结论：v1 码流可直接在裸 Nano 20K 上出声，插到载板上不工作。** 载板所需的 6 路 SENSE + 扫描链 RTL 不在 v1 中。

### 6.4 32–40 上挂的是什么

官方 HDMI 示例（`hdmi/src/hdmi.cst` 与 `nestang/src/nestang.cst`）与 LCD 示例同时占用这 8 个脚：

```
HDMI:  tmds_clk_p=33  tmds_clk_n=34  d0_p=35  d0_n=36
       d1_p=37  d1_n=38  d2_p=39  d2_n=40
LCD :  LCD_G4=33  LCD_G3=34  LCD_G2=35  LCD_G1=36
       LCD_G0=37  LCD_R4=38  LCD_R3=39  LCD_R2=40
```

同一组 8 个脚被 HDMI 座与 FPC 座共用（Sipeed 的省引脚设计，二者不能同时插）。此外 J5 第 19/20 脚（`53/52`）是 HDMI 的 DDC 通道 `EDID_CLK/EDID_DAT`，进一步佐证 HDMI 座是常驻连接的。

**对电容触摸的含义**：32–40 若用作电极，会并联 HDMI 连接器焊盘、走线与 ESD 器件的寄生电容；插上 HDMI 线时更是直接短路到源端设备。这是 v1 若从 FPC 座引 16 路电极时的已知代价，需要在标定时计入。

### 6.6 剩下唯一真正的风险：15–20 做输出

csv 把 6 个板载 LED 脚用作载板控制信号：

| 信号 | 脚 | 方向 | 后果 |
|---|---|---|---|
| `BUS_MOSI` | 15 | 输出 | LED0 随数据闪 |
| `SCAN_LATCH` | 16 | 输出 | LED1 随锁存闪 |
| `INPUT_LOAD_N` | 17 | 输出 | LED2 随装载闪 |
| `LCD_SHARED_DC` | 20 | 输出 | LED5 闪 |
| `LCD_HARM_CS_N` | 19 | 输出 | LED4 闪 |
| `LCD_VIS_CS_N` | 18 | 输出 | LED3 闪 |

LED 是**共阳极**接法（官方 cst 注释与 `PULL_MODE=UP` 均可证）：输出低 → 点亮，输出高 → 熄灭。因此：

- **作为数字输出：功能成立**，代价是 6 个 LED 跟着总线乱闪，且每根多 510 Ω 到 3V3 的负载（灌电流约 6.5 mA，在 GW2AR 单脚 8 mA 驱动能力内）
- **作为数字输入：不可靠**，510 Ω 上拉会把低电平抬起来
- **作为模拟电极输入：禁止**，510 Ω + LED 结电容会彻底破坏 `PULL_MODE=DOWN` 的放电计数

载板的 6 路 `SENSE`（`29,30,31,41,42,48`）**没有一个落在 15–20 上**，这点是对的。需要确认的只有一件事：**载板是否接受 6 个 LED 常闪**。若不接受，得把这几根挪到 `73/74/75/76/86/72/71` 这 7 个干净脚上，但那样排针脚位就与现有载板走线不符，属于改板范畴。

### 6.7 结论

1. `nano-header-candidate.csv` 的引脚映射**正确，不必实测**（原 §2.3 作废）
2. 排针只能给出 7 路 27–42，**载板不可能做 16 路直连**，扫描链是唯一出路
3. 32–40 是 FPC/HDMI 专用，v1 的 16 路若从 FPC 座引线则成立，但会带上 HDMI 座的寄生负载
4. 15–20 做输出的代价是 6 个 LED 常闪，需产品层决定是否接受
