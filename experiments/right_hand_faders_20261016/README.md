# 右手分区推子：独立RTL与交互原型

状态：控制器数字行为与浏览器原型在下述范围**已验证**；产品接合**部分实现**，实体屏驱动/声音应用/音频平滑/联合PnR/实机**待实现/待验证**。不替换现有GUI或码流，不把浏览器计算算成实体机实现。

用户已确认：竖直推子左右分侧；同侧取最近触点；两侧都有触点时取两者高度算术中点；松手保持。新增要求：每根推子有分区，B不能因距离更近抢A区触点，作用范围可调。

当前原型按**横向距离＋分区硬边界内的可调半径**实现。用户没有选择“无条件全屏最近”。区内调整与是否允许显式扩展邻区的进一步问答仍待答复，不把原型设置当作额外已批准规则。8组/800×480/5点是可替换的示例配置。

## 试用

在项目根目录运行：

```powershell
python experiments/right_hand_faders_20261016/serve_preview.py
```

打开 <http://127.0.0.1:8766/>。若8766已有本轮预览服务，直接打开，不重复运行。服务仅绑定本机；Ctrl+C停止该命令。

- 三个演示按钮分别展示同侧取近、左右中点、放大范围仍不跨区。
- 鼠标拖动；Shift＋单击固定触点，可继续拖动；右键删除固定点。支持真实浏览器多点触摸，最多5点。
- “松开全部触点”保留推子位置；“恢复初始位置”回到底部。恢复仅为几何目标，尚未接入声音侧RESET平滑。
- 原型没有声音、串口或设备存储访问；页面百分比是推子位置，不是最终增益/响度。8组到16分量的映射未冻结。

## 代码与接口

- `rtl/rh_fader_bank.v`：完整触点帧快照→逐推子分侧仲裁→整帧原子提交；NF/NT/坐标位宽可配；动态分区、轴线、半径、上下界；恢复优先并取消处理中旧帧。
- `rtl/rh_fader_panel.v`：800px/8组/5点示例封装，固定几何、动态半径，裁去未使用的调试输出，供资源探针/后续板级包装。
- `reference.py`、`preview/model.mjs`：独立参考与浏览器模型；`preview/app.mjs`为触摸/鼠标交互，不是FPGA驱动。
- `evidence/validation.json`、`ui-validation.json`：实际运行结果；完整源/日志/综合报告/备份绑定见`delivery.json`。

所有packed数组低位为元素0，坐标为像素，Y向下增大；半径包含边界，分区为按X顺序、不重叠的`[zone_lo,zone_hi)`。交界点只属于右侧分区。无触点保留旧位置、清除当前驱动标志。横向距离相同时取较小ID，保证报告顺序不改变结果；轴线上触点同时作为两侧最近者，直接跟随该点。中点使用加宽和再除2，半像素舍向较小Y，最大误差0.5px，随后限幅。

`frame_valid/frame_ready`握手时上游必须提供完整且可信的报告、唯一稳定ID和同一时钟域数据。忙时输入可变化，快照不受影响；输出在`frame_done`时整体提交。错误垂直范围/分区几何置`config_error`并拒绝该帧；恢复合法时优先、丢弃在途帧，`restore_done`表示目标恢复已发布。丢失/无效传感报告不能冒充“全部抬手”，由未来驱动的可信报告/超时层处理。

## 已运行验证

```powershell
python experiments/right_hand_faders_20261016/run_validation.py
```

需要既有`D:/iverilog/bin/iverilog.exe`与`vvp.exe`；浏览器模型交叉核对使用已有Codex Node运行时。11项规则单元测试；1/8/16根推子各620帧及固定面板封装620帧，共2480帧RTL/参考核对；快照隔离、原子提交、错误配置、恢复/复位抢占另有控制检查。浏览器模型对同2480组输入核对，不能把这两类结果加成4960种独立场景。

`test_ui.mjs`在独立无用户配置的Chrome上下文做实际触摸/按钮/布局测试，11项通过；含同帧双指释放不发布错误单指中间结果。浏览器按显示帧合并触摸事件，未验证物理传感器或光学响应。截图见`evidence/preview-midpoint.png`、`preview-zones.png`、`preview-mobile.png`，窄窗口只验布局，不代表7英寸手指操作已实测。

Gowin独立综合：通用动态版本1317Logic/784寄存器，示例封装564Logic/380寄存器，二者0BSRAM；均无真实IO约束或PnR。默认8×5接受帧到发布49时钟；27MHz名义换算约1.815µs，仅控制器处理，不含触摸扫描/I²C/音频，不是≤10ms整机验收。

实现前主目录/最新引擎/主机分别194/930/219个受保护输入已ZIP备份并校验。没有修改这些产品源文件，旧main192基线保持；未合入音频引擎，不改其采样率/包络/释放/谱逻辑。后续先明确作用范围，再接触摸驱动与独立演奏修饰层，保持基础谱/草稿/演奏状态分离。
