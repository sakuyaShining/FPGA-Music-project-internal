# 左手位置到音乐事件的接合原型

状态：**部分实现**。理想RC跳变→扫描/位置→实例事件/逐指绑定→真实合成PCM的数字链路**已验证**。原产品、GUI11版和此前68号接合区保持原样；没有上板、实物传感/显示、试听或采购。

## 接口和生命周期

`left_contact_bridge` 接受完整不可变的位置报告。每个音位当前一个接触，落指产生带实例身份的ON；保持/移动发送逐指位置，不再产生ON；松手用原实例和落指音高发OFF。每次仅一个请求在途，ready表示已被分配器接收，result表示完成分配/释放判断；两者均不表示已经听见声音。

13位实例为 `{8位世代,5位音位}`。只有上一次请求完成后才允许下一次，同一音位旧生命周期关闭后才递增世代。260次重按覆盖了世代回绕；这是有界、顺序、同钟协议，不声称可以防御无限期重放旧令牌。未来分层还需增加层/子声部组织，不把一个实例等于一层当成最终架构限制。

`note_map_owned` 对带身份事件按实例匹配，对原UART/定序器等输入继续按音高匹配，并隔离两域的OFF。两个音位即使是同MIDI仍占不同组。未匹配的OFF有明确success=0结果，不发布voice事件。新输入经独立端点与原FIFO公平轮转，不给旧队列偷偷增加/遗漏元数据，也没有改主机串口协议。

分配通知时gact/gact_q尚未全部稳定；桥等待后再发bind，避免绑定被同拍重用通知清除。声部被其他音抢占后，旧触点丧失控制，旧移动/松手不能影响替代声音；当前策略等待该触点真正松手后再允许重新起音，具体体验仍需试听确认。基准音高和位置尺度是分开的；测试沿用既有256位置单位/八度数字接口，不是毫米灵敏度或已冻结滑音范围。八度档位在奏切换未接，不把保留落指音高用于正确释放解释为最终八度策略。

## 失效处理（可配置原型）

- 连续8个无效报告释放对应实例并阻止保持中的手指自动再起音；恢复后需观察到有效松手。
- 100ms未收到报告时释放本桥拥有的实例；帧号跳变同样进入保护。只发送本实例OFF，不按MIDI关闭其他来源。
- 校准报告先释放原接触；实体校准UI尚未接。
- 请求/完成等待8192拍超限只报警，保留在途身份等待真实结果，不猜声部、不重新发送已接受的ON。若分配器本身停止响应，尚需整机故障/复位通路，不能宣称桥能独自释放失效的引擎。

这些值和故障策略是工程候选，尚未实物/试听签收。正常松手进入原释放包络，不代表声音立即硬切。
