# 整机实现跟踪入口

这是向完整实体机推进的开发接合区。整体仍为**部分实现**，按 `state.json` 区分已验证的数字行为、待接合的实体链路和讨论中的音乐细则。各次实验不会因为出现在这里就自动成为产品功能。

当前结构：

```text
六路RC整形输入 → 595受控扫描 → 完整原始帧 → 显式校准/差值 → 26条位置报告
                                                               │
                                    待接：音符实例/确认/逐指绑定 ──┘

数字音符/逐指输入 → 32组×16分量合成 → PCM/I²S
                         ↑               └→ 只读FFT/波形/轨迹 → 已有小屏
右手完整触点报告 → 分区推子/映射/平滑

待接：四槽完整配置/分层、7英寸真实报告/界面、EEPROM持久保存、TF/SDRAM录放/混音
```

开发顺序以共享接口和整机资源为依据。先让左手报告可靠地对应音符实例，再增加同音分层；否则多指/层/尾音难以正确释放。PCM伴奏与现场必须并行，不能复用“播放时禁用手奏”的旧状态。草稿、显式应用和断电保存继续分开，不能把连续表情写入EEPROM。

已有 `engine/` 和 `rtl/` 来自较新引擎与66/67号、音乐可视化实现；原工作树与历史证据保持。新增可选 `LEGACY_PAD` 默认1，联合探针显式0，避免把旧扫描与新扫描同时占用资源。`synthesis/joint_serial/` 则在构建时显式选择共享滑音运算，基础候选仍使用原实现，两者结果分别记录。

下一项落地先做事件身份及背压：每次接触有独立实例，必须知道事件是否被接收及分配到哪个组；释放、重用、同音和分层不能靠观察MIDI相同来猜。滑动只改变所属音高，不重奏。音位25/26端点、八度在奏切换、硬区是否显式扩展邻区、强调曲线/分组及PCM作用范围尚未最终裁定，不在接口接合时暗自改变。

制造仍受约500元约束。现有屏接口/整价、RC前端/保护资格、最终GPIO与资源/时序未闭环，PCB不可仅凭原理图规则检查0项就发布。
