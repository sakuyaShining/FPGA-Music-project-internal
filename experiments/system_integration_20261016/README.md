## 本轮实现

- `scan_shift595`：每次先完整移入8位，再锁存；支持总线申请/授权，授权须保持至事务结束。扫描控制字与既有小样约定一致：Q0…Q3地址，Q4禁用，Q5公共RC驱动。显示数据可以经过共享移位线，但不得触发扫描锁存。共享显示总线仲裁器本身仍待接。
- `rc_mux_scan`：先禁用旧通道，再切地址、接通/放电、锁存充电控制、并行计时。6路×16地址=96原始节点，逐路坏起始极性/超时诊断，报告背压、顺序与帧号；计时从实际锁存沿开始，经2级输入同步。理想测试相位中计数为注入延迟+1；这不是模拟电容SPICE或阈值资格测试。
- `rc_delta_store`：显式校准捕获完整一帧；没有“上电时必然没按”或自动吞掉长按的假设。正差值、有效性位、顺序/帧号检查，完整帧冻结给消费者。参考负载节点可存储，但尚未实现用它们评估模拟链资格。
- `rc_strip_positions`：26条三电极正差值的重心，位置0…256，阈值滞回/连续帧确认，串行共用除法，原子发布和背压。当前测试配置两帧确认；无效电极报告故障并保持旧触点/位置，**接音符前须补有界故障释放策略**，不能无限保持作为实体产品规则。
- `instrument_joint_probe`：上述前端与右手修饰、真实合成引擎、小屏可视化并行。左手位置还没有接到音符实例/分配反馈，音频由独立数字事件驱动，不能称实体滑条已经发声。
- `LEGACY_PAD` 默认1保留原扫描兼容路径；联合探针显式0，不叠加重复前端。
- `optimization/pitch_mod.v`：构建时显式选择的共享滑音运算候选。延后物化32组状态，但逻辑读口立即呈现原同时更新结果，装载优先级不变。相邻sample_en须至少33拍，实际链路为512拍；不支持更快时序并有超限诊断。原全局LFO实现及其已知跳变问题保留，没有借优化改变音乐行为。

节点映射、三电极、26音位、两帧确认、阈值和RC等待时间都是可替换原型设置。默认节点号=`地址×6+路号`，0…77供26条例，78…82可留给八度区、83备用、84…95可作每路两个参考负载。布局可能跨MUX，物理走线/串扰未资格；不能据此冻结最终26端点或5个八度档。当前原始容量预留不等于八度选档算法已实现，更不测力。

## 本版实际验证

| 范围 | 结果 |
|---|---|
| 扫描时序 | 32行、128完整控制字；禁用切换、物理锁存起点、超时/卡死、授权等待及背压通过 |
| 原始帧→位置 | 160帧独立Python参考；含未校准、重新校准、端点、大幅度算术、无效节点、滞回/确认、乱序重同步和冻结报告 |
| 完整扫描→位置 | 6路96节点26条，5帧，理想可编程数字电平模型通过 |
| 默认扫描时间 | 接近超时的2040拍充电、26条均参与位置计算：无总线等待50192拍=1.859ms；每控制字等待64拍时54288拍=2.011ms，**后一情景不满足2ms采集规划** |
| 原扫描兼容音乐 | 374 PCM样本、8事件，与原核心的音符状态/单位增益PCM及I²S一致性通过 |
| 联合扫描＋音乐＋FFT | 1574 PCM样本、43位置报告、1次FFT；频谱分析间隙83样本与独立42593拍运算预算一致，音频继续输出；释放尾音和推子恢复检查通过 |
| 共享滑音对照 | 40000周期、80000次输出/相位检查、2560000次逻辑组状态检查、4900装载、625更新纪元；碰撞/步进变化、开关及超限诊断通过 |
| 优化联合版 | 同一1574样本/43报告/FFT场景，对独立重命名的原引擎对照通过，未发生滑音调度超限 |

两帧确认不能简单当作总延迟=两倍帧长：特定节点刚错过扫描，还需等待下一帧采集及整帧发布，理想上限可接近三帧；任意总线阻塞或消费者长期不接收会继续增加。因此上述时间仅指定模型的左手扫描预算，不是实体最坏≤10ms已通过。右手100Hz触摸报告与真实屏仍各有延迟缺口。

首次联合测试误把FFT分析间隙当成必须为零；既有FFT本来就会在运算时暂停采集，未反压音频。已保留失败日志，改用独立运算周期预算核对实际83个间隙，同时保留PCM/I²S连续性门禁，没有把间隙改成0或删除旧缺陷。联合试验只走到小屏复位/分析，不包含完整LCD刷新或图像验收。
