# 右手分区推子到真实合成引擎的隔离原型

状态：**部分实现**。触点报告→推子→分量增益→平滑→真实合成PCM，在下述数字测试范围**已验证**；实体触屏、整机接线、布局布线、上板和试听仍**待实现/待验证**。未替换任何产品源码或码流。

## 实现与可替换设置

- 复用上一阶段 `../right_hand_faders_20261016/rtl/` 的完整报告、分区、同侧最近、双侧高度中点和松手保持逻辑。硬分区内调半径仍是原型解释；是否允许显式扩展到邻区尚待用户答复。
- `rtl/rh_fader_gain_map.v`：按运行时16分量→8推子映射读取增益表；整帧快照、背压、恢复取消未完成事务。
- `rtl/rh_timbre_slew.v`：每音频样本有界推进，完整增益组原子提交。恢复把目标改回单位增益，当前值平滑回落。
- `engine/tdm_engine_rh.v` / `tdm_top_rh.v`：最新引擎的独立可选副本，`RIGHT_TIMBRE=0` 默认关闭。只在读出的分量幅度上乘系数，不重载音符、不写回基础谱、相位、音高、包络或所有权。每次逻辑槽0固定整组系数，避免一个合成样本混用新旧控制帧。
- `rtl/rh_music_probe.v`：接入真实32声部×16分量、逐指表情、事件与I²S路径；端口是抽象数字接口，不是可直接接线的实体板顶层。

`audition-config.json` 是可替换的测试/试听配置：Y=52…420，单位增益Q8=256，顶端暂设512（2倍），每样本步进1。映射不是最终音乐规则，运行时输入可更换；测试还使用其他映射、步进和声部掩码。全幅256级恢复约4.85ms只是系数过渡时间，不是整机触控延迟。

当前夹具覆盖全部32个实时合成组，包括已松手但包络尚未结束的声音；范围由运行时掩码指定。此处“尾音”是合成声部的释放包络，已经渲染到混响/延迟缓冲的声音以及PCM伴奏不经过本修饰层。未实现多乐器分层分配，也未冻结回放修饰范围。

## 复现验证

在此目录运行（Icarus路径见脚本）：

```powershell
python check_assets.py
python run_validation.py
python run_external_probe.py
```

`run_external_probe.py` 要先已有 `prepare_synthesis.py` 与 `prepare_external_probe.py` 生成的诊断副本。它只测数字音乐输入，不模拟实体左手滑条，也不做可视化功能仿真。综合使用 Gowin V1.9.11.03 Education，生成入口 `synthesis/*/synth.tcl`，只运行 `syn`，没有CST/SDC或PnR。

实际结果见 `evidence/`：

| 测试 | 结果及边界 |
|---|---|
| 控制链 | 4报告，261个过渡样本；映射、中点、保持、恢复取消、步进与原子提交通过 |
| 合成内核对照 | 1030样本、全部512槽；关闭/单位增益逐拍一致；动态增益872个PCM样本改变；饱和20456次、零幅度66321次检查；相位/音高/包络等状态与原引擎一致 |
| 真实整链三音和弦 | 374样本、8事件；180个PCM样本改变，释放期40个PCM样本改变；保持中新增音符、恢复后PCM与I²S一致性通过 |
| 无旧扫描的诊断副本 | 同一374样本数字刺激通过；不含新实体输入前端，不代表完整联合功能验证 |
| 数据表 | 1024项与公式、单调性、端点及10位范围核查通过 |

`validation.json` 保留仿真当时输入。随后只给生成器增加几何/映射检查断言；`assets-check.json` 单独验证当前生成器，生成的LUT与已测RTL均未变化，不回写旧仿真记录。
