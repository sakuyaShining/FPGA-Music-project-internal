## 目录结构

```
FPGA-Music-project/
├── README.md                  ← 你在这里（目录索引）
├── PROJECT_MEMORY.md          ← 记忆库存档（自动生成，勿手改）
│
├── docs/                      ← 文档（要读的东西）
│   ├── 01-竞赛情报/            ← 赛事情报、选题总览
│   ├── 02-技术方案/            ← 方案、bring-up、形态建议
│   └── 03-学习路线/            ← 学习计划与教程笔记
│
├── src/                       ← 【主战场】我们写的 RTL 源码
│   ├── rtl/                   ← Verilog 源文件
│   ├── sim/                   ← Testbench 仿真
│   ├── constr/                ← 引脚约束 .cst / .sdc
│   └── gowin/                 ← Gowin 工程文件 (.gprj)
│
├── refs/                      ← 参考资料（只读，不用改）
│   ├── candidate-guides/       ← 7 家厂商选题指南原文 PDF + 抽取文本
│   ├── official-notices/       ← 官网通知、竞赛背景
│   ├── report-template/        ← 官方作品报告模板
│   ├── vendor-examples/        ← 厂商官方例程（Tang Nano 20K audio 等）
│   └── _site-archive/          ← 官网抓取的原始数据（存档，一般不用看）
│
├── tools/                     ← 辅助工具（非项目本体）
│   ├── scripts/                ← Python/PowerShell 小工具
│   └── pylib/                  ← 本地 Python 依赖（pypdf）
│
└── notes/                     ← 临时笔记、调试记录、随手记
```

## 自动化

| 机制 | 说明 |
|---|---|
| **官网周检** | Windows 计划任务 `FPGA竞赛官网周检`，每周五 20:00 自动检查官网新通知/新文件，结果追加到 `docs/01-竞赛情报/monitoring-log.md` |
| 手动触发 | `powershell -NoProfile -ExecutionPolicy Bypass -File tools\scripts\weekly_check.ps1` |

## 命名约定

- **文档**：`docs/<分类>/<序号>-<标题>.md`，序号 00 起
- **RTL**：`src/rtl/<模块名>.v`，模块名小写下划线（如 `i2s_tx.v`、`osc_wavetable.v`）
- **约束**：`src/constr/<顶层名>.cst`
- **笔记**：`notes/YYYY-MM-DD-<主题>.md`

## 文档权威顺序

当文档之间冲突时，按此顺序取信：

1. **官方原文**（`refs/` 下的 PDF / 通知）——最高
2. **`docs/01-竞赛情报/01-选题确认与约束条件.md`**（项目宪法）
3. 其他设计方案文档
4. 临时笔记（`notes/`）——仅参考
