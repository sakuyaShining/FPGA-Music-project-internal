# 通用乐器定位下的方案修正（2026-10-22）

> 触发：用户两条方向修正
> 1. **不希望有除音乐可视化以外的上位机强依赖功能**
> 2. **要做通用乐器，不是"听起来像钟"；打击乐难兼顾时优先钢琴/小提琴**

---

## §0 一句话

**时长和起音范围完全够**（实测 1 ms – 8 s 全可达），**缺的不是参数范围，是三样东西**：双段衰减、两张烧死的表、参数持久化。
而 Q1 的 auto curve 因为要上位机算，直接违反第 1 条，撤回。

---

## §1 Q1 撤回：auto curve 违反"不依赖上位机"

上一版我给的做法是：配置里 `d_k_curve: null`，编译期由 `default_curve(spectrum_span(spectrum))` 填。这在技术上是对的（0 LUT），但**它把"这个音色该用多大梯度"的判断交给了上位机**。

如果演奏时不连电脑，或者用户改了频谱但没重跑编译器，梯度就跟不上。这正是你要去掉的那种依赖。

**而且"按泛音数猜意图"本身就不是通用乐器该做的事**——它是在为钟/马林巴做特化。真正的通用乐器，每个参数都该是一个用户能拧的旋钮，没有"智能猜测"。

**改为**：

| 项 | 上一版 | 现在 |
|---|---|---|
| `d_k_curve` 默认 | `null`（auto） | **固定 `8`** |
| `suggest_curve(span)` | 参与默认编译 | **降级为参考建议**，只用于界面提示"改成 N 个泛音后建议设为 X"，不自动生效 |
| 依赖 | 上位机算 | **0 依赖** |

`articulation_v2.py` 已改，自测第 1 组新增三条断言守着"默认值必须是固定的"。

---

## §2 通用乐器的默认值：全部改成中性

我前面几版的默认值全是"钟琴取向"，与通用乐器定位冲突。逐条改：

| 参数 | 钟琴取向（上一版） | 通用中性（现在） | 理由 |
|---|---|---|---|
| `strike.s_lvl` | 2（12.5% 余音） | **0** | 钟才有"嗡嗡"尾巴。马林巴、吉他、拨弦都该衰减到无声。想要余音自己调 |
| `hybrid_parts` | 前 3 后 13 | **前 8 后 8** | 前 3 后 13 是钟琴的分组。通用默认不该带倾向 |
| `d_k_curve` | auto(span) | **8** | 见 §1 |
| `tone.decay_ms` | 1200 | **1200（保留）** | 这条跟钟无关，是"默认不要太短"的通用建议 |
| `auto_release_ms` | null → 1500（有余音时） | **null → 2×基频（无余音时 680 ms）** | 余音关闭时不该多占 0.8 秒 |

## §3 通用乐器的可达性实测

用 `fit_exp` / `fit_attack` 直接跑，看四类基准乐器需要的参数能不能编出来。

### 3.1 衰减时长：全部可达

```
小提琴 持续   请求  200ms -> m=3 k=11 shift= 8  实得   203.9ms
钢琴 中音    请求 2500ms -> m=3 k= 9 shift=10  实得  2504.9ms
钢琴 低音    请求 8000ms -> m=3 k=14 shift= 6  实得  7335.2ms   (-8%)
吉他 拨弦    请求 1500ms -> m=3 k= 8 shift= 7  实得  1551.0ms
马林巴       请求  400ms -> m=1 k=10 shift= 2  实得   390.3ms
```

**1 ms 到 8 秒全覆盖**，只有 8 秒那条差 8%（受 `shift ≤ 15` 与 32768 步上限夹逼）。钢琴低音的真实衰减是 10–20 秒，8 秒略短，但已经"像"了。

### 3.2 起音：全部可达

```
钢琴 1ms     -> inc=619 shift=0  实得 1.01ms
钢琴 5ms     -> inc=249 shift=1  实得 5.01ms
小提琴 120ms -> inc= 83 shift=4  实得 119.85ms
小提琴 400ms -> inc=199 shift=7  实得 400.50ms
```

**1 ms 到 400 ms 全覆盖。** 钢琴的锤击（1–5 ms）和小提琴的弓起音（100–400 ms）都在范围内。

### 3.3 释放：全部可达

```
请求   20ms -> 实得   20.2ms
请求  200ms -> 实得  203.9ms
请求 1500ms -> 实得 1530.7ms
```

### 3.4 力度→音色：已经有了，而且是查表

这条我一开始以为是缺口，查下来发现**做完了**。`vel_shape.v`：

```verilog
reg [11:0] wtab [0:255];
initial $readmemh("vel_wtab.hex", wtab);
wire [7:0] widx = {vel, part};          // 16 档力度 × 16 泛音
wire [8:0] w_rom = wtab[widx][8:0];     // 256 = 1.0 倍
```

- **256 项表**，能表达任意谱形（注释里举了"奇次优先的单簧管式空洞、弱音器的凹陷"）
- 三条硬约束：基音任何力度不置零、最少保留 3 条泛音、`base==0 ⇒ amp==0`
- 运行时连续旋钮 `vscale`（0 = 关，256 = 与表一致，511 ≈ 2 倍）

钢琴的"弹得重 → 高次泛音多"就是这张表在做。

### 3.5 发现：逐泛音 fit 会让衰减曲线"断掉"

`sustain` 的每泛音 `d_k` 现在由 `compile_tone` 里每个泛音**独立** `fit_exp`。实测这有问题：

```
钢琴中音 2500ms, s_lvl=120，逐泛音独立 fit：
  k= 0 -> d_m=3 d_k= 9 d_shift=10  2504.9ms  jitter 19.40
  k= 1 -> d_m=3 d_k= 7 d_shift=12  2485.5ms  jitter 77.65   ← m 相同但 shift 跳到 12
  k= 2 -> d_m=1 d_k=13 d_shift= 4  2363.2ms  jitter  0.28   ← m 从 3 跳到 1！
  ...
  k=10 -> d_m=3 d_k=15 d_shift= 3  1803.2ms  jitter  0.13   ← m 又跳回 3
```

两个后果：

1. **`d_m` 在 1 和 3 之间跳**。`m=3` 的衰减是 `(lvl×3)>>k`，初期比 `m=1` 快 —— 16 个泛音混用两种形状，频谱演化不连续，听感是"某些泛音消失得突然"。
2. **jitter 最高 78 ms**。`shift=12` 意味着每 4096 拍才衰减一步，时长误差 3%。

**改法：只 fit 基频，其余泛音按梯度递减**

```python
decay0 = fit_exp(tone["decay_ms"], sustain)          # 只算一次，m/shift 全局统一
for i in range(PART):
    d_k = max(0, decay0['k'] - round(spread * i / (PART - 1)))
    # m 和 shift 用 decay0 的，只有 d_k 递减
```

实测结果（已写进 `articulation_v2.py`，自测第 9 组守着）：

```
钢琴中音 2500ms, spread=4：
  m=3 统一，shift=10 统一
  d_k = [9,9,8,8,8,8,7,7,7,7,6,6,6,6,5,5]     ← 严格单调
  基频 2505ms → 第 16 泛音 155ms              ← 16.1 倍跨度
```

`spread=0` 时 16 个泛音时长完全相同（1228.0ms），可用来做"风琴"式的静态音色。

**`decay_spread` 是个新参数**（0–8），加在 `tone` 里。它是"高次泛音比基频快多少档"，每一档约 2 倍。默认 4（16 倍跨度）。

这是**纯编译器改动，0 LUT**，而且比 strike 的梯度更影响"像钢琴"——因为钢琴的频谱演化发生在 sustain 阶段，不是敲击瞬间。

## §4 真正缺的三样东西

### 4.1 双段衰减（最影响"像钢琴"）

`osc_env.v` 只有单段 `DEC`：

```
ST_IDLE → ST_ATK → ST_DEC → ST_SUS → ST_REL → ST_IDLE
```

钢琴的真实衰减是**先快后慢**：三根同音弦初期同相，能量快速耦合到共鸣板；后期逐渐失相，衰减变慢。单段指数只能均匀衰减，听感"电子味"就来自这里。

**放不下第二段的证据**：88 位词布局

```
[87:48] 40 位自定义包络：[39:36] 空闲 4 位 | [35] custom | [34:31] a_shift
                        | [30:15] a_inc | [14:11] d_shift | [10:7] r_shift
                        | [6:5] r_m | [4:0] r_k
[47:32] ratio_q8 | [31:24] amp | [23] 保留 | [22:7] s_lvl | [6:5] d_m | [4:0] d_k
```

第二段衰减至少要 `d2_level[15:0] + d2_m[1:0] + d2_k[4:0] + d2_shift[3:0] = 25 位`，而空闲只有 4 位 + `[23]` 的 1 位 = 5 位。

**三条出路**：

| 方案 | 做法 | 代价 | 11-04 前可行？ |
|---|---|---|---|
| A | 词宽 88 → 113 位 | 协议 11→15 字节，BRAM 10→13 块，`encode/decode` 全改 | ✗ |
| B | 加一张 `decay2_tab[64]`（4 槽 × 16 泛音 × 5 位） | 320 bit，新写口，+15 LUT | 勉强 |
| C | 不做，用"每泛音 epar"近似 | 0 | ✓ |

**C 能到什么程度**：每泛音独立的 `d_k` 已经能做"低次慢、高次快"的频谱演化，这是钢琴最重要的特征之一。缺的只是"同一个泛音内部先快后慢"。**听感上大概能到 70–80%**。

### 4.2 两张表都是编译期烧死的

```verilog
initial $readmemh("vel_wtab.hex",  wtab);      // vel_shape.v:62
initial $readmemh("tilt_wtab.hex", tilt_rom);  // note_map_owned.v:174
```

`initial $readmemh` 意味着**写进 bitstream**。后果：

- 用户想调"这个音色的力度曲线" → 改 hex → 重新综合 → 烧板
- 演奏现场做不到
- **这正是"不依赖上位机"的真正障碍**，比 EEPROM 还硬

**能改的**：`vscale`（力度灵敏度）、`tilt`（亮度表索引 0–15，选表里 16 种曲线之一）、`spec_ram`（16 个泛音幅度）、`instrument_table`（16 个泛音的 ratio/amp/epar）。
**不能改的**：表的形状本身。

**改成可写要付的代价**：`wtab` 256×12 = 3072 bit，用 BRAM 需同步读（+1 拍流水），而现在是异步读（`wtab[widx]` 组合）。加一拍会动 `note_map_owned` 的流水线对齐，风险高于收益。

### 4.3 参数持久化（EEPROM）零实现

`grep -rl "24LC\|eeprom\|EEPROM"` 在 `engine/src` 与 `rtl` 无结果。`i2c_master.v` 只在 `sim_build/board_diag_20261009/`。

没有 EEPROM 意味着：**每次开机，所有音色和演奏参数都要重新下发**。这是"依赖上位机"的根，比 §4.2 更急。

容量估算：`4 槽 × 2 bank × 16 泛音 × 11 字节 = 1408 字节/套`，加 `artic_*` 53 位（7 字节）。24LC256 有 32 KiB ≈ 23 套。

## §5 上位机依赖要分三层看

| 层 | 内容 | 现状 | 能不能去掉 |
|---|---|---|---|
| **演奏** | 按键盘 → 发声 | **不依赖**。板子独立跑，72/73 号测试工程已验证 | 已达成 |
| **参数编辑** | 改音色、改激发模式、改力度曲线 | 依赖上位机（GUI 7000 行） | 需要屏 + 菜单 + EEPROM |
| **音乐可视化** | 频谱、音符、波形显示 | 依赖上位机（`live_visualizer.py`） | **你说这条可以保留** |

所以真正要补的是中间那层。而它的三块拼图：

1. **EEPROM**（存参数）— 零实现，但器件便宜（24LC256 ¥4.50）
2. **本机输入**（改参数）— 现有 EC11 ×1、推子 ×8、触摸 ×16；够做"选参数 + 调值"，但菜单层级会很深
3. **本机显示**（看参数）— **没有屏**。88 号 BOM 里有 ER-TFTM070-5V4（¥280），但驱动（RA8875）在 89 号文档里还没完成

**11 月 4 日之前的现实**：第 3 块拼图做不出来。所以在那之前，"编辑依赖上位机、演奏不依赖"是唯一可行形态。这不违反你的要求——因为演奏本身不需要电脑。

## §6 按"优先钢琴/小提琴"重排优先级

你说"打击乐难兼顾就优先钢琴小提琴"。按这个重排：

| 优先级 | 事项 | 为什么排这里 | 工作量 |
|---|---|---|---|
| **P0** | sustain 路径调参：`decay_ms=2500`、`sustain_level=120`、`attack_ms=3` | §3.1/3.2 证明全部可达，**现在就能试听**，不用改一行 RTL | 改配置 + 试听 |
| **P0** | 力度曲线：`vscale` 从 0 调到 256，对比 | `vel_wtab` 已经存在，只要打开 | 改一个寄存器 |
| **P1 ✅** | 每泛音 `d_k` 梯度（`decay_spread`） | **已实现**，§3.5。16 倍跨度、单调、m/shift 统一 | 只改编译器，0 LUT |
| **P2** | EEPROM 持久化 | 去掉"每次开机重下发"的依赖 | 4 件工作 |
| **P3** | 双段衰减（方案 B） | 补上"先快后慢"，从 75% 到 90% | 新表 + 写口 |
| **P4** | 表可写（`wtab` 改 BRAM） | 让用户定义力度曲线 | 动流水线，风险高 |
| **P5** | 屏 + 菜单 | 彻底去掉编辑依赖 | 需要硬件 |

**P0 那两条不需要改任何 RTL，今天就能验证。P1 已经做完。** 这比继续讨论 strike 的梯度更有价值——因为你要的是通用乐器，而 sustain 是四类乐器里三类的共同基础。

## §7 需要你确认

**Q4｜`d_k_curve` 默认 8 这个数，是不是也该给一个"不猜"的做法？**
现在默认 8 是我拍的。如果你希望连这个都不预设，可以让它默认 0（无梯度），用户想用梯度自己拧。代价是"开箱即用"的音色会偏平。

**Q5｜sustain 模式要不要也用梯度？——我自己先答了，不用**

本来想问要不要把梯度也接到 `p_epar`（+10 LUT），查完发现**不需要**：

- **strike** 的 `d_k` 是绝对量，16 个泛音全一样，所以需要梯度来制造差异
- **sustain** 的 `d_k` 来自音色（`epar` 每泛音一份），预设 2 就是 17→10 的梯度

也就是说，**sustain 的梯度已经在音色里了**，只是当前编译器给 16 个泛音填了同一个 `decay_ms`。要改的是编译器，不是 RTL：

```python
# 现在：16 个泛音用同一个 fit_exp(decay_ms, sustain)
# 改成：按泛音序号给不同 decay_ms
for i in range(PART):
    part_decay_ms = tone["decay_ms"] * (1.0 - 0.4 * i / 15)   # 高次衰减快 40%
    decay = fit_exp(part_decay_ms, sustain)
```

**0 LUT，只改编译器。** 而且这条比 strike 的梯度更影响"像钢琴"——因为钢琴的频谱演化发生在 sustain 阶段，不是敲击瞬间。

**Q6｜11-04 的视频，目标是"像钢琴"还是"功能齐全"？**
如果是"像钢琴"，P0+P1 就够，不用碰 RTL；如果是"功能齐全"，得把 strike 也调好，那是 P3 之后的事。
