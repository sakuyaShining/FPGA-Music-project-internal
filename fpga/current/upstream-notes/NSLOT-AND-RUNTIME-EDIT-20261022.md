# NSLOT 三角约束 + 运行时音色编辑 · 2026-10-22

回应两个问题：
① 泛音数与复音数为什么被 `NSLOT` 绑死；
② 预设只是出厂默认，最终设计有实时编辑（音色 + 激发模式）——这条路径现在有什么、缺什么。

全部只读核查。

---

## 一、NSLOT 绑死的本质：一个样本周期被切成 NSLOT 拍

### 1.1 机制

```
NSLOT   = 时隙总数 = 同一时刻能同时存在的正弦振荡器个数
PART    = 每个音符占用的时隙数（= 泛音数）
音符数  = NSLOT / PART
```

而采样率的定义是：

```
fs = clk / NSLOT        （因为每个时隙每样本算一次，1 时隙 / 拍）
```

`tdm_top_owned.v:127` 写死 `NSLOT = 512`，`clk = 27 MHz`：

```
fs = 27,000,000 / 512 = 52,734.375 Hz     周期 18.963 µs
```

### 1.2 为什么是"1 时隙 / 拍"

引擎的流水线是 4 级（`LAT = 4`）：读地址 `sc+4`、`sc+1` 算包络与幅度、`sc+4` 累加。
一个乘法器要在 512 拍里轮流服务 512 个时隙——**每拍恰好一个时隙，没有空闲拍**。

所以 `NSLOT` 不是"想设多大就设多大"，它是**一个样本周期被切成的拍数**。

### 1.3 三种配置的取舍

| NSLOT | fs | 周期 | 16 泛音 → 复音 | 32 泛音 → 复音 |
|---:|---:|---:|---:|---:|
| 256 | 105.5 kHz | 9.48 µs | 16 | 8 |
| **512（现在）** | **52.7 kHz** | **18.96 µs** | **32** | **16** |
| 1024 | 26.4 kHz | 37.93 µs | 64 | 32 |
| 2048 | 13.2 kHz | 75.86 µs | 128 | 64 |

**想要 32 泛音又保持 32 复音 ⇒ 必须 `NSLOT = 1024` ⇒ fs 掉到 26.4 kHz ⇒ Nyquist 只剩 13.2 kHz。**

13.2 kHz 对音乐来说太窄：小提请的泛音能到 15 kHz 以上，会明显发闷。

### 1.4 想三个都要，只有两条路

| 路 | 代价 | 现实性 |
|---|---|---|
| 时钟 27 MHz → 54 MHz | `NSLOT=1024` 时 fs 回到 52.7 kHz | **不可行**：全功能构建 setup 已 −0.700 ns，翻倍时钟直接崩 |
| 每拍算多个时隙（并行乘法器） | DSP 从 22.75 用到 45.5 | **不可行**：DSP 上限 24，只剩 1.25 |

**所以这是个三角约束：时隙数 × 时钟频率 × 并行度。三样里只能挑两样。**

### 1.5 结论：不要动 NSLOT

现役配置（32 组 × 16 泛音 @ 52.7 kHz）是这三个资源下的合理折中。
**提升音质应该走"16 个泛音怎么用"而不是"用更多泛音"**——这正是下一节的问题。

## 二、运行时音色编辑：硬件其实已经完备

### 2.1 存储全貌

`engine/src/instrument_table.v` 第一行注释：

> `// Four volatile slots, two banks per slot. Commit needs all 16 words.`

```verilog
reg [87:0]  words[0:127];    // 4 槽 × 2 bank × 16 泛音 = 128 个 88 位字
reg [15:0]  written[0:3];    // 每槽 16 位，标记哪些泛音已写
```

读地址 7 位：`read_addr = {slot[1:0], bank, part[3:0]}`。

### 2.2 双缓冲：演奏中换音色不炸音

```verilog
words[{slot, !banks[slot], part}] <= word;
```

注意 `!banks[slot]`——**写入的是当前不活动的那个 bank**。
必须 16 个泛音全写完（`written[slot]` 全 1）才允许 `commit`，commit 时才翻转 `banks[slot]`。

**这是"演奏中无缝换音色"的基础机制，已经实现好了。**

### 2.3 88 位怎么分

| 位段 | 宽度 | 内容 |
|---|---:|---|
| `[87:48]` | 40 | **自定义包络**（`load_env`） |
| ├ `[35]` | 1 | custom 标志 |
| ├ `[34:31]` | 4 | 起音移位 |
| ├ `[30:15]` | 16 | 起音增量 `a_inc` |
| ├ `[14:11]` | 4 | 释放倍率 |
| └ `[10:7]` | 4 | 释放移位 |
| `[47:0]` | 48 | **泛音条目** |
| ├ `[47:32]` | 16 | `ratio_q8`（倍频，256 = 1.00×） |
| ├ `[31:24]` | 8 | `amp`（起音幅度） |
| ├ `[22:0]` | 23 | `epar` = `{s_lvl[15:0], d_m[1:0], d_k[4:0]}` |
| └ `[23]` | 1 | **保留，必须为 0**（校验会拒） |

> 关键：`epar` 存在 `epar_mem[0:NSLOT-1]`，**每泛音一份**；
> `load_env` 也存在 `pe_mem/epar_mem` 的扩展位里（`EPW = 31 + 40 = 71` 位），**也是每泛音一份**。
>
> **所以起音速率、释放速率、衰减速率、衰减终点，全部可以每泛音独立。硬件没有缺口。**

### 2.4 两个 bank = 激发模式

`strike.hex` / `sustain.hex`（各 16 行，格式与 `preset_part.hex` 相同）就是两种激发的示例：

| 文件 | 泛音 1 的 amp | `s_lvl` | 比例 | 含义 |
|---|---:|---:|---:|---|
| `strike.hex` | 90 | **0** | **0%** | 衰减到零 ⇒ **打击** |
| `sustain.hex` | 180 | 24584 | 75.0% | 衰减后保持 ⇒ **持续** |

这两个文件现在只在 `tb_layers.v` 里作为测试用例（`example_strike` / `example_sustain`），
**但 `bank` 这一位的设计意图很清楚：一个槽里放"打击"和"持续"两套参数。**

### 2.5 校验规则（编辑界面必须遵守）

`instrument_table.v:29-31` 会拒绝这些写入并置 `error`：

- `word[23]` 非 0（保留位）
- `|word[87:84]` 非 0
- `word[83]` 置位时：`word[78:63]` 为 0 或 >32768，或 `word[54:53]` 为 0，
  或 `word[47:32]` 为 0，或 `word[22:7]` >32768，或 `word[6:5]` 为 0

翻译成参数约束：

| 参数 | 合法范围 |
|---|---|
| `ratio_q8` | **不能为 0** |
| `d_m` | **不能为 0**（1–3） |
| `s_lvl` | **≤ 32768**（32768 = 100%，不是 65535） |
| `a_inc` | 视 custom 标志而定 |

> `s_lvl` 满量程是 **32768 = 100%**（`osc_env.v:42` 原文「0 = 静音，32768 = 满幅（1.0）」），
> 所以 `≤ 32768` 这条不是限制，正好等于"允许到 100%"。
> 界面的 `sustain_level` 是 0..255，映射关系为 `s_lvl = sustain_level × 128`
> （验证：默认 `sustain_level=192` → 192×128 = 24576，与 `sustain.hex` 的 24584 一致）。

## 三、预设表 vs 运行时表

| | `preset_part.hex` | `instrument_table` |
|---|---|---|
| 类型 | ROM（只读） | RAM（可写） |
| 容量 | 64 × 48 位 | 128 × 88 位 |
| 内容 | 4 预设 × 16 泛音 | 4 槽 × 2 bank × 16 泛音 |
| 每泛音可编辑字段 | ratio / amp / epar | ratio / amp / epar **+ 40 位自定义包络** |
| 何时生效 | 上电 `$readmemh` 加载 | 运行时写 + `commit` 翻转 bank |
| 掉电 | 保留 | **丢失**（`volatile slots`） |

**所以你说得对：预设只是出厂默认。真正要设计的是运行时表这一层。**

而且运行时表比预设表**多了 40 位自定义包络**——预设表根本没有这个字段。
也就是说：**"频谱演化"这件事在预设表里只能靠 `epar` 的 3 个参数做，
在运行时表里可以用完整的 40 位包络做，表达力强得多。**

## 四、实时编辑的缺口清单

| # | 缺口 | 现状 | 影响 |
|---|---|---|---|
| **E1** | **掉电丢失** | `volatile slots`，注释原文 | 用户调好的音色断电就没了。需要 24LC256 EEPROM（BOM 已有，¥4.50） |
| **E2** | **bank 只有 2 个** | 1 位 | 激发模式最多 2 种。"敲击 / 拨弦 / 弓擦"三种做不了 |
| **E3** | **编辑界面不存在** | 只有 `cfg_valid/slot/part/word` 这层寄存器口 | 需要上位机或实体界面把它组织成人能用的东西 |
| **E4** | **试听规则未定** | 65 号 §64 只提出"编辑草稿"概念 | "草稿 → 试听 → 应用"的流程没有成文规则 |
| **E5** | **校验规则硬编码** | `s_lvl≤32768`、`d_m≠0` 等 | 界面必须前置校验，否则用户操作被静默拒绝 |
| **E6** | `word[23]` 保留 | 1 位 | 少一个可用位，暂不影响 |

**硬件层面 E1/E2 是真实限制，E3–E5 是软件与规则层面的工作。**

## 五、这改变了什么：HEX 只是验证手段

我上一轮建议"改 `preset_part.hex`"，在你说明"预设只是默认"之后，它的定位应该调整为：

**不是最终方案，是 5 分钟的验证手段。**

理由：`preset_part.hex` 没有 40 位自定义包络字段，表达力比运行时表弱。
但它**改起来最快**——不用写上位机、不用改 RTL、不用碰 commit 时序，重烧就能听。

**建议的路径**：

| 步 | 做什么 | 目的 |
|---|---|---|
| 1 | 改 `preset_part.hex` 的 `epar`（高次泛音 `s_lvl` 更低、`d_k` 更小） | **验证"频谱演化"这个方向对不对**，5 分钟出结果 |
| 2 | 听感确认后，把验证过的参数搬进 `instrument_table` 的 88 位字 | 确定运行时数据模型 |
| 3 | 用 `commit` 双缓冲做"演奏中换音色" | 验证无缝切换 |
| 4 | 接 EEPROM 做持久化 | 补 E1 |
| 5 | 定激发模式规则（`bank` 怎么切、什么时候切） | 补 E2/E4 |

**第 1 步的价值在于：如果方向错了，后面 4 步全白做。** 所以先花 5 分钟验证。
