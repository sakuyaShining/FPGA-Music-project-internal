## §1 现有清单到底是什么

来源：`hardware/pitch-sliders/prototype-schematic-20261015/`（README + 19 项 BOM + 231 引脚网表）
和 `hardware/pitch-sliders/selection-20261015/`（7 类 12 件关键料核对 + 预算上限）。

### 1.1 规模

- **19 种 / 53 件 / 231 引脚**，其中 207 引脚接入 59 个网络，24 个明确 NC
- 嘉立创原生严格规则检查 **0 项**；独立网表比对 **0 差异**
- 状态：**电路草稿已接线，PCB 仍为空，不含 Gerber，不是制造发布版**

### 1.2 它测的是什么

**不是电位器推子，是电容触摸电极。**

```
J2（12 针）= STRIP0_E0 … STRIP3_E2      ← 4 条滑条 × 每条 3 个电极
      ↓ 12 路 1kΩ 串阻（R21–R32）
CD74HC4067M96 ×2（U1/U2，16 路 MUX）    ← 12 电极 + 6 校准负载
      ↓ 公共端
FPGA_SENSE_A / FPGA_SENSE_B             ← **只有 2 根 sense 线**（J1 针 8/9）
```

配套：
- **47kΩ ×2**（R1/R2）= 起始测量阻值，RC 计时的时间常数主项
- **10pF / 47pF / 100pF 各 2**（C16–C21）= 三种参考负载，标定用
- **SN74LV595ADR**（U4）= 送地址 + 充放电控制字
- **SN74LV165ADR**（U5）= 读回
- **SN74LVC14ADR**（U3）= 施密特整形（放电=1、充电=0，计数器在充电字物理锁存后才启动）

`rc_mux_scan.v` 的状态机就是这条链路的 RTL：
`DISABLE → ADDRESS → CONNECT → DISCHARGE(512 拍) → CHARGE → MEASURE → PUBLISH`

### 1.3 完整版容量（selection README §3）

| 音位示例 | 音高节点 | 八度节点 | 右手节点 | 感测合计 | 校准 | 总占用 |
|---|---:|---:|---:|---:|---:|---:|
| 25 | 75 | 5 | 24 | 104 | 16 | 120 / 128 |
| 26 | 78 | 5 | 24 | 107 | 16 | 123 / 128 |

**8 路 × 16 地址 = 128 总节点。** 每音位 3 电极（75/25 = 3），所以完整版是「每个音位一条 3 电极短滑条」——滑条内测连续音高（滑音），跨滑条测音位。

## §2 我错的三处，逐条说清

### 2.1 编码器：C470754 就是带按压的

我在 `BOM-PROTOTYPE` §1.2 第 9 项写：

> EC11 编码器 | EC11E183440C（30 定位/15 脉冲，**带按压开关**） | 1 | ¥15.56 | 八度/参数旋钮。**注意 C470754 无按压，不可用**

现有清单 `catalog-checked.json` 原文：

```json
{"mpn": "EC11E15244B2", "lcsc": "C470754",
 "role": "push rotary encoder candidate", ...}
```

`selection-20261015/README.md` §1 原文：

> 旋钮候选为 30 定位/15 脉冲、20mm 扁轴、**1.5mm 按压行程**；厂家列为 Standard。

**所以 C470754 是有按压的，已经选好型、已经进原理图（SW1）。** 我推荐的 EC11E183440C 反而是没验证过的型号。这一项直接省 ¥15.56，且不用改设计。

### 2.2 那批「等 PCB」的件，早就在实物 BOM 里了

我在 `BOM-PROTOTYPE` §2 列的：

| 我写的 | 现有 BOM 实际 |
|---|---|
| 74HC4067PW,118 ×6 @¥2.89 = ¥17.34 | **CD74HC4067M96 ×2**（SOIC-24，不是 TSSOP） |
| SN74LVC14ADR ×5 @¥1.4573 = ¥7.29 | **SN74LVC14ADR ×1** |
| SN74LV595ADR ×1 @¥3.16 | **SN74LV595ADR ×1**（数量对） |
| SN74LV165ADR ×5 @¥2.1232 = ¥10.62 | **SN74LV165ADR ×1** |
| 24LC256-I/SN ×1 @¥4.50 | **24LC256-I/SN ×1**（数量对） |

**型号不同（PW vs M96）、数量差 3–5 倍。** 而且它们不是"等 PCB 才有"，是 10-15 就已经在原理图里放好的。

唯一仍然成立的是 24LC256：**硬件在，RTL 零实现**（`engine/src/` 下没有 `i2c_master`，只有 `sim_build/board_diag_20261009/` 里有）。selection README 也写「165/EEPROM的软件时序、传感计时与总线仲裁尚未实现」。

### 2.3 最严重的一处：扫描路线是 MUX 分时，不是 16 路直连

我在 `BOM-PROTOTYPE` §0 的核心论证：

> 电极是 inout，充电、放电、读回都在同一根线上……**所以 16 路电极直接接 GPIO + 铜箔就行，不需要任何外部模拟前端**。而 88 号 BOM 里那批器件……属于 `rc_mux_scan.v` 那条 83 节点的扩展路线……**原型只做 16 路，这条路线整个用不上。**

这段话在"只有 2 根 sense"的板子上**不成立**。现有小样 J1 的 12 针里，只有 **针 8 = FPGA_SENSE_A、针 9 = FPGA_SENSE_B**。两根线要读 12 个电极，必须靠 4067 分时。

更关键的是**两块顶层互斥**：

| 顶层 | 传感前端 | 能发声？ | 资源 |
|---|---|---|---|
| `tdm_top_owned.v` | `pad_scan #(.NCH(16))`，16 路 inout 直连 | **能**（73 号已验证） | CLS 99.6% |
| `instrument_sensor_probe.v` | `rc_mux_scan #(.LANES(6), .STRIPS(26))` | **不能**（纯探针） | 95.4% Logic |

`rc_mux_scan` 在整个 `engine/src/` 里**只被 `instrument_sensor_probe.v` 实例化**，主顶层里没有。

**所以现状是：能演的固件跑不了现有小样板，能跑小样板的固件不发声。**

这是 11-04 之前必须解决的一个岔路口，不是买料问题。

## §3 力度到底从哪来（双方都没实现，但物理信号在）

### 3.1 设计里没有"力度推子"这个东西

- 现有设计：「两排逐音滑条/两个八度、**独立八度选档条（不测力）**」
- 小样：4 滑条 × 3 电极，J2 外接电极试验板
- 完整版：25/26 音位 × 3 电极

**没有一路是专门用来测力的。** 所以我 10-23 写的「退路 B：推子全局力度」作废——板上没有这个件，加一路就要多一个电极、多一次扫描、面板多一个开孔。

### 3.2 但每个音位自带 3 个电极，力度是免费的

`rc_mux_scan` 每帧输出的 `row_count` 就是该通道的裸放电计数。`rc_delta_store` 把它减去基线得到 `read_delta`。

- **轻按**：指尖接触面积小 → 电极对地电容增量小 → `delta` 小
- **重按**：覆盖层被压扁、接触面积大 → 电容增量大 → `delta` 大

`rc_strip_positions` 现在只用 `delta` 做**位置质心**和 `contact`/`invalid` 判定，**完全没算力度**：

```
grep -i "vel|force|pressure|strength" instrument_sensor_probe.v rc_strip_positions.v rc_delta_store.v
→ 零命中
```

所以力度通路在 MUX 路线上也**一行没写**——但跟 `pad_scan` 路线一样，原始信号每帧都在，不需要额外扫描。

### 3.3 时间预算：10 ms 指标够

`rc_mux_scan` 默认参数 @27 MHz：

| 阶段 | 拍数 | 时间 |
|---|---:|---:|
| 每地址送 4 字（DISABLE/ADDRESS/CONNECT/CHARGE） | 4 × 16 | 2.4 μs |
| DISCHARGE | 512 | 19.0 μs |
| MEASURE（典型 / 最坏 TIMEOUT） | 数百 / 2047 | ~10 μs / 75.8 μs |
| **每地址合计（典型 / 最坏）** | | **~31 μs / ~97 μs** |
| **16 地址整帧（典型 / 最坏）** | | **~0.5 ms / ~1.6 ms** |

selection README 两处写死「最坏触摸至声音 ≤10 ms」。**0.5–1.6 ms 有 6–20 倍余量，力度不需要额外扫描，不加时间。**

## §5 对 strike / 通用乐器方案的影响

### 5.1 不受影响的（照原样推进）

- `d_k` 梯度公式 `d_k(k) = max(0, base - (k*curve)>>4)`
- 寄存器 53 位定义（`artic_enable` / `artic_mask` / `strike_d_m` / `strike_d_k_base` / `strike_d_k_curve` / `strike_s_lvl` / `strike_auto_rel` / `strike_hold_ticks`）
- `default_curve(span)` 降级为界面提示
- `decay_spread` 只 fit 基频 + 梯度递减
- `articulation_v2.py` 十组自测
- 面积估算 73 LUT / 53 FF

**理由：这些都是音色参数层面的，跟前端是 MUX 还是直连无关。**

### 5.2 要改的

| 原方案 | 改为 |
|---|---|
| 退路 B「全局力度推子」 | **删除**。板无此件 |
| 「上板先量 `pad_scan` 的 CHARGE 参数」 | 小样路线要量的是 **47k 起始阻值 + 3 种参考负载下的裸计数落点**（`rc_mux_scan` 的 `DISCHARGE_CYCLES` / `TIMEOUT_CYCLES`） |
| 力度取 `raw - base`（单通道） | MUX 路线取**该滑条 3 电极 delta 之和**（或加权和），输出逐音位力度 |
| `ev_vel` 固定 12 | 逐音位力度 → `ev_vel[3:0]`，直接进 `note_map` 的 `vel_cur` |

### 5.3 新增一个必须先验的物理假设

`VELOCITY-PATH` §5 已写「重按/轻触 ≥1.5 倍」，现在要落到小样上：

> 用 4 滑条 × 3 电极的小样板，同一电极上轻触 vs 重压，`row_count` 的**差值幅度比**是否 ≥1.5。

**这是整个力度方案唯一的硬前提。** 如果达不到 1.5，`vel_wtab.hex` 的 16 级表就等于只有 2–3 级有效，那时才需要讨论"力度改由时长/位置间接推断"这类降级方案。

## §6 要你裁定的四件事

**Q7｜两块顶层怎么合？** 这是 11-04 前最关键的结构决定。

- **A**：把 `rc_mux_scan` 接进 `tdm_top_owned.v`，替掉 `pad_scan`。→ 能跑现有小样板，但 CLS 99.6% 已满，`rc_mux_scan` + `rc_delta_store` + `rc_strip_positions` 面积未知，可能放不下。
- **B**：保留 `pad_scan` 直连，**另做一块 16 路直连的板**（铜箔直接飞线到 GPIO）。→ 便宜、快，但现有 19 项 BOM 白选。
- **C**：11-04 前只做**演奏 + 力度**，传感用 `pad_scan` 直连（4–8 个电极手贴铜箔），小样板留到 11-04 后再接。

我倾向 **C**：11-04 是视频目标，不是产品发布。铜箔手贴能出声音、能出力度，成本 ¥30。

**Q8｜屏买不买？** 按 §4，买就破 500 元。建议 11-04 前**不买**，可视化走上位机（你已允许保留音乐可视化这一项上位机依赖）。

**Q9｜24LC256 在板上但 RTL 零实现，怎么办？** 三个选项：① 11-04 前不写，参数靠编译期预设（你已说"力度响应规则可以接受内部预设"）；② 写 I²C 主机（约 200 LUT，CLS 已满）；③ 只用它的前 32 字节存"上电默认音色"，简化版。

**Q10｜小样板的 12 电极，先验哪一条？** 建议先验力度那条（§5.3），因为它是 strike 方案的唯一硬前提，其余（位置连续性、串扰、覆盖层）不影响 strike。
