# 加法合成听感诊断 + 硬件驱动风险评估 · 2026-10-22

前提更正：板子**能出声**，上位机可以演奏（72/73 号测试工程，15258 Logic / 14 IO）。
本文只针对「听感不够好」与「改合成会不会把驱动搞坏」两个问题。全部只读核查。

---

## 0. 结论先行

1. **听感问题主要不是引擎不行，是音色表的数据问题。** 引擎支持每泛音独立包络（`epar_mem[0:NSLOT-1]`），
   但**预设 1 的 16 个泛音用了完全相同的包络参数** ⇒ 频谱完全不随时间变化 ⇒ 听起来就是风琴。
2. **改音色表（HEX）不会搞坏驱动**，因为不增加任何计算。
3. **改算法会搞坏驱动**，因为 TDM 时隙预算是 **1 时隙 / 拍，零余量**。
4. 有三个独立于听感的硬风险：电平标定、`nyq_kill` 高音区成批杀泛音、`s_lvl=0` 导致按住也自己消失。

---

## 2. 为什么"效果不够好"——五个可定位原因

### D1 预设 1 是静态频谱（最主要）

16 个泛音的 `s_lvl / d_m / d_k` 完全相同（30000 / 3 / 20）。
所以所有泛音**同生同灭、以同样速度衰减到同样比例**。

真实乐器（钢琴、吉他、马林巴）最关键的特征是**高次泛音衰减得更快**——你听到"叮"之后余音变暖，
就是高次泛音先走。预设 1 做不到这件事，所以它听起来像风琴或合成器 pad，不像乐器。

**这一条零成本可改**：只改 `preset_part.hex`，不动一行 RTL。

### D2 预设 2 衰减过头

`s_lvl` 从 12000（36.6%）一路降到 250（0.76%）。按住不放，最终只剩基音在 36.6% 的音量上。
听感是"按下瞬间亮一下，然后迅速闷掉，然后没气了"。

`s_lvl` 的意图是对的（高次泛音衰减到更低），但**量级设得太狠**。把曲线整体抬到 45%→12%
会比 36.6%→0.76% 自然得多。

### D3 所有预设都用最快衰减档

`d_m` 是 2 位，有 4 档，**四个预设全用 3**。所以没有任何"长余音"音色。
弦乐、长笛、人声这类需要慢衰减的音色做不出来。

### D4 预设 3/4 的 `s_lvl = 0` ⇒ 按住也会自己消失

`s_lvl=0` 意味着包络衰减到零后不再保持。所以**手指按住不放，声音也会自己消失**。

对打击乐（马林巴、钟）这是正确行为。但如果用户当成"按住应该持续"，就会认为是 bug。
**这是一个需要明确定义的交互规则，不是缺陷。**

### D5 `nyq_kill` 让高音区成批丢泛音

`note_map_owned.v:519`：

```verilog
wire nyq_kill = |inc_mul[PHASE_W+15:PHASE_W+7];   // inc_mul[39:31]
```

`inc_cal = inc_mul[31:8]`，Nyquist 对应 `inc = 2^23`，所以判据等价于 `f_partial ≥ fs/2 = 26367 Hz`。

数学上正确（避免混叠），但后果是**同一音色在不同音区听感完全不同**：

| 音高 | 可容纳的最高倍频 | 预设 3 存活泛音 | 预设 4 存活泛音 |
|---|---:|---:|---:|
| A3（220 Hz） | 119× | 全 16 个 | 11 个 |
| A4（440 Hz） | 59× | 12 个 | 8 个 |
| A5（880 Hz） | 29× | 8 个 | **5 个** |

**高八度丢掉一半以上泛音**，音色突然变闷。这不是"高频少"的自然结果，而是**一刀切**——
应该做渐进滚降（越接近 Nyquist 幅度越低），而不是到点直接清零。

## 3. 硬件驱动会不会出问题

### R1 TDM 时隙预算：1 时隙 / 拍，零余量 ★最关键

- `NSLOT = 512`（32 组 × 16 泛音），`clk = 27 MHz`，`fs = 27e6 / 512 = 52734.375 Hz`
- 每样本 512 拍，512 个时隙 ⇒ **每个时隙只有 1 拍**
- 流水线深度 4（`LAT = 4`）：`sc+4` 累加，`sc+1` 算包络/幅度/相位

**所以：**

| 改动类型 | 安全性 | 原因 |
|---|---|---|
| 改 `preset_part.hex`（倍频/幅度/包络参数） | **安全** | 纯查表，零新增计算 |
| 改 `note_map` 的 `epar` 分发方式 | **安全** | `epar_mem` 已是每时隙一份 |
| 在时隙循环里加计算（滤波、软限幅、插值） | **危险** | 塞不进同一拍，实时性直接崩 |
| 扩到 32 泛音 | **危险** | 见 R1.1 |

#### R1.1 泛音数与复音数被 `NSLOT` 绑死

`NSLOT = PART × 组数 = 16 × 32 = 512`，而 `fs = 27MHz / NSLOT`。所以：

| 配置 | NSLOT | fs | 复音 | 泛音 |
|---|---:|---:|---:|---:|
| **现在** | 512 | 52.7 kHz | 32 | 16 |
| 想加泛音 | 512 | 52.7 kHz | **16** | **32** |
| 两个都要 | 1024 | **26.4 kHz** | 32 | 32 |

**想多要泛音，必须拿复音换，或者降采样率。** 没有第三条路。

### R2 电平标定（`GAIN_UP = 4`）

`tdm_top_owned.v:1135`：`.GAIN_UP(4), .SHIFT(0)` ⇒ `scaled = acc << 4`。

- 每个泛音满幅贡献约 `32766`
- 16 个泛音全满 ⇒ `524,256 << 4 = 8,388,096`，而 `MAXV = 2^23-1 = 8,388,607`
- **恰好满量程**——也就是说，这个增益是按"16 泛音全部 255"标定的

但实际预设 2 的幅度总和只有 882（16×255 = 4080 的 21.6%），所以单音输出约满量程的 20%，
约 **−13 dB**。而同时弹 5 个音以上就会撞到硬饱和（`scaled > MAXV` 直接钳位，不是软限幅）。

**两个后果同时存在**：单音偏轻，和弦可能削顶。**没有动态归一化。**

### R3 `AMP_W = 8` 量化

谱幅度只有 256 级。预设 2 的泛音 16 幅度只有 12，相对误差 8%。
弱泛音基本是"有/无"开关，不是渐变——这会让频谱包络出现台阶感。

### R4 相位截断

`PHASE_W = 24`，但 `sine256.hex` 只有 **256 项** ⇒ 只用高 8 位查表，低 16 位丢弃，**无插值**。
杂散约 −48 dB。16 个泛音叠加会累积，是"数码味"的来源之一。

### R5 I²S 不受影响

`i2s_tx.v` 是独立模块，只要 `sample_out` 保持"每 512 拍出一个样本"的契约，改合成完全不碰 I²S。
**这一块可以放心。**

## 4. 改进路线（按性价比排序）

| 优先 | 动作 | 代价 | 预期效果 |
|---|---|---|---|
| **1** | 改 `preset_part.hex`：给预设 1 的 16 个泛音分别设 `s_lvl`/`d_k`（高次更低更快） | **零 RTL**，改 HEX 重烧 | 立刻从"风琴"变"乐器"，频谱开始演化 |
| **2** | 抬预设 2 的 `s_lvl` 曲线（36.6%→0.76% 改成 91%→24%） | 零 RTL | 余音不再"闷掉" |
| **3** | 用上 `d_m` 的另外三档，做一档慢衰减音色 | 零 RTL | 补上弦乐/长音类音色 |
| **4** | 打开效果器（写 `0x40` 的 bit1/bit2/bit6） | **零面积**，一行寄存器 | 混响/合唱立刻加厚 |
| **5** | `nyq_kill` 改成渐进滚降 | RTL，需塞进 1 拍 | 高音区不再突变 |
| **6** | 加软限幅或动态归一化 | RTL，需要额外拍 | 和弦不削顶、单音更响 |
| **7** | 正弦表加线性插值 | RTL + 面积 | 减少数码味 |
| **8** | 起音噪声瞬态 | RTL + LFSR | 打击感/真实感 |

**第 1–4 项全部零 RTL 或零面积，能解决大部分"不好听"。**
第 5–8 项才需要动引擎，每一项都要先算清楚能不能塞进那 1 拍。

---

## 5. 建议的第一步（今晚就能做）

**只改 `preset_part.hex`，重烧，听差别。**

具体：保持预设 1 的 6 条泛音与幅度不变，只把 `epar` 从"全部 30000/3/20"改成逐泛音递减：

| 泛音 | s_lvl 建议 | 意图 |
|---:|---:|---|
| 1 | 30000（91.6%） | 基音几乎不衰减 |
| 3 | 24000（36.6%） | |
| 5 | 18000（27.5%） | |
| 8 | 12000（36.6%） | |
| 12 | 8000（24.4%） | |
| 16 | 5000（15.3%） | 高次衰减到很低 |

`d_k` 同步从 20 递减到 10。这样一改，起音时是完整的 6 泛音，余音逐渐只剩基音——
**这就是"乐器"和"风琴"的差别**。

不动 RTL、不动约束、不增加面积，重烧即可对比。如果这一步听感明显改善，就证明
"问题在数据不在引擎"，后面 5–8 项的优先级可以全部下调。
