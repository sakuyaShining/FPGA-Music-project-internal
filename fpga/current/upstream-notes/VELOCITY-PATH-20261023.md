# 力度响应通路：现状、缺口与改法（2026-10-23）

> 触发：用户"力度响应是必要的，但力度响应规则我可以接受内部预设"
> 结论：**规则已经是对的，不用改；但整条通路现在是关着的，而且力度值是固定值。**

---

## §0 三句话

1. `vel_wtab.hex` 的设计**完全符合钢琴的力度-音色关系**，不需要改（§1）
2. `0x6E`（力度灵敏度）**没有初值 ⇒ 默认 0 ⇒ 功能关闭**，这是第一个 bug（§2）
3. 即使打开，所有输入源的力度都是**固定 12/15**，所以还是不变（§3）

要真正有力度响应，必须让力度从**触摸的 RC 计时**推出来（§4），这需要上板标定一次量程。

---

四个特征，正好是钢琴的行为：

| 特征 | 数据 | 物理对应 |
|---|---|---|
| **基音恒 256** | 16 行全是 256 | 力度不改变基频响度（响度由 `amp × vel` 单独控制） |

| **频谱重心单调上升** | 0.96 → 8.32（8.7 倍） | "越重越亮" |

**所以"规则内部预设"这条完全成立，表一个字都不用改。**

## §2 但功能是关着的：`0x6E` 没有初值

`tdm_top_owned.v:687-691`：

```verilog
wire [7:0]  r_vel_sens  = R[8'h6E*8 +: 8];
wire [8:0]  vel_vscale  = (r_vel_sens == 8'h00) ? 9'd0   :   // 关
                          (r_vel_sens <  8'h40) ? 9'd128 :   // 低半区 → 半灵敏
                          (r_vel_sens <  8'hC0) ? 9'd256 :   // 中区   → 一等一
                                                  9'd511;   // 高半区 → 最灵敏
```

`reg_bank.v` 的初始值表里**只有 `0x5C = 0x70`（tilt 恒等），没有 `0x6E`**。所以：

```
0x6E 复位值 = 0  ⇒  vel_vscale = 0  ⇒  vel_shape 输出恒等于输入  ⇒  力度不影响音色
```

**这就是"力度响应没生效"的第一个原因，而且是一个可以一行修好的 bug。**

**修法**：在 `reg_bank.v` 的初始值表里加一行

```verilog
mem[8'h6E] = 8'h80;   // 中区 ⇒ vel_vscale = 256 ⇒ 与 vel_wtab 一等一
```

或者走自举表（`tdm_top_owned.v` 的 `b_addr/b_data` 序列）加一条，好处是"上电后也能被 UART 覆盖"，坏处是自举期间有几十拍的空窗。**建议改 `reg_bank`**，因为它是"上电即有"的语义。

`0x5C` 已经是 `0x70`（档位 7，`w(k) ≡ 256`），不需要动。

## §3 力度值本身是固定的：这是第二个原因

查三路输入源：

| 来源 | 力度 | 位置 |
|---|---|---|
| `pad_scan`（触摸） | **固定 12/15** | `pad_scan.v` 头注释：「力度 v1 固定 12/15」 |
| `pitch_pos`（推子音高） | **固定 `4'd12`** | `tdm_top_owned.v:645` |
| `seq`（定序器） | 来自序列数据 | `sq_ev_vel[7:4]` |
| `u_ev_vel`（上位机） | **`wr_data[3:0]`，唯一可变的** | `tdm_top_owned.v:579` |

**所以现在不管怎么弹，都是 vel12 那一行。**

vel12 的实际效果：前 14 个泛音，k13 = 360（1.41 倍），**k14/k15 为 0（消失）**。

对比 vel15：16 条全开，k15 = 466（1.82 倍）。

也就是说，**现在的音色相当于"中等偏亮"的一档固定住**，弹轻弹重完全一样。

## §4 力度必须从触摸的 RC 计时来

物理链：**按得重 → 接触面积大 → 电极电容大 → 放电慢 → 计数大**。

`pad_scan.v` 内部已经有全部素材：

```verilog
cnt[i]    <= cnt[i] + 1'b1;                              // :136 放电计数（12 位）
raw[i]    <= cnt[i];                                     // :147 上一轮锁存值
base[i]   <= (cnt[i] < base[i]) ? cnt[i] : base[i];      // :151 标定窗取最小
hi = base[i] + (base[i]>>3) + (base[i]>>5);              // :159 ×1.156 触摸阈值
lo = base[i] + (base[i]>>4) + (base[i]>>6);              // :160 ×1.078 释放阈值
```

`raw` 已经通过 `dbg_raw_sel` / `dbg_base_sel` 输出（`:47-48`），就是为"上板逐根量 RC 量程"准备的。

### 4.1 改动

```verilog
// 新增输出
output reg  [3:0]  ev_vel,     // 与 ev_note/ev_on/ev_valid 同拍
// 新增参数/寄存器
input  wire [3:0]  vel_shift,  // 标定值：base/4 对应满力度时的右移量

// edge_on 那一拍，用【触发通道】的 raw 算力度
always @(posedge clk) begin
    if (edge_on_pulse[i]) begin
        // excess = 超过基线多少（不是超过阈值多少，那样会丢掉前 15% 的行程）
        excess = raw[i] - base[i];          // 12 位减法
        ev_vel <= (excess >> vel_shift > 4'd15) ? 4'd15 : excess >> vel_shift;
    end
end
```

**成本**：12 位减法 ≈ 12 LUT + 4 位桶形移位 ≈ 16 LUT + 4 位钳位 ≈ 4 LUT = **约 32 LUT**，加 4 位寄存器（`vel_shift`）。

### 4.2 为什么用 `raw - base` 而不是 `raw - hi`

`hi = base × 1.156`。如果用 `raw - hi`，那"刚摸到"时 `excess = 0`，力度永远是 0，只有按到很重才有值。用 `raw - base` 保留了完整行程，只是"刚摸到"对应 15.6% 的力度而不是 0。

如果希望"刚摸到 = vel 0"，可以在结果上减一个常量，或者把 `base` 换成 `lo`。

### 4.3 `vel_shift` 怎么定

目标：`base/4` 的相对变化对应满力度 15。

```
满量程 raw - base ≈ base/4
vel = (raw - base) >> shift 要能到 15
⇒ (base/4) >> shift ≈ 15
⇒ shift ≈ log2(base/60)
```

- `base = 480` → shift = 3
- `base = 960` → shift = 4
- `base = 1920` → shift = 5

`base` 取决于内部下拉电阻和电极电容，**必须上板量**。

## §5 必须先做的验证：RC 到底能分出几档

这是整条方案的前提，而且**是个物理假设**，不能靠推算。

`dbg_raw_sel` / `dbg_base_sel` 已经就绪，上板后对同一路电极量三个状态：

| 状态 | 期望 `raw` | 与 `base` 之比 |
|---|---|---|
| 不摸 | ≈ base | 1.00 |
| 轻触（指尖刚放上） | base + 少量 | 1.05–1.20 |
| 重按（指腹压实） | base + 较多 | 1.30–2.00 |

**判据**：`重按 / 轻触 ≥ 1.5` 才算能分出 3 档以上。如果只有 1.15–1.25，那 RC 只能做"摸/不摸"，力度这条路就废了。

**这一步需要铜箔电极 + 板子。** 按 `BOM-PROTOTYPE-20261022.md`，铜箔是今晚就能买的东西。

## §6 如果 RC 分不出力度，三条退路

| 退路 | 做法 | 代价 |
|---|---|---|
| A | 上位机/MIDI velocity 下发 `u_ev_vel` | **违反"不依赖上位机"** |
| B | 一个推子做"全局力度"（演奏时推） | 不是真力度响应，是表情控制；而且推子已分配给右手泛音 |
| C | 固定 vel12（现状） | 力度响应等于没有 |

**如果 RC 不行，我建议 B**：把右手 8 个推子中的一个或一个专用旋钮做"力度"，虽然不是"按键力度"，但至少演奏中能实时改变音色亮度——这比固定值强，而且不依赖上位机。

## §7 优先级

| 序 | 事项 | 依赖 | 工作量 |
|---|---|---|---|
| **1** | `0x6E` 初值改 `0x80` | 无 | 一行 |
| **2** | 上板量 RC 量程（轻触/重按） | 铜箔 + 板子 | 半小时 |
| **3** | `pad_scan` 加 `ev_vel` 输出 | 第 2 步的结论定 `vel_shift` | 约 32 LUT |
| 4 | 若 RC 不行，做推子全局力度 | — | 中等 |

第 1 步现在就能做，而且**做完之后 vel12 那一行的效果会立刻出现**（前 14 泛音、高次 1.41 倍）。这本身就是一个可听的改善——因为现在 `vscale=0` 意味着连 vel12 的谱形都没有，所有泛音都是预设幅度原值。
