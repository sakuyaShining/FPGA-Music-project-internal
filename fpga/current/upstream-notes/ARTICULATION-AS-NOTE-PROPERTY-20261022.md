# strike 按住自消失 / 激发模式作为音符属性 / 泛音实时修改 · 2026-10-22

回应三点：
① 「strike 模式下按住不放声音自己消失」到底指什么；
② 激发模式是**全局性的音符属性**，不跟音色绑定；
③ 泛音结构可以在演奏中**实时修改**。

---

## 一、「按住不放声音自己消失」的两层含义

### 1.1 听感层：包络走到 0 就停在 0

`osc_env.v` 的状态机：

```
IDLE ──trig_on──► ATK ──电平升到 32768──► DEC ──降到 s_lvl──► SUS
                                                              │
                                            gate 松开(trig_rel) ▼
                                                            REL ──降到阈值──► IDLE
```

`ST_DEC` 的判定（`osc_env.v:143`）：

```verilog
ST_DEC: begin
    if (trig_rel)              stg_o = ST_REL;
    else if (lvl_i <= s_lvl)   begin lvl_o = s_lvl; stg_o = ST_SUS; end
    ...
```

**`strike` 模式下 `s_lvl = 0`**，所以电平一路减到 0，然后进 `ST_SUS`、`lvl_o = 0`，停在那里。

所以：**手指还按着（gate 仍是 1），但电平已经是 0，听不见。**

对钢琴、马林巴、拨弦——这是**正确行为**（按住琴键，声音本来就会衰减到没有）。
对风琴、弦乐——这是**错误行为**（按住应该一直响）。

**同一套硬件，两种乐器期望相反。** 所以这条必须由"激发模式"来明确表达，而不是让演奏者猜。

### 1.2 资源层：声音没了，时隙还占着 ★这才是真问题

关键在状态机**停在 `ST_SUS` 而不是回 `ST_IDLE`**。而时隙的释放只看 gate：

`note_map_owned.v:227`：

```verilog
reg [NG-1:0] gact;   // 该组是否正在发声（gate=1）
```

`gact` 由 note-on 置位、**note-off 清零**。**包络归零不会清 `gact`。**

后果：

| 场景 | 结果 |
|---|---|
| 演奏者按住 32 个 strike 音 | **32 组 × 16 = 512 个时隙全被占满** |
| 此时弹第 33 个音 | 分配器找不到 `!gact` 的空组 ⇒ 只能抢占已有音 |
| 听感 | 前 32 个音其实**早就没声了**，却被无声地"霸占"着时隙 |

**也就是说：`strike` 音色下长按，会白白吃掉复音数。**

32 组是硬上限（`NSLOT = 32 × 16 = 512`）。按住 32 个已静音的音，等于复音数变 0。

### 1.3 这条规则要你定：怎么处理"静音但仍占用"

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A** | 不管，靠演奏者松手 | 零 | 长按仍占时隙 |
| **B** | `strike` 模式下 gate 自动限时（`2 × decay_ms` 后强制 note-off） | note_map 加约 20 位计数器 + 比较 | 若 `decay_ms` 估错，音会被提前掐掉 |
| **C** | 引擎回传"该组包络已归零"位图，分配器自动释放 | 新增 32 位反馈 + 比较逻辑 | 改动最大，但最准确 |

**我建议 B**：规则简单、代价小、可解释——"打击型音色的发声时长由衰减时间决定，与按多久无关"。
这本身就是打击乐器的物理事实。

## 二、激发模式作为音符属性：现在的结构不支持，但改动很小

### 2.1 现状：`epar` 绑在音色条目里

`note_map_owned.v:442` 和 `:684`：

```verilog
wire [22:0] p_epar = pentry[22:0];      // pentry 来自 instrument_table 的音色条目
...
load_epar <= p_epar;                    // 装载时写入该时隙
```

**`epar` 只有一个来源：音色表里那个 48 位条目。** 没有任何"音符级"的覆盖通路。

所以你说"激发模式不跟音色绑定、是音符的属性"——**现在的硬件做不到**，需要加一条覆盖路径。

### 2.2 好消息：改动极小，因为装载是串行的

`note_map` 装载时**一次只处理一个泛音**（`k` 是循环索引），所以覆盖逻辑只需要**一份**，不是 16 份。

提案：加四个顶层可写寄存器

```verilog
reg [22:0] artic_epar_a;   // 变体 A（如 sustain：s_lvl=24576, d_k=17）
reg [22:0] artic_epar_b;   // 变体 B（如 strike：s_lvl=0,     d_k=8）
reg [15:0] artic_mask;     // 哪些泛音用 B（1=B，0=A）
reg        artic_enable;   // 总开关，默认 0 = 保持现有行为
```

在装载处加一个二选一：

```verilog
wire [22:0] p_epar_eff = artic_enable
                       ? (artic_mask[k] ? artic_epar_b : artic_epar_a)
                       : p_epar;
load_epar <= p_epar_eff;
```

**为什么这天然就是"音符属性"**：`epar_mem[0:NSLOT-1]` 是**每时隙一份**。
note-on 时写入后，**这个音符在整个生命周期里持有自己的副本**，之后音色怎么改都不影响它。
这正是"音符属性"的硬件含义。

### 2.3 成本核算

| 项 | 数量 |
|---|---:|
| 寄存器 | 23 + 23 + 16 + 1 = **63 位** |
| 二选一 mux | **1 个 23 位 mux**（不是 16 个，因为装载串行） |
| `artic_mask[k]` 查表 | 1 个 16:1 mux ≈ 4 LUT |
| **合计** | **约 30 LUT + 63 寄存器** |

**在当前 CLS 只剩 41 格的状况下，这是可以接受的量级。** 但要在时序收敛的同一轮里一起算。

### 2.4 三种模式如何落到这套寄存器

| 模式 | `artic_mask` | `artic_epar_a` | `artic_epar_b` |
|---|---|---|---|
| `sustain` | `16'h0000` | 持续参数（s_lvl = sustain_level×128） | 不用 |
| `strike` | `16'hFFFF` | 不用 | 打击参数（s_lvl = 0，d_k 小） |
| `hybrid` | 任意 16 位（默认 `16'hFF00` = 低 8 持续 / 高 8 打击） | 持续参数 | 打击参数 |

**三种模式就是同一个寄存器的三种取值**，不需要三套硬件。

### 2.5 这条规则要你定：音符属性怎么选

既然是"音符的属性"，那**每个音符进来时，谁决定用哪套**？

| 方案 | 机制 | 需要什么 |
|---|---|---|
| **N-1** | 上位机在发 note-on 之前改 `artic_mask` | 零 RTL，协议上加一条"激发预设"命令 |
| **N-2** | 跟力度联动（轻按=strike，重按=sustain） | 需要一条 `vel → mask` 的映射规则（阈值？线性？），可能还要第二个 mask 维度 |
| **N-3** | 物理开关/旋钮选（演奏者手动切） | 需要面板上一个控件 + 引脚 |
| **N-4** | 跟"层"绑定（4 层各一种激发） | 需要层→mask 的映射表 |

**N-2 表达力最强但规则最复杂**。如果要做，`artic_mask` 得拆成"轻按用的 mask"和"重按用的 mask"两套，再加一个力度阈值。

**这条必须现在定，因为它决定寄存器结构。**

## 三、泛音结构实时修改：已经支持，但只限幅度

### 3.1 现有通路

`note_map_owned.v` 有独立的谱写口：

```verilog
input wire        spec_we;       // 写使能（1 拍）
input wire [3:0]  spec_addr;     // 0..15，选哪个泛音
input wire [7:0]  spec_wdata;    // 8 位幅度
input wire        spec_replace;  // 1=替换 / 0=叠加
```

存储：`reg [7:0] spec_ram [0:P-1];` —— **16 个泛音各一个 8 位幅度，可运行时写**。

生效方式（`:459-462`）：

```verilog
wire [7:0] spec_eff = pad_mask[k] ? 8'd255 : spec_ram[k];
wire [7:0] amp_add  = min(255, p_amp + spec_eff);
wire [7:0] amp_src  = spec_replace ? spec_eff : amp_add;   // 默认叠加
```

- **默认叠加**：`amp = 音色底谱 + spec_ram`（上限 255）
- **替换模式**：`amp = spec_ram`（完全由运行时谱决定）

**这个改动立即生效，不需要 commit，不影响正在响的音符。**

### 3.2 但有三条边界

| 能改 | 走哪条路 | 生效时机 |
|---|---|---|
| **泛音幅度**（哪个泛音更响） | `spec_ram` 16×8 位 | **立即** |
| **泛音频率**（倍频 `ratio`） | `instrument_table` | 每音符（commit 后） |
| **泛音包络**（`s_lvl`/`d_m`/`d_k`） | `instrument_table` 或新的 artic 覆盖 | 每音符 |
| **泛音个数** | 靠把幅度写 0 | 立即（但时隙仍占着） |

**注意最后一行**：把某个泛音的 `spec_ram` 写成 0，它就不发声了，但**时隙还在算它**（只是乘 0）。
所以"减少泛音个数"不省资源，只省听感。

### 3.3 一个坑：叠加模式的上限

默认叠加模式下 `amp = p_amp + spec_ram`，上限 255。
如果音色底谱已经是 200，`spec_ram` 最多只能再加 55 就到顶。
**想要"实时把某个泛音推满"，得先把底谱压低，或者切到替换模式。**

## 四、汇总：四个"改"分别走哪条路

| 演奏中想改什么 | 通路 | 生效 | 是否影响正在响的音 |
|---|---|---|---|
| 泛音幅度 | `spec_ram`（16×8） | **立即** | 是（下一拍就变） |
| 泛音频率 | `instrument_table.ratio` | 每音符 | 否 |
| 泛音包络 | `instrument_table.epar` | 每音符 | 否 |
| 激发模式 | 新增 artic 覆盖（63 位） | 每音符 | 否 |
| 音色整体 | `instrument_table` + `commit` | 每音符（原子） | 否 |

**"立即"和"每音符"的差别就是双缓冲的意义**：想改整体音色不影响当前音，想改幅度可以立刻听到。

## 五、需要你拍板的三条

| # | 问题 | 影响 |
|---|---|---|
| **A** | `strike` 下"静音但仍占时隙"用哪个方案？（A 不管 / **B 自动限时** / C 引擎反馈） | 决定 note_map 要不要加计数器 |
| **B** | 音符属性由谁决定：上位机预设 / **力度联动** / 物理开关 / 跟层绑定 | 决定 `artic_mask` 是 16 位还是两套 |
| **C** | 泛音实时修改用**叠加**还是**替换**做默认？ | 决定界面语义与底谱设计 |

**B 是最关键的一条**：如果选力度联动，`artic_mask` 要拆成两套 + 一个阈值，寄存器从 63 位涨到约 90 位，还要定"轻/重"的分界。
