# 全功能组合的降险方案 · 2026-10-23

> 针对你选的 **Q2=A + Q1=C + Q3=B + Q4=B + Q5=A + Q6=A**。
> 结论：**能降，而且能降一大截**。依据是三个结构性发现，不是"小心一点"这种空话。

---

## 一、三个结构性发现（降险的根据）

### 发现 1 · G2「一指绑 N 组」不是新架构 —— 它已经写好了

我原以为这是最实质的改动。查了 `layer_dispatch.v` 之后发现**父-子结构已经完整存在**：

```verilog
// layer_dispatch.v 端口里已有：
output wire [1:0] child_preset,        // ← 已经能派发到不同槽！
output wire [4:0] parent_group,
input  wire [4:0] in_finger_id,        // ← 手指身份已经绑到父实例
input  wire signed [11:0] in_finger_position,
localparam IDLE=0,PICK=1,SEND=2,WAIT_RESULT=3,FINISH=4,BIND=5;   // ← BIND 状态已有
```

它缺的只是**数组写死了 2 份**：

```verilog
reg [4:0] groups0[0:NF-1],groups1[0:NF-1];   // 只有 2 层
reg [1:0] slots0 [0:NF-1],slots1 [0:NF-1];
reg [1:0] count [0:NF-1];                    // 2 位 ⇒ 最多数到 3
```

扩到 4 层 = `groups0..3` / `slots0..3` / `count[2:0]` + PICK 循环 4 次。

| 项 | 增量 |
|---|---:|
| `groups2/groups3` | 26 × 5 × 2 = **+260 FF** |
| `slots2/slots3` | 26 × 2 × 2 = **+104 FF** |
| `count` 2→3 位 | 26 × 1 = **+26 FF** |
| 合计 | **+390 FF** |
| 寄存器占用 | 4302 → 4692（28% → 30%） |

**这是"改参数"，不是"改架构"。** 原计划里 G2 标的"大"要降成"中"。

### 发现 2 · 四层可以完全脱离触控屏验证

`tdm_top_owned.v:662-665` 的 UART 事件源：

```verilog
wire u_ev_valid = wr_en && (wr_addr == 8'h61);
wire u_ev_on    = r_note_num[7];     // R[0x60] bit7 = 1 开 / 0 关
wire [6:0] u_ev_note = r_note_num[6:0];
wire [3:0] u_ev_vel  = wr_data[3:0];
```

⇒ 写 `0x60 = note|0x80`，再写 `0x61 = vel`，就是一个 note-ON。

**这意味着四层、移调、力度曲线、归一全部能纯 UART 验**，不需要 J10、不需要 84 节点 MUX、不需要屏幕到货。

**这是最大的降险点：把 RTL 风险与硬件到货风险解耦。**

已落地工具：`tools/play_note.py`
```
python tools/play_note.py chord 60 64 67 --port COM6 --vel 10 --dur 1.5
python tools/play_note.py scale
python tools/play_note.py layers 60      # 分层试听的对照基线
```

### 发现 3 · 这六条里，只有两条是"打磨"，其余四条是"能力"

| 问题 | 性质 | 为什么 |
|---|---|---|
| Q2=A 移调 | **能力** | 没有它四槽失去意义 |
| Q4=B 每层力度表 | **能力** | 决定"四层像不像四种乐器" |
| Q5=A 归一 | **能力** | 不归一必削顶 |
| Q6=A 额度 | **能力** | 不降层就装不下 |
| **Q1=C 双模** | **打磨** | 只是"切换手感"，不切也能用 |
| **Q3=B 完整度抢占** | **打磨** | 只在满 8 键时才有区别 |

而且 Q1=C 和 Q3=B 恰好是**最难写对、最难验证**的两个：

- Q1=C 要在「按住 + 切层 + 归一系数变」这个三维时序组合上验，tb 很难写；软接入还要处理"原音还在 ATK 时新层比它响"
- Q3=B 要在「满 8 键 + 抢」这个极端场景验，而且"抢得对不对"是听感判断，仿真判据写不出来

**⇒ 砍这两条，功能覆盖只掉一点点，风险掉一大半。**

## 二、降险方案：砍两条 + 分六刀

### 建议先做的降级

| 问题 | 从 | 降到 | 你损失什么 |
|---|---|---|---|
| Q1 | C 双模（软接入） | **A 迟滞** | 演奏中加层必须抬手，有断口 |
| Q3 | B 完整度加权 | **A 先抢尾音→最老** | 按满 8 键时最早的和弦整块消失 |

**其余四条全保留。** 这样能力一个不少，砍掉的只是手感打磨。

### 六刀施工顺序（每一刀独立可演示、独立可回退）

| 刀 | 内容 | 结构改动 | 单层/关闭时是否逐位不变 | 板上能单独听？ |
|---|---|---|---|---|
| **0** | `tools/play_note.py` | 无（纯上位机） | — | ✅ 已做 |
| **1** | Q4=B 每层力度表 | `vel_shape` 的 `widx` 加 2 位 | ✅ slot=0 时地址高位 0 | ✅ 换表就能听出差别 |
| **2** | Q2=A 移调 | 4 字节新寄存器 + 装载加偏移 | ✅ offset=0 时逐位不变 | ✅ 写 offset 立刻听 |
| **3** | Q5=A 归一（**放输出级**） | 全局增益 + ramp | ✅ N=1 时增益=1.0 | ✅ 需要刀 4 才能听 |
| **4** | G1+G2 四层派发 | 数组加宽（发现 1） | ✅ selection 单槽时不变 | ✅ **第一次听到四层** |
| **5** | Q1=A 迟滞 + Q6=A 总降 2 层 | 层选择在 note-on 锁存 | ✅ 本来就是这个行为 | ✅ 切层试 |
| 6 | （可选）Q3=B / Q1=C | — | — | — |

**为什么这个顺序**：刀 1–3 都是**零结构改动的加法**，每刀都能独立上板听，风险接近 0。把最核心的刀 4 放在后面，是因为前三刀已经就位，四层一开就是"完整功能"，不用再等。

**如果时间不够，砍在刀 4 之后**：那时已经有一个能演示的四层乐器，只是没有 Q1 的双模和 Q3 的优雅抢占。

## 三、每一刀的"不变性守卫"

这是本项目已经在用的纪律（`artic_enable=0 时逐位走原来的 p_epar`），每刀都必须满足：

1. **默认关闭**。功能关闭时，输出与上一版**逐位相同**。
2. **跑全量回归**（当前 7 个 tb 全绿）—— 一刀都不能让旧的变红。
3. **加反向对照**（mutation test）。至少一个"故意改错"的变体必须让新判据变红，否则判据没有牙（DECAY2 那次的教训：D3 第一版没牙）。
4. **每刀跑 PnR 看 CLS**，不看 Logic。
5. **每刀单独烧、单独听**，`play_note.py` 打和弦。

## 四、剩余风险清单（诚实版）

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | CLS 从 80% → 约 84% | **中** | 见 §5。实测余量 2103 CLS，够用 |
| R2 | 四层抢占时留下"半个音" | 中 | 抢占按 instance 整体回收 + tb 判据（每个 instance 的 N 个组必须同时死） |
| R3 | Q5 归一放输出级，与"回放/现场分组"语义冲突 | 低 | 按**总 N** 算本来就是对的总功率；不分组 |
| R4 | Q2 移调越界 | 低 | 越界该层不发声（不折叠、不静音整键）+ tb |
| R5 | 板上只能验单层/双层，四层靠耳朵 | 中 | `play_note.py` 打和弦；判据靠仿真，听感靠你 |
| R6 | `layer_dispatch` 不在产品顶层，接线改动面未知 | 中 | 刀 4 先只接 UART 源（`arb_u`），不动电极/定序器，缩小改动面 |
| R7 | 按键计时（若做 Q1=C）与 `led_ind` 的拍点计时抢资源 | 低 | 已降级，暂不涉及 |

## 五、R1（CLS）实测：没有我一开始担心的那么严重

当前 `build_decay2_v1`（顶层 `tdm_ship_owned`）实测：

| 资源 | 用量 | 占比 | 剩余 |
|---|---:|---:|---:|
| Logic | 12562 / 20736 | 61% | 8174 |
| **CLS** | **8265 / 10368** | **80%** | **2103** |
| Register | 4302 / 15750 | 28% | 11448 |
| BSRAM | 15 / 46 | 33% | 31 |
| DSP | 10 / 24 | 42% | 14 |
| setup | +11.300 ns | — | — |

`86-联合探针资源调整与布线失败边界` 里那次路由失败（PR0004）是 **10357/10368 = 99.9%**，而且用的是**另一个更重的顶层**（`joint_timing_top` + 全套 SDRAM 探针，实测 10327–10366 CLS）。

**产品顶层 `tdm_ship_owned` 现在只有 8265 CLS，比那个失败点低 2100 格。** 四层派发估 +400 CLS（390 FF + mux），落到 8665/10368 = **84%，仍有 1703 CLS 余量**。

**结论：R1 从"高"降到"中"。** 不需要先做 CLS 预算体检，直接按六刀走，每刀跑 PnR 盯着就行。真正会把 CLS 逼到边界的不是四层，而是**以后接 SDRAM 录放**——那部分 11-04 演示不需要。

## 六、一句话结论

**能降。** 三条降险措施按性价比排序：

1. **砍 Q1=C 和 Q3=B**（降级为 A）—— 零成本，砍掉两个最难验证的项
2. **用 `play_note.py` 做板级验证** —— 已落地，把 RTL 与硬件到货解耦
3. **分六刀施工，每刀默认关闭 + 反向对照** —— 任何一步都能退回

**我一开始担心 CLS 会翻车，实测数据不支持这个担心**：产品顶层还有 2103 CLS 余量，四层只吃约 400。真正会逼紧 CLS 的是以后的 SDRAM 录放，不是四层。

## 七、明确没做的事

- 没有改任何 RTL。
- `tools/play_note.py` 是新加的**上位机工具**，不碰码流。已实测能往板上打音符。
- 没有替你决定降级 Q1/Q3 —— 那是你的选择，我只说明代价。
