## 二、新增模块

### 2.1 `engine/src/scan_bus_arbiter.v`

595 与 165 共用 `BUS_SCK`。若同时驱动，SCK 变成两个时钟源的线与，两边同时移位 —— 595 的移位寄存器被打乱、165 位序错位。

**核心约束：持有到释放，不抢占。** 因为 `scan_shift595.v` 里有：

```verilog
if (state >= LOW && !bus_grant) grant_error <= 1;
```

一旦开始打 SCK 就撤 grant，会直接置错误位。这条比公平性优先。

固定优先级，`request[0]` 最高。在顶层里 `request[0]` 接 165（低频、单次、必须及时），`request[1]` 接 595（高频、可等，`rc_mux_scan` 有 `waiting` 兜底）。反过来则 595 持续请求时 165 可能被长期压住。

### 2.2 `engine/src/scan_shift165.v`

74HC165 是 8 位并行输入 / 串行输出移位寄存器。载板用 `INPUT_LOAD_N` + 共用 `BUS_SCK` + `BUS_RETURN` 读回按键与预置状态。

**最易错的一点：74HC165 是 MSB first，不是 LSB first。**
内部 8 个 D-FF 串成 A→B→…→H→QH，`QH` 是**最后一级**。并行装载时 H 直接进最后一级，所以：

```
PL 拉低后          QH = H  (bit7)
第 1 个 CP 上升沿  QH = G  (bit6)
第 2 个 CP 上升沿  QH = F  (bit5)
```

按 LSB first 拼字节会让按键位序整体颠倒。方向做成参数 `MSB_FIRST`，默认 1，依据写在注释里。

采样点放在 **SCK 拉高之前**（`SAMPLE` 状态），此时 QH 已稳定一个完整 `HALF_PERIOD`，不依赖建立时间余量。

### 2.3 `engine/src/sensor_frontend_board.v`

把仲裁器 + `rc_mux_scan` + 165 组装成可综合的整体，输出规范化的行数据与按键位图。

**为什么不直接输出音符事件**：`pad_scan` 是「16 按键 → 音符」语义，载板是「26 滑条 × 3 电极 → 重心位置」语义。把滑条塞进按键接口，等于在驱动层替产品层决定「哪条滑条对应哪个音、位置怎么量化成音高」—— 那是 `PRODUCT-SPEC.md` 的事。所以本模块只输出原始行数据（地址 + 6 路计数 + 故障位 + 帧序号）和按键位图，映射交给上层。

通道账本：6 lane × 16 地址 = 96 物理通道，载板实接 14 个地址 ⇒ **84 个电极**。地址 14/15 悬空，扫到会读固定电平，属正常。

### 3.1 一个必须记下来的教训：位回文让测试变成假的

第一版测试向量用的是 `0xA5` / `0x5A` / `0x3C`。全部 PASS。
做反向验证（把 `MSB_FIRST` 改成 0）时，**仍然全部 PASS**。

原因是这三个数**全是位回文**：

| 值 | 二进制 | 反转 | 回文？ |
|---|---|---|---|
| `0xA5` | 1010_0101 | `0xA5` | 是 |
| `0x5A` | 0101_1010 | `0x5A` | 是 |
| `0x3C` | 0011_1100 | `0x3C` | 是 |

位序整体颠倒后数值不变，所以这个测试**永远不可能失败** —— 等于没测。

换成非回文向量后，反向验证立刻抓到：

```
[FAIL] 位序错误: 读回 0x80，模型输入 0x01
[FAIL] 第二次位序错误: 读回 0xd9，期望 0x9b
```

| 值 | 二进制 | 反转 |
|---|---|---|
| `0x01` | 0000_0001 | `0x80` |
| `0x9B` | 1001_1011 | `0xD9` |
| `0x2D` | 0010_1101 | `0xB4` |

**规则：任何位序类测试，激励必须是非位回文，且必须做一次反向验证证明测试能失败。**

## 四、引脚账本：一个必须让所有人知道的结论

**`32–40` 这 9 个脚不在 2.54 mm 排针上。**

依据：Sipeed 官方引脚框图 `tang_nano_20k_pinlabel.png`，左右两列各 20 个焊盘经像素检测确认，标签区放大 5× 逐脚读取。交叉验证：右列第 7/8/11/15/16 脚读得 `56/54/55/GND/3V3`，与 `expected-pin-nets.json` 的 J5 记录逐条吻合。

由此得出：

| 结论 | 说明 |
|---|---|
| 排针上属于 27–42 的只有 **7 个** | `27, 28, 29, 30, 31, 41, 42` |
| `32–40` 只连 FPC 座与 HDMI 座 | 官方 HDMI 与 LCD 例程同时占用这 8 个脚 |
| v1 的 16 路**从排针取不到** | 从 FPC 座引线才成立 |
| 载板必须走扫描链 | 这不是优化，是排针物理上给不出 16 路 |

完整账本见 `hardware/current/context/pin-map-audit-20261024.md` §六。

**同时撤销一条旧结论**：`nano-header-candidate.csv` 的 J6/J5 → FPGA 引脚映射经逐条核对**全部正确**，原 §2.3 提出的「万用表量 J6-6 ↔ 15」**不需要做了**。真正要决定的不是映射对不对，而是「15–20 那 6 个 LED 脚要不要拿来当载板输出」——功能成立，代价是 6 个 LED 常闪。

## 五、`constraints/tdm_ship_board.cst`

载板前端约束，端口名对应 `sensor_frontend_board.v`。**没有对应顶层之前不能单独参与 PnR。**

6 路 `SENSE` = `29, 30, 31, 41, 42, 48`，全部避开 15–20 的 LED 组（这点已逐条核对）。

文件末尾标出两处会在 PnR 阶段爆发的冲突：

1. `led[0]/[1]/[2]/[4]` 与载板 4 个控制信号是同一批物理脚（15/16/17/19），不能共存，故这 4 条已注释；`led[3]`(18) 与 `led[5]`(20) 载板未连接，正常保留
2. `32–40` 不在排针上，任何试图接到载板的设计都无效

### 5.1 二次修正：LED 只被占 4 个，不是 6 个

初版按 csv 认为载板占用 15–20 全部 6 个。核对载板全部 14 张原理图后修正：

`01_Nano_headers.esch2` 的 Nano 排针只接 **15 个**信号网络：

```
BUS_SCK  BUS_MOSI  BUS_RETURN  SCAN_LATCH  INPUT_LOAD_N
SENSE_0..5 (6)  I2C_SDA  I2C_SCL  HARM_CS_N  TP_INT
```

与 csv 的 17 条相比**正好缺 `LCD_VIS_CS_N` 和 `LCD_SHARED_DC`**。全目录搜 `VIS_CS` / `SHARED_DC` / `DISP_DC` 零命中 ⇒ 这两条是过时或臆想条目，**18 和 20 在载板上是空焊盘**。

实际占用：

| 脚 | 载板信号 | LED |
|---|---|---|
| 15 | `BUS_MOSI` | `led[0]` 丢失 |
| 16 | `SCAN_LATCH` | `led[1]` 丢失 |
| 17 | `INPUT_LOAD_N` | `led[2]` 丢失 |
| 18 | **无连接** | `led[3]` **保留** |
| 19 | `LCD_HARM_CS_N` | `led[4]` 丢失 |
| 20 | **无连接** | `led[5]` **保留** |

**保住的两个恰好最要紧。** `led_ind.v` 的分工里：

- `led[5]` = 曲谱拍点 / 手弹 1 Hz 心跳 → **自证时钟与逻辑在跑，bring-up 最关键的一颗**
- `led[3]` = 定序器运行指示 → **产品状态最关键的一颗**

丢失的是 `led[4:0]` 的音高台阶与音域档图案，载板可用 SPI 屏替代显示。

**这个占用物理上本来可以避免**：排针 34 个信号脚里，除 LED 组外有 19 个不受板载器件约束（`27,28,29,30,31,41,42` + `73,74,75,76,86,72,71` + `77,25,26,48,49`），载板只需 15 个。现状占用 15/16/17/19 是载板引脚分配未做这层优化，**属改板范畴，RTL 无法解决**。
