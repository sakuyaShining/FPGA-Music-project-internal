# 音高映射定稿：电极 → 通道 → 音符 → 声部

> 2026-10-24 · 依据《音高与八度规格》v2.0（`pad_pitch.v`、`strip_ctrl.v` 头部引用）、
> `project/PRODUCT-SPEC.md` R02、载板 `01_Nano_headers` / `02_Shift_and_memory` / `07–12_Scan_lane_*` 原理图。

## 0. 一句话纠正

**「26 条滑条」是错的。物理上只有 3 根条：A 音位条、B 音位条、八度档条。**

`rc_strip_positions` 的 `STRIPS=26` 是**模块参数默认值**，且 `instrument_sensor_probe.v` 给它的
`NODE_MAP` 是恒等占位映射（`example_map[n*7+:7]=n`，即第 n 个 strip 直接用第 3n/3n+1/3n+2 号电极）。
参数默认值不等于产品定义，把 26 读成"26 条滑条"是把实现细节当成了规格。

**音位（半音格）数量是 25，不是滑条数量，也不是 26。**

> **2026-10-24 更新**：音位数已由产品层定为 **25**（`D-021-PITCH-ENDPOINTS-25`），
> 见 §1.2。文中凡出现「26 音位」均为决策前的旧值，保留在历史说明里以便对照。

## 1. 通道表（权威定义）

`pad_pitch.v` 头部逐字抄录规格 v2.0，共 **38 个语义通道**：

| 通道 | 含义 | 发声 | 物理载体 |
|---|---|---|---|
| `0..11` | 下排 C3..B3，12 个半音 | 是 | A 音位条，每音位 3 电极 |
| `12..23` | 上排 C4..B4，12 个半音 | 是 | B 音位条，每音位 3 电极 |
| `24` | 独立高音 C5 | 是 | 单电极，独立一格（§1.2 已定，不再争议） |
| `25..29` | 八度档条，5 档 | 否 | 5 个单电极 |
| `30..37` | 泛音键，8 个 | 否 | 8 个单电极 → `HARM_PADS` 位图 |

音符号计算（`pad_pitch.v` 第 67 行）：

```
note = 48 + 通道号 + 12 × rel
rel  = pos - 1        pos ∈ 0..4  ⇒  rel ∈ {-1, 0, +1, +2, +3}
```

即默认档（`pos=1`, `rel=0`）下：通道 0 → MIDI 48 = C3，通道 12 → MIDI 60 = C4，通道 24 → MIDI 72 = C5。
换档时整体移调 12 个半音/档，**按下时锁存音符号，松开用锁存值发 note-off**（判据 P6 防挂音）。

### 1.1 八度档条不是滑条

`strip_ctrl.v` 明确：

```
cell_t 0 = -1 octave, cell_t 1 = 0 (default), cell_t 2/3/4 = +1/+2/+3
a press must be held >= HOLD_MS ms to take effect (anti-mistouch, P13)
several cells touched at once -> no action
this module never emits note events (P11, P15)
```

输出 `pos[2:0]`（0..4）是**离散档位**，不是连续位置；`led[4:0]` 单热点亮当前档。
所以用户说的「输出的不同位置的信号，对应不同的八度状态」在 RTL 里的准确形态是：
**5 个 cell 各自 on/off → 一个 3 位档位码**，全程不产生音符事件。

### 1.2 25 还是 26 —— 已定：25

PRODUCT-SPEC R02 原文：「保留 84 电极能力；**25/26 音位端点**、八度切换对在奏音的行为待明确」。

**2026-10-24 已由产品层拍板：取 25。**（决策 `D-021-PITCH-ENDPOINTS-25`，
证据 `project/reviews/20261024-pitch-endpoints-25/evidence/user-decision.json`）

原话：「无需两个高音位，因为另一边自带了」。

**关键发现：规格 v2.0 本来就已经是 25。** `docs/02-技术方案/25-音高与八度规格.md` §2：

| 行 | 原文 |
|---|---|
| 20 | `\| 0 – 11 \| 下排第 1–12 键 \| 音高：C3 → B3 \|` |
| 21 | `\| 12 – 23 \| 上排第 1–12 键 \| 音高：C4 → B4 \|` |
| 22 | `\| 24 \| 上排最右 \| 单独的高音 C5 键 \|` |
| 29 | 「没有两个通道映射到同一个音。高音端点 C5 由单独的通道 24 提供，**而不是让两排都包含端点**——若两个相邻物理键对应同一个音，按在交界处会同时触发两个通道，白白占用两个声部并发出两条 note-off」 |
| 30 | 「每排是 12 个等宽键（C 到 B），加上右侧独立的高音 C 键」 |

所以本次决策的实质不是「新定 25」，而是**回到规格 v2.0，把载板原理图的 26 组认定为异常**。
规格还额外给了技术理由：重复顶端格会导致交界处双触发，白烧一个声部加一条 note-off。

> 规格第 16 行写「每排 13 个触摸位置」，与第 20–22 行的 12+12+1 冲突。该文档第 3 行已声明
> 「存在旧稿残留」，以 §2 表格与第 29–30 行为准。

定稿形态：

```
A 条（下排）  C3 C#3 D3 D#3 E3 F3 F#3 G3 G#3 A3 A#3 B3      12 格，止于 B3
B 条（上排）  C4 C#4 D4 D#4 E4 F4 F#4 G4 G#4 A4 A#4 B4      12 格，止于 B4
C5 键         上排最右，独立一格，通道 24                     1 格
                                                           ─────────
                                                           25 格
```

- 两排之间**不重复**：A 条顶端不是 C4，C4 只由 B 条第 1 格提供
- C5 只由通道 24 提供一次
- 音高集合 = C3..C5 半音阶共 **25 个不同音高**

> 用户当时把物理格数推成「12+12+2 高音位」。这个推导**不成立**——
> `78 = 26 × 3` 只能证明载板上有 26 个音位组，区分不了「每排 13 格」与「12+12+2」两种分解。
> 但用户据此得出的结论（不重复顶端格）与规格 v2.0 §2 逐字吻合，故按结论采纳，不按推导采纳。

## 2. 32 组不是映射目标

`tdm_top_owned.v:15`：

```
NG = 32 组 × P = 16 泛音 = NSLOT 512
=> 最大复音 32 音（对应赛题拓展要求 1 的"复音数 ≥32"）
```

32 是**同时发声的声部数**（复音池），与音位数量是两个正交维度：

- **音位**决定「弹哪个音」（1 个音位 → 1 个 MIDI 音符，25 个音位 = 25 个可选音高）
- **32 组**决定「同时能响几个音」（25 个音位全按住也只占 25 个声部，还有 7 个余量给同音多指）

所以**不存在「26 音位 → 32 组」的映射**。真实链路是三段：

```
电极(84) ──重心插值──▶ 音位/档位(38 通道) ──+48+12×rel──▶ MIDI 音符 ──按音高分配──▶ 声部池(32 组)
```

## 3. 84 电极怎么装下 38 通道

载板器件（`02_Shift_and_memory.esch2` 型号统计）：

| 器件 | 数量 | 位宽 | 用途 |
|---|---|---|---|
| `SN74LV595ADR` | 2 | 16 位输出 | 驱动/LED/使能 |
| `SN74LV165ADR` | 2 | 16 位输入 | 泛音键 + 八度档 + 备用 |
| `CD74HC4067M96` | 6 | 96 通道（用 84） | 模拟电极选通 |

`07–12_Scan_lane_*` 每条通道实际接 14 个电极（`L*_E00..E13`），MUX 的 16 个地址里
`M14/M15` 悬空（`L*_M14`、`L*_M15` 只有 2 处连接，是 MUX 引脚本身）。

⇒ **6 × 14 = 84 个模拟电极**。

分配推演（2026-10-25 定稿，见 §3.1 / §3.2）：

| 用途 | 数量 | 走哪条链 | 依据 |
|---|---|---|---|
| 音位电极 | 25 × 3 = **75** | 模拟（4067） | `rc_strip_positions` 三电极重心插值；25 格见 §1.2，C5 也用 3 电极见 §3.1 |
| 八度档 | **5** | 模拟（4067） | 见 §3.2 的位宽反推 |
| 备用 | **4** | 模拟 | 未定义 |
| 泛音键 | 8 | **数字（165）** | 见 §3.2 |
| 预设键 | 4 | **数字（165）** | `06_Controls` PRESET0–3 |
| 编辑键 | 1 | **数字（165）** | `06_Controls` EDIT |
| 编码器 | 3 | **数字（165）** | `06_Controls` ENC_A/B/PUSH |

合计：`75 + 5 + 4 = 84`，正好用满。

> **2026-10-25 定稿**：C5 用 3 电极（`D-022-C5-THREE-ELECTRODES`），音位电极 75、备用 4。
> 此前一度在 73 与 75 之间悬着，现按表情需求定为 75。
>
> **2026-10-24 变更**：本表原为「26 × 3 = 78 音位 + 5 八度 + 1 备用」。
> 取 25 音位后每排少一组，78 → 75，备用从 1 升到 4。
> 载板尚未投板，改动只是删掉每排顶端一组走线，成本为零（见 `D-021` 的 `hardware_impact`）。

### 3.1 C5 用 3 个电极（已定）

规格 §1 把通道 24 叫「**单独的高音 C5 键**」，措辞像单电极。但表情需求把它否掉了。

**为什么 3 电极是唯一选择，不是偏好**：

| 表情维度 | 物理来源 | 需要几个电极 |
|---|---|---|
| D1 力度 | 起音瞬间**接触面积** = `d0+d1+d2` | 1 个就够（绝对电容幅度） |
| D2 触后颤音 | 起音后**面积相对变化** | 1 个就够 |
| D3 滑音 / 推弦 | **格内连续位置** = 重心插值 `(d1+2·d2)·128/sum` | **必须 ≥3 个** |

⇒ 单电极的 C5 只能 on/off + 力度，**没有位置**，会成为整台乐器唯一不能滑音/推弦/颤音的键。
⇒ 3 电极是同一组电极同时给出「位置 + 面积」，不额外花钱。

依据：`docs/01-竞赛情报/01-选题确认与约束条件.md:76` E2「支持力度动态、滑音、颤音等演奏效果」；
`docs/02-技术方案/31-演奏表情规格.md` D1–D4；`D-022-C5-THREE-ELECTRODES`。

账目：`75（25×3）+ 5（八度档）+ 4（备用）= 84`。

### 3.2 165 的 16 位刚好装满，所以八度档只能走模拟

`06_Controls.esch2` 的 10 个网络里，除电源地外有 **8 个数字信号**：

```
PRESET0, PRESET1, PRESET2, PRESET3   （4 个预设键）
EDIT                                  （1 个编辑键）
ENC_A, ENC_B, ENC_PUSH                （编码器 3 个信号）
```

而 `01_Nano_headers.esch2` 的 Nano 排针只接 15 个信号，**不包含这 8 个**。
⇒ 它们只能走 165 读回。

于是 2 片 165 的 16 位是：

```
8（泛音键 H1–H8）+ 4（预设）+ 1（编辑）+ 3（编码器）= 16
```

**一位不剩。** 所以八度档 5 格不可能走 165，只能占模拟侧电极。

按 §1.2 定稿的 25 音位、§3.1 定稿的 C5 三电极，模拟侧账目是：

```
75（25 × 3 电极）+ 5（八度档）+ 4（备用）= 84
```

| 方案 | 模拟侧 | 165 侧 | 状态 |
|---|---|---|---|
| 26 音位（旧假设） | 78 + 5 + 1 = **84** | 8 + 4 + 1 + 3 = **16** | 已作废（§1.2） |
| **25 音位 + C5 三电极（定稿）** | 75 + 5 + 4 = **84** | 8 + 4 + 1 + 3 = **16** | ✅ 采纳 |

**关键点：音位数从 26 改成 25，165 侧完全不受影响**——八度档从来不走 165。
变的只是模拟侧：78 → 75，多出 3 个备用电极。

> 三处 RTL 仍按 26 写（`rc_strip_positions.v:6` 的 `STRIPS=26`、
> `instrument_sensor_probe.v:4` 的 `STRIPS=26`、`left_contact_bridge.v:5` 的 `NF=26`），
> 需随本次决策改为 25。见 §5 表第 5 行。

**结论：音位 25 格、音位电极 75 个、备用 4 个，全部定稿。**

## 4. 电极 → 音位的映射（建议定稿）

```verilog
// NODE_MAP：音位 n 用哪 3 个电极
//   电极全局编号 e = lane*14 + ch，lane ∈ 0..5，ch ∈ 0..13，e ∈ 0..83
//   NODE_MAP[(n*3 + k)*7 +: 7] = e_k     k ∈ {0,1,2}
//
// 建议按物理顺序连续排列（与面板丝印一致，便于故障定位）：
//   音位 0..9   → 电极 0..29   （10 音位，lane 0..1）
//   音位 10..18 → 电极 30..56  （9 音位，lane 2..3）
//   音位 19..24 → 电极 57..74  （6 音位，lane 4..5；24 就是 C5）
//   电极 75..83 → 八度档 5 个 + 备用 4 个（见 §3）
```

**前提**：这个顺序假设电极在面板上按 lane 顺序物理排列，**尚未用面板机械图核对**。
现有 `NODE_MAP` 是恒等占位，从未验证过真实接线。

> 音位占电极 0..74（75 个），电极 75..83 给八度档与备用。C5 已定为 3 电极（§3.1），边界不再摇摆。

#### 5.2.1 G1 的实现细节

`rc_strip_positions` 新增端口：

```verilog
output reg [STRIPS*(CW+2)-1:0] area,   // 每 strip 一段，CW+2 位（三个 CW 位项求和要 2 位进位）
```

行为约定（三条，都进测试）：

| 情况 | `area` | `position` |
|---|---|---|
| 正常触摸 `sum > 0` | `sum` | 重心 `(d1+2·d2)·128/sum` |
| 无触摸 `sum = 0` | `0` | **保持**上一帧（原有语义，不动） |
| 读失败 `!good` | **`0`** | **保持**上一帧 |
| 校准帧 `cal_q` | **`0`** | **保持**上一帧 |

> 面积与位置的失败语义**故意不同**：位置保持是为了避免手指还在但位置跳变；
> 面积清零是因为「坏节点」或「校准」都不能被上游读成一次轻触。
> 校准帧尤其关键——标定时手指可能正按在面板上，若不清零会把标定值当成重按报上去。

## 7. 与 v1 的关系
