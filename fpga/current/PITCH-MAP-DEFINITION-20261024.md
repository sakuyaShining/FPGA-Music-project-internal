# 音高映射定稿：电极 → 通道 → 音符 → 声部

> 2026-10-24 · 依据《音高与八度规格》v2.0（`pad_pitch.v`、`strip_ctrl.v` 头部引用）、
> `project/PRODUCT-SPEC.md` R02、载板 `01_Nano_headers` / `02_Shift_and_memory` / `07–12_Scan_lane_*` 原理图。

## 0. 一句话纠正

**「26 条滑条」是错的。物理上只有 3 根条：A 音位条、B 音位条、八度档条。**

`rc_strip_positions` 的 `STRIPS=26` 是**模块参数默认值**，且 `instrument_sensor_probe.v` 给它的
`NODE_MAP` 是恒等占位映射（`example_map[n*7+:7]=n`，即第 n 个 strip 直接用第 3n/3n+1/3n+2 号电极）。
参数默认值不等于产品定义，把 26 读成"26 条滑条"是把实现细节当成了规格。

**26 是音位（半音格）数量，不是滑条数量。**

## 1. 通道表（权威定义）

`pad_pitch.v` 头部逐字抄录规格 v2.0，共 **38 个语义通道**：

| 通道 | 含义 | 发声 | 物理载体 |
|---|---|---|---|
| `0..11` | 下排 C3..B3，12 个半音 | 是 | A 音位条，每音位 3 电极 |
| `12..23` | 上排 C4..B4，12 个半音 | 是 | B 音位条，每音位 3 电极 |
| `24` | 独立高音 C5 | 是 | 单电极（争议项，见 §4） |
| `25..29` | 八度档条，5 档 | 否 | 5 个单电极 |
| `30..37` | 泛音键，8 个 | 否 | 8 个单电极 → `HARM_PADS` 位图 |

音符号计算（`pad_pitch.v` 第 67 行）：

```
note = 48 + 通道号 + 12 × rel
rel  = pos - 1        pos ∈ 0..4  ⇒  rel ∈ {-1, 0, +1, +2, +3}
```

即默认档（`pos=1`, `rel=0`）下：通道 0 → MIDI 48 = C3，通道 12 → MIDI 60 = C4，通道 24 → MIDI 72 = C5。
换档时整体移调 12 个半音/档，**按下时锁存音符号，松开用锁存值发 note-off**（判据 P6 防挂音）。

### 1.1 八度档条不是滑条

`strip_ctrl.v` 明确：

```
cell_t 0 = -1 octave, cell_t 1 = 0 (default), cell_t 2/3/4 = +1/+2/+3
a press must be held >= HOLD_MS ms to take effect (anti-mistouch, P13)
several cells touched at once -> no action
this module never emits note events (P11, P15)
```

输出 `pos[2:0]`（0..4）是**离散档位**，不是连续位置；`led[4:0]` 单热点亮当前档。
所以用户说的「输出的不同位置的信号，对应不同的八度状态」在 RTL 里的准确形态是：
**5 个 cell 各自 on/off → 一个 3 位档位码**，全程不产生音符事件。

### 1.2 25 还是 26

PRODUCT-SPEC R02 原文：「保留 84 电极能力；**25/26 音位端点**、八度切换对在奏音的行为待明确」。

- 发声音位共 **25** 个（0..24）
- 若 A 条物理上排 13 格（C3..C4 含顶端）、B 条排 13 格（C4..C5 含顶端），则物理格数 **26**，
  但 C4 在两条上重复出现，**不同音高只有 25 个**
- 顶端格（A 的 C4 格、B 的 C5 格）是否独立发声，即「25/26 端点」争议

**这是尚未定稿的产品决策，不是 RTL 能自己决定的。**

## 2. 32 组不是映射目标

`tdm_top_owned.v:15`：

```
NG = 32 组 × P = 16 泛音 = NSLOT 512
=> 最大复音 32 音（对应赛题拓展要求 1 的"复音数 ≥32"）
```

32 是**同时发声的声部数**（复音池），与音位数量是两个正交维度：

- **音位**决定「弹哪个音」（1 个音位 → 1 个 MIDI 音符，25 个音位 = 25 个可选音高）
- **32 组**决定「同时能响几个音」（25 个音位全按住也只占 25 个声部，还有 7 个余量给同音多指）

所以**不存在「26 音位 → 32 组」的映射**。真实链路是三段：

```
电极(84) ──重心插值──▶ 音位/档位(38 通道) ──+48+12×rel──▶ MIDI 音符 ──按音高分配──▶ 声部池(32 组)
```

## 3. 84 电极怎么装下 38 通道

载板器件（`02_Shift_and_memory.esch2` 型号统计）：

| 器件 | 数量 | 位宽 | 用途 |
|---|---|---|---|
| `SN74LV595ADR` | 2 | 16 位输出 | 驱动/LED/使能 |
| `SN74LV165ADR` | 2 | 16 位输入 | 泛音键 + 八度档 + 备用 |
| `CD74HC4067M96` | 6 | 96 通道（用 84） | 模拟电极选通 |

`07–12_Scan_lane_*` 每条通道实际接 14 个电极（`L*_E00..E13`），MUX 的 16 个地址里
`M14/M15` 悬空（`L*_M14`、`L*_M15` 只有 2 处连接，是 MUX 引脚本身）。

⇒ **6 × 14 = 84 个模拟电极**。

分配推演（2026-10-24 二次修正，见 §3.1）：

| 用途 | 数量 | 走哪条链 | 依据 |
|---|---|---|---|
| 音位电极 | 26 × 3 = **78** | 模拟（4067） | `rc_strip_positions` 三电极重心插值 |
| 八度档 | **5** | 模拟（4067） | 见 §3.1 的位宽反推 |
| 备用 | **1** | 模拟 | 未定义 |
| 泛音键 | 8 | **数字（165）** | 见 §3.1 |
| 预设键 | 4 | **数字（165）** | `06_Controls` PRESET0–3 |
| 编辑键 | 1 | **数字（165）** | `06_Controls` EDIT |
| 编码器 | 3 | **数字（165）** | `06_Controls` ENC_A/B/PUSH |

### 3.1 165 的 16 位刚好装满，所以八度档只能走模拟

`06_Controls.esch2` 的 10 个网络里，除电源地外有 **8 个数字信号**：

```
PRESET0, PRESET1, PRESET2, PRESET3   （4 个预设键）
EDIT                                  （1 个编辑键）
ENC_A, ENC_B, ENC_PUSH                （编码器 3 个信号）
```

而 `01_Nano_headers.esch2` 的 Nano 排针只接 15 个信号，**不包含这 8 个**。
⇒ 它们只能走 165 读回。

于是 2 片 165 的 16 位是：

```
8（泛音键 H1–H8）+ 4（预设）+ 1（编辑）+ 3（编码器）= 16
```

**一位不剩。** 所以八度档 5 格不可能走 165，只能占模拟电极的 6 个余量
（5 格 + 1 个备用）。

反推验证两种自洽方案：

| 方案 | 模拟侧 | 165 侧 | 自洽 |
|---|---|---|---|
| **A：26 音位** | 78 + 5 + 1 = **84** | 8 + 4 + 1 + 3 = **16** | ✅ |
| B：25 音位 | 75 + 8 + 1 = 84 | 5 + 4 + 1 + 3 = 13（剩 3 位） | ✅ |

两种在算术上都成立，但 **A 更可能**：`rc_strip_positions` 的 `STRIPS=26`、
`left_contact_bridge` 的 `NF=26`、`check_joint.py` 里 `for i in range(26)`
三处 RTL 都按 26 写。**仍需实测确认**（量一下哪 5 个电极是八度档）。

**结论：84 − 78 = 6 个电极里，5 个是八度档、1 个备用。** 这是推断，不是实证。

## 4. 电极 → 音位的映射（建议定稿）

```verilog
// NODE_MAP：音位 n 用哪 3 个电极
//   电极全局编号 e = lane*14 + ch，lane ∈ 0..5，ch ∈ 0..13，e ∈ 0..83
//   NODE_MAP[(n*3 + k)*7 +: 7] = e_k     k ∈ {0,1,2}
//
// 建议按物理顺序连续排列（与面板丝印一致，便于故障定位）：
//   音位 0..9  → lane 0..1（电极 0..29）
//   音位 10..18 → lane 2..3（电极 30..56）
//   音位 19..25 → lane 4..5（电极 57..77）
//   电极 78..83 → 待定（见 §5）
```

**前提**：这个顺序假设电极在面板上按 lane 顺序物理排列，**尚未用面板机械图核对**。
现有 `NODE_MAP` 是恒等占位，从未验证过真实接线。

## 5. 当前代码与规格的 4 处不一致

| # | 位置 | 现状 | 应为 | 性质 |
|---|---|---|---|---|
| 1 | `sensor_frontend_board.v:43` | `KEY_WIDTH = 8` | **16**（2 片 165 级联） | 位宽不足，会丢一半按键 |
| 2 | `sensor_frontend_board.v:26` | 注释「26 条滑条 × 3 电极」 | 「26 音位 × 3 电极」 | 语义错误 |
| 3 | `rc_strip_positions` 输出 | 只有 26 路 `contact`/`position` | 还需 5 档八度 + 8 泛音键 | **端口缺失**，载板方案跑不通 |
| 4 | `pad_scan.v` vs `pad_pitch.v` | 五声音阶 8 键（C4 D4 E4 G4 A4 C5 D5 E5） | 半音阶 25 音位（C3..C5） | 两套音阶表，v1 与载板不通用 |

第 3 条最要紧：`rc_strip_positions` 的 `contact`/`position` 只覆盖 26 个 strip，
**八度档、泛音键、预设键、编辑键、编码器全都没有输出通路**。载板方案要完整工作，需要补两级：

**（a）数字侧**——把 165 读回的 16 位拆开（位序待实测）：

```verilog
wire [7:0] harm_mask   = keys[7:0];    // 泛音键 → pad_pitch.harm_mask
wire [3:0] preset_key  = keys[11:8];   // PRESET0–3
wire       edit_key    = keys[12];     // EDIT
wire [2:0] enc         = keys[15:13];  // ENC_A / ENC_B / ENC_PUSH
```

**（b）模拟侧**——八度档 5 格不经过 `rc_strip_positions`（它只认 26 个 strip），
必须直接从 `rc_mux_scan` 的 `row_count` 里取那 5 个电极地址的计数，
自己做阈值判定，得到 `octave_cell[4:0]` 送 `strip_ctrl.cell_t`。

这两级目前**都不存在**。上一轮写的 `sensor_frontend_board.v` 只做到了
「165 → 16 位原始数据」和「4067 → 6 路计数」，没有再往产品语义上拆。

## 6. 待决策（需产品层拍板）

1. **25 还是 26 音位**：顶端格（A 的 C4、B 的 C5）是否独立发声？
2. **哪 5 个电极是八度档**：§3.1 推断 84 = 78 + 5 + 1，但具体是哪 5 个（`L?_E??` 编号）仓库里没写，需实测或向设计者确认
3. **八度切换对在奏音的行为**：换档时正在响的音是否跟着变调？（规格 P11/P12 说"换档不产生事件、已在响的不受影响"，即**不跟变**）
4. **165 的位序**：两片级联后主片在低 8 位还是高 8 位？原理图网络名看不出来，只能靠「只按一个已知键、看哪一位翻转」实测。这一条不定，读回的 16 位可能高低颠倒

## 7. 与 v1 的关系

v1（`impl_pnr_board.fs`）是**五声音阶 8 键**，载板是**半音阶 25 音位**。
两套音阶表不同，码流与载板不通用。91 号文档 §3.1 的五声音阶表只对 v1 有效。
