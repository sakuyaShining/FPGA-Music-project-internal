# N-12 演奏音频可视化

用户2026-10-10明确提出上位机查看波形/知道乐器应该怎样响，并进一步确认“至少实现看到音频曲线”，希望演奏结果可见。记录为新增需求N-12，原N-01～N-11不改号、不改变音乐语义。

## 首版必须提供的可见反馈

- 在上位机提供“音频观察”页，展示横轴时间、纵轴幅度的音频波形，支持采样、冻结、导出。
- 清楚显示来源：FPGA实际内部数字采样 / 模型预览 / 历史文件。未连接、未采样、过期或失败数据不可冒充当前输出；失败时保留上一帧并标历史/失败。
- 显示采集时间、采样率、窗口时长、峰值/RMS/数字满幅标记。静音也显示真实零样本；没有数据不画成“已测静音”。
- 观察不改变配置草稿、不触发额外note-on；采样和串口控制须协调，不能新增串口客户端抢占COM。
- 第一版显示实际FPGA内部合成曲线。它证明合成样本，不证明DAC电气/喇叭听感；未来真实模拟回录需ADC/声卡与安全线路输入。

频谱是下一步建议：帮助看到基频、泛音和分量变化。多音时不把FFT最大峰简单称为唯一音符；波形/RMS也不自动识别具体手势。模型预览及电脑试听仍是独立提议，未实现，不替代实际板采样。

## 现有实现能力与缺口

现有dsp_gui有谱分量编辑与旧RC遥测，没有音频波形页；SimLink模拟寄存器，不产生音频。已有柱图代表参数/电极，不能当作真实音频频谱。

当前tdm_board_test BOARD_DIAG1包含2048×24bit观察器，主机test_board_hardware.py经0x80启动、0x81读取长度、0xA8请求完整流，返回1字节标记+6144字节样本。已验04有原始流/npy与真实两指变调谱证据，可以作为首版接口基础。

fs=52734.375Hz，2048样本窗口约38.84ms；115200/8N1下6145字节理论线传输约0.5334s，再计捕获/轮询和调度。现有流适合定期波形快照，不能叫连续实时示波器。视觉更新速度和触摸→音频≤10ms是两个指标，不能混算。

产品默认tdm_ship未启用诊断观察器，不能无身份/能力检查发送私有命令。GUI采集先核对诊断ID、协议、版本/长度；不支持设备显示不可采集。今后迁入产品要独立评估资源、协议、带宽和PnR，CLS95%不能忽略。

## 实现与验收拆分

1. 波形控件＋解析/指标：离线用已归档实际样本验证正负24bit、时间轴、零样本、满幅、错误长度和来源标记。
2. GUI单串口采样：后台执行并超时，界面不假死；timeout在发送流请求前配置，失败保存原始字节。串口关闭/切换/参数命令与采样互斥，完整结束再恢复，不能重现主机SetCommState竞争。
3. 可见板验：在已识别配置上捕获静音、单音、和弦、音高移动、释放；比较GUI数据和同次原始流，记录实际刷新率、最后采集时间和失败状态。只签收此配置的内部数字波形。
4. 新GUI源码必须捕获新完整源清单，跑相应GUI/解析/串口与回归门禁；原04清单/码流/证据保留。波形功能代码完成、GUI验证、真板采集、产品接入分开记录。

当前状态：**需求已确认、接口调查完成；波形页/解析/采集接入尚未实现。** 输出模块和触控采购不因这一需求改写；首版可利用当前板测采样，无需先采购ADC。
