# 上位机音乐可视化：先显示FPGA实际波形

2026-10-11。用户要求改善上位机，建立操作→UART→FPGA→UART→可见反馈，并讨论连接电脑与实体屏幕两种显示方式。

不需要先选实体屏幕。计算模块与显示后端分离：FPGA生成实际声音样本，未来生成轨迹/波形分析/频谱结果；UART向电脑传数据，电脑解析并绘制。未来FPGA直接渲染到实体屏幕，二者可复用同一结果接口。电脑绘制线条不等于替FPGA合成或做FFT。设备实际样本与主机命令意图必须分开，外部电气/DAC验收另计。

已问用户是否允许显式标注的电脑FFT调试模式；用户询问FFT含义，尚未批准双模式。当前继续不添加电脑FFT，也不修改全FPGA产品约束。FFT将时域音频变成各频率强度，便于观察基频/泛音；目前FPGA FFT和已接受事件轨迹接口未实现。

## 本次已实现

- GUI新增第04页“音乐可视化”，未采集时明确无数据，SimLink不制造声音。
- 真实full32诊断设备身份门禁：D3/rev2/proto11/scope32，配置标签不是唯一码流指纹。
- 单次2048点24bit采样；可选合成干声或效果后节点，固定原始满幅单位，可手动显示放大。没有PC FFT/RMS等分析。
- 独占现有串口、后台QThread捕获；停止RC轮询，其他发送/读回/断开受串口事务锁保护。所有timeout变更在流请求前完成，失败保留原始字节/历史快照。
- 导出JSON、自动归档原始流/样本/时间/配置标签；提供A4命令与释放按钮。命令发送不是执行证据，需看实际回传曲线。正常断开/关闭释放页面发出的测试音。
- 音符轨迹和频谱明确显示“等待FPGA接口”，不把已有参数柱图或电脑FFT签收为三视图完成。

新源身份`integration-20261011-01.json`共228输入；仅tools/host四项新增/修改，RTL/数据/约束/构建与回归脚本逐项SHA等于04。旧04完整源与板测证据保留，本次不重新PnR或下载，不把旧板码流绑定成新GUI版构建。

## 使用

`python tools/host/dsp_gui.py --audio`

选COM6连接→发送A4测试音→采集一次→查看真实快照→释放A4。也可先在设备实验页播放曲谱再切到本页采集。串口忙时等本次完成，采样不与其他程序共用COM6。截图不是连续实时音频；当前线传限制保持原样。
