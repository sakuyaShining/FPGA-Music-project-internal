# 上位机定位、当前功能与后续设计建议

2026-10-11，针对当前228输入GUI版integration-20261011-01核对源码。本页是设计评审建议，不自动批准新功能或改音乐语义；没有修改产品代码。

上位机宜定位为“乐器配置与演奏观察工作台”：准备配置、显式应用、观察FPGA实际结果、排查异常。Nano20K独立完成应用计算；电脑承担配置编辑和图形呈现，电脑FFT调试模式尚未批准。

## 推荐产品流程

1. 音色设计：完整草稿→保存→能力检查→显式应用→设备确认。文件保存和设备应用分开；失败不把草稿标成已生效。保持当前已决定的草稿不自动改变在奏音原则。
2. 演奏观察：轨迹、波形、频谱使用FPGA实际结果，同一时间基准；三者以同一视图可对照。电脑命令轨迹若单独显示，标“已发送”，不能混成“FPGA已执行”。轨迹记录所属音高/触点身份，频谱看音频基频/泛音，避免从FFT猜全部触点。
3. 设备与诊断：型号/能力/配置、连接/采样状态、吞吐/数据年龄、队列/视觉溢出和错误；底层寄存器/旧实验放高级区。CRC/序号/重传等协议建议须结合资源和时限另评估，不冒充当前协议已具备。

页数不是主要目标；现四页可继续保留，不急着重排。优先建立草稿、已发送、设备确认、实际观测四层状态。不要单一绿色“正常”同时表示连接、音频内部运算、DAC电气和声音。

## 当前优先缺口

- 完整配置应用设备及确认机制；配置版本、当前生效配置与草稿差异可见。
- FPGA已接受事件/实际音高时间线和频谱分析结果接口，连到当前波形页；联合资源、通信与时序评估，不能电脑FFT代签收。
- 带时间戳/来源/过期状态的持续观察与冻结比较；“前后音色”比较必须是实际不同配置采样，模型预览另标。
- 串口事务调度与响应性继续验证，波形采集当前保护已接，不能用更多程序分别占串口。
- 真实声音/触控全链验证：数字正常与电气/听感正常分开显示，测不到的状态显示未验证。

上述建议尚未变成实现或用户批准的缩减/新增语义。音频引擎与实体输入/可视化计算仍在Nano20K，屏幕是另一个显示后端，不阻碍电脑观察功能。
