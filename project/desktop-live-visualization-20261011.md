# N-12 电脑连接模式：实际演奏与音频实时观察

2026-10-11用户明确更新计算边界：连接电脑时允许上位机使用电脑计算资源进行音乐可视化；实体机独立运行时保留FPGA轨迹、波形、频谱功能。原禁止PC计算可视化的决定在这一场景被覆盖，触控/发声和实体功能仍由Nano20K完成，外部采集MCU仍禁止。

## 目标与数据真实性

用户需要演奏过程中持续看到演奏行为和实际音频变化。电脑可对收到的实际音频做FFT、响度与波形分析并绘图；不能依据键盘或预设在电脑另合成一段声音冒充FPGA输出。当前快照实现不能签收本目标，添加FFT到旧快照也不算实时完成。

默认先观察FPGA效果后实际数字音频；此信号就是送往音频输出链的内部数据来源，但与I²S输出的16bit取高位、DAC模拟信号、扬声器声压分别记录。若用户需要验证物理发出的声音，可在音频硬件到位后增加线路录音/麦克风声学观测，标明来源并处理录音延迟。不能用内部样本验证DAC是否已发声。

## 双模式计算分工

| 工作 | 连接电脑 | 独立实体机 |
|---|---|---|
| 演奏输入 | 键盘操作经UART送入FPGA，实体触控接入后可并用 | FPGA实体输入 |
| 生成声音 | Nano20K现有合成与效果引擎 | 同一FPGA引擎 |
| 执行轨迹 | FPGA输出接受/执行事件与采样时间，电脑管理历史并绘制 | FPGA记录并呈现 |
| 波形/频谱分析 | 电脑根据实际连续音频分析 | FPGA模块处理 |
| 显示 | 上位机三视图 | FPGA驱动实体显示 |

电脑分析合法且算正式上位机功能；它不代替或证明实体侧算法已完成。实体方案无需因电脑模式立刻装进同一诊断配置，两个运行配置需各自身份和验收，不能缩减既有音乐能力来宣布统一完成。

## 所需实时链路

FPGA音乐引擎持续运行，增加有界的音频传输缓冲与执行事件队列。音频帧带采样编号、长度、格式/采样率、丢失标志和校验；事件使用同一时间基准。主机接收线程持续组帧，分析线程使用环形缓冲，GUI独立刷新。绘制波形不等整秒事务；不在GUI线程等待串口或每帧写证据目录。录制按用户开启，错误证据有界保留。

波形提供滚动的秒级音量变化以及毫秒级振荡细节两个时间尺度；FFT对实际音频分窗计算，使用窗函数与重叠更新，并显示频率范围/分辨率。轨迹分别显示主机发送意图和FPGA执行事件，执行结果中有拒绝/溢出/丢失标记。三视图依据采样编号关联，不能将电脑收包时间当音符真实发生时间。

## 带宽是实际阻碍，电脑计算无法补回缺失数据

现有115200 8N1最多11520B/s；原24bit单声道52734.375Hz为158203.125B/s。原链路只支持抓段，不能完整搬运。

候选一：更高UART波特率＋观察流16bit格式，在921600条件下原采样率16bit约105468.75B/s仍超92160B/s，因此仍须适当减采样或提高到更高可验波特率。例如经FPGA抗混叠滤波后2倍减采样至26367.1875Hz，16bit音频约52734.375B/s，在921600理论可留帧/事件余量，可观察频带上限约13.18kHz；音频输出保持原采样率，不因观察流改变音质。波特率能力、滤波资源、链路稳定性全部尚未验证，不直接配置上线。

候选二：独立音频采集通路，由电脑声卡获取实体DAC线路输出，原UART仅传控制和执行事件。当前DAC/采集设备未就绪，不能把此路径当立即可用。音频带宽、通道和时间对齐需实测。

115200下可发送FPGA连续统计的波形摘要改善包络显示，但摘要无法重建全音频FFT；不得宣称三视图已完成。只提高GUI帧率或对静态片段插值同样无效。

## 建议验收方向

刷新目标可先以20–30次/秒、输入到可视化目标100ms内作为工程候选，频谱低音分辨率与窗口延迟单独标明；这些不是已冻结或已通过指标。必须测持续吞吐、帧完整性、音频最大空隙、事件到显示延迟分布与最大值、快速按放、和弦、失焦/断连、丢帧提示、CPU/队列/磁盘增长。实际音频频谱与执行轨迹不能只用模拟源验收。

本文件记录新决定和所需架构；本轮未改产品源码、没有新构建/下载。当前integration-20261011-03 GUI仍只有快照，实体FPGA可视化仍未实现。后续开发要先验证持续数据入口，再联调三视图，避免用可见UI替代数据链路验收。
