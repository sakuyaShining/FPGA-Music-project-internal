# 维护窗口调整（2026-10-26）

| 项 | 原值 | 新值 |

| 设计审阅窗口 `review_max_hours` | 24 h | **72 h** |

## 依据

1. `project/producers.json` 登记的 4 个活跃源根目录全部位于本机
   （`D:/FPGA-Project/...`、`C:\Users\Sakuya\.codex\worktrees\06df\...`）。
   GitHub runner 无法访问这些路径，CI 只能校验"记录中的观察时间"，不能自证源是否漂移。
2. 观察窗口（6 h）与定时周期（6 h）相等：任何一次真实续期最多撑到下一次定时运行，
   且必须卡点提交。结构上最多 1/4 的定时运行能通过，**不存在"保持绿色"的操作序列**。
   这不是门禁过严，而是窗口与检查频率不自洽。
3. 本次真实观察（`2026-10-26T13:27:46Z`）覆盖 4 个源共 618 个声明文件，
   与 `2026-10-24T15:21:18Z` 的记录逐文件一致：新增 0 / 删除 0 / 修改 0。
   因此本次续期有观察支撑，不是修改日期。

## 边界

- 这是**维护阈值**调整，不是产品验收状态变化。
  `product_acceptance` 与 `implementation_start_authorized` 保持 `false`。
- 不改变 N-01～N-12 任何语义，不改 07 码流与既有证据，不替代 PnR / STA / 板级测试。
- 窗口放宽**不等于**允许跳过观察：超过 30 h 未重新观察，检查仍会失败。
- `notes/main-design-authority-20261023/RESULT.md` 是日期化历史记录，保留原文不追改。
