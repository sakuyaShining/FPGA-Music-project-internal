## 一、AUX：方向对，但有四件事必须先知道

### 1.1 板载 MAX98357A 不能直接当 AUX 用

`39号` 原文：

> 板载 MAX98357A **差分喇叭输出不能直接接普通共地耳机/AUX**

`43号` 原文：

> 板载 MAX98357A 为喇叭功放，**不是线路输出**；两端桥接输出不接地式 3.5mm 线路输入

所以 AUX 必须是**独立 I²S DAC 支路**：PCM5122 + 3.5 mm 插座 + 外围（2.2 µF×3 / 100 nF×4 / 输出 RC）≈ **¥28**。这已经在 88 号 BOM 里。

### 1.2 但 I²S 信号**不出排针** —— 这是最硬的约束

| FPGA 脚 | 信号 | 是否在 J5/J6 排针 |
|---|---|---|
| 51 | `pa_en`（MAX98357A 使能） | ❌ 板内直连 |
| 54 | `dac_din` | ❌ 板内直连 |
| 55 | `dac_ws` | ❌ 板内直连 |
| 56 | `dac_bck` | ❌ 板内直连 |

`nano-header-candidate.csv` 里 17 个信号脚**没有一个**是 51/54/55/56。

**后果**：载板拿不到 I²S 信号。要接 PCM5122，必须让 FPGA **另外**在 3 个排针脚上输出同一组 I²S（BCK / LRCK / DIN；SCK 由 PCM5122 内部 PLL 从 BCK 恢复，可省）。

**引脚账**（现有规划）：

| 用途 | 脚 | 数量 |
|---|---|---:|
| 共享 SPI（扫描链 + 屏） | SCK 27、MOSI 15 | 2 |
| 屏 | CS 19、DC 20 | 2 |
| 扫描链 | LATCH 16、LOAD 17、DATA 28 | 3 |
| I²C | SDA 25、SCL 26 | 2 |
| 触摸中断 | 77 | 1 |
| 电极 sense | 29/30/31/41/42/48 | 6 |
| **小计** | | **16 / 17** |
| **可视化屏取消后空出** | **18（原 `LCD_VIS_CS_N`）** | **1** |

**AUX 需要 3 个，只空出 1 个，还差 2 个。**

解法（载板设计时必须一起定，不能先买芯片再想脚）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 用 74HC4067 的地址线复用，把 6 路 sense 压到 2 路 | 要重写扫描时序 |
| B | 牺牲 2 路电极（7 → 5） | 左手音域变窄 |
| C | 用 I²C 扩展（PCF8575）出 3 根脚给 I²S | **不可行**，I²C 太慢，出不了 I²S |
| D | 在板载 MAX98357A 的 54/55/56 焊盘上飞线 | 破坏性，不建议产品用 |

**推荐 A**：产品本来就要用 6×4067 做 83 节点，地址线复用是顺带的。

### 1.3 PCM5122 需要 I²C 配置 —— I²C 总线变第 4 个从机

| 从机 | 地址 |
|---|---|
| PCF8575（16 键） | 0x20 |
| 24LC256（音色） | 0x50 |
| **PCM5122（AUX DAC）** | **0x4C / 0x4D** |
| 触摸 IC | 0x5D（GT911）/ 0x70（FT5316） |

**上电顺序变成**：I²C 调度器 → 先配置 PCM5122（解除静音、设 I²S 从模式）→ 再出声。**没配置就完全静音**，而且不会报错。

> ⚠️ 需要核实：PCM5122 能否在**免 I²C**的默认状态下直接出声。若能，可省掉这一步和 0x4C 从机；若不能，必须写初始化序列。这一条我不确定，不要当成已定。

### 1.4 不接喇叭的真实代价

**没有喇叭就必须接外部有源音箱/调音台才能出声**，拍视频也一样。板载 MAX98357A 仍在板上（不驱动 `pa_en` 即可静音），不算浪费。

`49号` 记录的产品规格是"**保留 4Ω/3W 喇叭 + 新增 AUX 双路**"。你现在改成 **AUX 单路**，这是一次设计变更，需要写进版本库——否则以后看文档的人会以为喇叭还在。

## 二、触控屏：推荐 7" RA8875 + 电容触摸

### 2.1 先纠正我上一轮的两个错误

| 我说过 | 实际 |
|---|---|
| "真正自由的只有 48，最多加 77" | **错**。18/19/20 在原规划里就是 `LCD_VIS_CS_N` / `LCD_HARM_CS_N` / `LCD_SHARED_DC`，**屏的 SPI 早就规划好了**，不是"没有引脚" |
| "RA8875 渲染器已写好并实测 −628 Logic"（引自 `BOM-PROTOTYPE` §1.3） | **不能套用到 J10**。`89号` 那个渲染器是给**已取消的可视化屏**做的 ILI9341→RA8875 替换，而且只在 `experiments/renderer_swap_ra8875_20261019/` 里，**产品树里零实现**（全仓库 grep 无任何 `ra8875` 的 `.v`） |

**所以：J10 的显示驱动，不管选哪块屏，都要从零写。** 这削弱了"选 RA8875 因为渲染器已有"这个理由。

### 2.2 但依然推荐 RA8875，理由是另外三条

**① 尺寸是硬约束，3.5" 放不下**

右手要 8 组竖直推子，手指触摸需要 **≥12 mm** 间距（指尖宽约 10–12 mm）。

| 屏 | 有效宽 | 8 组间距 | 能用吗 |
|---|---:|---:|---|
| 3.5"（SKU30896） | 73 mm | 9.1 mm | ❌ 放不下 |
| 5" | 110 mm | 13.8 mm | ⚠️ 勉强 |
| **7"（ER-TFTM070）** | **154 mm** | **19.3 mm** | ✅ |

`62号` 原文：7 英寸有效区 154.08×85.92 mm，8 组节距约 19.26 mm，2 mm 间隔时净宽约 17.51 mm。

**② RA8875 自带图形引擎 + 768 KB 显存，FPGA 不用存帧**

这是 7" 能不能跑起来的关键：

| | 纯像素流（ST7796S/ILI9488 类） | RA8875 命令模式 |
|---|---|---|
| 一帧 800×480×16 bit | **768 KB** | 不传帧 |
| 更新一根推子 | 要重画相关区域 | 发"画矩形"命令，**几十字节** |
| FPGA 侧需要帧缓存 | **需要**（占 SDRAM 带宽） | **不需要** |
| 一次 UI 刷新的 SPI 占用 | ~1.5 MB | < 100 B |

7" 用纯像素流，每帧 768 KB，SPI 跑 25 MHz 也要 30 ms ⇒ 33 fps 上限，且 SDRAM 被帧缓存吃掉。**RA8875 把这件事变成"发命令"，是 7" 唯一现实的做法。**

**③ 4 线 SPI 正好对上现有引脚规划**

SCK 27 / MOSI 15 / DC 20 / CS 19，**不需要新增任何引脚**（写-only，不需要 MISO）。

### 2.3 推荐结论

| 项 | 推荐 |
|---|---|
| 屏 | **7" 800×480，RA8875 控制器，电容触摸** |
| 具体型号 | **ER-TFTM070-5V4 的「4 线 SPI + 电容触摸」版** |
| 触摸 IC | FT5316（I²C **0x70**）—— 若实际是 GT911 则 0x5D |
| 预算 | **¥300–350**（¥280 是 US$40.18 起的换算，电容触摸是**加价项**） |
| 接口 | 显示 4 线 SPI（写-only）+ 触摸 I²C + `TP_INT` |

**下单前必须确认三件事，否则买错**：

1. **模块确实引出 4 线 SPI**。`62号` 原话：「芯片支持 SPI **不等于**所有使用它的成品模块均引出了 SPI」。要卖家给原理图或引脚表。
2. **触摸 IC 到底是 FT5316 还是 GT911**。决定写哪个驱动，也决定 I²C 地址。
3. **是否含 3.3 V 电平转换**。模块若为 5 V 逻辑，必须确认 SPI 侧可 3.3 V。

**不推荐**：

| 选项 | 为什么不行 |
|---|---|
| 3.5" SKU30896 / 2.8" SKU27579 | 物理尺寸不够，8 组推子放不下 |
| SSD1963 类 | 16 位并口，需 16+ 引脚；且无字库/画线引擎 |
| 纯 HDMI 屏 | Nano 20K 的 HDMI 是**输出**，不能反接 |
| LT7680A | 国内已停售、库存 0（62号） |
| MRB7966 | 16 位并口，同样引脚不够 |

### 2.4 一个降低风险的顺序

**先花 ¥15 买 CH341A，读手上任何一块屏的触摸 IC 地址，再决定买哪块。** 或者直接找卖家要模块原理图——这比读地址更可靠，而且免费。

## 三、产品级采购单（不是原型实验单）

### 3.1 先承认：上一份清单确实是原型清单

它从 `BOM-PROTOTYPE-20261022.md` 的框架里长出来，那份文档标题就是「可直接下单的**原型**采购清单」，目的写得很明确：「不等 PCB 也能搭出一台能演的桌面原型」。

**你要的是产品。这两件事的物料清单不一样**——原型要洞洞板、杜邦线、面包板、USB 转 I²C；产品要载板打样、覆盖膜、结构件、SMT 装配。我混在一起了。

### 3.2 但产品化前面缺的不是采购，是 PCB

我核了实际硬件状态（`hardware/pitch-sliders/prototype-schematic-20261015/connectivity-audit.json`）：

| 项 | 实际 |
|---|---|
| 原理图 | 有，嘉立创 EDA 工程，53 元件 / 231 引脚 / 59 网络 |
| 连通性 | **207 接入 + 24 明确 NC = 231，mismatches 0**，原生 DRC 0 项 |
| PCB | **仍为空，不含 Gerber** |
| `manufacturing_release` | **false** |
| 覆盖范围 | **只有左手电极前端（四滑条小样）**，不含屏、不含 AUX、不含完整 16 电极面板 |

> **顺带纠正一处**：`NOV04-PLAN.md` 写「PCB 59 项未连通」。审计原文是 **nets: 59**（59 个网络）、**mismatches: 0**、**intentional_nc: 24**。**没有"59 项未连通"这回事**——是把"59 个网络"读成了"59 项未连通"。这让硬件看起来比实际糟得多。

**所以产品化真正的路径是**：

```
画完整载板 PCB（含屏接口 / AUX / EEPROM / PCF8575 / 6×4067）
  → 电极面板 + 覆盖膜
  → 打样
  → SMT 选择性装配
  → 装配调试
```

**采购可以现在下（器件不会因为 PCB 没画而变），但打样不能。**

## 四、下一步的顺序（产品路径，不是原型路径）

| 步 | 内容 | 依赖 |
|---|---|---|
| 1 | **定屏**：找卖家要 ER-TFTM070-5V4 电容触摸版的**引脚表/原理图**，确认 4 线 SPI + 触摸 IC | 免费，今天能做 |
| 2 | **定 AUX 引脚**：I²S 那 3 根脚从哪来（推荐复用 4067 地址线） | 需要载板设计 |
| 3 | **画完整载板 PCB**：在现有四滑条小样原理图上加屏接口 / AUX / PCF8575 / 完整 16 电极 | **这是最大的缺口，不是采购** |
| 4 | 采购 A+B 组器件（¥93） | 现在就能下 |
| 5 | 打样 + SMT（¥190） | 依赖第 3 步 |
| 6 | 屏到货后写 J10 显示驱动（从零） | 依赖第 1 步 |

**注意第 3 步**：它不是"买料"，是几天的 PCB 设计工作。**你现在感觉像原型实验，根本原因就是这一步没做**——没有 PCB，任何物料清单都只能按"面包板能不能接"来组织，看起来就像实验。
