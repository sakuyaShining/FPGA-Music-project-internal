# 产品规格与使用规则（v1 / build_v1）

**对应码流**：`board.fs` SHA256 `78650B34EC24CD863A40DD928FCAFFB434F55C9D42453959941499D564C7B533`
**顶层**：`tdm_ship_owned` ｜ **器件**：GW2AR-LV18QN88C8/I7（Tang Nano 20K）
**时钟**：27 MHz 单时钟域（SDC 周期 37.037 ns）｜ **构建**：`build_product.py build_v1 full 1`

---

## 0. 这个产品是什么，不是什么

**是**：一台 16 电极直接输入的加法合成电子琴。32 组声部 × 16 分量，I²S 数字输出，UART 配置，可脱机运行。

**不是**：冻结基线里的完整形态。**没有** 84 电极节点 MUX、J10 触控显示、EEPROM 非易失、TF 卡录放。这些在 v1 里不存在，不是"默认关闭"——是**没有对应模块**。

| 能力 | v1 | 冻结基线要求 | 差距 |
|---|---|---|---|
| 电极输入 | 16 路直连 | 84 电极 + 节点 MUX | 未实现 |
| 合成分量 | 32 组 × 16 | 同 | ✅ |
| 右手修饰 | 无（`RIGHT_TIMBRE=0`） | J10 全和弦修饰 | 未实现 |
| 逐指音高 | 无（`FINGER_EXPR=0`） | 两排逐音滑条 | 未实现 |
| 配置保存 | 断电丢失 | EEPROM | 未实现 |
| 录制回放 | 无 | TF 卡 | 未实现 |
| 音频输出 | I²S（PCM5122） | 同 | ✅ |

## 1. 硬件接口

### 1.1 引脚定义（取自 `constraints/tdm_ship_owned.cst`）

| 信号 | 引脚 | 方向 | 说明 |
|---|---|---|---|
| `clk` | 4 | in | 27 MHz 晶振 |
| `btn_rst` | 87 | in | 板载按键 S1，**高有效**，外部下拉 |
| `uart_rx_pin` | 70 | in | 上位机发送 → FPGA |
| `uart_tx_pin` | 69 | out | FPGA → 上位机 |
| `dac_bck` | 56 | out | I²S 位时钟 |
| `dac_ws` | 55 | out | I²S 左右声道选择 |
| `dac_din` | 54 | out | I²S 数据 |
| `pa_en` | 51 | out | 功放使能 |
| `led[0..5]` | 15,16,17,18,19,20 | out | 6 个 LED |
| `pad[0..7]` | 27–34 | inout | **左手音高电极** |
| `pad[8..15]` | 35–42 | inout | **右手泛音电极** |

> ⚠️ **54/55/56 是 GW2AR-18 的 SSPI 复用脚**。构建时必须 `set_option -use_sspi_as_gpio 1`，否则布线阶段报 "pin already used by SSPI"。代价见 §6.2。

### 1.2 电极电学

每个 `pad[n]` 是**充放电 RC 测量**：同一根线先驱动高电平充电，再放开读放电计数，计数差即接触量。所有 pad 内部下拉（`PULL_MODE=DOWN`），**悬空即无触摸**。

## 2. 上电行为

上电时序：POR（上电复位）→ 内部 `rst_gen` 消抖 → `rst_n` 释放 → 引导序列写入默认寄存器。

**引导序列写入的默认值**（来自 `tdm_top_owned.v` 的 boot scrub 表）：

| 寄存器 | 默认值 | 含义 |
|---|---|---|
| `0x50` SEQ_CTRL | `0x00` | 定序器关闭 |
| `0x51/0x52` TEMPO | `0x027C` | 120 BPM（636 分频） |
| `0x48` REV_FB | `0x80` | 混响反馈 0.5（**`0xC0` 会让线缓冲冲饱和**，实测 91.9% 样本被限幅） |
| `0x49` REV_DAMP | `0x03` | 混响阻尼 |
| `0x54` SEQ_VEL | `0x80` | 定序器力度 |
| `0x5A` SPEC_MODE | `0x02` | 叠加 + 自动刷新 |
| `0x60` NOTE_NUM | `0x00` | **无待发音符 ⇒ 上电静音** |
| `0x5B` HARM_PADS | `0x00` | 右手泛音位图清零（不清会让 3 个泛音被 boost 到 255） |
| `0x58` SPEC_IDX | `0x00` | 谱指针归零 |
| `0x59` 谱[0..15] | 全 `0x00` | **谱 RAM 显式清零**——综合后未初始化 RAM 读出是 `x`，会整条变 `x` |
| `0x6E` VEL_SENS | `0x80` | 力度灵敏度中区 ⇒ vscale=256（表一等一） |
| `0x6F` VEL_SHIFT | `0x05` | 每档右移 5 位 ⇒ 每档力度约 32 拍 |

**结论：上电默认静音，不按电极不发声。** 这是设计意图，也是板级验收的第 1 条。

## 3. 怎么演奏

### 3.1 左手音高（`pad[0..7]`）

**五声音阶固定映射**（`pad_scan.v` 里写死的 case 表）：

| 电极 | 音名 | MIDI |
|---|---|---|
| `pad[0]` | C4 | 60 |
| `pad[1]` | D4 | 62 |
| `pad[2]` | E4 | 64 |
| `pad[3]` | G4 | 67 |
| `pad[4]` | A4 | 69 |
| `pad[5]` | C5 | 72 |
| `pad[6]` | D5 | 74 |
| `pad[7]` | E5 | 76 |

C 大调五声音阶，跨一个八度多。**按下即发音，松开即释放**；多指可同时按（受 32 组声部限制）。

**八度切换在 v1 里固定关闭**（顶层 `oct_up` 接 `1'b0`）——只会发出上表这一个八度。

### 3.2 右手泛音（`pad[8..15]`）

右手 8 路是**泛音修饰位**，不改变音高，改变该音的泛音配比（音色）。位图寄存器 `0x5B` 记录当前按下的右手位。

> v1 的右手通路是**位图式**，不是冻结基线要求的"J10 分区推子 + 全和弦连续修饰"。这两者的操作感受完全不同，不要把 v1 当成最终右手方案。

### 3.3 力度

**没有压力传感**。力度来自 RC 放电计数的差值：充放电越快=接触越实。映射由两个寄存器决定：

- `0x6E` VEL_SENS：`0x00`=关（力度对音色零影响）/ `<0x40`=半灵敏 / `<0xC0`=一等一 / `≥0xC0`=加强
- `0x6F` VEL_SHIFT：差值右移位数，越大每档越细

出厂默认 `0x80 / 0x05`。**电容读数不等于物理压力**，这是近似手感，不是力度键盘。

## 4. LED 指示

6 个 LED 为**共阳极：写 0 点亮**（`assign led = test_mode_eff ? 6'b000000 : led_ind_o`）。

- 正常模式：`led_ind_o` 驱动，指示引擎活动状态
- 测试模式（`test_mode=1`）：恒定全亮 `6'b000000`

> v1 的 LED 语义只有"引擎活动"这一类，没有错误码显示。这是 v1 的不足。

## 5. UART 配置接口

**参数**：115200 baud，8N1，无流控。FPGA 的 `uart_rx_pin`=70、`uart_tx_pin`=69。

### 5.1 协议形态

**不是**命令行文本协议，是**寄存器对传输端点**（`uart_cfg_transport.v`）：上位机按"地址-数据对"逐字节写，FPGA 用地址做状态机。

### 5.2 状态回读（只读寄存器）

| 地址 | 含义 | 默认值 |
|---|---|---|
| `0xD0` | 魔术字节 | `0x75` |
| `0xD1` | 主版本 | `1` |
| `0xD2` | 次版本 | `4` |
| `0xD3` | 每乐器分量数 | `16` |
| `0xD4` | 每分量字节数 | `11` |
| `0xD5` | 乐器槽数 | `7` |
| `0xD6` | 状态机状态 | IDLE=0 / 传输中=1·2 / DONE=3 |
| `0xD7` | 最近结果码 | 见 5.4 |
| `0xD8/0xD9` | 序列号 lo/hi | — |
| `0xDA` | 当前槽号 | — |
| `0xDB` | 已收字节数 | — |
| `0xDC/0xDD` | CRC lo/hi | — |
| `0xDE/0xDF` | 修订计数 lo/hi | — |
| `0xE8` | 已使能槽位图 | — |
| `0xE9` | `{6'd0, sandbox, idle_allowed}` | — |

### 5.3 乐器上传流程（沙盒式，坏数据不会进活动区）

| 步骤 | 地址 | 数据 | 说明 |
|---|---|---|---|
| 1 | `0xE0` | `0xA5` | 进入沙盒，开始一次上传 |
| 2 | `0xE1` | `0..3` | 槽号（`<4` 才合法） |
| 3 | `0xE2/0xE3` | 任意 | 序列号 lo/hi |
| 4 | `0xE4` × **176** | 数据 | 16 分量 × 11 字节 = 176 字节 |
| 5 | `0xE5` | CRC lo | CRC16-CCITT，初值 `0xFFFF`，多项式 `0x1021` |
| 6 | `0xE6` | CRC hi | |
| 7 | `0xE7` | `0x5A` | 结束标记；CRC 不对则拒绝 |
| 8 | — | — | 16 个分量逐个提交；成功后修订计数 +1 |

- `0xE0 = 0xC3` → 退出沙盒
- **静默超时**：270,000 个时钟无新字节 ⇒ 传输自动复位
- **整体超时**：2,700,000 个时钟 ⇒ 终止并置结果码 5

### 5.4 结果码

| 码 | 含义 |
|---|---|
| 0 | 进行中 |
| 1 | 成功 |
| 2 | CRC 错 |
| 3 | 数据阶段收到错误地址 |
| 4 | 引擎拒绝提交 |
| 5 | 超时 |
| 6 | 忙（非空闲，禁止上传） |
| 7 | 协议/头部/结束标记错 |

### 5.5 配套上位机工具（仓库 `tools/`）

python tools/uart_probe_read.py      # 读寄存器

## 6. 烧录

### 6.1 两种码流

| 文件 | 目标 | 掉电 | 用途 |
|---|---|---|---|
| `board.fs` | FPGA 内部 SRAM | **丢失** | 快速调试 |
| `board.bin` | 外部 Flash | **保留** | 成品出厂 |

用 Gowin Programmer，选对应器件 `GW2AR-LV18QN88C8/I7`，JTAG 连接 Tang Nano 20K 的 USB。

### 6.2 必然会看到的报错，不是故障

烧写时 "SRAM Program and Verify" 的校验阶段会报：

```
Error: Verify Failed
Status Code 0x00006020
```

**原因**：构建时启用了 `-use_sspi_as_gpio 1`，把 SSPI 配置口当普通 IO 用于 I²S（54/55/56）。校验阶段读回配置口失败是**这个开关的直接后果**。

**判定标准**：只要 program 阶段 100% 走完就视为成功。**唯一可靠验证**是串口读寄存器：

```powershell
python tools/board_velocity_check.py dump
```

能读到 `0xD0 = 0x75` 就说明码流在跑。

## 7. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 上电无声，按键也无反应 | 码流没烧进去 | 读 `0xD0`，不是 `0x75` 就重烧 |
| 上电一直响 | 未走引导序列 / 谱 RAM 为 `x` | 确认用的是 `tdm_ship_owned` 且 `BOARD_BOOT_SCRUB=0` |
| 混响像破音 | `0x48` REV_FB 太大 | 改回 `0x80` |
| 某一音特别响 | `0x5B` HARM_PADS 残留 | 清零 |
| 力度没变化 | `0x6E` = 0 | 写 `0x80` |
| 力度只有"有/无"两档 | `0x6F` = 0 | 写 `0x05` |
| 烧录报 Verify Failed | 见 §6.2 | **忽略**，改用读寄存器验证 |
| 电极乱触发 | 基线未收敛 / 相邻串扰 | 上电后等基线稳定；检查电极间距与覆盖层 |

## 9. 复现构建

```powershell
# 1. 工具链（Gowin EDA V1.9.11.03 Education，装到纯 ASCII 路径）
$env:FPGA_GOWIN_GW_SH = 'C:\Gowin\Gowin_V1.9.11.03_Education_x64\IDE\bin\gw_sh.exe'

# 2. 必须在纯 ASCII 目录构建（Gowin 处理不了中文路径，会变成 E:/??/）
robocopy "E:\项目\current-design\fpga\current" "E:\build\fpga-current" /E /XD evidence
cd E:\build\fpga-current

# 3. 出码流（约 65 秒）
python build_product.py build_v1 full 1

# 4. 产物
#    impl\pnr\board.fs   → SRAM 配置
#    impl\pnr\board.bin  → Flash 烧写
```

> 若 `gw_sh` 跑完不退出：日志里出现 `GowinSynthesis finish` 或 `Bitstream generation completed` 即可终止进程，产物已落盘。

## 10. 下一步（要成为"完整产品"还缺什么）

| 缺项 | 需要什么 | 谁能决定 |
|---|---|---|
| 84 电极节点 MUX | 新写 RTL + 硬件电极阵列 | 需先定 Q1（触控前端路线） |
| J10 触控显示 | 模组 SKU/CTP/接口契约，再写驱动 | 需硬件签收 |
| EEPROM 非易失 | 器件选型 + I²C 时序 + 存贮格式 | 需硬件确认 |
| TF 卡录放 | 文件系统 + 事件配对格式 | 需定产品语义 |
| 右手连续修饰 | 替换位图式通路 | 需 Q4 编辑边界 |
| 实物验收 | 板卡 + 示波器/逻辑分析仪 + ≤10ms 测法 | 需硬件到手 |

**v1 的价值**：证明整条工具链、综合、时序、码流、配置协议都是通的，并把"产品边界"写清楚了。后续每加一块，都在这个可烧录基线上增量验证。
