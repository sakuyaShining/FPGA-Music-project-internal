## 一 R5：I²S 三线无串阻 + 双电源域倒灌

### 1.1 事实（网表实测）

| 网络 | 焊盘 | 说明 |
|---|---|---|
| `I2S_BCK` | **J5.7**、**U12.21** | 只有两个焊盘 ⇒ **直连，无串阻、无缓冲** |
| `I2S_DIN` | **J5.8**、**U12.22** | 同上 |
| `I2S_LRCK` | **J5.11**、**U12.23** | 同上 |

两个电源域的来源也查清了：

| 电源 | 从哪来 | 关键焊盘 |
|---|---|---|
| `3V3_IO`（FPGA I/O 域） | **Nano 经 J5.16 送进来** | `J5.16`、`J6.19`、U1–U11 的 VCCIO、U14.1 |
| `DAC_3V3`（DAC 域） | **载板自己的 LDO**：J13 → F1 → 5V_PROTECTED → U17 → 5V_PERIPH → **U13** → DAC_3V3 | `U13.5`、`U12.1/8/18/28`、R40.1 |

**两个域之间没有任何上电时序控制。** 谁先上电完全取决于用户先插 USB 还是先插 J13。

### 1.2 失效机理

最常见的操作顺序是「先插 Nano 的 USB 调试，J13 还没接」：

```
3V3_IO = 3.3 V   （Nano 供）
DAC_3V3 = 0 V    （载板 LDO 未工作）
```

此时 FPGA 的 I²S 三个输出脚是 3.3 V 推挽输出，而 U12 的 VDD = 0 V。
电流经 U12 输入脚的 ESD 保护二极管灌进 `DAC_3V3` 轨：

```
FPGA 3.3V ──▶ U12.21/22/23 输入ESD二极管 ──▶ DAC_3V3 轨（死轨，被抬起来）
```

后果：
- `DAC_3V3` 被抬到 2 V 左右，U12 处于**半上电**状态 —— 这是最难受的状态，
  既没完全关断（内部节点已带电），也没正常上电（基准/电荷泵没建立）
- 三路同时灌入，电流叠加，超过单个二极管的额定值
- 之后 J13 接上、`DAC_3V3` 正常爬升时，芯片可能已经处于**闩锁（latch-up）** 前态
- 即使不闩锁，长期反复也会退化

反向（先 J13 后 USB）不成立：`DAC_3V3` 是 3.3 V 输出，`3V3_IO` 是 0 V 输入侧，
U12 是**收**的一方，不会往外灌。所以只有「FPGA 先上电」这一种危险顺序。

### 1.3 修法

在三根线上各串一个电阻，位置贴近 U12（越近越好，这样它同时兼作源端匹配）：

| 网络 | 串入位置 | 建议值 | 封装 |
|---|---|---|---|
| `I2S_BCK` | J5.7 ↔ U12.21 之间 | **33 Ω** | 0402 |
| `I2S_DIN` | J5.8 ↔ U12.22 之间 | **33 Ω** | 0402 |
| `I2S_LRCK` | J5.11 ↔ U12.23 之间 | **33 Ω** | 0402 |

新增位号建议 `R214 / R215 / R216`（现有电阻最大位号 **R213**，已用 124 个，R214 起空闲）。

> 顺带纠正：R74/R75/R76 在网表里**确实空着**，但不要用——
> 一个已经排到 R213 的设计里插回低位号，将来 BOM 对账和丝印追溯都会出问题。

**33 Ω 够不够？** 单线故障电流 ≈ (3.3 − 0.7) / 33 ≈ **79 mA**。
这个值能防止"整轨被轻易抬起来"，但不算严格保护。

如果想按"限流到 10 mA 以下"来做，**可以用 220 Ω**：

- 限流：(3.3 − 0.7) / 220 ≈ **12 mA**
- 信号：U12 输入脚约 10 pF，RC = 220 × 10 p = **2.2 ns**
  而 BCK 周期 667 ns（1.5 MHz）、上升沿预算 ≥ 10 ns ⇒ **完全不受影响**
- 所以 220 Ω 在本板是安全的，信号代价可以忽略

**建议：取 100 Ω 作为折中**（限流 ≈ 26 mA，RC = 1 ns）。
如果优先保可靠性而非通用性，直接上 220 Ω 也没问题——本板 BCK 只有 1.5 MHz，
不存在高速信号的边沿要求。

### 1.4 不改板也能缓解的做法（不推荐作为唯一手段）

在说明书里写死操作顺序：「必须先接 J13 载板电源，再插 Nano 的 USB」。
这只能靠人遵守，产品化不可接受，但可以作为改板前的临时措施。

## 二 R6：XSMT 不可控

### 2.1 事实（网表实测）

| 网络 | 焊盘 | 说明 |
|---|---|---|
| `DAC_XSMT` | **R40.2**、**U12.25** | **只有两个焊盘**：一个 100 kΩ 上拉，一个芯片脚 |
| `DAC_3V3` | R40.1 等 | R40 另一端接 DAC_3V3 |

也就是说 `DAC_XSMT` 上**没有测试点、没有排针引出、没有任何 FPGA 连接**。
它唯一的定义就是「跟着 DAC_3V3 经 100 kΩ 慢慢爬上去」。

### 2.2 后果

XSMT 是 PCM5122 的软静音/关断脚（低有效）。当前接法下：

1. **上电 pop 无法避免**：DAC_3V3 爬升 → XSMT 跟着爬升 → 芯片在电源还没稳的时候就解除静音
2. **运行时无法软静音**：切歌、待机、检测到异常时都没法把 DAC 静下来，
   只能靠 I²C 写 `Reg0x03`（软件静音），而软件静音是数字域的，
   挡不住模拟侧的 pop

### 2.3 修法

**做法：把 `DAC_XSMT` 引到一个空闲排针脚，由 FPGA 控制。**

排针上真正空闲的脚（Nano 侧无任何板载负载，已与 `pin-map-audit-20261024.md` §6.2 交叉核对）：

| J5 脚位 | FPGA 脚 | Nano 侧丝印 | 产品 CST 是否占用 |
|---|---|---|---|
| J5.3 | 76 | IOT30B | 未占用 ✅ |
| J5.13 | 86 | IOT4A | 未占用 ✅ |
| J5.17 | 72 | IOT40B | 未占用 ✅ |
| **J5.18** | **71** | IOT44A | **未占用 ✅（推荐）** |

**推荐 J5.18 → FPGA 71**：它在排针末端，走线离 U12 最近，且 71/72 是同一 bank，
将来如果要用差分或相邻布线都方便。

**然后 R40 的处理有两种，必须二选一：**

| 方案 | R40 改法 | 上电默认 | 效果 | 代价 |
|---|---|---|---|---|
| **A（保守）** | 保持 100 kΩ 上拉到 DAC_3V3 | XSMT 高 = 芯片工作 | 只能做**运行时**软静音；**上电 pop 依然存在** | 无新增失效模式 |
| **B（彻底）** | 改成 100 kΩ **下拉到 GND** | XSMT 低 = 芯片静音 | **上电全程静音**，FPGA 配置完、I²C 初始化完再拉高 ⇒ pop 消除 | FPGA 挂掉 = 完全没声 |

**建议取 B。** 理由：这个产品的音频通路本来就完全依赖 FPGA（I²S 是 FPGA 发的），
FPGA 挂了本来就没声，所以"FPGA 挂掉就没声"不是新增的失效模式，只是把已有的
依赖关系显式化。而换来的上电 pop 消除是实打实的音质收益。

B 方案的 RTL 侧时序（`pcm5122_init.v` 里加一个输出即可）：

```
复位 → xsmt = 0（静音）
     → I²C 17 条写完、PLL 锁定（Reg0x04 b4 = 0）
     → Reg0x03 解除软静音
     → 延时 ~50 ms 等输出稳定
     → xsmt = 1（解除芯片静音）
```

### 2.4 J5.9 能不能复用：取决于最终产品要不要板载喇叭

J5.9 在载板上是 **NC**（网表实测，`J5.9 → 未连接`），而它接的是 FPGA 脚 51 = `pa_en`。

**情况一：最终产品保留板载 MAX98357A**（`PA_EN_MODE=2` 的默认假设）

**不能**接 XSMT。`PA_EN_MODE=2` 在检测到载板在位（PLL 锁定）时会把 `pa_en` 拉低去静音板载喇叭，
若 XSMT 也挂在这个网络上：

```
载板在位 → pa_en = 0 → XSMT 同时被拉低 → DAC 静音 → AUX 没声
```

**恰好在我们最想要 AUX 出声的时刻把 AUX 关掉了。**

**情况二：最终产品不要板载喇叭**（2026-10-26 产品决策）

这时 J5.9 反而变成**比 §2.3 更好的解**：

| | 复用 J5.9 | 引到 J5.18（§2.3） |
|---|---|---|
| 新增走线 | **0**（J5 排针一个孔都不用加） | 1 条 |
| 新增排针占用 | 0 | 1（FPGA 71） |
| 逻辑冲突 | 无（见下） | 无 |
| 前提 | `pa_en` 必须改成"初始化完成后拉高" | 无 |

**不冲突的理由：两个信号同向。**

- `PA_EN`：高 = 板载功放使能（`02_硬件bringup-TangNano20K音频通路.md` 确认高有效）
- `XSMT`：高 = DAC 解除静音

都是"1 = 正常工作"，接在一起不会出现"一个要开一个要关"。

但 `pa_en` 的**驱动方式**必须改，三种取值只有一种能用：

| 驱动 | XSMT 结果 | 问题 |
|---|---|---|
| 恒 0（`PA_EN_MODE=0`） | 恒静音 | **AUX 永远没声** |
| 恒 1（基线 `assign pa_en = 1'b1`） | 恒不静音 | 上电 pop 仍在（配置期间 51 靠内部上拉就是高） |
| **初始化完成后拉高**（推荐） | 先静音、后放开 | 无 —— pop 消除 |

最后一行意味着 `PA_EN_MODE` 这个参数本身可以删掉，`pa_en` 的语义从
"板载功放使能"变成"PCM5122 的 XSMT 控制"，交给 `pcm5122_init.v` 输出。

> 注意：**失败路径也必须拉高**。若 I²C 初始化失败就停在低电平，等于整机静音；
> 必须做到"不管成功失败，只要序列跑完就放开"，否则等于给自己埋一个哑巴。

（顺带：J5.9 是 NC 这件事本身，正好从硬件侧证实了 R4 的前提
——载板确实关不掉板载功放。所以只要最终产品**保留**板载喇叭，
就必须由 FPGA 侧门控，`PA_EN_MODE=2` 才是有意义的。）

## 三 R7：J12 输出无 ESD

### 3.1 事实（网表实测）

| 网络 | 焊盘 | 说明 |
|---|---|---|
| `AUX_L` | **R41.2**、**C27.1**、**J12.1** | 100 Ω 串阻 + 1 nF 对地 + 插座，**无 ESD 器件** |
| `AUX_R` | **R42.2**、**C28.1**、**J12.2** | 同上 |
| `DAC_L_RAW` | R41.1、U12.6 | DAC 左声道输出 |
| `DAC_R_RAW` | R42.1、U12.7 | DAC 右声道输出 |
| `GND` | J12.3 | 套筒地 |

链路：`U12.6/7 → R41/R42(100Ω) → C27/C28(1nF 对地) → J12.1/2`
`C27/C28` 与 100 Ω 构成 1.59 MHz 低通（仅 EMI 滤波，不影响音频带）。

### 3.2 风险

J12 是**对外暴露的 3.5 mm 插孔**，人手插拔时 ESD 直击。现有 100 Ω 串阻能限一部分流，
但：

- 人体模型 8 kV 放电，100 Ω 上的瞬时电流仍有数十安培量级（上升沿 ns 级，电阻的寄生电感主导）
- 能量最终要靠 U12 输出脚的内部 ESD 结构吸收，超出额定会损伤
- 原理图自己也注了这条未定型（见 `REPORT.md` §五）

### 3.3 修法

在 J12 旁加一颗**双通道双向 TVS**：

| 项 | 建议 |
|---|---|
| 器件类型 | 双向 TVS 阵列，2 通道 |
| 候选 | `USBLC6-2SC6`（SOT-23-6，常见、便宜）、或 `PESD5V0S2BT` |
| 接法 | 两通道分别接 `AUX_L`、`AUX_R`，公共端接 GND |
| 位置 | **紧贴 J12**，TVS 到地的回路越短越好 |
| 关键参数 | 结电容 **< 10 pF**（避免影响 1.59 MHz 滤波拐点）、工作电压 ≥ 5 V |

注意：**不要**为了"加强保护"把 R41/R42 加大。它们与后级负载构成分压，
虽然 100 Ω 对 10 kΩ 负载影响可忽略，但无谓地加大只会增加噪声。

## 四 复现方法（网表查询工具）

本次所有"事实"行都可用 `netlist_query.py` 复现：

```bash
cd project/reviews/20261025-pcm5122-aux

python netlist_query.py stats          # 227 器件 / 1038 焊盘 / 256 网络
python netlist_query.py part U12       # U12 全部 28 脚
python netlist_query.py part J5        # J5 全部 20 脚（看哪些是 NC）
python netlist_query.py net I2S_BCK    # 某网络上的所有焊盘
python netlist_query.py grep DAC       # 模糊查网络名
```

### 4.1 这个工具踩过的坑（写下来免得下次再踩）

1. **不能用 `.esch2` 做连通性**：原理图侧 `WIRE` 记录是空壳
   （`{"type":"WIRE","id":"..."}|||`），几何被剥离，取不到端点坐标。
2. **位号不在 `COMPONENT` 里**：`COMPONENT` 的 `attrs` 只有
   `Reuse Block / Group ID / Channel ID / Unique ID / DeviceName`，**没有 Designator**。
   位号在独立的 `ATTR` 记录里，`key="Designator"`。
3. **`ATTR` 必须过滤 `parentId`**：`parentId` 为空的是**库符号定义**，
   `value` 形如 `U?` / `C?`，是模板不是实例。不过滤会把 286 条 Designator 全算进来
   （实际实例只有 227 个）。
4. **`PAD_NET` 的 id 是 JSON 数组字符串**：`["PAD_NET", <器件uuid>, <焊盘号>, <padid>]`，
   要 `json.loads` 两次（外层记录头一次、id 字段再一次）。

- R6 方案 B：`pcm5122_init.v` 增加 `xsmt` 输出，时序见 §2.3
- R5 / R7：无需 RTL 改动
