# 曲谱/现场与多层音符资源合同

用户已明确选择：共享32组且不区分来源优先级；整音符全层回收、新音完整起音；先空闲、再已松键尾音、最后最早仍按住的音符。本页将这些选择展开为可实现、可测试的合同，不表示当前RTL已经做到。

## 资源与身份

- 总预算仍为共享32组，每组16分量；每个音符选择1至4个槽/层，每个实际层占一组。不是每个槽独占32组，也不预留一半给曲谱。
- 曲谱和现场通过同一资源管理入口，每次新起音获得独立音符实例。身份须区分来源、来源内实例及代次，不能仅凭MIDI音高匹配；两个来源同时演奏C4是两个音符。
- 一个音符实例保存起音顺序、原层选择、所属组、按住/已释放状态与仍有效的子层。音符换槽、滑音和右手修饰不能把原实例伪装成新起音以逃避抢占。
- 自然结束的子层与被迫抢占不同；自然结束可释放真正空闲组。主动淘汰某实例时必须同时退场它的所有剩余层，不能保留半个音色。

## 分配顺序

1. 优先使用真正空闲的组。真正空闲须确认没有仍有效的音符/包络、未提交装载或退场事务；某一拍PCM为0不能证明空闲。
2. 空闲不足时，优先选择已收到OFF、仍有尾音占组的音符实例；同类按原起音先后选最早者。
3. 仍不足时，选择最早开始、仍按住的音符实例。曲谱和现场同等，不额外保护某个来源，也不按层数或音高加权。
4. 新音需要多组时，可依次淘汰多个旧实例直到资源足够；不能仅取到一组就给四层新音缺层起音。所需层数为0或超出4等非法请求须明确拒绝，不能静默截断。

本顺序是用户对旧严格FIFO的明确细化。录音PCM的播放缓冲不属于可按音符淘汰的合成组，不能对PCM文件声称实现“删除其中最老音符”。

## 完整起音与退场

- 先预留全部所需组，再装载各层，最后提交新实例；对音频输出可见的起音边界必须一致，不出现只响了前一层的过渡产品行为。
- 退场、组复用和新起音之间有完成确认。在旧音尚未安全退场或旧装载仍在途时，不把同一组交给新实例。
- 若在接纳中途收到取消/OFF，必须撤销预留或完成有定义的清退，不遗留占组。重复请求不得产生第二份实例或重复释放。
- 被抢占实例的迟到OFF、滑音和配置回包不得影响已经复用组的新实例。需要身份/代次核验，不能仅清一个全局音高位。
- 被抢占但手指仍按住时，持续扫描/移动不应自动循环重触发被淘汰音符；需等新的有效起音事件。曲谱的后续独立同音高事件可以正常起音。
- 实现应协调退场和新起音并验证抢占瞬变；退场时间与全部扫描/排队/音频处理仍须满足整机触摸至声音≤10ms目标，不能在未测量前承诺无爆音或具体退场时长。

## 顺序与完成边界

- 起音顺序以管理入口接受并最终提交的顺序为准；同一音频时刻到达的事件也须有确定、可复现的顺序，不引入来源优先级。
- 维护显式有效状态和可证明的起音顺序；不能把每组8位group_start_tag直接当作全局年龄比较。长期运行、序号回绕及组重复使用都需反例测试。
- 音符OFF只表示进入释放，不自动等于资源已空闲；合成组释放需依据包络/声学处理结束反馈。全局混响/延迟的历史缓冲与音符组占用分开处理。
- 当前note_map_owned在OFF时清gact并将gtab设FREE，layer_dispatch仍最多两层。这些是待替换/接合的旧行为，不能原样签收本合同。
