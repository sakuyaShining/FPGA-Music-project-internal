# M0：总集成与正式PCB唯一写入者

由用户分配，当前待分配。先读[入口](../START-HERE.md)、[合同](../CONTRACT.md)、[验收](../ACCEPTANCE.md)和根AGENTS。你负责B轴集成，不接管旧owner工程，不替其他角色签独立验证。

## 输入、权限与首个检查点

使用固定951检查点和任务包确切提交；写`hardware/pcb-parallel/integration/`、`hardware/pcb-parallel/coordination/`及任务包`assignments.json`。在用户分配后登记owner、分支、工作树和路径；中央协作板/producer登记由你统一提交，其他人交提案。只接受用户真实分配，不自行启动其他聊天。

首个60分钟检查点交`baseline.json`：恢复校验、工程/PCB ID、工具能力、实际原生DRC、对象/网表/层叠、当前硬件审阅和遗留项。若工具不能运行，交精确错误及恢复方案，不把旧42项报告当新运行结果。通过G0后创建唯一隔离集成工程B0，原始951只读。

## 工作与产物

1. 维护`coordination/STATUS.md`、`integration-ledger.json`和CAD排他锁：当前正式SHA、各候选父SHA、认领、依赖、检查点、卡点、下个验收人。任何时刻都能找到最后通过的恢复点。
2. 与E3/V4建立约束版本及布局空间预留。R1/R2先各自产生独立候选；重叠整板候选互斥，不能文本合并PCB。记录`selection.md`：实铜闭合、剩余通道、供电/参考、制造风险，而非局部搜索次数。
3. G2后以选定方案推进K1，再为K2/K3发布明确的对象、空间、网络和共享铜影响合同。存在物理交叉时串行；目录不同不代表互不影响。未选路线作者接剩余批次或按新方法接替，不无限继续竞争实验。
4. 每次集成保留前后原生工程、ECO及哈希。顺序重放变更，原生重铺/DRC/保存关闭重开；V4针对最新聚合板复核。新基线使受影响旧验证失效。
5. 对全部12网负责，不把R1/R2的有界失败视为工程完成。两路线失败则组织具体数字区局部重构方案；涉及用户锁定平台/板外接口/保护区等变化，向用户一次提交有图、有影响和验证条件的选项。
6. G4冻结Bfinal；把源和签核交F5。G6后交`FINAL-HANDOFF.md`、精确远程提交、可下载包和未实测项。制造放行由用户决定。

## 可验证完成条件

V4签核G0、G2、G3、G4、G6；E3关闭影响PCB的约束。正式板12网全部闭合且其他网不退化，原生硬DRC全0，同SHA生产包齐全、清洁恢复成功。M0不能仅以汇总报告宣告完成；失败批次必须继续分配或明确阻塞，保留可恢复成果。

每45分钟检查成果；按共同合同的两次失败/90分钟无新证据规则更换方法。M0协调工作避免与四个重计算任务抢占CAD/CPU；用户未授权跨聊天通信时通过用户转交检查点。
