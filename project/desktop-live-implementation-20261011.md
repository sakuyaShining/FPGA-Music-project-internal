## 实现

- 新顶层 `tdm_live_test`：GW2AR-LV18QN88C8/I7，完整32组/32逐指接口，BOARD_DIAG=1/FINGER_EXPR=1，UART 1.5Mbps（27MHz/18整除）。原115200 D3/rev2顶层及其码流保留。实时配置身份D4/rev3/proto11/scope32；主机明确选择模式，不能对旧码流静默切波特率。
- FPGA `live_audio_monitor.v` 连续复制效果后音频高16bit，与现有I²S 16bit输出取值口径一致；音频合成采样率不变，也不增加观察用减采样/滤波。两份512点缓冲交替写/发，接受事件用32项队列。UART忙或队列满时不阻塞音乐引擎；损失标志和样本编号向电脑暴露中断，不重复旧数据补洞。
- `live_visualizer.py` 在独占接收事务的后台线程持续解析校验帧；音符写仍可全双工。电脑维护最多4秒PCM和1024条完成事件；按33ms显示定时器分析/刷新，不逐帧写磁盘。停止流后排空最后一帧才恢复诊断读回。断流会冻结并提示，空图不冒充静音。
- 电脑频谱：4096点Hann窗、实数FFT、窗幅度校正、dBFS，频点间隔约12.87Hz、窗口约77.67ms；每次刷新用最新窗，有重叠，但实际刷新/延迟必须实测，33ms定时器不等于30fps验收。
- 演奏轨迹源为note_map接受事件，音符按下/释放使用FPGA样本时间。它表示事件接受和释放，不能解释成DAC实际发声时刻、包络尾音持续时间或实体触点轨迹。
- 波形可切2秒演奏包络/200ms/20ms细节，显示倍率1/4/16；真实帧发生缺口时丢弃不连续分析窗，CRC/序号/损失提示保留，避免把缺失样本接成假连续音频。

## 协议

连续模式B5=1开始，B5=0停止并结束当前帧。1.5Mbps配置下旧两字节寄存器读回仅在流停止后使用。实时期间音符0x60/0x61可以发送。

每帧：4字节ASCII `FMV1`、type1字节、sequence LE16、payload length LE16、FPGA sample counter LE32、observation-loss-cycles LE16、format1字节、payload、CRC16-CCITT大端2字节。CRC初值FFFF，覆盖magic之后至payload结束。序号跨音频/事件统一递增。

type1音频payload1024字节，512个有符号小端16bit样本，timestamp为第一点编号；format=1采样率固定27000000/512Hz，节点固定效果后。type2事件payload2字节，首字节bit7为on、低7位音符，第二字节低4位力度；timestamp为FPGA接受事件时的样本计数。此版本没有组所有权/逐指位置轨迹。

音频单帧1042字节，每秒约103帧，音频及头部约107.3kB/s（另加事件），低于150kB/s名义UART负载上限。损失计数饱和，单位为发生观察数据损失的时钟周期，音频样本编号另外用于识别具体断点；不把观察丢失计数当音乐引擎丢事件计数。
