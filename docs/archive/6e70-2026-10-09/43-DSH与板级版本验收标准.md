# DSH 工作与板级版本验收标准

2026-10-07。目的：在接合 DSH 改动前，明确验收对象、证据和阻断条件。
本页是验收标准，不是通过报告。已有总入口为 `tools/scripts/accept_all.ps1`，不能用“PASS 项数”代替下方行为核对。

## 1. 三种验收对象

| 对象 | 完成含义 | 不代表 |
|---|---|---|
| **A：DSH 基础修复/维护** | 约定问题修复或定性，改动可接合，判据可信、维护入口可用 | 新产品交互全做完、码流已生成、板级通过 |
| **B：首轮板级实验版本** | 确定源码/数据/约束，回归及最新 PnR 通过，生成匹配 20K 的码流/下载入口与实验卡 | 触控实测与完整乐器已通过 |
| **C：首版演奏行为** | 42 号清单各必交付项有实际代码与对应验收，包含真实输入验证 | 只要基础回归全绿就自动完成 |

昨晚讨论的新交互以 C 类追踪；验收 A 时不追加“必须先实现所有新交互”的范围，但需明确其仍未实现。

## 2. A 类：接收 DSH 工作的标准

| ID | 要求 | 证据 / 拒收条件 |
|---|---|---|
| A01 范围与版本 | 交付完整提交 SHA、改动清单、解决/未解决问题 | 未提交迁移先整理成可审查结果，不接合未知删除/遗漏；有意保留的问题必须有理由及后续处理 |
| A02 可重现 | 从选定候选版本独立构建/回归，使用新产物与完整日志 | 不复用旧 `sim_build` 文件假通过；记录工具版本、配置、数据表与退出码；缺依赖/缺表必须可识别失败 |
| A03 事件通路 | 支持的负载下不漏、不重复、保序，off 正确送达 | 真实 UART 字节流、pads、仲裁/反压与队列判据；先定义支持事件速率，不能宣称无限速率都不丢 |
| A04 声部生命周期 | 填满 32 组后可回收；有释放候选时不抢按住音；旧 off 不误关替代音 | 不只测小于声部总数的弱激励；释放电平/重触发/复位另按行为验证，未覆盖的明确列出 |
| A05 参数与输出 | 声部装载不串用参数；饱和不回绕；音频逐位参考和音高规则可信 | “装载第三音不改旧音”不能外推到“刷新保持力度”；正常区与饱和区分别有激励 |
| A06 Nyquist/提交 | 明确保护行为与更新粒度，测得结论匹配宣称 | 审计完成不得称无混叠；若逐槽跨帧生效，报告真实窗口，不能称整组原子；保护效果需输出证据 |
| A07 维护迁移 | 日常构建/回归入口不依赖丢失的外部文件；公开导出工具迁移有路径/用法 | 新 `public_spec.py` 跟踪入库；迁移目录及依赖完整；失败返回非零；必须测试坏输入确实能失败 |
| A08 文档一致 | 当前状态不同时写“已完成”和“待接线”；已知问题与新需求不消失 | 需求编号与实现状态保留；不把审计类 PASS 混成已解决行为数 |

验收结论可为：通过、部分通过（明确阻断/未交付）、不通过、待证据。不能把“未测”算通过。
严重阻断：事件/off 失真、复位不可靠、饱和回绕、版本不可复现、关键判据假绿或运行依赖丢失。

## 3. B 类：允许生成并用于首日实验的码流

1. **范围明确**：默认静音、UART 单音/和弦/释放/复位、固定音色、先干声；未实现触控/新交互明确列出。
2. **无悬空误动作**：检查包装顶层、调试口、未接电极与复位后行为，不能只在仿真中将它们理想化为零。
3. **参数一致**：实际顶层 `DIV_BCK=16`、`BCK_PER_LRCK=32`、27 MHz，即 fs=52734.375 Hz，帧长 512 拍。
   `audio_clk_en` 单元默认 18 的测试不能直接当作该顶层配置的测量；ROM 生成、上位机、Nyquist、FFT和时长换算须用匹配配置。
4. **代码门禁**：选定版本全量回归退出 0；关联修改的 GUI/配置自检通过；测试失败、跳过、已知异常分开报告。
5. **最新构建**：Gowin 综合/布局布线成功，器件确为 GW2AR-LV18QN88C8/I7；顶层与 `.cst/.sdc` 匹配，SSPI 释放选项正确。
6. **时序/警告**：保留项目已有 SETUP slack ≥5 ns 工程门槛，并核对时钟约束覆盖、hold 与关键警告；不能只看一个正 slack 掩盖未约束路径。
7. **交付绑定**：源码 SHA、数据表/约束版本、构建命令与日志、码流 SHA256、生成时间、支持行为清单、正确下载方式一起交付。
8. **入口正确**：下载脚本目标为本次 20K 验证码流；现有指向 9K 文件的入口不得直接沿用。

`accept_all.ps1 -SkipGate` 或 `-SkipPnr` 可用于开发诊断，但不构成完整 B 类通过；使用旧时序文件也不能替代本次构建。
B 类通过只表示可以开展板级实验，实际 I²S 电气、音频输出与控制延迟仍需 40 号实验卡验证。

## 4. C 类：新行为验收入口

沿用 `42-需求实现追踪.json` 的 R01–R10；每项记录用户决定、代码提交、可复核判据与未测条件。
R02 现已完成文件与 GUI 本地闭环；本轮完整上位机检查 30 项通过，设备应用与实体配置槽仍未完成。当前复盘见 44 号记录。
重点判据：编辑/导入不自动发帧；显式应用不重起包络或串用力度；三方式的按住/松手正确；
右手组合/平滑/保持有明确结果；左手表情按已选输入方案驱动真实音高变化且不串声部。
任意多指追踪仍是候选，其验证结果与范围须先确认，不能因写入 JSON 或 README 就称完成。

## 5. 等待期间可以独立推进

- 配置文件及 GUI 本地保存/导入，不向当前设备发送尚未实现的字段。
- 板级版本的行为清单、正确下载入口设计、日志/码流绑定方法和首日测试激励。
- 触控候选资料、借仪器与到货确认，持续保持 PCB+I²C 路线。
- 在独立分支做新功能单元原型；与 DSH 接合后重新验证关联路径，避免同时写同一工作树。
