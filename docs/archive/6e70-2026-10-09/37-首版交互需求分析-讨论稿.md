## 已明确的需求

| 编号 | 用户选择 | 实现含义 |
|---|---|---|
| R01 | 明确的“应用到在奏音”操作 | 编辑不自动改变在奏音；新音配置更新与在奏音更新须区分，具体按钮关系待定 |
| R02 | 保存完整乐器配置 | 保存基础谱、发声方式/包络参数、颤音配置、效果配置；包括后续确定的右手映射，排除瞬时按键、相位与效果缓冲 |
| R03 | 实体多个配置按钮 | 配置槽可独立选择；槽数量、映射、装载途径与断电保持方案尚未选择 |
| R04 | 持续、瞬间、混合三种发声方式 | 持续暂按“按住保持”理解，不能默认等于周期重击；混合先比较分量分组与双包络混合 |
| R05 | 右手主功能为强调分量 | 基础谱在演奏前自由配置；演奏中修饰不覆盖已保存谱 |
| R06 | 多触点组合 | 用户明确：强调当前音色的两个泛音/分量，不产生新音符；不再取最小编号，需定义组合、幅度上限与多指位置语义 |
| R07 | 右手作用于整个在奏和弦 | 同一修饰作用于所有目标声部，各音仍保留独立音高/力度/包络 |
| R08 | 保持接触跨位置时泛音强调平滑变化，左手基准音符不变 | 用户已澄清，这是谱形/音色渐变，不是音高滑音；“不变”指基准音符，颤音允许瞬时频率小幅变化 |
| R09 | 右手松开保留最后强调后的声音 | 用户已澄清，不恢复基础谱；需要独立恢复基础音色的动作，运行期保留不自动等于写入保存文件 |
| R10 | 左手左右往返产生真正音高颤音 | 用户明确：音高表情属于左手；围绕左手音符轻微升降，不改变基准音符。右手只负责泛音强调，不能用谱形摆动代替颤音 |

## 尚不能替用户定案的含义

- 已确定真正音高颤音；尚需选择：手指位移直接产生音高变化，还是往返手势控制 FPGA LFO 深度/速率。
- 全和弦颤音应按相同音分/频率比调制，保持和弦音程；不是每个音加相同 Hz。这是实现建议，尚未试听验收。
- 左手普通选音与连续音高表情须区分；此前把右手分量强调与颤音放在同一位置轴，是理解错误，撤回该冲突与右手表情修饰键建议。
- 多指按和弦后各指控制所属声部的移动，是正在评估的候选交互；尚未冻结，也未有触控实物支持证据。
- 保留的右手状态是运行期修饰，还是需要“保存当前演奏结果”操作写入完整配置？
- 新音是否继承保留的修饰？建议全局继承，尚未确认为用户选择。

## 核心冲突与候选处理

| 冲突 | 原因 | 候选处理，尚未冻结 |
|---|---|---|
| 显式应用 vs 全局参数实时变化 | 改公共参数可能影响旧声部，即使未按“应用” | 本地草稿、后续新音配置、在奏声部配置分开；旧声部保存必要参数或稳定的配置引用 |
| 完整配置按钮 vs 演奏连续性 | 效果常为混音后的全局模块，不能自然做到“旧音旧效果、新音新效果” | 区分逐声部参数与全局效果；配置切换时明确统一效果过渡、保留旧全局效果或停止后切换 |
| 谱形平滑 vs 滑音名称 | 用户明确基音不变，幅度插值不是音高滑音 | 统一称谱形/音色渐变；不能将此功能作为音高滑音证据 |
| 左手选音与连续移动 | 离散触摸位不能唯一证明手指身份与位置连续性 | 比较受限独立滑条与多点坐标面板，先做两指独立移动实验 |
| 左手多指表情 vs 平均位置 | 两指反向移动时平均位置可能不变 | 若要逐指独立表情，必须有足够的多点位置与身份信息，不能用全手平均位置代替 |
| 松手保留谱形 vs 颤音结束 | 保留强调不自动意味着仍要保持音高颤音 | 谱形与颤音状态分开；候选：强调保持，手势音高颤音退回零 |
| 多指部分松开 vs 最终保持 | 只锁存最后一指会把前一指的强调抹掉 | 需比较整体手势结束后锁存完整谱，或每指贡献独立锁存；尚未选择 |
| 瞬间音衰减完 vs 右手强调 | 乘法强调无法把已为零的包络变成可闻声音 | 默认不复活已结束的音；再激发必须是独立、明确动作 |
| 组合强调 vs 失真 | 多分量、多手指、多声部提高峰值 | 有界权重/增益与必要限幅；验证峰值、音量变化及饱和不回绕 |

## 资源与持久性分析

估算示例：每配置 64–256 字节、8 槽约 0.5–2 KiB；仅是方案预算，未确定最终格式或综合占用。
保存参数，不保存录音、振荡器相位或延迟/混响缓冲。存储容量通常小于访问控制与可靠写入的工程成本。

候选路径：固化预设表随码流发布；电脑写入 RAM 槽（断电丢失）；非易失存储保存可编辑槽。
后一种可比较专用 EEPROM/Flash 与板载 Flash 分区；板载 Flash 用于码流，不能直接假定可安全用于用户数据。
SD 卡适合可交换大量文件，但需接口/文件解析与拔卡处理；配置载入后应驻留 RAM，不在逐样本合成时访问卡。
实体按钮只选择配置槽，不要求一个按钮对应一个独立存储器。首版还需决定按钮数量与选中指示。

公开赛题要求 FPGA HDL 实时合成，禁预录 PCM；未见针对参数保存在 SD 卡或其他存储器的扣分条款。
这是对已公布条款的分析，不是对评委审美或最终分数的保证。
