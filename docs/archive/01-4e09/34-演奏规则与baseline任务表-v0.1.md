## 1. 目标与事实边界

**交付目标：可靠和弦、独立表情、实时泛音塑形、可复现的比赛指标。** 保留 32 声部 × 16 分量的引擎目标，先完成当前 8 个物理音高键的可靠演奏，再扩展输入。

| 项目 | 当前证据 | 本轮目标 |
|---|---|---|
| 合成容量 | 32 组 × 16 时隙；测试模式有 512 峰证据 | 通过正常音符路径证明 32 独立声部；不以时隙数量代替可闻复音 |
| 输入 | 16 路 RC pad，8 音高键 + 8 泛音键；物理力度固定 | 8 键并发按放不丢事件；模拟量输入另做原型验证 |
| 音频时钟 | 顶层 27 MHz / 512 = 52734.375 Hz；04 单元测试仍用 /576 | 明确产品采样率与 DAC 兼容性，所有频率表和测试使用同一配置 |
| 回归 | 本轮 full 30/31 PASS，09 的旧 LED 判据失败；GUI 有旧定序器预期 | 必过清单统一，失败、超时、缺表和旧产物均不能判绿 |
| 资源 | Logic 14781/20736、BSRAM 31/46、CLS 8744/10368；setup +15.229 ns | 每个里程碑重新记录资源和时序；这些历史数值不算新版本证据 |

baseline 是后续功能的可靠基础，不代表四种表情已完成，也不代表板级指标已验收。数字 baseline 和板级 baseline 分开签收。

## 2. 演奏规则：建议冻结的行为

下面是**拟定行为**，不是对现状的描述。先冻结目标和作用对象；力度曲线、死区、渐入时间等手感参数保留可调。

| ID | 动作或场景 | 拟定规则 | 对应验收 |
|---|---|---|---|
| P01 | 默认弹奏、同时按多个音 | 默认复音模式，各按键独立起音、释放；快速连弹不自动变成滑音 | B02、B03 |
| P02 | 多个来源演奏同一音高 | 用来源 + 音符实例识别音；不同来源的同音允许独立声部，互不关断。同一来源重新起音生成新实例，旧实例进入释放 | B03 |
| P03 | 松手 | 当前实例进入 release；保持力度、谱形与当前表情值，使尾音延续。释放阶段拒绝新的手势写入；回收时才清状态 | B03、B04 |
| P04 | 分配满员 | 优先 idle，其次最早进入 release 的组，最后最早起音的 held 组；同龄用组号打破平局。有 idle/release 时不抢 held | B03 |
| P05 | 起音力度 | 收到有效触摸后用可用读数立即起音；约 10 ms 窗口内采峰并平滑更新该实例，窗口关闭后锁存。不得等待完整窗口才起音 | B10、E01 |
| P06 | 按后揉音 | 力度窗口关闭后，以该实例的接触参考值计算触后变化；从零深度开始，各声部独立深度和 LFO 状态。默认约 200 ms 渐入仅作调试起点 | E02 |
| P07 | 滑音 | 用明确开关进入滑音模式；手势开始时绑定一个音符实例，后续合法移动只重定向它的音高，保留包络。无法判明归属的多指移动不执行猜测滑音 | E03 |
| P08 | 滑音中旧键松开 | 松手事件按手势与实例归属处理；离开旧键不关掉已迁移的音。手势结束才触发该实例释放；间隙宽限只在滑音模式内使用 | B03、E03 |
| P09 | 右手泛音排 | 演奏模式用于连续亮度；音色编辑模式用于离散泛音选择。用明确模式指示消除“点按还是滑动”的等待判定 | E04、E05 |
| P10 | 和弦中改变亮度 | 右手接触开始时锁定当前选中实例；默认选中最近起音且仍 held 的实例。手势持续期间，新音不改变目标；目标释放/被抢占后停止写入，直到右手重新接触 | B03、E04 |
| P11 | 连续泛音塑形 | 只更新目标声部的分量幅度；保持相位、音高、包络状态和滑音状态。整组在同一音频帧提交，再按已定义曲线平滑过渡 | B04、B05、E04 |
| P12 | 改音域或预设 | 默认影响后续新音，已发声音保留原音高与音色。明确执行“应用到当前音”才更新已有声部；note-off 仍按起音实例找到旧音 | B03、B04 |
| P13 | 多指操作右手排 | 首轮只支持单个右手控制位置；多点歧义时保持最后有效值并显示状态，不跳到其他目标。稳定的多指扩展以后再定义 | E04、E05 |
| P14 | 连续控制拥塞 | 同一实例、同一参数允许合并为最新目标值；note-on/note-off 不可合并丢弃。来源内顺序保持，仲裁不得长期饿死物理输入 | B02 |
| P15 | 复位与模式切换 | 用户复位清音符、待处理事件、待提交数据与效果尾音，完成后静音。模式切换保持已有音符归属，仅改变后续手势解释；有显式全停操作 | B07、E05 |

说明：数字实例可用 source、instance/generation 和 voice 关联；具体字段宽度在 B03 设计中确定。单纯触摸位图不能保证跟踪真实手指身份，P07 的能力必须由输入证据决定，不能由时间窗凭空推断。

建议首轮保留四种表情目标，但滑音先用一个明确选中实例验证，再扩展多手势。默认复音和最终 32 声部目标不因此缩减。

## 3. 与旧规格冲突的裁定建议

| 旧描述 | 本轮建议 | 原因与边界 |
|---|---|---|
| 31 号力度取瞬时值；32 号改为约 10 ms 峰值 | 立即起音 + 窗口内更新 + 窗后锁存 | 不把力度估计窗口直接加到起音等待上；物理动态范围待原型测量 |
| 31 号颤音 50 ms；32 号 200 ms | 200 ms 作为初始可调值 | 属于手感参数，不是 baseline 硬门槛 |
| 所有短暂全松都等待 30–50 ms | 仅明确滑音手势使用间隙宽限 | 默认模式正常 note-off，避免快速重复音被吞并 |
| 泛音排点按/滑动靠等待窗消歧 | 显式演奏/编辑模式 | 两种动作在起始阶段信息相同；先保证可预测，再验证是否值得增加自动消歧 |
| note-off 时表情值清零 | release 保留，idle 才清 | 避免尾音音色、频率或幅度突然跳变 |
| “几十拍刷新只能缓慢推拉” | 以输入速率、调度最坏等待和实测控制带宽判定 | 27 MHz 下几十拍为微秒级，不能单凭拍数限制手势速度 |
| 已声明某寄存器即可视为功能完成 | 依据当前实现与端到端验收 | 例如当前 tilt 非零只启用力度表，并非已具备连续亮度轴 |

### B02 的容量与溢出合同

“永不丢事件”必须给出适用负载。首轮必须覆盖一次8键全按、全放，并在全声部刷新及其它来源同时输入时完成；扩展要求测试25键位图突发。每来源保留事件至接收确认，位图 seen 只在成功交接后更新。队列深度按突发上限和最坏服务时间推导，不能先随意选深度再宣布可靠。

测试用事件账本比较产生、接受、执行与拒绝，结束后队列空且无 held。超出声明负载时须有明确拥塞/溢出记录及恢复策略；单纯“计数溢出但继续静默丢 note-off”不满足通过判据。连续参数可以合并，结构事件必须保序；不通过无条件提升 note-off 优先级来打乱同来源 on/off。

### B08 的争议处理

保留已有04 PASS，其证明范围是现有接收模型下的单元结果。它从 `0x8000` 起跑64帧，每帧+37，未跨入正数；接收模型在首次观察WS改变的上升沿收MSB。审计标准模型对 `0x1234` 得到 `0x2468`，这是独立数字失败证据，尚无本轮板测。

因此把标准判据、声道/帧覆盖、top集成分为三个子项，不再用“已有独立模型”或“需要补左右不同值”替代协议裁定。标准定义见 [NXP I²S §3](https://www.nxp.com/docs/en/user-manual/UM11732.pdf)。

### B09 的工作点依据

[MAX98357A 数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/max98357a-max98357b.pdf)列出的LRCLK为8、16、32、44.1、48、88.2、96 kHz，52.734375 kHz不在列表中。这表示当前工作点缺少文档支持，不等于已经板测证实不能发声。标准48 kHz是建议方向，时钟方案尚未确定；PLL可实现性、ROM音准、效果时间和512时隙预算必须一起验证。

## 5. baseline 后的四种表情与反馈任务

| ID | 交付行为 | 首轮可验收证据 | 前置 |
|---|---|---|---|

| E04 泛音塑形 | 单音由暗到亮；和弦只改变选中音 | 先GUI注入亮度目标，再接传感器。选定有足够非零分量的音色与音域下，谱心/高频能量按参考曲线变化；另一声部不变，相位包络不中断。预先定义响度补偿与过渡时间，记录实际控制带宽 | B03–B06；定向幅度更新 |

泛音塑形建议先做E04数字纵向链路：保持一个音→推亮度→保持两个音→只推其中一个→释放目标→验证不会写入新占用者。E01的数字隔离与硬件采样可同步推进，E02/E03依赖输入可辨识程度。

若触摸模拟量不能稳定支持力度/触后，先保存测量数据再选择专用控制轴或传感器。固定力度、自动揉音和离散位置平滑只能作为阶段演示，不能直接标为原定四种表情的物理完成。

## 7. 验收如何签收

每个任务沿用下面的记录，不再额外维护一份重复状态表：

```text
任务：Bxx / Exx
状态：未开始 / 进行中 / 待验证 / 已通过 / 失败 / 待板测
负责人：实施人；复核人
关联规则：Pxx
输入场景：具体按键、事件序列、参数、到达相位与负载
预期：数值、顺序、状态或声音变化；注明容差
源码：commit SHA；未提交时补diff/输入文件哈希，不能只写HEAD
环境：工具版本、宏、产品顶层、时钟配置、ROM哈希；板测补板卡版本
执行：命令、起止时间、退出码
实际：接受/执行计数、误差、最大延迟、资源等
证据：原始日志、波形/音频、判据报告路径
结论：通过范围、尚未覆盖的情况、失败原因
```

数字baseline关闭要求：B01–B12数字部分全部通过，清单内无跳过项冒充PASS。整机baseline还要求对应板级项目通过。数学参考测试模式、物理输入集成和DAC输出是不同证据范围，不能互相替代。

32声部验收通过正常事件接口注入32个合法音符、独立开关与参数，检查每组独立状态、输出与频谱参考；第33音抢占符合P04。音量配置须避免以饱和失真掩盖声部，不要求16个分量在所有音色/音域都可闻。报告真实有效分量和实际采样率。

板级稳定性建议首轮至少15分钟混合演奏，包含同时按放、快速重触发、表情、音色切换与复位；保存异常计数，要求无意外挂音/丢事件/复位后残留。这是项目拟定检查，不是赛题明定时长。

赛题的≥4独立声部、控制信号到输出≤10 ms、扩展≥32复音等依据见[高云2026赛题二](https://www.gowinsemi.com.cn/university/match2026)。本文≤1 ms数字预算、≥5 ns setup余量、力度≥20 dB等均为拟定工程目标，不能误称官方统一门槛。

## 8. 第一批落地任务

1. 评审P02/P04/P07/P09/P10/P12；其余规则与这些选择一起冻结。先用明确规则搭建能力，手感参数随后原型调节。
2. 将R2的busy与8键反例转成必失败/必通过判据，增加事件账本；确定接收确认、队列容量和调度合同，实施B02。
3. 为B08a补标准接收判据，保留旧04；独立裁定协议结果。并行提交B09的48 kHz可实现方案，未通过评估前不直接改分频常量。
4. 用持60、按放61..91、再按92与弱/强音刷新场景验收B03/B04，随后实现B05的整组提交。
5. 完成数字baseline后，把E04作为第一段独立表情演示，再接真实右手输入。

本草案的评审只需先看第2节的动作规则和第4节的通过判据；实施时再细化接口与位宽，避免提前建通用框架。
