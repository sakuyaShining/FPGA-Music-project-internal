# 演奏表情规格 v1.0

> **2026-10-09：本文包含目标规格与早期实现判断；“三维齐备”“legato 已可演示”不是当前事实。**
> 32 号设计层把力度采样改为约 10 ms 峰值窗、颤音渐入改为默认 200 ms；正常 legato 未打通、颤音仍全局。统一整理见 [39-最新设计构想与落地差距](39-最新设计构想与落地差距-2026-10-09.md)。

> 2026-10-05 · 四维表情（力度 / 触后颤音 / 滑音 / 音色亮度），全部**逐声部**。
> 依赖触控原型结果的分支见第 6 节；判据沿用现有 E2 的写法（写参数 → 实测物理量）。

## 0. 定义与边界

**演奏表情** = 演奏者**在演奏过程中**、针对**正在发声的音**做出的实时控制。

据此把乐器上的一切动作分成三层：

| 层 | 是什么 | 算表情吗 | 例子 |
|---|---|---|---|
| **结构层** | 演奏**之前**（或换段时）设定音色身份 | **不算** | 点按泛音键选泛音、上位机写 `0x5B` 掩码、`spec_ram` 谱形 |
| **自动层** | 乐器**内置**的随时间演化 | **不算**（但影响听感） | 包络的"起音亮 → 稳态暗" |
| **演奏层** | 演奏**之中**、针对正在响的音 | **算** | 力度、触后颤音、滑音、滑动改亮度 |

**关于"泛音构造算不算表情"**：取决于什么时候变。

- 演奏之前摆好 16 条泛音 ⇒ 音色设计 ✗
- 演奏之中实时改变泛音构成 ⇒ 表情 ✓

我们的 8 个泛音键因此是**双重身份**：

| 用法 | 归类 | 处理 |
|---|---|---|
| **点按** | 结构层（选一套泛音） | 不计入 E2 的三维 |
| **滑动** | **演奏层（连续改亮度）** | 即第 4 维 D4 ✓ |

## 1. 维度总览

| 编号 | 维度 | 手势 | 传感来源 | 作用范围 |
|---|---|---|---|---|
| **D1** | 力度 | 起音**瞬间**的接触面积 | I²C 模拟量【待原型】 | 逐声部 |
| **D2** | 颤音深度 | **触后**：起音后面积的变化 | I²C 模拟量【待原型】 | 逐声部 |
| **D3** | 滑音 | 键间滑动 / legato | 离散事件 + 时间窗 | 声部复用 |
| **D4** | 音色亮度 | 在泛音排上滑动 | I²C 模拟量【待原型】 | 逐声部 |

自动层（包络的亮度演化）**不计入 E2**，但保留。

## 2. 逐维规格

### D1 力度

| 项 | 规格 |
|---|---|
| 采样时刻 | note-on 判定后**一个映射周期内**取一次并**锁存到该声部** |
| 量化 | 模拟量 → **4 位（16 档）** |
| 曲线 | 带**曲线寄存器**，默认线性；实测手感后可改成对数/分段 |
| 死区 | 低于起音阈值的抖动不改变力度 |
| 与 D2 的关系 | **只取起音瞬间**；之后的变化一律归 D2（防止"按得重"被算两次） |

**判据 E2-D1**：写 16 档力度 → 实测包络峰值**单调递增**，最大/最小比值 ≥ 20 dB。

### D2 颤音深度（触后）

| 项 | 规格 |
|---|---|
| 触发 | 起音之后，接触面积**相对起音值**的变化超过死区 |
| 映射 | 0 → `VIB_DEPTH=0`；满值 → **可配置上限**（默认 2000 ≈ 52 音分） |
| 渐入 | 变化后按约 **50 ms** 平滑到目标深度（避免突变） |
| 逐声部 | 每声部独立深度 + **独立 LFO 相位** |
| 可选 | 延迟起振：先直音，按住一段时间后才加颤音 |

**判据 E2-D2**：

1. 触后 0 → 满，实测频偏 **0 → 52 音分**（±5%）
2. **和弦中两个音给不同触后，各自频偏独立** ✓（这一条区分逐声部与全局）

### D3 滑音

两种触发方式：

| 方式 | 条件 | 引擎路径 |
|---|---|---|
| **(a) legato** | 新音按下时旧音**仍在响** ⇒ 复用声部 | 引擎自动算 `gq`（已实现 ✓） |
| **(b) 滑动** | 相邻跨键间隔 **< W**（默认 50 ms【待原型】）且连续 | 对**同一**声部做"音高重定向"，仍走 `gq` ✓ |

要点：

- 滑动时**不产生新的 note-on**（否则每个中间键都会响 ✗）
- ~~`GLIDE_EN` 从编译期常量改成**寄存器位**~~ → **已完成**：`CTRL[2]`（`tdm_top` 取 `r_ctrl[2]` → `pmod_cfg[0]` → `pitch_mod.glide_en`，在**应用处**门控）
- 滑音时间由 `GLIDE_STEP`（`0x35–0x36`）控制

**判据 E2-D3**：

1. 已有：两组 `GLIDE_STEP` 的时间常数比 ≈ 8:1 ✓
2. 新增：滑动一次经过 5 个键，产生的 note-on 数量 = **0**，且音高连续变化

> **2026-10-06 现状与拆法**：
> - **方式 (a) legato 已具备**：引擎侧（`gq` 初值 + 线性速率 + `CTRL[2]` 开关）**全都在，判据也过了**，
>   而且**不依赖任何新传感器** —— 打开 `CTRL[2]` 就能演示。
> - **方式 (b) 滑动仍缺输入层**：需要"手指未离开面板"与"时间窗内跨键"的判定，
>   依赖触控原型的采样率与状态位（见《33-滑音颤音实现方案v1》第 3.1 节与第 4 节 P3/P4）。

### D4 音色亮度

| 项 | 规格 |
|---|---|
| 手势 | 手指在泛音排（H1–H8）上**滑动** |
| 映射 | 位置 → 泛音构成**插值**（若干预设谱之间，从"少而暗"到"多而亮"） |
| 引擎 | 写每声部表情寄存器 → 触发 A1 逐声部刷新（`0x63`） |
| 限制 | 刷新有延迟（几十个周期）；**手势级够用，音频级不行** |
| 消歧 | 点按 = 选泛音（结构层）/ 滑动 = 改亮度（演奏层） |

**判据 E2-D4**：写亮度值 → 实测**谱心（或高频能量占比）单调变化**（可复用 12 f1 的谱分析工具 ✓）。

> **2026-10-06 实测修正（重要）**：`0x5C TILT` 已落地，验收时发现**"谱心"这条口径会给出反向结论**。
> 本功能在低力度会**砍掉高次泛音**（条数机制），高次一没，谱心被拉回低处 ——
> 逐峰比较是"变亮"的，谱心却是"变暗"的。实测数据：
>
> | v=14 | 264Hz | 791Hz | 1301Hz | 2092Hz | 3146Hz | 4184Hz | 谱心 |
> |---|---|---|---|---|---|---|---|
> | 功能关 | 1.000 | 0.650 | 0.402 | 0.351 | 0.224 | 0.199 | 1666 Hz |
> | 功能开 | 1.000 | **0.710** | **0.475** | **0.460** | **0.339** | （被砍） | **1601 Hz** |
>
> ⇒ **亮度这一维的判据改用「高次能量占比（谐波 k≥3 的能量 / 总能量）」**，
> 实测 v4→v14 为 **49.7% → 66.6%（1.34 倍）**，单调且与听感一致。
> 谱心仍可作旁证，但**不得单独作为通过依据**。
> 工具：`python tools/scripts/vel_audition.py`（一条命令出 wav + 对照报告）。

## 3. 消歧与优先级（本节最关键）

| 冲突 | 处理规则 |
|---|---|
| 力度 vs 触后 | 起音取力度；之后的变化**只**归触后 |
| 点按泛音键 vs 滑动改亮度 | 时间窗 + 位移连续性：< W 且连续 ⇒ 滑动 |
| 滑动 vs 逐个弹奏 | 同一条时间窗判据（阈值待原型定，因为它决定采样率） |
| 触后 vs 音域切换 | 音域是**设定**动作；切换期间**冻结**表情（防止整体变调） |
| 多指同时 | 逐声部：每声部用自己的值，互不干扰 |
| 长按不放 | 触后持续有效；不产生重复触发 |

## 5. 判据清单（对齐 E2）

| 编号 | 判据 | 方法 |
|---|---|---|
| E2-D1 | 16 档力度单调，动态范围 ≥ 20 dB | 写 16 档 → 实测包络峰值 |
| E2-D2 | 触后 → 频偏 0…52 音分；**和弦逐声部独立** | 两音给不同触后 |
| E2-D3 | 时间常数可控（8:1）+ 滑动不产生 note-on | 已有 + 新增 |
| E2-D4 | 亮度值 → 谱心单调 | 复用谱分析 |
| E2-X1 | 滑动 vs 点按消歧正确 | 时间窗边界测试 |
| E2-X2 | 力度与触后互不污染 | 重按 → 力度大、颤音深度不变 |

## 6. 待原型确认的分支

| 实测结果 | 分支 |
|---|---|
| 模拟量 ≥ 4 档且重复性 < 1 档 | D1/D2/D4 按本文实现 |
| 模拟量不可靠 | D1 用固定值；D2/D4 改由**拇指条/脚踏**提供 |
| 采样率 < 100 Hz | D3 只做 legato，不做滑动 |
| **无 IRQ 引脚** | **架构重算延迟预算**（可能必须换器件） |

## 7. 与 E2 得分的关系

E2 要求「≥3 维演奏表情」：

| 维 | 来源 | 状态（2026-10-06） |
|---|---|---|
| 力度动态 | D1 | ✅ **已实现**（力度→音量 + 力度→音色，`0x6E` 可调灵敏度）；输入层的"接触面积→力度"仍等原型，但**引擎侧通路与判据已齐** |
| 颤音 | D2 | ⚠️ **引擎已有但是全局**；逐声部为最大短板 → 方案见《33-滑音颤音实现方案v1》P1/P2 |
| 滑音 | D3 | ✅ legato 通路已具备且运行时可开关；滑动式等原型 |
| （加分）音色亮度 | D4 | ✅ **已实现**（`0x5C TILT` + 判据 L1–L6） |

⇒ **三维齐备，第四维已落地。** 剩余主要工作量集中在"颤音逐声部化"与"输入层滑动判定"。
