## 图里的事实来源

- `src/rtl/tdm_top.v` —— 事件仲裁
- `src/rtl/note_map.v` —— 16×8 谱 RAM、谱合成、相位增量查表
- `src/rtl/tdm_engine.v` / `src/rtl/osc_env.v` —— 时隙合成与包络
- `src/rtl/fx_delay.v` —— 效果器

- `src/rtl/reg_bank.v` —— 寄存器堆
- `src/rtl/song_seq.v` —— 片内定序器

## 现状与提案的分界线

`04` 与 `05` 是成对的一对，回答的是同一个问题"泛音构造的交互是什么"，但分属两个状态：

| | `04-泛音构造-当前实现` | `05-泛音构造-提案手势` |
|---|---|---|
| 状态 | 已在 RTL 中，能上板跑 | 一行代码都没写 |
| 右手 | 8 键二值：按住把对应泛音顶到满幅，松开复原 | 位置轴：双向、绝对、抬手回中 |
| 可触及范围 | 只有低 8 条泛音（掩码高 8 位恒为 0） | 一根轴走结构层选定的路径 |
| 电平档位 | 只有 0 与 255 两档 | 相邻两格桥接可给 15 档 |
| 逐声部 | 引擎支持（`0x63`），但只有上位机能触发 | 按住某个音即只作用于该声部 |
| 谱形随时间变化 | 不支持 | 包络层：起音谱 → 稳态谱 |

看答辩材料时建议先看 `04`（现状），再看 `05`（提案）——这样"说的"和"做的"不会混。

`03-交互层三层分工` 是提案的**结构视角**（维度怎么分配到三个时间尺度），`05` 是提案的**行为视角**（手怎么动、什么顺序），两者互补。

## 两张图的诚实边界

第三张图标了"设计提案"，因为其中**谱形随音符时间演化**与**演奏轴（`0x5C TILT`）**尚未实现——协议里已声明、RTL 里没有。已实现的部分是：谱 RAM、叠加/替换、逐声部刷新（修正案 A1 / `0x63`）、逐槽包络。

前两张图的全部结论来自仿真与综合；板卡尚未上电，电极真实 RC 量程未实测。

## 怎么改图

图由 Archify 生成（Node CLI，零运行依赖）。改 `.candidate.json` 后重新生成：

```powershell
node C:\Users\Sakuya\archify\archify\bin\archify.mjs finalize architecture `
  "docs\04-架构图\01-运行时架构.candidate.json" `
  "docs\04-架构图\01-运行时架构.html" `
  --repo-root . --quality showcase --out-dir "docs\04-架构图\.build-01" --json
```

图型名按文件里 `diagram_type` 填（`architecture` / `sequence`）。注意两点：

- 证据仓库需要一个名为 `origin` 的远端，且它与图里 `meta.repository.url` 必须一致
- 重复生成要换 `--out-dir`（它不会覆盖上一次的浏览器证据）
