## 一、先破除一个误区

你说"零基础"——但 FPGA 这个赛题有个特点：**它奖励的是"想清楚"，而不是"写得多"**。

原因很实在：
1. **我们的赛题得分公式是「振荡器数 × 采样率」**。一个振荡器在 RTL 里就是十几行——相位累加器 + 查表 + 包络。学会它，你就有了 1 分；把同样的东西复制 32 份，你就有 32 分。**从 1 到 32 是参数，不是难度。**
2. **RTOS/软件工程那套复杂抽象，这里几乎用不上**。FPGA 的本质是"用时钟驱动一堆寄存器"，是被动、确定、看得见波形的。
3. **你已经有的优势**：一个已经打通硬件通路的官方例程（I2S 音频验证过的），和一份把赛题规则嚼碎的方案。很多队伍要花两周才走到你现在的起点。

所以真正的问题不是"零基础够不够"，而是**"怎么在 47 天里把学习顺序排对，让每一天的产出都能直接塞进项目"**。

## 三、第 1 段详解：能出声（9/18 - 10/05）

### 你要学的（按顺序，别跳）

| # | 知识点 | 为什么需要 | 学多久 |
|---|---|---|---|
| 1 | `module` / `input` `output` / `wire` `reg` | 一切的基础 | 1 天 |
| 2 | `always @(posedge clk)` 时序逻辑 | **FPGA 的灵魂**：时钟来了才更新 | 2 天 |
| 3 | 计数器与分频 | 采样率、音高都靠它 | 1 天 |
| 4 | `case` / `if` 组合逻辑 | 控制逻辑 | 1 天 |
| 5 | 仿真（Testbench） | **不仿真等于盲写** | 2 天 |
| 6 | ROM / 查表（`$readmemh` 或 case） | 波表音源 | 2 天 |
| 7 | 引脚约束 .cst 怎么写 | 让信号连到物理引脚 | 1 天 |
| 8 | Gowin 工程流程（综合→布局布线→烧录） | 把代码变成电路 | 2 天 |

**学习资源就用官方的**：
- 高云官方视频教程：`gowinsemi.com.cn/video_complex.aspx?FId=n15:15:26`
- 高云 B 站：`space.bilibili.com/1930822744`
- Verilog 语法（中文，刷起来快）：`runoob.com/w3cnote/verilog-tutorial.html`
- 练手题库（选做题，只做计数器/状态机类）：`hdlbits.01xz.net`

> ⚠️ **不要**去啃 HDLBits 全部题目。**只做**"计数器、状态机、移位寄存器"这三类，做完就回来写项目。刷题不是目的。

### 第一个里程碑任务（第 1 周内必须做到）

**任务 A：跑通官方 audio 例程**
- 文件在 `refs/vendor-examples/tang20k-audio/`
- 建 Gowin 工程 → 导入这些文件 → 综合 → 烧录 → 喇叭响
- **意义**：验证你的板子、线、IDE、驱动全链路没问题。这一步不过，后面全白搭。

**任务 B：自己写一个 1Hz 闪烁 LED**
- 别笑。这是你的"Hello World"，验证你能独立完成"写代码→约束→烧录"闭环。

**任务 C：自己写 I2S 发送器**
- 参考 `refs/vendor-examples/tang20k-audio/audio_src_audio_drive.v`
- 但**要理解每一行**，注释写清楚
- 关键点：`b_cnt` 数 0~31，每 32 拍发一个采样点

**任务 D：自己算正弦，发 440Hz**
- 相位累加器：`phase <= phase + PHASE_STEP;`
- `PHASE_STEP = 440 / 46875 × 2^N`（N 是相位位宽，比如 24）
- 取相位高位当 ROM 地址 → 查表 → 送给 I2S
- **里程碑达成：喇叭里是你自己算出来的 440Hz**

## 四、第 2 段详解：能弹曲（10/06 - 10/19）

### 核心跳跃：从"1 个"到"32 个"

这是全项目最关键的一次认知升级，但它其实很简单：

```verilog
// 不是写 32 遍，而是用数组 + generate
genvar i;
generate
  for (i = 0; i < NUM_VOICES; i = i + 1) begin : voice_gen
    osc_wavetable u_osc (
      .clk        (clk),
      .phase_step (phase_step[i]),   // 每个声部自己的音高
      .env        (env_level[i]),    // 每个声部自己的包络
      .sample     (voice_out[i])
    );
  end
endgenerate
```

**从 4 复音改到 32 复音，只改 `NUM_VOICES` 一个数。** 这就是 FPGA 相对 CPU 的暴力美学，也是赛题的爽点。

### 你要学的

| # | 知识点 | 用途 |
|---|---|---|
| 1 | 模块例化与端口连接 | 搭积木 |
| 2 | `generate` / `genvar` | 批量生成 32 个声部 |
| 3 | 数组 `reg [15:0] x [0:31]` | 存每个声部的状态 |
| 4 | 加法树 / 流水线 | 32 路混音不卡时序 |
| 5 | 饱和限幅（防破音） | 混音后必须做 |
| 6 | 状态机（ADSR 四段） | 包络控制 |
| 7 | 按键消抖 | 交互基础 |

### 关键设计：音符分配器（note allocator）

按下第 5 个键，但只有 4 个声部时怎么办？→ 抢最老的声部。

```
输入：note_on(note, velocity)
逻辑：
  找一个空闲声部 → 有就用
  没有空闲 → 抢"最早触发且已进入释放段"的声部
  再没有 → 抢最早触发的（voice stealing）
输出：该声部的 phase_step 和 env 参数
```

### 第 2 段产出

```
src/rtl/voice.v            单个声部（振荡器+ADSR）
src/rtl/note_alloc.v       音符分配器
src/rtl/mixer.v            混音+限幅
src/rtl/debounce.v         按键消抖
src/rtl/top.v              整合
```

**里程碑：按住 4~8 个键同时响，音高正确，能弹《小星星》**

## 七、四个最容易卡住的地方（提前打预防针）

| 卡点 | 症状 | 解法 |
|---|---|---|
| **1. 只仿真不上板** | 仿真全对，一比划就不对 | 每天都上板。仿真通过≠硬件可用 |
| **2. 时序不收敛** | 布局布线报错 / 行为异常 | 先降频试试；学会看时序报告；流水线打拍 |
| **3. 混音破音** | 32 路一响就爆音 | 混音后**必须**饱和限幅，不能直接截断 |
| **4. 死磕完美架构** | 前两周都在"设计"，没写过代码 | **先跑通最丑的版本**，再重构 |

## 九、关于"争取进线下决赛"

决赛门槛 = 初赛作品评审通过。初赛看的是：

| 评审维度 | 我们能拿什么 |
|---|---|
| 作品完整度 | 引擎跑通 + 能真实演奏 + 报告完整 |
| 专业性 | 纯 RTL 全硬件合成、延迟可测量、资源有分析 |
| 创新性 | 自研交互（≥3 维）、加法合成音色、测试模式 |
| 合规性 | **无预录 PCM**（我们有测试模式自证） |

**结论：进决赛不需要"惊艳"，需要"完整 + 自证合规"。** 这正好适合"边学边做"——因为按上面的路线走，你天然就会得到一套完整的东西。
