# 一、相位累加器 / DDS

## 原理（一句话）

> 想要一个频率为 f 的正弦波，不去"算"正弦，而是维护一个**相位**变量，
> 每个采样周期让它加上一个固定的增量 `inc`，然后拿相位的高位去查表。

```
phase += inc            // 每个采样周期
addr   = phase[高 8 位]  // 取高位当查表地址
sine   = table[addr]
```

推导：相位是 24 位，`2^24` 对应"转一整圈"。所以每采样转过的圈数 = `inc / 2^24`，
频率 `f = inc × fs / 2^24`，反过来 `inc = f × 2^24 / fs`。

**关键性质**：改 `inc` 就改频率，**相位不中断** → 变调时不会有咔哒声。

## 我们用在哪

`osc_core.v` 里 `phase_adv = phase_in + inc`（组合逻辑），
`osc_additive.v` 里在 `sample_en` 拍把它寄存回 `phase_q`。

**注意**：相位寄存器在**壳层**（`osc_additive.v`），不在运算核里 ——
这是"状态与运算分离"纪律，为了将来上 TDM 时能把相位搬进 BSRAM。

## 自测

1. 我们的 `inc` 是 24 位，`fs` = 46875 Hz。要产生 440 Hz，`inc` 是多少？
   > `440 × 2^24 / 46875 = 157482`（正好是顶层里第 2 个泛音的常量）。
2. 为什么改频率不用清相位？
   > 相位代表"波形走到哪个位置"，只要它连续，输出波形就连续，听不到断点。

# 二、正弦表与 Q1.15 定点

## 原理

FPGA 里做小数有两种办法：**浮点**（贵、慢）或**定点**（便宜、快）。
我们全程用定点：把 [-1, 1) 映射到 [-32768, 32767] 的整数，这叫 **Q1.15**
（1 位符号 + 15 位小数）。

- 正弦表 256 项 × 16 bit：`table[i] = round(sin(2πi/256) × 32767)`
- 幅度也是定点：8 位无符号 0..255，`amp/256` 就是倍率
- 相乘后右移还原量纲：`(sine × amp) >> 8`

## 为什么不用浮点

| | 定点 | 浮点 |
|---|---|---|
| 资源 | 一个乘法器 | 需要 IP 核，面积大 |
| 确定性 | **逐位可复现** | 舍入行为依实现而异 |
| 我们的验证 | Python 模型与 RTL **逐位一致** | 做不到 |

**"逐位一致"是我们最重要的验证手段**，定点是它的前提。

## 自测

1. Q1.15 能表示的最小正数是？最大是？
   > 最小 `1/32768`，最大 `32767/32768 ≈ 0.99997`。
2. 为什么 `(sine × amp) >> 8` 里的 `>>` 必须是**算术**右移（Verilog 的 `>>>`）？
   > 因为 sine 是有符号数，负数右移必须补符号位；用逻辑右移会把负数变成大正数。

# 三、同步读表 → BSRAM（这是 v1→v2 那次修复的核心）

## 原理

Gowin 的块存储器（BSRAM）是**同步读**的：地址打进去，**下一个时钟**数据才出来。
而 Verilog 里写 `assign y = mem[addr];`（组合读）在综合器眼里是"异步读"，
**它没法用 BSRAM 实现**，只能退化成一大坨查找逻辑。

| 写法 | 综合结果 | 代价 |
|---|---|---|
| `assign y = mem[a];` | LUT 选择树 | v1 实测 **LUT 2070**、路径极深、时序违例 |
| 地址寄存一拍再读 | **BSRAM** | v2 实测 **LUT 19** |

代价是**多一拍延迟**——完全值得。

## 我们用在哪

`osc_core.v`：
- 级 1：`addr_r <= phase_in[...]`（锁地址）
- 级 2：`s_val <= sine_tab[addr_r]`（同步读）

## 自测

1. 为什么异步读会导致 LUT 爆炸？
   > 256 项的表要用 LUT 搭成多级选择树，还要为 8 个泛音各搭一份。
2. 同步读换来了什么？
   > 表进了 8 块 BSRAM，LUT 从 2070 降到 19，时序从违例变成 slack +4.2ns。

# 四、流水线

## 原理

一段组合逻辑太长，就跑不到高时钟频率。**在中间插寄存器**，把它切成几段，
每段都变短，时钟就能跑快。代价是**延迟增加**。

我们 7 级：

| 级 | 做什么 |
|---|---|
| 1 | 锁表地址 |
| 2 | 同步读表 |
| 3 | 乘幅度 |
| 4 | 加法树 8→4 |
| 5 | 加法树 4→2 |
| 6 | 加法树 2→1 |
| 7 | 饱和输出 |

**7 级 = 7 个采样周期的延迟 = 7/46875 s ≈ 149 µs** —— 相对 10 ms 的指标而言可以忽略。

## ⚠️ 最容易错的细节

**所有流水线寄存器都必须由 `sample_en` 使能。**

因为 `sample_en` 每 576 个时钟才来一拍，如果流水线每个时钟都推进，
就会把样本之间的空闲拍也当成数据处理 —— 结果是"看起来在跑但音不对"。

## 自测

1. 加法树为什么要分 3 级而不是一级算完？
   > 8 个数串行相加是一条长链（v1 实测单这一条就 ~5.6ns），分层后每级只有一次加法。
2. 如果忘了给某一级加 `sample_en` 会怎样？
   > 那一级会以 27MHz 而不是 46875Hz 推进，输出完全错乱。

# 五、饱和限幅

## 原理

多个泛音相加，结果可能超出 24 位有符号的范围。两种处理：

| | 行为 | 听感 |
|---|---|---|
| **截断** | 丢掉高位，数值"回绕" | 大信号突然变成反相噪声，**很刺耳** |
| **饱和** | 卡在最大值/最小值 | 削顶失真，但可接受 |

## 自测

1. 为什么饱和放在**求和之后**而不是每个泛音之后？
   > 逐泛音饱和会破坏线性叠加关系；而且包络要乘在"求和之后、饱和之前"，
   > 核内饱和会堵死包络的插入点。

# 六、ADSR 包络

## 原理

一个音从按下到松开，振幅经历四段：

```
        /\
       /  \___________
      /               \
     /                 \
   A起音  D衰减  S延音   R释放
```

| 段 | 触发 | 作用 |
|---|---|---|
| **A**ttack | 按键按下 | 从 0 升到满 |
| **D**ecay | 起音结束 | 从满降到延音电平 |
| **S**ustain | 衰减结束 | 保持（可调电平） |
| **R**elease | **按键松开** | 降到 0 |

## ★ 我们在这一点上的关键决策

赛题原文定义：

> 「独立发声单元为包含**独立相位累加器、频率调控、包络控制**的完整振荡器」
> 「加法合成**按运算分量统计**」

加法合成的"运算分量"就是**每个泛音**。所以：

> **包络必须做成"每泛音一份"，不能只做在声部级。**
> 否则严格读法下每个泛音并不拥有自己的包络控制，"完整振荡器"不成立，
> **而它直接决定核心指标能不能算。**

我们为此实例化了 8 个 `osc_env`（每个泛音一个），代价很小（包络是慢变量）。

## 自测

1. 如果评委问"你的包络是每声部一个还是每泛音一个"，怎么答？
   > 每泛音一个。因为指标按"运算分量"计数，分量就是泛音；
   > 每个泛音都有自己的包络状态机（`osc_additive.v` 的 `G_ENV` 生成块实例化了 8 份）。
2. `RELEASE` 由什么触发？
   > 门信号的**下降沿**（按键抬起）。`tb_osc_env.v` 的 A5 断言专门守这条：
   > 不给 `trig_rel`，延音段 20000 拍都不许自己离开。

# 七、一阶指数为什么用移位而不是乘法（这是实测逼出来的）

## 原理

想要"每秒固定掉多少 dB"的自然衰减，就是每拍乘一个略小于 1 的系数：

```
lvl = (lvl × coef) >> 15      // coef 是 Q1.15 的系数
```

但这**每个泛音要 2 个乘法器**（衰减 + 释放）。

## 我们踩的坑

综合报告显示：加包络后 **DSP 从 3/24 飙到 15/24（63%）**。
一个声部就 63%，4 个声部必然溢出。

## 修法

```
lvl = lvl - ((lvl × m) >> k)      // m ∈ {1,2,3}
```

`×m` 只用移位与加法（m=2 就是左移一位；m=3 就是 `lvl + (lvl<<1)`），**一个 DSP 都不占**。

它**仍然是一阶指数**（等比衰减），只是时间常数 τ ≈ 2^k/m 是离散的：

| 目标 | m, k | 实际 τ | 误差 |
|---|---|---|---|
| 释放 0.40 s | 3, 13 | 2731 采样 | 0.5% |
| 释放 0.10 s | 3, 11 | 683 采样 | 0.6% |

**结果：DSP 从 15 降到 7**，逻辑从 1515 涨到 1971 ——
用富余的逻辑（还剩 90%）换紧俏的 DSP（只剩 70%）。

## 自测

1. 为什么说这笔交易划算？
   > 因为器件上 LUT 有 20736 个（我们只用 10%），DSP 只有 24 个。
   > 用不紧张的资源换紧张的资源。
2. 移位版和乘法版听感有区别吗？
   > 没有。两者都是一阶指数（dB 线性下降），只是时间常数分辨率不同。

# 八、使能脉冲 vs 派生时钟（单时钟域铁律）

## 原理

新手常犯的错：为了得到 46875 Hz，写个 ÷576 计数器，把输出当成**时钟**去驱动别的模块。

**这在 FPGA 上是危险做法**：派生时钟要走全局时钟网络，会引入偏斜，
时序分析也要按多时钟域处理。

**正确做法**：全局只有一个 27 MHz 时钟，用**使能脉冲**（一个时钟宽的 `1`）告诉别的模块"该干活了"。

```verilog
// ✗ 错误
always @(posedge slow_clk) ...

// ✓ 正确
always @(posedge clk) if (sample_en) ...
```

## 我们的时钟链

```
27 MHz 晶振
  └─ ÷18  → bck_en（使能）+ bck（引脚方波 1.5 MHz）
  └─ ÷32  → lrck（WS 引脚，46875 Hz）+ sample_en（每帧一拍）
```

**全部整除、零抖动**：`27 000 000 / 18 / 32 = 46875`。

> 这也是**为什么不用 48000 Hz**：27 MHz 除不出 48000 的整数分频，
> 会有抖动。46875 虽然不是标准采样率，但 DAC 不在乎——它是从属方。

## 自测

1. 为什么不干脆用 PLL 倍频到 108 MHz？
   > 地板阶段不需要。108 MHz 只有 TDM 大规模才用得上，现在引入只会增加
   > PLL 锁定风险与时序收敛难度。实测 27 MHz 下 slack +31.5 ns，裕量巨大。
2. `bck_en` 和 `bck` 有什么区别？
   > `bck_en` 是内部使能（一个时钟宽）；`bck` 是输出到 DAC 的引脚方波，
   > 每 18 拍一个完整周期（前 9 拍低、后 9 拍高）。

# 九、I2S 协议与"1 bit 延迟"

## 三根线

| 线 | 作用 |
|---|---|
| **BCK** | 位时钟，每来一个沿发一位 |
| **WS / LRCK** | 字时钟，低=左声道，高=右声道；**频率 = 采样率** |
| **SD / DIN** | 串行数据，**MSB 先出** |

一个 WS 周期 = 32 个 BCK = 左 16 位 + 右 16 位。

## ★ "1 bit 延迟"到底是什么意思（我曾理解错并改坏过）

I2S 规范说"WS 变化比 MSB 早一个 BCK"。**这句话不是让你把数据挪一格。**

正确理解是：

> **发送方在 BCK 的下降沿换数据，接收方在 BCK 的上升沿采样。**
> 那半个周期的错开，本身就构成了"WS 先变、下一拍才采到 MSB"。

**如果再去人为地把装载推迟一个 BCK，整帧会错位一位** ——
接收方收到"左 bit14..bit0 + 右 MSB"，解码值变成 `源值 >> 1`，**幅度减半**。
（这是实测出来的：`i2s_dec.txt` 里一眼可辨。）

## 我们怎么验证它

`src/sim/tb_i2s_tx.v` 内置一个**独立的 I2S 接收模型**：

```
发送器串行化 → 接收模型按规范采样、移位、拼回 16 bit → 与原样本比对
```

结果：**128 个字逐位一致，0 处差异**。
一条证据同时证明了位序、声道对齐、位宽截取、BCK/WS 相位四件事。

## 自测

1. 你怎么证明 I2S 时序是对的（没有示波器）？
   > 闭环自检：把串行流用独立的接收模型解码回样本，与源逐位比对，0 差异。
2. BCK/LRCK 是多少？为什么？
   > 32。16 bit × 2 声道。MAX98357A 支持 32/48/64 三档。

# 十、时分复用（TDM）—— 你要拍板的那个决策

## 现在的架构（全并行）

8 个泛音 = **8 套独立的运算硬件**同时在跑。

问题：**每 576 个时钟才用 1 拍**，利用率 0.17%。

## TDM 的想法

**只用 1 套运算硬件，在 576 个时钟里轮流服务 576 个泛音。**

```
全并行：8 套硬件 × 用 1 拍 / 576 拍   → 8 个泛音
TDM   ：1 套硬件 × 用满 576 拍        → 576 个泛音
```

| | 全并行 | TDM |
|---|---|---|
| 振荡器上限 | ~46（BSRAM 读口限制） | 576（27MHz）/ 2304（108MHz） |
| 吞吐量 | 375 000 | **27 000 000** |
| 正弦表 BSRAM | 每个泛音 1 块 | **1~2 块** |
| 复杂度 | 低 | 高 |
| 答辩难度 | 好讲 | **要论证"共享运算硬件算不算独立振荡器"** |
| 调试难度 | 一眼一条线 | 出错是"某个音偶尔错一拍" |

## 为什么现在不做

1. 9 个必须项现在才刚完成一半，没有余量去赌
2. 步骤 4 做完就会有**真实数据**（8/16/32 泛音的资源曲线）——那时用数据拍板
3. **门开着**：`osc_core` 已经无状态，`osc_env` 已经是槽式接口，
   上 TDM 是"换一个状态持有层"，**不是重写引擎**

## 自测

1. TDM 最难的三个地方是什么？
   > ① 状态存储变成新瓶颈（相位搬进 BSRAM，每样本读-改-写）
   > ② 时隙调度（576 个时隙要分给泛音/包络/混音/控制）
   > ③ **bug 极难查**——而且我们没板子、没逻辑分析仪，这个难度会被放大
2. 为什么说"门开着"？
   > 因为状态（相位、包络电平）已经全部移出运算核，放在壳层的寄存器里。
   > 上 TDM 只需把那些寄存器换成 BSRAM + 时隙调度，运算核一行不改。

# 十一、吞吐量指标怎么算

> 赛题原文：**「同时活跃可闻独立振荡器总数 × 实际音频输出采样率」为核心评分依据，过采样不叠加加分。**
> 计数规则：**加法合成按运算分量统计**。

## 算给我们看

| 配置 | 振荡器数 | 采样率 | 吞吐量 |
|---|---|---|---|
| 现在（1 声部 × 8 泛音） | 8 | 46875 | **375 000** |
| 做完步骤 4（4 声部 × 8 泛音） | 32 | 46875 | **1 500 000** |
| 拓展项门槛（E1 要 ≥32） | 32 | 46875 | 1 500 000 |
| TDM @27 MHz | ~576 | 46875 | **27 000 000** |

## 一个必须注意的软约束

指标里写的是「**可闻**」独立振荡器。一个 220 Hz 的音，只有前 ~90 个泛音在 20 kHz 以内：

| 基频 | 可闻泛音上限 |
|---|---|
| 220 Hz | ~90 |
| 440 Hz | ~45 |
| 880 Hz | ~22 |

**所以单声部堆到 2304 个泛音没有意义**（听不见）。要撑高数字必须靠**声部数**。

## 自测

1. "过采样不叠加加分"是什么意思？
   > 如果我们用 187.5 kHz 内部处理再降到 46875 Hz 输出，**不能**按 187.5 kHz 算。
   > 必须按实际输出采样率算。
2. 提高吞吐量有哪两条路？
   > ① 增加同时发声的振荡器数（更多泛音 / 更多声部）
   > ② 提高输出采样率——但采样率受 DAC 与时钟链约束，且"过采样不叠加加分"。

# 十二、答辩自测题（按评委最可能问的顺序）

| # | 问题 | 答案要点 |
|---|---|---|
| 1 | 你的振荡器为什么算"完整振荡器"？ | 三要素：独立相位累加器（每泛音一个）、频率调控（`inc`）、**包络控制（每泛音一份 `osc_env`）** |
| 2 | 加法合成 50 年前就有了，你的新意在哪？ | **不能答算法**。答：把音色的内部结构做成一条可实时演奏的轴（每泛音独立幅度谱 + 实时改），加上位精确可验证的工程方法 |
| 3 | 怎么证明没有播放预录？ | ① 设计上不可能：代码里没有任何音频存储器，正弦表是赛题明确允许的波表 ② RTL 内置测试模式输出多路不同频率、频谱可数峰 ③ 测试模式用 LFSR 随机触发，预录无法匹配 |
| 4 | 为什么用 BSRAM 不用分布式 RAM？ | 容量与端口。而且同步读才能映射到 BSRAM，异步读会退化成 LUT 树（实测 LUT 2070 → 19） |
| 5 | 流水线几级？延迟多少？ | 7 级，7 个采样周期 ≈ 149 µs（vs 指标 10 ms） |
| 6 | I2S 的 1 bit 延迟怎么实现的？ | 发送方踩 BCK 下降沿、接收方踩上升沿，**错开半个周期本身就构成延迟**，不额外挪数据 |
| 7 | 采样率为什么是 46875 而不是 48000？ | 27 MHz 整除：`27e6/18/32 = 46875`，零抖动。48000 除不出整数 |
| 8 | 包络为什么用移位不用乘法？ | 一个声部 8 泛音 ×2 个系数乘法 = 16 个 DSP，实测 DSP 15/24（63%）会溢出。改移位后 **7/24** |
| 9 | 你的吞吐量指标怎么算？ | 8 泛音 × 46875 = 375 000（当前）；做完多声部 32 × 46875 = 1 500 000 |
| 10 | 怎么证明设计是对的？ | 五套自检：Python 模型 ≡ RTL 逐位一致、包络 A1~A9、时钟链 S1~S6、I2S 闭环解码、演奏回归 |
