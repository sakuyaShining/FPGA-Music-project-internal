# 自动连接与完整演奏视图修复

用户指出默认分栏难用、视图不完整，要求连接后自动传输并直接演奏。本次按此修复，不要求另点开始观察或先应用草稿。

## 修改

- 主视图默认完整三视图/琴键，音色与设备编辑按需展开；适配1024×640及1280×720。恢复可访问的显示设置入口，展开编辑时保留三视图和演奏。
- FT2232双通道默认选择UART B（本机COM6），避免把下载通道A（COM5）作为默认端口；显式选择其他串口仍保留。
- 连接后唯一后台线程核对D4/rev4/32组能力，读当前参数，清CTRL测试模式位、保留表情位、选择寄存器预设，自动发送B5=1。收到有效PCM后启用演奏并把键盘焦点交回窗口。起音无需另点观察按钮或应用草稿。
- 初始参数读回移到后台，免除主线程逐寄存器等待读回。无应答有限次重试；超时、版本不符和可演奏状态区分。
- 一次断开操作先释放主机拥有的音符并结束流，线程退出后关闭串口；关闭窗口也按后台停止流程完成。
- 发现PROTO_VER虽被文档称作只读，但实际RTL允许写入。D4/A5/A9实时能力字段为顶层固定诊断值。实时和支持字段适配以固定能力核对为准，异常PROTO_VER保留并提示，不改成0x11伪造确认。

## 验证

66项主机测试通过，新增自动连接→准备演奏→按键→自动断开的完整协议夹具、错误能力拒绝、无应答提示、异常RAM版本标志和小窗口布局判据。

真实COM6测试通过：约0.25秒自动进入数据接收；36音频帧；C4起音及释放事件被设备接受；内部PCM峰值约0.2674；CRC/缺帧/时间中断/损失均0；一次点击断开成功。此次测试未下载任何码流，不证明当前完整源码/码流SHA，也不签收DAC或实体触控。

实际读回PROTO_VER=0x0F、CTRL=0x88、PRESET=0xF8、FX_CTRL=1、SPEC_MODE=2；保留异常值。PRESET有效音色按低2位解释。连接初次诊断曾无应答，随后读回稳定且固定诊断值为D4/rev4/32组；未确定RAM标志异常来源，不将其归因为用户断电。
