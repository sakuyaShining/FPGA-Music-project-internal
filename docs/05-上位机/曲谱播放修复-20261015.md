# 曲谱下载与播放修复（上位机10版）

## 原因

旧入口 `MainWindow.seq_download/seq_play` 在主线程调用 `_protocol_v11_supported`，直接回读协议版本。实时模式的 LiveWorker 持有串口接收事务；通信层的非阻塞保护在其他线程读取时返回 None，旧入口把它当作“不支持v1.1”并拒绝发送。它不是已经证实的锁死，而是只有高级日志可见的失败，用户看到按钮没有生效。

即使绕过旧检查，普通非音符写入也不允许在实时接收期间直接进行，因此需要完整接入后台事务调度。

实板还暴露独立错误：`Frames.w16/w24` 连续向同一个地址发送各个字节。RTL寄存器并不自动递增地址，TEMPO的中高字节未被更新，240BPM设置实际约96BPM。已改为连续地址写入，增加独立固定地址测试及速度回读，避免用同一个错误构帧函数互相比对而漏检。

## 实现

- 下载、下载并播放、停止统一由实时流所属线程执行：停止观察、排空完整帧、下发并回读、恢复观察。主线程立即返回。
- 核对D4/rev4/完整32组能力；曲谱与速度在任何写入前全部校验。先停止旧曲谱，最后才使能新曲谱；回读SEQ_CTRL、SCORE_LEN及24位TEMPO。
- 下载仅写开发板RAM，不自动播放；下载并播放从头循环。0音高表示休止。播放期间暂停手动按键，避免同音符互相释放；停止后恢复。
- 下载期间点击停止会排队执行；“停止所有声音”也停止定序器。断开/关闭时停止曲谱及观察流。
- 主界面新增“曲谱播放”入口，将原高级工具中的卡片移入独立窗口，并显示已下载、循环播放、停止和失败状态。
