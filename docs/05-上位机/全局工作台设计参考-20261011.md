# 全局演奏、音色应用与验证工作台方案

2026-10-11，针对用户指出的页面分裂、预设无可见效果和演奏入口不明确。关联固定需求N-08（配置）、N-11（交互）、N-12（三视图）。当前实现基准integration-20261011-07，241输入；本文件是设计方案，不代表新界面或设备适配已实现，不改已有音乐语义。用户确认松键尖峰已修复，07源码、构建及证据保留。

## 当前缺陷与必须满足的目标

现有01音色设计只保存本地草稿，预设不发送；周期预览只用手绘谱，不含预设。02设备实验能组织预设写命令，但没有实时观察窗口。04拥有真实PCM、接受事件、PC频谱和键盘，导致编辑与演奏分离。

另外，SerialLink.send在实时接收事务占用时只放行0x60/0x61音符，PRESET/CTRL/谱与效果写入会被拒绝。不能仅把预设按钮搬到演奏页就认为生效；必须同时解决命令调度、回读与当前设备状态。

最终用户应能在一个窗口完成：选择/编辑音色→明确应用→直接弹奏→持续观察→执行受控测试→保存证据。切换工作页只替换编辑内容，既不隐藏琴键和三视图，也不重建采集线程或自动释放正在演奏的音。

## 布局和导航

推荐一个全局工作台，左侧可折叠编辑栏、右侧共享观察区、底部常驻演奏区。

| 区域 | 常驻内容 | 操作意义 |
|---|---|---|
| 顶部 | 连接、真实/模拟标识、当前设备音色及确认状态、数据新鲜度、释放全部 | 第一眼知道能否演奏、设备实际用了什么 |
| 左侧音色 | 预设、16分量谱、支持的效果/表情参数、草稿保存载入、应用动作 | 编辑与设备实际参数分开，不把草稿当已生效 |
| 左侧验证 | 标准音、单音/和弦/力度/释放测试、预期与实测对照、结果明细 | 不离开演奏窗口即可检查音色 |
| 左侧设备 | 身份、能力、版本来源、寄存器/协议/引脚诊断及日志 | 原设备实验收纳于此，诊断不再代替演奏入口 |
| 共享观察 | 演奏轨迹、包络/周期细节、实测频谱与预期谱 | 所有编辑页引用同一设备会话和真实音频 |
| 底部 | 屏幕琴键、电脑键位、八度、力度、释放全部、输入状态 | 固定演奏入口，参数面板滚动不把琴键卷走 |

默认打开演奏工作台，而非草稿编辑页。提供“专注演奏”收起编辑栏，三视图及键盘扩大。1280×720无整页滚动；窄窗口优先保留琴键、设备状态和实际波形，编辑栏收起、轨迹/频谱折叠可展开，仍持续采集。日志默认折叠，错误显示在相关操作旁。

草稿示意图移入“预期”区域并明确标注，不能占据实际波形位置。停止/断流后历史图覆盖时间和“历史”，空数据不能画成已验证静音。全部页面共用唯一串口会话、唯一接收线程和有界分析缓冲。

## 演奏交互

保留当前Z/X/C/V/B/N/M/逗号五声音阶，显示实际音名、八度与力度，避免静默更换键位。可增加可选半音布局，作为GUI输入映射，不擅自改变实体面板与演奏语义。电脑键盘无力度传感器：力度滑块是指定值；新起音锁存音符与力度，按住时换八度不会改松键目标。

鼠标与电脑键盘均支持复音。系统自动连发不重复起音；同一MIDI音符的重叠输入按当前引擎单组语义协调，不把两个键来源称为两个独立同音声部。真实实体同音多指所有权问题仍按N-02挂账。

给琴键区明确“电脑键盘演奏已启用”的状态；在名称/数字输入框打字不发音，退出输入框可回到演奏区。切换内部编辑页不失去演奏会话；窗口失焦/最小化、模式切换、断连执行明确的释放流程。发送失败时标记设备音符状态未知，重连后先清理，再允许新的演奏。硬件键盘多键冲突与FPGA声部容量分开显示。

轨迹中的按下/释放来自FPGA接受事件，键盘按下反馈来自本地输入，串口发送来自主机记录；不能将三者混作确认。活动音符与释放尾音分别表达：收到off不等于PCM立即为零。移动/表情测试不得以额外note-on伪装连续改变音高。

## 音色应用和生效状态

保持N-08“草稿编辑/载入不自动改变在奏音”。统一状态：草稿未应用→正在应用→已发送待确认→参数确认/部分可确认→实际音频已验证。错误显示具体字段，不能只用通用绿色“成功”。

主要动作“用于下一次起音”：明确使用已编译的设备配置；新的音符使用它，已有声部继续原音色。初期只有预设和已支持谱字段能保证该行为；全局效果/颤音可能立即作用于现有声音，适配器必须显示影响范围，必要时要求无活动音再应用，不能把全局字段假称下一次起音才生效。

次要动作“更新在奏音”：显式刷新目标在奏声部，不重新note-on、不擅自清相位、不能使释放跳变复发。已有0x63刷新是底座，并非“所有参数都可无缝变化”的证明；保留力度、生命周期与全和弦作用的专项通过后才启用。不能宣称整和弦原子更新，当前RTL仍逐槽装载。

完整文件先由能力适配器检查，显示支持、需要量化、超范围、未实现字段。三种发声方式/混合分组/完整包络毫秒语义尚未完整设备接入，第一期保持禁用或草稿标记。任何未实现字段都不能被静默丢弃后宣称“完整配置已应用”。若提供“仅应用支持部分”，必须作为单独明确动作，并生成部分设备配置及未应用列表。

选中预设只改变草稿，按应用动作才发命令；设备音色名称始终来自已知设备配置，草稿名称不直接覆盖它。内置四预设先形成明确可演奏路径，避免等待全部新音乐语义完成。

当前读回可确认PRESET/CTRL等寄存器；谱数据口最后一个字节回读不证明完整16项已发布，现协议没有全配置活动哈希，也没有每次参数应用的确认帧。必须将完整谱确认标为不支持/待音频验证，不能虚构应答。版本区显示“最近已核对下载记录”，D4/rev4本身不等于能够远程证明07完整源码SHA。

## 串口与全局采集调度

第一期无需重写音乐引擎，继续使用07真实连续PCM与接受事件。配置操作提交给后台会话控制器，而非GUI线程等待：

1. 固定演奏输入的优先级，松键不能因配置操作排队失去释放机会。
2. 协议无法并发读回时，结束当前音频帧、停止流并排空接收；界面显示“应用音色，观察暂暂停”。
3. 保持线程、写锁与事务唯一归属，发送合法配置、回读支持字段；整谱按v1.1草稿/提交操作，必要刷新按明确动作执行。
4. 恢复流，留下可见配置应用标记和实际采样缺口。不会补造这段音频，也不拼接成连续测量窗。
5. 失败保留发送字段、原始读回及已改变子集；设备状态未知时不自动反复应用，不把半成功称作成功。

刷新、应用和重新采集全部异步；在奏音刷新不能自动释放以掩盖状态保持缺陷。若仅能在无音时安全应用，界面在有活动音时禁用并说明原因。后续可审计放行不返回字节的安全写命令，或者新增配置确认帧，但要有协议与RTL专项，不能直接移除现有互斥保护。

## 音色有效性的三层验证

| 层级 | 可见证据 | 能证明的范围 |
|---|---|---|
| 参数确认 | 应用配置、量化值、可读寄存器匹配、配置事务记录 | 支持字段进入设备；不能单独证明音频变化 |
| 行为确认 | FPGA接受的on/off时间、力度、事件序列、释放后活动状态 | 设备接收演奏行为；不能代表真实声压/传感器触点 |
| 音频确认 | 新鲜连续PCM、非零/RMS/峰值、谱峰位置与相对幅度、起音/释放变化 | 当前内部数字音频与目标特征相符；不证明DAC/喇叭 |

普通用户结果用具体语言，如“管风琴配置已回读；A4音频已测得，分量分布符合当前预期”；明细提供参考配置、输入序列、时间窗、数值与误差。未匹配、无法观察、没有数据分开，不能统一成“音色正常”。

音色不是只看主频：同音高预设主频本可相同，要比较各分量强度、非整数分量频率及包络。谱图同时支持绝对dBFS和归一化形状，后者用于区分谱形，不掩盖绝对静音/削顶。四预设的名字不等于真实乐器相似度已经听感验收；测试证明实现符合本项目谱表与包络，不证明“像真钢琴”。

预期参考从当前版本preset_part.hex、实际量化谱/力度/亮度/包络、已知滤波和采样配置生成，明确为电脑参考。实测从FPGA回传PCM生成，使用独立参考判据，不能从UI草稿直接生成“实测曲线”。支持预期与实测叠加，冻结A/B同音高、同力度、同采样窗口；目标信号和参考数据的来源/版本可追溯。

现观察样本率13183.59375Hz、63tap FIR截止约5kHz、上限约6.59kHz、1024点Hann频率间隔约12.87Hz。预期必须包含滤波与窗函数影响，不能将理想分量柱高度直接与dBFS峰值比较。低音半音、瞬态和非整数分量可能不满足当前分辨能力；缺少可观察能量时显示“本次无法判断”，必要选更合适标准音或增加主机分析窗并明确延迟。包络图2秒与周期细节20ms分别服务不同用途；不是要求每个预设在2秒图上一定有明显差别。

## 标准测试操作

“验证当前音色”使用用户显式选择的标准音和力度，记录设备现配置。测试期间手动演奏入口标为测试占用，避免混入数据；中止按钮先释放测试拥有的音符。若发现别的来源在奏，等待空闲或明确提示先结束，不擅自发128音符清理造成用户音被切断。

执行前记录可恢复的已知设备配置与观察状态；未知现场配置不能冒充可完整恢复。测试仅更改必要字段，若需要关闭效果得到参考干声，先明确该条件并保存对应配置；当前实时只观察效果后PCM，不能在菜单上伪造同时取得干声/效果后数据。测试结束恢复已记录字段与流状态，失败也在finally释放测试音。

第一组标准用例：

| 测试 | 输入与观察 | 通过条件/限制 |
|---|---|---|
| 预设生效 | 同一标准音/力度，应用4预设后重新起音，保存A/B | 可读字段匹配；各预设符合其参考谱和包络；不以“图不一样”作为唯一判据 |
| 新音/在奏范围 | 按住A，应用新配置，再起B；另测显式刷新 | 已约定影响范围成立，刷新不新增note-on；尚不支持时明确禁用 |
| 草稿谱 | 提交完整16项；替换/叠加分别起音及刷新 | 草稿不提前影响设备；可观察分量随配置变化，零谱规则按实际能力解释 |
| 力度 | 指定1/4/8/12/15，同音高，固定其他参数 | 与量化参考一致，不静音/削顶；离散力度不是键盘测得的压力 |
| 包络释放 | 起音/保持/松键，保存时域窗 | release不提升基幅，承接07连续性门禁；正常尾音不是失败 |
| 复音 | A4+C5分别按放，再快速交替 | 接受事件顺序和释放正确，其他声部不被误释放；同音归属能力单列 |
| 频率与谱峰 | 选满足观察能力的标准音，比较峰与参考窗 | 频率/幅度误差阈值按量化模型和观察误差制定，分辨不足不硬判 |
| 全局观察 | 边弹边切音色/验证/设备页 | 同一流与历史保留，切页不暗中停流或挂音；输入框打字不发音 |
| 传输/故障 | 流期间应用、断连、错身份、超时、磁盘不足 | 松键不被阻塞，缺口有标记，失败不变成PASS；导出失败不影响音乐流 |

保存一个测试会话，绑定源码/构建记录、设备身份、实际寄存器、配置文件及未支持项、量化后设备配置、输入序列、原始wire/PCM/接受事件、参考数据、图表、指标与退出状态。保存位置可选D盘并检查容量，流默认只保留有界内存；显式开始记录才持续写盘，不能每次刷新无限创建文件。测试失败和补验记录分开，不覆盖原失败。

## 性能与交付验收

建议首期目标：1280×720琴键和观察不被遮挡；页面切换不产生流缺口；采集、配置、测试、导出不阻塞GUI；连续30分钟输入与观察无已知CRC/序号/时间缺口、内存有界；实际显示刷新率和note-on→画面延迟分位数/最大值量测后给出，不把33ms计时器等同实测30fps。视觉延迟暂不宣称≤10ms，实体触控到声音的≤10ms仍是另一验收项。

阶段一：常驻全局三视图/键盘、预设可演奏路径、统一草稿/设备状态和串口调度。阶段二：受支持音色适配器、参数回读、标准音与A/B、参考谱和导出证据。阶段三：在奏应用的状态保持验证、可选半音布局及已经确认的表情调试；触控实体交互和完整三发声方式另按固定设计项实现，不在GUI里假完成。

每阶段有新源身份与关联主机/协议/真实GUI板测；主机界面改动不自动要求修改RTL，新RTL/协议变化才关联专项、全量与新PnR/绑定/下载。保留07释放修复和其板级证据，不从旧界面回退替代统一工作台。本轮只交付方案及布局示意，没有修改产品源码或占用用户串口。
