# 快速重按同一琴键时变小或静音

2026-10-15：已修复并下载临时 SRAM。继续使用 `host-workbench-20261015-08`，无需替换上位机。

## 原因和改动

上位机按下/松开命令及 FPGA 接受事件完整。问题位于 `osc_env.v`：起音事件仅在 IDLE 状态处理。松键后，声部组很快可被复用，但上一音的 RELEASE 尚未结束；新的上升沿被消费后，包络仍继续释放。等到静音回到 IDLE，门已经为高，没有另一个起音沿，于是第二次音量变小或完全无声。

新的起音事件在所有有效状态进入 ATTACK，并保留当前电平，从尾音电平连续起音。IDLE 仍从零开始；原来的松键连续性修复、参数保留和时隙门控路径保留。未通过延迟、过滤或吞掉快速按键来规避问题。

## 实板结果

相同 C4、力度12、钢琴、CTRL10、FX_CTRL1、512点早期 PCM 窗口对比：修前第二次/第一次 RMS 为 0.232–0.370；修后钢琴为 0.995–0.998。

修后四种音色 × 三种间隔 × 两种演奏条件，共24组通过：

- C4，保持160ms：第二次/第一次 RMS 0.983–1.010。
- C5，保持60ms：第二次/第一次 RMS 0.975–1.002。
- 间隔请求值5/20/60ms；实际间隔以 FPGA 接受事件时间戳记录，受 Windows 调度与 UART 影响，不能把请求值当作已测精确间隔。
- 全部试验均有两次起音和两次松键，PCM采样窗完整；未见CRC、缺帧、观察中断或设备损失计数增加。
- 最后自动连接/数据传输/按下松开/单击断开复测通过，COM6已释放，恢复之前的钢琴与控制位。

测量窗口为设备接受起音后8ms开始的512个降采样PCM样本。时间戳单位为原始52,734.375Hz音频帧，PCM步长4，不重复乘除4。内部数字PCM不代替DAC听感验收。
