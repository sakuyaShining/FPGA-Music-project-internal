## 2. 能验证的功能

多指落指、独立音符、同音多指、连续滑音、手动颤音、释放与追踪恢复。右手可通过位置编辑并保持泛音修饰；单块面板左右手合计触点受五点上限约束。起音力度暂用预设值；触摸面积可以记录，但不能标记为真实受力。

首轮优先左手面板。左右手完整目标触点数和是否增加第二块，另行依据交互需求与预算决定。

## 3. 计算职责与已知实现差距

GT911 完成基础坐标检测，FPGA 负责轨迹/身份管理、音符映射、连续音高、修饰和音频。该方案需要明确调整原规格“基础坐标由 FPGA 从原始观测计算”的职责，不能称为原始电极处理路线。

现有 I2C 驱动有历史已知失败，触控坐标解析和基于身份的 PITCH_UPDATE 尚未完整接入；不是买到面板就能运行现有工程。还需解决已复现的事件丢失。

## 4. 延迟与到货后的实验

GT911 普通模式坐标更新周期约 7–10ms，低功耗模式更慢。不能据此保证输入到音频 ≤10ms。必须检查实际配置、读出开销、启动/省电状态和滤波，并实测。

验收顺序：读器件与配置 → 单指轨迹/释放 → 多指同音及反向移动 → 身份稳定性/邻近与交叉 → 独立音高且不重起包络 → 物理输入至声音的最坏延迟。

可先不安装 LCD，使用 LED 与遥测观察；最终演奏反馈要求另行保留。显示接口和触控接口是独立职责，不为了触控实验默认购买 LCD 总成。
