# 板卡 Bring-up 一页卡片（Tang Nano 20K · 第一版）

> 用途：板子到手当天，照这张卡片从"拆快递"走到"出声 + 首批实测"。
> 原则（9K bring-up 教训）：先官方码流后自己的码流，把"线/驱动/板"整类问题先排除；
> 只用 SRAM 烧录（掉电即失、零风险）；每一步先写清"预期看到什么"，不吻合就停下判读。
> 引脚全部来自官方例程（见 `src/constr/tdm_top.cst` 头注释），无一猜测。

---

## 0) 需要的东西

| 物品 | 备注 |
|---|---|
| Tang Nano 20K + **带数据线的 USB-C 线** | 充电线（只有电源芯）会"灯亮但永不枚举"——9K 实测教训 |
| 电脑 + Gowin 编程器驱动已装 | 设备管理器应出现 **2 个 USB Serial Converter + 1 个 COM 口** |
| 板载扬声器 | MAX98357A 板载 D 类功放直接驱动，无需外接 |

## 1) 引脚速查（已约束在 `tdm_top.cst`，勿改动）

| 信号 | 引脚 | 说明 |
|---|---|---|
| clk | 4 | 27 MHz 晶振 |
| rst_n | 87 | 板上按键 S1（低有效） |
| pa_en | 51 | MAX98357A 使能（上拉=默认开） |
| dac_din / ws / bck | 54 / 55 / 56 | I2S → MAX98357A |
| uart_rx / tx | 70 / 69 | BL616 USB 串口（运行时参数通道） |
| led[5:0] | 20/19/18/17/16/15 | 共阳，**低电平点亮** |
| ev_note/vel/valid/on, preset, test_mode | 27–42 | 40P 排针音符事件接口（下拉=悬空为 0） |

## 2) 五步流程

| 步 | 操作 | 预期现象 | 不吻合时的第一怀疑 |
|---|---|---|---|
| **S0 连接** | 插 USB-C（靠 S1/S2 侧），等 10 s | 设备管理器出现 2×converter + 1×COM | 换**数据线**→换口→重装驱动 |
| **S1 官方码流** | 烧官方 audio 例程（SRAM，下载频率 2.5 MHz，**不勾 Verify**） | 板载扬声器出测试音（官方标注 "A bit loud"，**离耳朵远点**） | 不响=硬件/线/例程问题，**不要继续烧自己的码流** |
| **S2 我方码流** | `tools\scripts\flash_sram.cmd`（或 programmer_cli --operation_index 2） | LED 亮；**注意下一条的上电模式确认** | 编译产物先过 R0 黄金参考再上板 |
| **S3 上电模式确认** | ⚠️ `test_mode` 引脚是**上拉**：悬空=测试模式。第一次听演奏需把它接 GND 或（更好）改成下拉重新综合 | 测试模式=32 谱峰音；演奏=定序器/事件驱动 | 上电行为与我方预期不符时，先查这一个引脚 |
| **S4 实测验收** | ① 示波器 CH1=音符事件 GPIO、CH2=I2S DIN，量端到端延迟（对齐 0.104 ms 的仿真值）② 示波器 FFT 数谱峰 ③ I2S 三线波形 | 延迟 ≪10 ms；谱峰数=振荡器数；I2S 时序符合 Philips 格式 | 偏差大→回仿真比对，不上来就改 RTL |

## 3) 失败判读速查

| 现象 | 最可能原因 |
|---|---|
| 完全不枚举 | 充电线 / 没等驱动 / 口插错 |
| 烧录极慢或失败 | 勾了 Verify / 频率非 2.5 MHz |
| 官方例程响、我方不响 | 我方综合产物问题：先看是否过了 R0（`tdm_compare.py` 0/2495），再看 PnR 时序 slack |
| 声音破音/爆音 | 增益链溢出——检查 FX_CTRL/增益寄存器默认值，把湿声/主增益降档 |
| 音高整体不对 | 采样率口径：当前 fs=52734.375 Hz（÷16÷32），音分计算要用这个数 |

## 4) 烧板前必须全绿的三件事（我方纪律）

1. R0 黄金参考：`tdm_compare.py` → 0/2495（含起音段）
2. 全量自检回归（additive/包络/时钟/I2S/多声部/测试模式/寄存器/E2/E3/E7/fx）
3. 最终配置重综合：**SETUP slack 当前仅 +0.591 ns**——上板前确认最终码流是收敛的
