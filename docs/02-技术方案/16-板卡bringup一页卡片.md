# 板卡 Bring-up 一页卡片（Tang Nano 20K · 第二版）

> 用途：板子到手当天，从"拆快递"走到"出声 + 遥测可用 + 输入可用"。
> 原则：**先官方码流**排除"线/驱动/板"整类问题；**只用 SRAM 烧录**（掉电即失、零风险）；
> 每一步先写清"预期看到什么"，不吻合就停下判读，不要连做两步。
> 引脚以 `src/constr/tdm_top.cst` 为准（全部来自官方例程，无一猜测）。

---

## 0) 需要的东西

| 物品 | 备注 |
|---|---|
| Tang Nano 20K + **带数据线的 USB-C 线** | 充电线（只有电源芯）会"灯亮但永不枚举"——已踩过的坑 |
| 电脑 + Gowin 编程器驱动已装 | 设备管理器应出现 **2 个 USB Serial Converter + 1 个 COM 口** |
| **逻辑分析仪**（8 通道）或示波器 | 看 I²S 三线、UART、以及将来的 I²C |
| 小喇叭 8Ω 3W | **先确认板上有没有喇叭/扬声器焊盘**；没有才需要外接 |
| 电极面板 + 触摸控制器 | 第三段才用到 |

## 1) 引脚速查（以 `tdm_top.cst` 为准，勿凭记忆）

| 信号 | 引脚 | 说明 |
|---|---|---|
| clk | 4 | 27 MHz 晶振 |
| rst_n | 87 | 板上按键 S1（低有效） |
| 按键 S2 | 88 | 预留：音域条/设定模式 |
| led[5:0] | 20 / 19 / 18 / 17 / 16 / 15 | 共阳，**低电平点亮** |
| pa_en | 51 | MAX98357A 功放使能（高有效） |
| dac_din / ws / bck | 54 / 55 / 56 | I²S 三线 → 板载 MAX98357A |
| uart_rx / tx | 70 / 69 | BL616 USB 串口（上位机通道） |
| pad[0..15] | 27–42 | 40P 排针：**现行**的 16 路触摸电极（RC 测量） |
| sda / scl | 48 / 77 | **预留**：I²C 触摸控制器（改走此路时电极接控制器，不接 FPGA） |

## 2) 三段流程

### 段一 · 只验硬件（不碰我们的代码）

| 步 | 操作 | 预期现象 | 不吻合时的第一怀疑 |
|---|---|---|---|
| S1 连接 | 插 USB-C（靠 S1/S2 侧），等 10 s | 设备管理器出现 2×converter + 1×COM | 换**数据线** → 换口 → 重装驱动 |
| S2 官方码流 | 烧官方 audio 例程（SRAM，下载频率 2.5 MHz，**不勾 Verify**） | 板载喇叭出测试音（官方标注 "A bit loud"，**离耳朵远点**） | 不响 = 硬件/线/例程问题，**不要继续烧自己的码流** |

### 段二 · 只验数字通路（不需要耳朵）

| 步 | 操作 | 预期现象 | 不吻合时的第一怀疑 |
|---|---|---|---|
| S3 我方码流 | `tools\scripts\flash_sram.cmd`（或 programmer_cli --operation_index 2） | **LED 心跳亮** = 时钟与配置正常 | LED 不亮说明配置/时钟有问题，先别管音频 |
| S4 串口遥测 | `python tools\scripts\dsp_host.py --port COMx --check-map` 与 `... padmon` | 地址表全对齐；逐通道打印 base/raw 与判定 | 串口不通 → 查 COM 号与波特率；地址不符 → 版本不匹配 |
| S5 无音自检 | 测试模式（`test_mode` 见第三节的坑） | 频谱上 512 个独立谱峰（配合逻辑分析仪或上位机 FFT） | 谱峰数不对 → 回仿真比对，不要先改 RTL |

### 段三 · 验输入

| 步 | 操作 | 预期现象 |
|---|---|---|
| S6a 现行路径（RC 电极） | 接好电极与外接 1 MΩ + 22 pF，`dsp_host.py padmon` | 逐通道 raw 随手指变化、松手回落；据此定阈值 |
| S6b 新路径（I²C 触摸控制器） | 接 SDA=48 / SCL=77（外接上拉）；先只用一片 | 能读到该片、地址应答正常、单键触摸可辨 |
| S6c 四片地址 | 依次设置 0x5A–0x5D | 四片互不干扰，逐片可读 |
| S7 音高与八度 | 按《音高与八度规格》P1–P15 逐条验 | 键位映射、档位、**挂音防护**、跨档同时发声、防误触全部通过 |

## 3) 三个容易出事故的点

| 点 | 说明 |
|---|---|
| **SRAM 掉电即失** | 只用 SRAM 烧录意味着**拔电就没了**。演示或录像前必须重新烧一次，别到台上才发现板子是空的 |
| **`test_mode` 是上拉** | 悬空 = 进测试模式（32 谱峰音）。第一次想听**演奏**而不是测试音时，必须把它接 GND，或改成下拉后重新综合 |
| **采样率口径** | fs = **52734.375 Hz**（27 MHz ÷ 512，每样本 512 拍）。音分、混响时长、延迟换算都必须用这个数，不能用 46875 或 48000 |

## 4) 烧板前必须全绿的三件事（我方纪律）

1. **R0 黄金参考**：`tdm_compare.py` → **不符 0 / 2495**（含起音段）
2. **验收总入口**：`powershell -File tools\scripts\accept_all.ps1` 全绿——它包含编译、全量回归（当前 30 项 PASS / 0 FAIL）与**时序判据**（slack ≥ +5 ns，**当前 +16.039 ns**）
3. **最终配置重综合**：确认上板用的码流就是验收通过的那一份，不要拿旧产物去烧

## 5) 失败判读速查

| 现象 | 最可能原因 |
|---|---|
| 完全不枚举 | 充电线 / 没等驱动 / 口插错 |
| 烧录极慢或失败 | 勾了 Verify / 频率非 2.5 MHz |
| 官方例程响、我方不响 | 先看 R0 是否 0/2495，再看 PnR slack 是否 ≥ +5 ns |
| 声音破音/爆音 | 增益链溢出——检查 FX_CTRL 与主增益默认值，先降湿声/主增益 |
| 音高整体不对 | 采样率口径用错（见第三节） |
| LED 心跳不亮 | 时钟或配置问题，与音频无关，先解决这个 |
| 串口读不到 | COM 号、波特率、或烧的是旧码流 |
| I²C 读不到器件 | 上拉缺失 / 地址冲突 / SDA-SCL 接反 |
