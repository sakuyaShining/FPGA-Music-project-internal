> 使得上板当天不需要再做任何设计决策，照着做即可得到可复核的结论。

> 相关背景见 `33-审计复核记录-2026-10-06.md` §一。

## 1. 争议是什么（先把问题说准）

有人报 `i2s_tx` 的**标准 I²S 对齐错位**（左右声道/字对齐偏一位）。

我方**未能复现**：

| 证据 | 结果 |
|---|---|
| `tb_i2s_std.v`（标准接收器） | 源样本**逐位相等**，滞后 2 字，不符 0/99 |
| 既有 `04 i2s` | 不符 0/63 |
| `tb_i2s_top.v`（顶层链路） | 逐样本一致，不符 0/5999 |

**但两条接收模型都出自我手，相位假设同源 ⇒ 不能据此排除。**
审计探针在复位后立即开累加，其首字取自复位期位流 —— 这提示
"错位"可能只在**复位后的第一个字**，也可能是探针本身的问题。

⇒ 需要一份**不依赖我方接收模型假设**的独立证据。板上实测正好是。

### 关键认识：**不需要示波器也能定论**

因为 FPGA 自己就能当测量仪：把 `dac_ws` 与 `dac_din` 在 **BCK 上升沿**采下来，
再经由 UART（本仓已有 `uart_tx` 与 `0x0F` 回读通路）送出。
主机侧对这份"位流快照"做**离线解码** —— 解码规则是 I²S 规范本身，
不是我方的接收器实现 ⇒ 独立。

## 2. 测量方案

### 2.1 要抓什么

在 `i2s_tx` 的 WS 上升沿（= 某一声道起始）之后，按 BCK 上升沿连续采 `dac_din`，
采够 **64 位**（两个声道各 32 位）即可覆盖一个完整帧。

对每一位记录：`位序号`、`din`。

### 2.2 判据（I²S 规范，Philips 标准）

标准 I²S 的时序约定：

```
WS:    ┌───────────────┐               ┌───────────────┐
       │   LEFT (0)    │               │  RIGHT (1)    │
   ────┘               └───────────────┘               └───
BCK:   _┌─┐_┌─┐_┌─┐_ ... （WS 变化后**再过一个 BCK**，MSB 才出现）
DIN:   ──╳─MSB──────────────────LSB──╳──MSB──────────LSB──
         ↑ 延迟 1 个 BCK        ↑填充    ↑ 延迟 1 个 BCK
```

**合格判据（逐条可查）**：

| # | 判据 | 说明 |
|---|---|---|
| P1 | WS 变化后，**第一个 BCK** 上的 DIN 不属于数据（是前一字的 LSB 或填充） | 这是 I²S 与"左对齐"的唯一差别 |
| P2 | **第二个 BCK** 上出现该声道数据的 **MSB** | MSB-first |
| P3 | 每个声道 16 位数据，之后补零到 32 位（或反之，与 `i2s_tx` 的 `sr` 装载一致） | 补位必须为 0 |
| P4 | 左右两声道的数据应与"我们送进去的两条已知样本"相符 | 端到端定论 |

**只要 P1/P2 成立 ⇒ 标准 I²S，错位指控不成立**；
若 MSB 出现在**第一个** BCK ⇒ 那是"左对齐"（I²S 的一种变体，
不是缺陷，但**若 DAC 期望标准 I²S 则必须改**——这正是争议的实质）。

### 2.3 激励（让判据可判）

理想情况是送**两条已知且互补的定值样本**，使左右与 MSB/LSB 一眼可辨：

```
左声道 = 0x5555_55（24 位 0101…0101）
右声道 = 0xAAAA_AA（24 位 1010…1010）
```

任何错位（偏一位、左右互换、MSB/LSB 颠倒）都会破坏这个交替图案，一眼定位。

**但现有 RTL 给不出定值**（见 §2.4 的纠正）。所以实际用两档：

- **首选（零 RTL 改动）**：用现有 `test_mode` 的确定性斜坡，按 §2.4 离线算期望。
  代价是图案不"一眼可辨"，需要靠逐位比对定位 —— 但结论一样可靠。
- **次选（愿意加一点 RTL）**：加一个"常量样本"测试档（左右各一个定值），
  读数最快、最直观。若打算长期做板级调试，这个投入是值得的。

### 2.4 执行步骤

★ **先纠正一个我一开始想当然的做法**：我曾写"用 `test_mode` 输出任意定值样本"。
**这是错的** —— 查 `tdm_top.v:952-958` 后确认，`test_mode` 装载的是
**固定的 512 时隙频率斜坡**（`tm_load_inc = 24'd71583 + tm_cnt*24'd8800`），
**不能输出任意定值**。要输出定值就得改 RTL 加一个新测试档 —— 那是"为测量而改产品"，
不划算且有风险。

**改用"已知激励 + 离线算期望"的办法，不需要改任何 RTL**：

1. **取已知激励**：直接用现有的 `test_mode`（512 时隙频率斜坡）。
   它虽然不能给定值，但它是**确定性**的 —— 同样的复位与同样的输入，
   仿真里的 `sample_out` 序列就是板上应该出现的序列。
2. **离线算出期望位流**：在**仿真**里跑同样的 `test_mode`，
   把 `tdm_top.sample` 每个样本的 24 位打印出来（`tb_i2s_top.v` 已经在做类似的事，
   它把 `sample_out[23:8]` 落到 `i2s_top_ref.txt`）。
   再把这份样本序列按 `i2s_tx` 的装载规则**离线展开成位流** ——
   这一步用的是 I²S 规范，不是我方接收器 ⇒ 独立。
3. **板上抓位流**：按 §2.1 在 WS 上升沿后采 64 位（或用 §2.5 的示波器读法）。
4. **比对**：把板上抓到的位流与第 2 步的期望位流按 §2.2 的 P1–P4 判定。

   这样"期望"来自**仿真中的同一份 RTL + I²S 规范**，
   "实测"来自**板上的真实引脚** ⇒ 两者独立，能真正定论。

   （若想更省事：抓 **一个帧** 就够。因为只要 P1/P2 成立，
   整条链路就是标准 I²S；不需要抓长序列。）

### 2.4b 把位流送回主机

复用 **`0x0F` 回读通路**（`tdm_top.v:380`：写 `0x0F` 触发"回读两字节"状态机，
先回地址再回该寄存器的值）。该通路已由 `09 regctl` 判据过测，**通路本身可信**。

要送 64 位需要 8 次 `0x0F` 回读 —— 可以先把抓到的 64 位存进 8 个寄存器槽
（例如 `0x30..0x37`），再逐个回读。**但这需要写一小段 RTL**（抓取 + 存槽）。

⇒ 若手边**有示波器，§2.5 更省事、且不需要改 RTL**；若没有，再考虑加这段采集逻辑。
两条路都能得到可复核结论，**选哪条取决于手边设备**。

### 2.5 若坚持用示波器（更直接但需要设备）

探头：`dac_ws`（CH1，触发源）、`dac_din`（CH2），时基取 BCK 的 3–4 个周期。
读法：**看 WS 跳变沿之后，DIN 上第一个 BCK 里的值是什么** ——
若第一个 BCK 里就是 MSB，则是左对齐；若是"无关位"、第二个 BCK 才是 MSB，则是标准 I²S。

## 3. 结论怎么记录（可复核性要求）

无论结果如何，都要留下**绑定源码 SHA** 的记录：

- 固件 commit SHA（`git rev-parse HEAD`）
- 抓到的 64 位原始位流（存成文本文件，不要只写结论）
- 按 §2.2 逐条给出的 P1–P4 判定
- 结论：**"标准 I²S 对齐正确"** 或 **"实为左对齐，需改 `i2s_tx` 或换 DAC 配置"**

**不允许**只写"实测没问题"——那与当前的"两个模型都不复现"没有区别，
仍然是不可复核的断言。

## 4. 若结论是"实为左对齐"（改法预案）

`i2s_tx` 的改法很小，且**不需要动 TDM 内核**（符合"保留内核不重写"原则）：

标准 I²S 要求 WS 变化后**延迟一个 BCK** 再出 MSB。当前实现若在 WS 变化同一拍
就出 MSB，则只需把 WS 的产生**提前一个 BCK**（或用 `sr` 的最高位做填充位），
使数据相对 WS 后移一位。

★ 注意：**不要重复我之前那次失败的尝试** —— 我曾把 `i2s_tx` 的输出整体延后
一个 BCK，结果解码值变成一半（见 `35-五阶段推进状态.md` 的相关记录）。
正确的做法是只调整 **WS 与数据的相对相位**，不是把数据整体延后。
改动后必须同时回归：
- `04 i2s`（既有判据）
- `15 i2s std`（标准接收器）
- `16 i2s top`（顶层链路）

三条都绿才算改对。
