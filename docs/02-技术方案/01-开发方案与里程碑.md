## 一、赛题要求 → 设计指标映射

| 赛题原文要求 | 量化门槛 | 我方设计目标 |
|---|---|---|
| 自研演奏交互，≥2 个独立可控维度 | ≥2 维 | 目标 3 维（音高 / 力度 / 表情），先按键+编码器 bring-up，后上电容触摸/光电 |
| 完整音频通路全部基于 FPGA HDL，逐样本实时运算 | 无软件串行 | 全 RTL 流水线，无软核、无 MCU 参与发声 |
| 经 I2S 输出至 DAC 解码发声 | I2S→DAC | I2S 主模式发送器 → 板载 I2S DAC |
| 控制信号到音频输出总延迟 | **≤10ms**（拓展 ≤5ms 且无抖动） | 目标 ≤5ms 确定性延迟；固定流水线级数，无仲裁/无缓存抖动 |
| 基础复音数 | **≥4** | 先 8 复音打通，再冲 **32 复音** |
| 单音实时变调、ADSR 包络、多声部实时混音 | 必须支持 | 全部硬件实现 |
| ≥2 种音色自由切换 | 拓展 | 波表多音色（≥4 种）实时切换 |
| ≥3 维表情调控（力度/滑音/颤音） | 拓展 | 力度 + 滑音 + 颤音/LFO |
| 硬件内实现混响、延迟、合唱 | 拓展 | BRAM 延迟线 + 梳状/全通混响网络 |
| 可视化（LED 指引、李萨如、实时频谱、波形） | 拓展 | 先用板载 LED/WS2812，后续评估 HDMI 频谱/李萨如 |
| **严禁播放预录 PCM / 预置推流 / 整段录音触发** | **红线** | 全部样本由振荡器实时生成；代码中不出现任何 PCM 播放通路 |
| 现场验证：多路不同频率音频 → 频谱出现对应数量独立谱峰 + RTL 佐证 | 必须 | 内置**测试模式**：可配置 N 个振荡器输出互质频率，频谱可数峰 |

**核心评分依据（原文）**：
> 系统吞吐量指标 = 「同时活跃可闻独立振荡器总数 × 实际音频输出采样率」，过采样不叠加加分。

> 独立发声单元 = 包含独立相位累加器、频率调控、包络控制的完整振荡器；单波表采样查表不计多谐波数量，仅计单个振荡器；加法合成按运算分量统计、FM 按调制运算器统计、物理建模按并行弦/模态单元统计。

→ 结论：**"数振荡器"就是得分**。每个 voice 必须是完整振荡器（相位累加器 + 频率控制 + 包络），而不是共享相位的取巧结构。要能亮出 32 个以上真实独立的振荡器，并让频谱上真的出现对应数量的谱峰。

## 三、系统架构

```
                      ┌──────────────────────────────────────────────┐
   演奏交互（≥2 维）   │                 FPGA 纯硬件                   │
 ┌───────────────┐    │                                              │
 │ 电容触摸 / 光电 │───▶│ ① 事件解析层                                  │
 │ 压力 / 手势     │    │   · 按键消抖 / 触摸扫描 / 传感器采样            │
 │ 按键 / 编码器   │    │   · 选音、和弦、触发、拨弦 识别                 │
 └───────────────┘    │   · 力度映射 → 包络参数                        │
                      │   · 音符分配器 (note allocator / voice steal)  │
                      ├──────────────────────────────────────────────┤
                      │ ② 合成引擎层（得分核心）                       │
                      │   Voice[0..N-1]：                              │
                      │     相位累加器 → 波表/加法/FM 运算 → ADSR 包络  │
                      │     + 实时变调（相位增量重算）                  │
                      │   多音色波表 ROM（≥4 音色，实时切换）           │
                      │   混音器：Σ voices → 饱和/限幅                 │
                      ├──────────────────────────────────────────────┤
                      │ ③ 效果层（BRAM 延迟线）                        │
                      │   合唱（调制延迟）→ 延迟 → 混响（梳状+全通）     │
                      ├──────────────────────────────────────────────┤
                      │ ④ 输出层                                       │
                      │   I2S 主模式发送器 → DAC → 功放/耳机            │
                      ├──────────────────────────────────────────────┤
                      │ ⑤ 可视化 / 控制层                              │
                      │   LED 演奏指引、WS2812、李萨如/频谱/波形        │
                      │   测试模式（N 路互质频率 → 频谱数峰）           │
                      │   参数配置（按键 / UART）                      │
                      └──────────────────────────────────────────────┘
```

**延迟预算（目标 ≤5ms，硬上限 ≤10ms）**

| 环节 | 预算 |
|---|---|
| 交互采样与消抖 | ≤1 ms（扫描周期 ≤1ms，避免传统 20ms 消抖——改用快速扫描 + 状态机） |
| 事件解析 + 音符分配 | ≤1 ms（固定周期，单周期决策，无迭代仲裁） |
| 振荡器 + 包络 | 流水线级数固定，一般 < 10 个采样周期（≈0.2ms @48kHz） |
| 混音 + 效果 | 效果器若串在干路上会引入延迟 → **混响/延迟按"湿声"路径并联，干声直通**，保证干声延迟不随效果增加 |
| I2S 输出 FIFO + DAC | ≤1 ms（FIFO 深度固定且浅） |

> 关键设计原则：**干声路径尽量短且固定**；所有效果器挂在并联湿声支路。这样才能同时宣称"低延迟"和"有混响"。

**资源估算（Tang Mega 60K，59904 LUT4 / 2124 Kb BSRAM / 118 DSP）**

| 模块 | 估算 | 说明 |
|---|---|---|
| 1 个波表振荡器 voice | ~150–300 LUT + 1 乘法器/若干 | 相位累加器 32bit、相位→波表地址、包络乘 |
| 32 voices | ~6–10K LUT + 32–64 DSP | 纯波表法；若用加法合成 32 分量则显著更重 |
| 混音树 | ~1–2K LUT | 32 路流水线加法 + 限幅 |
| 延迟/合唱/混响 | 几十–200 Kb BSRAM + ~2–4K LUT | 延迟线用 BSRAM；44.1/48kHz × 16bit × 数十 ms |
| I2S + 控制 + 可视化 | ~2–5K LUT | 含频谱/李萨如则更多 |

结论：**Mega 60K 余量充足**；Nano 20K 需精简（例如 32 复音但效果器设限、可视化降级）。
