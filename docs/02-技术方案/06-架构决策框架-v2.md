# 第一部分　为什么要审计（v1 的问题）

## 1.1 v1 犯的错：只优化了"一层"，漏掉另外两层

`02-什么才叫好作品` 那份分析指出，这个竞赛的得分是**三层结构**：

```
第1层 组委会：资格审查 → 初赛线上评审（报告+视频）→ 决赛现场
第2层 厂商赛题：高云选题二的评分规则（振荡器数 × 采样率）
第3层 现场：FPGA基础编程考核 + 作品演示 + 专家提问
```

**v1 决策框架的措辞统计**：

| 关键词 | v1 中出现次数 |
|---|---|
| 振荡器 | **18** |
| 指标 | 13 |
| 赛题 | 10 |
| 演示 | 2 |
| 答辩 | 2 |
| 评委 | 1 |
| **完整性** | **0** |
| **创新** | **0** |
| **场景** | **0** |
| **量化** | **0** |
| **可复现** | **0** |

→ **v1 几乎只盯着第 2 层，把第 1 层和第 3 层整个漏掉了。**

后果会很实际：
- 按 v1 选出的架构，可能"指标很高但演示讲不清"→ 决赛现场失分
- 可能"技术上很强但报告写不出故事"→ 初赛就被刷
- 可能"做成一个孤立的引擎，不像一件产品"→ 违反"完整度"判据

## 1.2 审计还发现：v1 缺少一类关键选项

v1 的 D2 只给了"全并行 / TDM / 混合"三种**实现方式**，但没有讨论**产品定位**。
而 `02-什么才叫好作品` 显示：**26% 的一等奖作品名称含具体应用场景词**，且"应用场景清晰"是六大判据之一。

→ **产品定位本身就是一项架构级决策**，它反向决定技术选型。v1 完全没提。

## 1.3 结论：框架需要一次结构性升级

| | v1 | v2 |
|---|---|---|
| 评价维度 | 只算"赛题指标" | **三层评审全覆盖** |
| 决策项数 | 5 项（纯技术） | **8 项**（新增定位层 + 演示层） |
| 优先级 | 未排序 | **按决策依赖排序，并标出阻塞关系** |
| 年度背景 | 无 | 纳入"今年全新题目、无先例可抄"的约束 |

# 第二部分　v2 决策框架总览

## 2.1 新增的评价维度：每个决策都要过三道闸

从本版起，**每个决策项都必须回答三个问题**，而不是只看指标：

| 闸 | 来自哪一层 | 要回答的问题 | 权重参考 |
|---|---|---|---|
| **闸 1：合规与指标** | 第 2 层 | 满足赛题硬指标吗？振荡器数×采样率能到多少？踩红线吗？ | 高 |
| **闸 2：完整与演示** | 第 3 层 | 做得出实物吗？现场演示稳定吗？能讲清 FPGA 为何不可替代吗？ | **高** |
| **闸 3：报告与可复现** | 第 1 层 | 能写出故事吗？有量化数据吗？别人能复现吗？ | 中高 |

> 依据：高云给另一道题的权重是「FPGA 实际作用 40% + 系统稳定性 25% + 创新 10%」。
> **"能演示、够稳定"的权重高于"指标漂亮"。** 这与 v1 的隐含假设相反。

**阻塞关系**（重要）：
- **D0 不定，D1~D8 都是空转** —— 因为"做什么产品"决定后面一切
- **D2 不定，D3/D5 只能纸上谈兵** —— 架构决定资源预算
- **D7 不是"最后再测"** —— 测量方案要一开始就设计（比如怎么测延迟、怎么测 THD），否则拿不出数据

## 2.3 年度背景（影响所有决策）

来自 `03-今年课题与往年对比`：

| 事实 | 对决策的影响 |
|---|---|
| 今年题目**全新**，历届无"电子乐器"先例 | 不能抄做法；**D0 必须自己定义清楚**，靠演示说服评委 |
| 2025 年音频类获奖**减少一半**（24 件 vs 48 件） | 形势不算热；**更要靠完整度和演示取胜**，不能指望"沾音频就有分" |
| 但**高云+音频历史上出过一等奖** | 方向可行，有历史背书 |
| 主题风向转向 **AI / 具身智能** | 若作品能沾一点"智能"（如智能音色/自适应），可能有额外好感；但**不能为了蹭而牺牲核心** |
| 题目对所有人都是新的 | **"祖传项目"优势被清零** → 比赛回到"谁把新题做扎实" |

## D0 · 产品定位与场景故事 ★ 最先定

### 背景

`02-什么才叫好作品` 的结论：**好作品 = 完整、可演示、有真实应用场景、FPGA 不可替代的系统级作品。**
而历届 26% 的一等奖作品名称里带具体应用场景词。

**我们的赛题叫"电子乐器引擎"——这个词对评委来说是抽象的。** 我们必须把它变成一个具体的、能一句话说清的产品。

### 选项：产品的场景定位

| | **A. 音乐教育乐器** | **B. 无障碍演奏乐器** | **C. 舞台/演出合成器** | **D. 声学实验/科研平台** |
|---|---|---|---|---|
| 一句话 | 给音乐初学者/课堂用的低成本电子乐器 | 给手部活动受限者用的非接触演奏设备 | 给现场演出用的高表现力硬件合成器 | 给声学/电子教学用的可配置信号源 |
| 故事强度 | 强（教育是政策热点） | **很强**（社会价值打动人） | 中（偏专业小众） | 弱（像实验装置） |
| 与赛题契合 | 高（多音色/和弦/教学曲目指引） | **高**（赛题明确点名"无接触手势"） | 高（低延迟、效果器、表情） | 中 |
| 交互形态指向 | 键盘式为主 | **手势/光电为主** | 键盘+滑条+旋钮 | 任意 |
| 演示难度 | **低**（弹曲子，直观） | 中（手势识别要稳定） | 中（要好听才有说服力） | 高（抽象，不易看懂） |
| 风险 | 故事略平 | **手势现场稳定性风险高** | 需要真的演奏得好 | 难演示 |
| 扩展项兑现 | 好（脱机曲目指引、LED 指法） | 好（手势=第3维表情） | 好（效果器、表情调控） | 中 |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 合规与指标 | 四种都能满足；场景本身不直接影响振荡器数。**但要警惕：场景越复杂，越挤占引擎开发时间** |
| 闸2 完整与演示 | **A 最稳**（弹琴演示人人看得懂）；B 最动人但现场手势识别有翻车风险；D 最难演示 |
| 闸3 报告与可复现 | A/B 都容易写出"为什么做这个"；D 需要更多理论铺垫 |

### 我的观察（非结论）

- **A（音乐教育）与 B（无障碍）可以叠加**：做成"面向音乐教育、同时支持非接触演奏"的乐器 —— 既保住演示稳定性（键盘为主），又拿到赛题点名的"无接触手势"亮点与社会价值故事。
- **D 不建议**：难以在几分钟演示里让评委"看懂"，违反闸 2。
- **C 的风险在于"要好听"**：如果演奏水平不够，现场效果反而扣分。A/B 对演奏技巧要求低。

### 需要你回答

1. 选哪种定位（可选 A/B 组合）？
2. 有没有你个人有兴趣、能持续做 47 天的方向？（**这条很重要**——兴趣决定你能不能坚持到 11 月）

## D1 · 乐器形态与交互方案

### 背景

赛题硬要求：**≥2 个独立可控演奏维度**（选音/触发/拨弦/力度感应）。
拓展要求：**≥3 维表情调控**（力度动态、滑音、颤音）。

### 选项

| | **A. 键盘式** | **B. 触摸滑条式** | **C. 无接触手势式** | **D. 吹奏/气压式** |
|---|---|---|---|---|
| 维度来源 | 键位(音高) + 力度 | 音高(连续) + 压力 + 滑音 | 位置 + 距离/速度 | 音高 + 气息 + 咬合 |
| 可达维数 | 2~3 | **3** | 2~3 | **3** |
| 器件成本 | 极低 | 低 | 中 | 中 |
| 硬件难度 | ★☆☆ | ★★☆ | ★★★ | ★★★ |
| **现场稳定性** | **★★★★★** | ★★★★ | ★★（灯光/反光干扰） | ★★★ |
| 和弦演示 | **最强** | 弱 | 弱 | 弱 |
| 与 D0-A 契合 | **最好** | 中 | 差 | 差 |
| 与 D0-B 契合 | 差 | 好 | **最好** | 中 |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 | 都满足 ≥2 维；B/C/D 更易达到 ≥3 维 |
| 闸2 | **A 演示最稳**；C 最炫但**现场翻车风险最高** |
| 闸3 | A 容易拍照记录；C 需要额外说明识别原理 |

### 我的观察（非结论）

- **推荐组合：A 为主 + C 为辅**（键盘保底 + 一路手势当第 3 维/亮点）
  - 键盘保证"能弹、能演示、能展示复音"
  - 手势满足赛题点名的"无接触"、贡献第 3 个维度、撑起故事
  - **即使手势现场失效，键盘仍能完成演示** —— 这叫"演示冗余"，是决赛策略
- 注意：Nano 20K **无 ADC**，模拟力度需用 **RC 充放电时间测量法**（纯数字，零额外器件），这本身也是个技术亮点。

### 需要你回答

1. 主交互形态选哪个？
2. 是否接受"A 保底 + C 亮点"的冗余设计？

## D2 · 引擎并行架构 ★ 技术地基

（选项内容同 v1，新增三道闸评估）

### 选项回顾

| | **A. 全并行** | **B. TDM 分时复用** | **C. 混合** |
|---|---|---|---|
| 振荡器上限(Nano 20K) | ~32 | **200+** | 64~128 |
| 乘法器 | N | 1–4 | 组数 |
| 延迟 | 最低(1 采样周期) | 低(N 时隙) | 中 |
| 控制复杂度 | **低** | 高 | 中高 |

### 三道闸（这是 v1 缺失的部分）

| 闸 | 全并行 A | TDM B | 混合 C |
|---|---|---|---|
| **闸1 指标** | 受 48 乘法器限制，~32 | **最高，200+** | 高 |
| **闸2 演示与答辩** | **最好讲**：每个声部一块独立硬件，评委一看就懂 | **要论证**"共享硬件算不算独立振荡器"；调试要抓时隙，现场排障难 | 中 |
| **闸3 报告** | 好写 | 需要专门一节论证合规性 | 中 |

### 关键权衡（v1 没讲透的）

**TDM 的指标优势是"账面"的，但要付出两个代价：**
1. **答辩成本**：赛题原文定义"独立发声单元为包含独立相位累加器、频率调控、包络控制的完整振荡器"。TDM 下每个逻辑声部**状态上确实独立**，但**运算硬件共享**。评委追问时你需要能守住这个论证。
2. **调试成本**：出问题时你看到的是"时隙里的数据流"，比全并行的"一眼一条线"抽象得多。**这对零基础是个实际负担。**

**而全并行的 32 只是"舒服的上限"，不是死限** —— 可以通过 D3 的算法配比（加法/物模）在 32 个声部内把振荡器计数推高。

### 我的观察（非结论）

- 结合"零基础 + 47 天 + 决赛要现场排障"，**全并行在闸2 优势明显**。
- 但**指标是第 2 层的核心**，完全放弃高指标也可惜。
- → **建议路径：先全并行（保闸2），把声部数做成参数；到 P4 阶段若资源与时间允许，再考虑局部 TDM 化冲指标。**
- **重要补充**：可以做一个"**双模式对照**"——平时跑全并行，测试模式下启用更多振荡器。这样既保演示，又保指标。

### 需要你回答

选 A / B / C，还是采纳"先全并行、P4 再评估"的推迟策略？

## D3 · 合成算法配比

（选项内容同 v1，新增三道闸）

### 计数规则回顾（决定指标效率）

> 单波表采样查表**只计 1 个**振荡器；**加法合成按运算分量统计**；**FM 按调制运算器统计**；**物理建模按并行弦/模态单元统计**。

### 四种算法

| 算法 | 一个"声部"产出几个振荡器 | 资源成本 | 指标效率 | 音色 |
|---|---|---|---|---|
| 波表采样 | 1 | 中 | 中 | 万能 |
| 加法合成 | **=分量数** | 高 | **高** | 风琴/钟琴/拨弦 |
| FM 调频 | **=调制器数** | 中 | 中高 | 电钢/贝斯/金属 |
| **物理建模** | **=并行弦数** | **低**（一条延迟线） | **最高** | 拨弦，极自然 |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 指标 | 加法/物模效率最高；**物模性价比之王** |
| 闸2 演示 | **物模拨弦最好听、最讨喜**（拨一下就有吉他声）；加法风琴适合展示"多分量"；FM 有复古感 |
| 闸3 报告 | 多算法混合是个亮点，但**报告要解释清每种算法怎么计数**（容易写乱，也容易被追问） |

### 我的观察（非结论）

- 若采纳 D0-A（音乐教育）：**波表为主**（音色覆盖广）+ **物模拨弦**（演示讨喜）+ **加法风琴**（拉高指标）。
- **注意复杂度预算**：三种算法都做，调试量很大。**对零基础 47 天，建议先做波表，物模和加法作为 P4 的加分项**。
- 一个务实的顺序：波表(必须) → 物模(便宜且好听) → 加法(贵但指标高) → FM(可选)。

### 需要你回答

1. 音色风格偏好？（管风琴感 / 电子琴 / 拨弦民乐 / 合成器 / 都要）
2. 是否接受"分阶段增加算法"（先波表，后期再加）？

## D4 · 采样率与音频时钟

（内容同 v1，新增闸2/闸3 视角）

| | **A. 46.875 kHz** | **B. 48 kHz** | **C. 更高** |
|---|---|---|---|
| 时钟 | 27MHz 整数分频，零附加复杂度 | 需 MS5351 | 需 MS5351 |
| 音质 | 优于 CD | 标准 | 更好（收益有限） |
| 时序余量 | **最好** | 好 | 差 |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 | **对指标中性**（采样率×2 → 声部上限÷2，乘积持平） |
| 闸2 | A 时序余量最大，**调试最容易**；B/C 要额外调 MS5351，**是纯增加的风险** |
| 闸3 | A 的 46.875k 在报告里要解释一句"为什么不是 48k"（其实是个体现严谨性的机会） |

### 我的观察（非结论）

**A（46.875 kHz）**。理由：零复杂度 + 时序余量最大 + 音质已达标 + 指标中性。把省下的精力投入 D2/D3 更划算。

## D5 · 精度规格（相位位宽 / 波表深度 / 插值）

（内容同 v1，新增闸2 视角）

| 项 | 选项 | 建议 |
|---|---|---|
| 相位位宽 | 20 / 24 / **32** | 32（TDM 下几乎免费；全并行下 32 声部约占 6.6% FF） |
| 波表深度 | 256 / 512 / **1024** / 2048 | 1024（4 音色仅占 BSRAM 8%） |
| 线性插值 | 要 / 不要 | **要**（256 表+插值 ≈ 1024 表无插值的质量） |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 | 位宽影响音准；表深影响 THD —— **都是可以在报告里量化的指标** |
| 闸2 | 太浅的表会有明显阶梯噪声，**现场一听就露馅**；插值能救 |
| 闸3 | **THD/SNR 是可写进报告的量化数据**，规格越高越好写 |

## D6 · 效果器与可视化

### 背景

赛题拓展要求：硬件内实现**混响、延迟、合唱**（≥2种音色切换、≥3维表情也在此项附近）。
扩展要求还包含可视化：**LED 演奏指引、李萨如图形、实时频谱、波形显示**。

### 三道闸（这项在 v1 里被低估了）

| 闸 | 评估 |
|---|---|
| 闸1 | 效果器是**加分项**，不满足也能及格 |
| 闸2 | **可视化对演示的价值极高** —— 频谱/波形让"纯硬件实时合成"**肉眼可见**，直接服务赛题红线自证！ |
| 闸3 | 效果器参数（混响时间等）是很好的量化指标 |

### 关键洞察

**可视化不只是"好看"，它是合规自证的武器。**
赛题要求现场"用频谱独立谱峰 + RTL 代码佐证无预录播放"。**如果你把实时频谱做成板载/HDMI 显示，等于自带证据。**

→ **建议：可视化优先于效果器**。先做频谱/波形显示（服务闸2 和红线自证），再做混响/延迟。

### 风险

- 效果器若串在**干声路径**上会拉高延迟 → **必须并联湿声支路**（这条已写入约束文档 D2）
- HDMI 输出会消耗较多资源和开发时间 → **先用板载 LED/WS2812，HDMI 作为后期选项**

## D7 · 测量与自证方案 ★ 决定能否"拿出量化指标"

### 背景

`02-什么才叫好作品` 的两条判据：
- **可现场演示 + 有量化指标**
- **能自证无预录**（赛题红线）

**v1 完全没提这项**，但它是"专业性"和"合规性"的直接来源。

> ✅ **已确认：有示波器（学校实验室）** —— 延迟实测、抖动分位数、THD 测量全部可行。
> 这把 D7 从"需要妥协"变成"可以做到专业级"。

### 需要设计的测量项

| 指标 | 怎么测 | 难度 | 可行性 |
|---|---|---|---|
| **端到端延迟** | 示波器双通道：触发信号（演奏按键/GPIO 脉冲）vs 音频输出模拟波形 | 中 | ✅ **可行** |
| **抖动分位数** | 多次测量取 P50/P95/P99 | 中 | ✅ **可行**（示波器统计功能） |
| **复音数/振荡器数** | 测试模式输出 N 路互质频率 → 频谱数峰（示波器 FFT） | **低** | ✅ **自证刚需** |
| **THD / SNR** | 示波器 FFT 功能，或声卡回采 + 软件分析 | 中 | ✅ **可行** |
| **资源占用** | Gowin EDA 综合报告（LUT/FF/BSRAM/DSP） | **低** | ✅ 自动生成 |
| **吞吐量指标** | 振荡器数 × 采样率（由上面两项计算） | **低** | ✅ 计算得出 |
| 功耗（可选） | 实验室若有电源分析仪 | 中 | ❓ 待确认 |

### 三道闸

| 闸 | 评估 |
|---|---|
| 闸1 | 吞吐量指标直接来自此 |
| 闸2 | **测试模式是赛题强制的现场验证手段** |
| 闸3 | 这张表就是报告里的"主要性能指标"章节 |

### 延迟测量方案（具体做法）

```
        演奏动作（按键/触摸）
              │
              ├──→ GPIO 输出一个脉冲 ──────────→ 示波器 CH1
              │                                    │
              └──→ 合成引擎 → I2S → DAC ──→ 音频输出 ──→ 示波器 CH2
                                                   
        测量 CH1 上升沿 到 CH2 波形起始 的时间差 = 端到端延迟
```

**注意点**：
- 这是"演奏动作 → 音频输出"的**全链路延迟**，正是赛题要求的定义
- 建议在 **100 次以上**测量，报告 P50 / P95 / P99 / 最大值（**不要只报平均值** —— 高分作品的共性是有分位数数据）
- 若采纳 TDM 架构，此测量还能验证"时隙是否引入额外抖动"

### 需要你确认

1. 实验室的示波器**带宽和通道数**大概是多少？（≥100MHz、2 通道就够用）
2. 有没有**音频分析仪 / 频谱仪**，或者能借到？（有的话 THD 测量更权威）
3. 是否同意把"**测试模式**"作为早期必做项（而不是最后补）？

> **建议：测试模式在 P1 阶段就搭好骨架**（哪怕只有 2 个振荡器），后面每加一种算法就往里塞。
> 理由：赛题现场验证靠它；而且它同时是"多路互质频率"的演示工具，一举两得。

## D8 · 板卡档位（横切项）

（内容同 v1，补闸2/闸3）

| | **A. 只用 Nano 20K** | **B. 换 Mega 60K** | **C. 双目标** |
|---|---|---|---|
| 资源 | 20736 LUT / 48 乘法器 | 59904 LUT / 118 乘法器 | 一套代码两目标 |

| 闸2 风险 | **零**（已验证过的通路） | 需先确认 codec 与引脚 | 低 |

### 我的观察（非结论）

- **闸2 角度：Nano 20K 明显更稳** —— 板载 MAX98357A 是标准 I2S DAC，官方例程已验证通路；Mega 60K 的音频 DAC 型号还没从原理图确认，是个未知数。
- **闸1 角度：Mega 60K 上限更高**（若走全并行，118 乘法器很值）。
- → 若采纳 D2 的"先全并行"策略、且预算允许，**Mega 60K 值得考虑**；否则 Nano 20K 零风险起步。
