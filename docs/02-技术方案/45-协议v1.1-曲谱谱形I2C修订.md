# 协议 v1.1：曲谱、谱形与 I²C 修订

日期：2026-10-07

这份修订把上位机命令和 RTL 的行为写成同一条可测试的协议路径。它描述的是当前实验分支的目标契约；合入 DSH 后仍需用同一组仿真和板级读回重新验收。

## 曲谱下载

曲谱写入采用“停止、清空写指针、写入、提交长度、播放”的顺序：

1. `SEQ_CTRL=0`，停止旧曲谱并释放当前定序器音符。
2. `SCORE_LEN=0`，将曲谱写指针归零。
3. 交替写 `SCORE_NOTE` 与 `SCORE_BEAT`；写拍数后索引自动加一。
4. 写入最终 `SCORE_LEN=N`，其中 `1 ≤ N ≤ 63`。
5. `SEQ_CTRL=1` 开始播放。曲谱长度大于零时自动使用下载曲谱。

`SCORE_IDX=0x72` 不再承担下载起始索引，避免“先写长度、再写起始索引”造成上位机和 RTL 对指针状态的分歧。

停止动作必须产生一次当前音符的 note-off，再清空定序器状态；重复停止不得产生重复 note-off。

## 谱形提交

谱形更新分为草稿阶段和提交阶段，避免演奏中逐字节写入造成半幅谱形短暂生效：

1. `SPEC_MODE=0x80` 开始一次草稿事务，同时关闭自动刷新。
2. 依次写 `SPEC_IDX=0..15` 和对应的 `SPEC_VAL`。
3. 最后写 `SPEC_MODE=0x01`（替换）或 `0x00`（叠加）提交整幅谱形。
4. 提交等待当前音符刷新端口空闲后一次性发布；随后上位机可写 `SPEC_REFRESH=0xFF` 触发全声部刷新。

旧式单字节 `SPEC_VAL` 写入仍可用于低级调试，但完整配置和 GUI 使用上述事务路径。自动刷新只在提交完成、且 `SPEC_MODE` 的自动刷新位有效时运行。

## 协议版本门禁

`PROTO_VER (0x7F)` 的默认值由 `0x10` 提升为 `0x11`。发送完整曲谱或谱形配置前，上位机先读取该寄存器；设备未确认 `0x11` 时停止发送并记录原因。这样不会把 v1.1 的事务命令误发给旧码流。

## I²C 主机契约

当前分支的 I²C 主机仿真契约包括：7-bit 地址、写后重复 START 读、1–4 字节读写、低字节在低位的返回顺序、最后一字节 NACK、时钟拉伸采样、缺失从机 NACK、非法长度拒绝、SCL/SDA 卡死超时和复位释放。

`tb_i2c_master` 与 `tb_i2c_contract` 均通过；这只证明主机模块和模型的接口契约，不代表它已经接入 `tdm_top` 或完成 Tang Nano 板级验证。DSH 合入后需要确认实例化、引脚约束、时钟频率和真实外设读回。

## 当前验收边界

在 DSH 完成前，可以验收协议帧、寄存器顺序、事务状态机和离线 I²C 契约；不能把当前分支称为最终板级 bitstream。板级实验码流应在 DSH 变更合并后重新编译，并重复本文件列出的读写和曲谱/谱形回归。
