### 接线未完成的真实原因（下一轮从这里开始，别重走）

**问题 1（已定位、已修过一次）**：`out_ready` **不能用 `~nm_busy` 这种电平**。

`note_map` 的"忙"是**状态输出**：事件被接收后 `busy` 要**下一拍**才拉高；
在那之前 `~busy` 仍为 1，队列会在那几个连续空闲拍里**连续出队**，
而 `note_map` 在忙期间只接收第一个 ⇒ 后面几个静默消失。
修法：给 `note_map` 加单拍"接收确认" `ev_ack = (st == ST_IDLE) && ev_valid`，
队列用它做 ready。

**问题 2（已定位、已修过一次）**：队列与 `note_map` 之间**不能再插一级寄存器**。

`event_hold` 的输出已经是寄存过的。原来那级 `ev_valid_r` 会把 `ev_valid`
拉成**连续两拍为高**的电平，`note_map` 遂把同一个事件消费两次。
修法：`wire ev_valid_r = ev_q_valid;` 直接连（那一级本来就是为切断
"寄存器堆→mux→note_map"长链而加的，现在长链已由队列断开）。

**问题 3（未解决 —— 这是下一轮的起点）**：修完 1、2 之后实测仍只到 **10/28**，
但**症状换了形状**，这是最有价值的线索：

```
发出 28 条，note_map 侧收到 10 条
 第 1 条 期望(note=61,on=0,vel=2) 实测(note= 0,on=0,vel=2)   ← note=0，而 vel 正确
 第 2 条 期望(note=62,on=1,vel=3) 实测(note= 0,on=0,vel=3)
 第 3 条 期望(note=63,on=0,vel=4) 实测(note= 0,on=0,vel=4)
 M3 note-off：期望 14 条，实测 9 条
 M4 队列溢出计数 = 26（应为 0）
```

**关键观察：同一条事件里 `vel` 正确（2/3/4…）而 `note` 恒为 0。**
三个字段的正确性不一致 ⇒ 这**不是**"整条事件丢失或错位"，
而是**某个字段的通路本身有问题**（`note` 与 `vel` 走的是同一组锁存、
同一个队列条目，却一个对一个错）。方向应查 `mh_note` 这条优先级链，
而不是继续怀疑队列或握手。

**下一轮省时间的第一步**：不要再跑完整 28 条激励。改成**只开排针一个源、只发 3 条**，
并在 `dh_pend` 被置位的那一拍打印
`mh_valid / mh_note / mh_on / ev_in_ready / dh_pend`。
先把"单源的三个字段是否同时正确"钉死，再引入 UART 源。

> 教训一：**电平不能当握手**。凡"消费者说自己不忙"的信号，先问
> "这个不忙状态会持续几拍？"——多于 1 拍就不能直接当 ready。
>
> 教训二：**修好一个 bug 后症状换了形状，说明那个是真的修掉了。**
> 不要因为"还是红的"就以为白改 —— 要看红的方式有没有变。
