## 1. 本轮用户明确的实体目标

- 音高区：压力感应条用于八度切换；用户随后明确每排一个完整八度，两排共两个八度。键上方滑条可直接发音并实现滑音、颤音；独立琴键是否保留，用户要求比较两种方案后再选择。
- 音乐可视化区：一块屏幕显示音乐。
- 音色构造区：沿用已有泛音构造方向；保留全和弦修饰、松手保持、RESET平滑恢复等已有决定。
- 四个预设按钮：可选择一种或多种乐器，用于自定义乐器演奏及音色分层。
- 编辑按钮：按下后选择一个预设槽，在实体机上编辑该乐器的音色、激励模式等。

此需求扩大了实体机编辑范围，不再仅依靠电脑修改乐器。四槽不代表框架仅支持四类声音；设备保存与断电保留仍须分别定义。

## 2. 音高区候选

建议把键形布局与连续滑动区域合并：每个触控键直接产生基准音，落指位置作为相对滑音锚点，沿键移动改变所属音符音高，往返移动产生手动颤音。保留琴键外形、分区与触觉边界；不要求额外机械键盘。该建议替代键外上方独立滑条布局，尚待用户选择。

若保留机械键与独立滑条，必须另定：滑条能否独立触发、同键同时触发如何计数、按键转移至滑条是否保持音符、各自松手如何终止控制。不能将两路简单OR后宣称身份连续。

每键单触点、多指跨键与同键多触点为不同能力，传感原型通过前不承诺同键双指。滑音量程、跨键动作、松手音高、追踪丢失宽限仍未冻结。

八度条建议按位置划分有迟滞的档位，压力用于确认接触而非默认按用力大小切档；器件需核实是否输出位置，不能从“压力感应条”名称推定。建议切档只影响之后新音，已有按住音维持音高，避免整和弦跳变；待用户确认。

两排各一八度已由用户明确；12个半音键/排共24键、或含高端C共13键/排26键、或共享端点等仍需确定，不直接从“两八度”推定旧25键/38通道。

### 2.1 用户要求的两方案比较

| 维度 | 独立琴键＋上方独立滑条 | 琴键自身为滑动触控区域 |
|---|---|---|
| 直接发音 | 两路都能发音时需处理重复触发；若滑条不发音则改变用户原意 | 同一触点落指起音、移动表达、离开释放 |
| 从稳音进入滑音 | 通常需从键移动到条，交接空隙、两指重叠、跨区所有权需要规则与原型验证 | 同一键内原手指移动，无独立区域交接 |
| 稳定音高 | 独立键可完全固定音高；滑条独立承担变化 | 需位置锚定、静止区/迟滞、滤波平衡抖动与微小颤音 |
| 多音表情 | 每键有对应滑条才有直接逐音映射；共享一条需另定作用对象 | 每键独立位置自然对应各自音符；仍需原型证明并行能力 |
| 面积和实现 | 两排各12或13键外再配逐键滑条会增加面板与输入规模；不一定是机械键 | 合并发音区与表达区，但长条几何、行距和可达性需手板验证 |
| 力度/触觉 | 只有额外行程/测力结构才有对应能力，独立按键本身不保证真实力度 | 单纯电容条不自动有真实压力/机械回弹；可做表面分隔 |
| 适合的产品方向 | 明确保留传统独立键手感、允许两种演奏入口，愿意承担交接与更多传感硬件 | 同一动作兼顾起音与逐音连续表达，优先统一控制框架 |

建议优先验证一体式触控滑动键，但不代替用户定案。可制作单键/少量键原型：静按不飘音、缓慢小幅往返能表达、快速落指不起偏、多键保持独立、松手无挂音；再扩展两排。独立方案可作为保留独立按键手感的候选，不以主观喜好直接淘汰。

## 3. 演奏与编辑状态机候选

`演奏 → 编辑选槽 → 单槽草稿编辑/试听 → 保存或放弃 → 恢复演奏`

- 演奏：预设按钮短按切换该层启用状态；允许全关，屏幕明确显示无启用乐器。开层仅接收之后新音；关层解除已有持续驱动并按原定义释放，既有尾音不硬切。此为候选，需用户确认。
- 按编辑：记录原启用层掩码，屏幕提示选择编辑槽；这时槽按钮只选编辑目标，不改变记录的演奏分层。
- 选择槽：复制完整已应用乐器定义到草稿；左手新音仅试听草稿。进入编辑前已有音按原定义释放，不突然改归草稿。编辑期间泛音区编辑草稿，不兼作演奏修饰；原演奏修饰单独保留，试听使用中性修饰。
- 草稿修改：幅度/增益采用有界平滑试听；激励类型、频率结构、包络等结构改变优先在之后新音生效。旧试听音继续原版本。首版不默认对已有音符热切换激励。
- 退出编辑：无修改直接退出；有修改显示保存、放弃、继续编辑。保存只写目标槽，不写其它层；恢复原分层选择。其它层与原修饰保持原状态，更新槽之后新音使用新定义。
- 编辑中选择另一槽：有未保存修改时先显示同样的处理选项，不静默丢弃。
- 未选择目标时再按编辑：返回演奏。故障/复位必须清理试听音所有权，防挂音。

编辑不是切换预设、保存也不是把整组分层混成新预设。基础定义、运行期修饰、编辑草稿、活动音符状态各自独立。“将当前修饰写入基础谱”若需要，应是单独显式命令，不默默随保存发生。

## 4. 实体控件与编辑页候选

用户已提出四预设键＋编辑键。建议额外配置一只带按压的旋转编码器，用于页面/字段导航、数值微调和确认；既有RESET恢复动作需有明确入口，其独立按键数量尚未冻结。编码器属于新增建议，未定器件和采购；屏幕不假设有触控。若严格限制按钮数，需另定泛音区菜单操作，不能留下无法导航的编辑页。

| 编辑页 | 内容 | 泛音区/编码器分工候选 |
|---|---|---|
| 激励 | 瞬间、持续、混合；瞬态与持续占比/分组 | 编码器选择类型及有界参数；类型是行为配置，不声称物理建模 |
| 频谱 | 16分量幅度、频率比 | 沿用8组区域；幅度编辑可分1–8/9–16页，频率比由选中分量后编码器调整；8组映射尚未冻结 |
| 时间 | 起音、自然衰减、持续量、松手释放/阻尼 | 先全体或分量组，精细逐分量编辑后续评估；保持时衰减与松手后释放分开 |
| 表情 | 左手滑音响应；右手各组修饰深度/方向；有实测力度才开放力度映射 | 校准属设备，不随预设改；传感器不存在的控制量不能伪装可用 |
| 混合/输出 | 该槽基础音量、分层平衡、可选效果发送 | 公共效果与各层增益分开，不承诺四套独立效果器 |
| 管理 | 保存到槽、恢复出厂内容、导入导出状态 | 覆盖需明确确认；恢复出厂不得误触；持久化能力另行签收 |

四个按钮的灯/屏幕状态区分：演奏启用、编辑目标、有未保存修改。采用亮/闪/屏幕标识不依赖一定配有RGB灯。

## 5. 屏幕、保存和实现边界

演奏默认显示启用层、音域、音符/滑动轨迹，波形与频谱作为可切换视图；编辑显示槽名、页名、字段/单位、草稿状态和简化试听视图。不要求所有图同时刷新；需待屏幕型号与联合资源验证确定刷新率。

保存区分：草稿RAM、已应用运行槽、断电持久化。建议最终支持实体独立保存，具体Flash区域/写入保护/断电恢复须核实实现后才能承诺；暂存不能标成已持久保存。已有原配置草稿“显式应用”的规则仍保留，试听为独立受控目标，不等于草稿自动覆盖正式在奏乐器。

32×16是共享声部资源：若每父音符使用4层，理论最多8个完整四层音符实例，包含未回收尾音；并非每层各32声部。实际吞吐、满载回收及屏幕/传感并发仍待实现验证，不私自更改已讨论的复音与抢占规则。

## 6. 本轮证据与下一步

### 6.1 滑条选型先于面板定案（本轮追加）

用户指出滑条选型是重大问题。对此修正决策顺序：一体式滑动键仅是交互倾向，尚无已验传感方案；先做测量前端/电极/位置算法的小样，再冻结键形和采购全量。独立琴键＋独立滑条同样没有消除滑条问题，若保持逐键独立表达仍需逐键位置输入。

候选比较：定制PCB电容电极＋FPGA测量/插值（预算内首选原型，非成熟成品签收）；SoftPot类膜式位置电位器（真实现成位置元件，需ADC、释放检测及逐键尺寸/报价核对，未确认24～26路预算）；原始CDC如AD7147（可做对照，扩展规模与扫描时间需核算）。普通测力条不能因“条状/压力感应”就推定有位置输出；测力与测位置必须按料号分开。

规模仅作设计计算：24～26键×每键候选3电极=72～78原始测量节点，尚不含右手、八度条。不能把这些节点当作72～78根FPGA直连IO，也不能把单芯片峰值速率当整机扫描率。已有43号8并行路径/MUX架构只是候选，MUX仅切换信号，不负责测电容。FDC2114虽4通道可读原始测量，但这类规模需要另算芯片、LC网络、布线、读出和预算，不直接继承旧小通道候选优先级。

先做4键候选3电极的小样，对比直连/复用；测位置单调、静止漂移、多键独立、滑音微动、快速按放和音频/屏幕噪声；记录全量轮询预算与端到端≤10ms。通过前不下全尺寸板，也不宣称三电极足够。样机采购金额需实时报价，500元是总预算并非已核实可覆盖全部路线。
