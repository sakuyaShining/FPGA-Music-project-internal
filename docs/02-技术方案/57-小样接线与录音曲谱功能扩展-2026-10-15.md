## 1. 新增需求与建议边界

用户要求继续推进小样原理图，并新增“保存演奏音频并播放、实体录入演奏、曲谱指引、播放”。保留原有自定义乐器、四预设同音分层、两八度逐音滑条、独立八度选择条、按压旋钮、断电保存参数和音乐可视化。没有因此增加计算MCU或替用户决定双FPGA。

建议把一次演奏保存为配对的两份数据：

| 数据 | 保存对象 | 用途 | 介质候选 |
|---|---|---|---|
| 音频轨 | 最终发声链输出的单声道16位PCM，包含当时音色/表情/效果 | 重现录下的实际数字声音，之后修改预设也不改变录音 | 板载TF卡；SDRAM作缓冲 |
| 演奏轨 | 带时间戳的落指/离开、连续音高、右手修饰、预设/层状态及配置快照引用 | 屏幕跟弹提示、演奏事件重放 | 同一张TF卡，独立版本格式 |
| 乐器槽 | 乐器配置、版本和校验 | 无卡也能恢复自定义乐器 | 现有24LC256候选，继续独立 |

不从混合PCM自动识别多声部曲谱。录音轨与演奏轨共用样本计数时间基准；区分原始演奏输入、被引擎接受/拒绝的音符、实际PCM，避免把未发声输入假称为录到的声音。参考曲谱状态不受实时演奏修改；跟弹目标直接来自演奏轨/曲谱，不能以FFT主峰代替和弦音符。

待用户答复：最少单段录音时长；“实体录入”是否先指直接演奏录入，还是也包含逐音编辑/导入外部曲谱。候选按至少5分钟、多段、设备演奏录入＋屏幕跟弹提示评估；**建议值未冻结**。逐音编辑、外谱格式、自动量化、等待弹对才前进、变速、评分、伴奏叠录均不能从本次简述自动推定。

建议实体入口：按压旋钮进入录音/曲目列表，转动选择录制、停止保存、原声回放、曲谱指引，屏幕明确显示状态与时间；四预设与Edit的原用途保留。小样先复用现有控制接口，不先增加专用按键；若需独立REC/PLAY键可串接第二颗165，具体手势和是否增键仍待决定。

## 2. 存储与引脚结论

[Sipeed官方板卡说明](https://wiki.sipeed.com/hardware/en/tang/tang-nano-20k/nano-20k.html)列有一个TF卡座、64Mbit SDR SDRAM与MAX98357A。SDRAM是8MiB易失缓冲，不能作为断电录音介质；板载配置Flash继续保存码流，不把它分区覆盖作录音。

[官方3921 Rev1.30原理图](https://dl.sipeed.com/fileList/TANG/Nano_20K/2_Schematic/Tang_Nano_20K_3921_Schematics.pdf)第2/5页对应：

| TF信号 | FPGA封装脚 | 规划 |
|---|---:|---|
| DAT2 | 80 | 保留 |
| DAT3 / SPI片选 | 81 | 保留 |
| CMD / SPI MOSI | 82 | 保留 |
| CLK | 83 | 保留 |
| DAT0 / SPI MISO | 84 | 保留 |
| DAT1 | 85 | 保留 |

以上为特定官方板版证据，须对照用户实板版号；不是新小样J1的插针号。TF使用独立总线，触控/显示的候选共享SPI不直接接到TF时钟。无需在触控小样上再焊一个TF卡座。触控/屏幕/音频/串口与保留TF的最终CST仍待制作和冲突审计，不修改旧产品约束冒充已接合。

[官方示例仓库](https://github.com/sipeed/TangNano-20K-example)中nestang的SDLoader为读卡/加载路径，不能直接当可写文件系统或录音器。SD写入、CRC/超时/忙检测、文件分配/提交、播放读出和SDRAM仲裁均需实现/验证。

## 3. 可量化预算与资源门槛

原引擎fs=27MHz/512=52734.375Hz，单声道PCM16为105468.75字节/秒；按平均速率推算5分钟约31.64MB（30.17MiB），30分钟约189.84MB，实际按完整样本/存储块取整并另计文件与事件元数据。重复的左右I²S声道不必存两份；未来独立立体声须重新翻倍预算。

32KiB EEPROM即使全部用于PCM也仅约0.311秒，因此只适合参数。8MiB SDRAM即使全用于PCM也仅约79.54秒，且必须留控制/缓冲空间；候选256KiB录音环形缓冲约2.4855秒，是否够用取决于实际卡的最长忙时间与控制器服务延迟，不能由卡的平均速度保证。另留事件队列和播放预取缓冲，不能把全部8MiB重复分配给多个用途。

内部录音以准确原生采样率和样本总数为准。通用PCM WAV采样率字段是整数，直接写52734存在约7.11ppm差异；产品实现需明确导出策略（整数标称＋精确元数据，或离线重采样到48kHz）。不为WAV格式擅改音乐时钟。超过RIFF容量或长录音应分段，文件长度/写入完成后更新并校验；掉电应保留此前已提交片段，未提交末段不能承诺无损。

54/55号核心＋可视化综合19777/20736Logic、38/46BSRAM尚无全机PnR；不能据8MiB容量便断言单板有余力做录音。新增控制器与文件逻辑后要联合综合/PnR，必要时用旧16路扫描替换后的实际回收量评估。双板仍为依据证据的备选，未选型/采购。

原则：音频/触控实时路径不等待TF；PCM写入缓冲，低优先级后台成块落盘；溢出、读空、卡拔出/写失败必须可观测并结束本次录音，不把丢样文件标作成功。播放在输出链选择PCM，避免重复经过合成效果器；同时演奏混音、录音时是否包含回放、叠录和混音余量规则仍待定义。

新增卡/介质暂预留30元，先从原60元预备金内划转，使总规划仍为500元；实际容量品牌及成交价未选定，500元不是含全部新功能的已报价BOM。若用户已有合适卡则不必采购。不先增加TF模块/音频ADC；本次“录音”先按设备自身数字输出评估，外部麦克风录音不是已确认需求。

## 4. 实现顺序与验收

1. 小样先把两路RC、移位扩展、EEPROM和实体控制接线并导出核对；保护、连接器、实板引脚和电极封装再收口。
2. 在隔离实验里验证TF读写和SDRAM控制器、忙停顿下无丢样；先建立实际Logic/BSRAM/PnR和总线吞吐证据，再决定是否单板。
3. PCM录放应检验连续样本数/序号/校验一致、停止后重启仍可播放、文件可读取，以及卡满/掉电/失败状态。测试缓冲覆盖的服务停顿，不假定任意卡永不超时。
4. 演奏轨验证同音多指身份、和弦/尾音、连续表情、配置版本、音画时间戳；指引验证目标音集合、当前八度与屏幕提示一致。旧64步单音曲谱RAM/板载LED指示仅为基础，不能视作新曲谱指引完成。
5. 全机同时发声/显示/录音/触控测最坏触摸至声音≤10ms、音频不掉样、显示指标、实物卡电源干扰，最后签收制造方案。

## 6. 新增已确认需求：已录伴奏与现场独立演奏

用户明确批准：**先演奏并保存钢琴伴奏，启动回放，再以弦乐音色现场演奏另一段旋律，两部分同时输出**。这是预先录制内容与现场演奏组成的个人合奏；原实时同音音色分层继续保留。需求已确定，实现状态**待实现**，不把文字设计标为完成。

最低功能闭环：

1. 选择一种乐器并演奏、录制，停止后保存为可选择的伴奏。
2. 选择已保存伴奏并开始回放，现场输入继续有效。
3. 为现场演奏选择另一种乐器，演奏独立音符与节奏；现场乐器选择与伴奏使用的乐器/保存内容分开管理，防止配置串改。
4. 两部分在设备内部混音，经内置喇叭或3.5mm AUX输出。曲谱指引继续可作为配套功能，不从此推定自动生成伴奏。

实现候选（尚未冻结）：优先评估**原PCM伴奏回放＋实时合成**，使伴奏保持录制时声音；保留配对演奏事件以支持指引。未来若用事件轨重放/换音色，需要独立音符实例与配置快照，且伴奏与现场共同占用32组音源。PCM回放虽不必重新占用合成声部，仍增加TF读取、缓冲、混音和仲裁资源，不能当成零开销或据此保证单板足够。

必须补齐的实现与验证：伴奏回放与实时输入拥有独立状态和停止路径；不得因同MIDI音高而互相松音。音频/事件时间基准、起播位置与到达末尾状态需明确，不能先假定节拍量化或自动循环。混音要有音量配比与幅度余量，并检查回放原音频不重复经过原已录入的效果链。TF读空、错误和停止需可观测；现场音频和触控不可等待读卡。将“伴奏回放＋现场分层＋双屏显示＋触控”纳入联合资源/PnR及最坏≤10ms评估。

当前ca03上位机11版曲谱播放仍通过`sequence_playing`禁用手动演奏，那是此前旧单音曲谱路径的保护行为，**不满足本新增功能**；不能简单删掉互斥检查便宣称完成，新路径必须完成事件所有权和混音隔离。此前主机100项测试不作为本功能验收。

待继续讨论：伴奏是否循环、是否能边回放边继续录入新轨、最大轨数/时长、速度调整、右手修饰作用于现场还是也作用于事件伴奏、录制时保存现场独奏还是最终混音，以及专用录放按钮/旋钮菜单。未决定自动伴奏生成、外部麦克风录入或完整多轨编辑器。

硬件范围继续沿用TF/SDRAM、FPGA音源及新增线路输出，不直接新增第二FPGA/计算MCU或改变约500元预算；能力是否足够需实证。下一步先形成录制/回放/现场并行状态与数据路径，再做隔离资源探针和读卡/混音验证。本轮仅更新设计文档，main192输入身份PASS，无代码、原理图、PCB、旧快照或板上状态变更。
