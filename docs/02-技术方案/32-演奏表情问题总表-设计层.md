# 演奏表情问题总表 —— 设计层

> 2026-10-05 · 配套：`32-演奏表情问题总表-实现层.md`、`32-演奏表情问题总表.json`
> 本文件只记**意图、规则、取舍**（设计层）。落到哪个模块、哪条判据，见实现层那份。
> 编号 `D-xx` 在设计层与实现层、JSON 中**一一对应**。

## 0. 层的划分依据

| 层 | 回答什么 | 谁改 | 改动的代价 |
|---|---|---|---|
| **设计层** | 想做成什么样、按什么规则判定 | 你（演奏者视角） | 改文档；**不影响已验证的代码** |
| **实现层** | 用什么模块实现、怎么证明它对 | 我（RTL 视角） | 改 RTL + 判据 + 跑闸口 |

判据：**如果一个问题的答案可以用"手感/音乐性"来争论，它属于设计层。**

## 1. 四个维度的意图

| 维 | 意图（一句话） | 归属层 |
|---|---|---|
| D1 力度 | 用手指接触多少来决定"这个音多响、多亮" | 演奏层 |
| D2 颤音 | 按下之后继续"用力"⇒ 加揉弦 | 演奏层 |
| D3 滑音 | 手指不离开面板地移到另一个音 ⇒ 滑过去 | 演奏层 |
| D4 亮度 | 在泛音排上滑动 ⇒ 音色连续变亮/变暗 | 演奏层 |

**结构层不在此表**：点按泛音键选泛音是音色设定，不算表情（见《31-演奏表情规格》第 0 节）。

## 2. 设计层问题清单

### D-01 手指面积因人而异

| 项 | 内容 |
|---|---|
| 现象 | 同一个"轻按"，不同人、不同湿度下读数差很多 |
| 设计决策 | **不做绝对映射，做相对映射**：演奏前标定"最轻/最重"两端，中间线性插值 |
| 理由 | 绝对阈值换个人就失效；相对映射换人只需重标定 |
| 待定 | 标定动作放在哪（开机？每次进演奏模式？）【待确认】 |
| 关联 | 实现层 I-01 |

### D-02 起音瞬间的面积还在变化

| 项 | 内容 |
|---|---|
| 现象 | 手指落下是几十毫秒的过程，按下那一刻测到的是最小值 |
| 设计决策 | **不取瞬时值，取"起音窗内（约 10 ms）的峰值"** |
| 后果 | 弹得越轻越不易被误采为"无力度" |
| 修正记录 | 《31-演奏表情规格》原来写"一个映射周期内取一次"，**已确认不准确** |
| 关联 | 实现层 I-02 |

### D-03 力度只改音量会像音量旋钮

| 项 | 内容 |
|---|---|
| 现象 | 若力度只缩放包络峰值，听感是"音量旋钮"，不像"在弹" |
| 设计决策 | 力度同时影响**音量 + 音色亮度**（重按更亮） |
| 附加 | 可再影响**起音速度**（重按起音更快）——列为可选 |
| 理由 | 真实乐器"重击更亮"，这是力度最有说服力的部分 |
| 得分 | 直接支撑 E2"力度动态"这一维 |
| 关联 | 实现层 I-03 |

### D-04 16 档够不够

| 项 | 内容 |
|---|---|
| 决策 | **16 档足够**（实验上 8–16 档已被感知为连续） |
| 待定 | **曲线**（线性 / 对数 / 分段）**必须用耳朵定**，不能靠公式【待确认】 |
| 关联 | 实现层 I-04 |

### D-05 触发方式的选择（颤音）

| 项 | 内容 |
|---|---|
| 候选 | 触后 / 长按自动渐入 / 专用轴（拇指条·脚踏） |
| 设计决策 | **触后为主**；触后不可用（原型判定模拟量不可靠）时退到**长按自动渐入** |
| 理由 | 长按渐入零传感依赖，是可用的兜底 |
| 关联 | 实现层 I-05 |

### D-06 触后与力度共用同一个信号

| 项 | 内容 |
|---|---|
| 现象 | 起音窗要"窗口内最大值"；触后要"起音之后的变化"——同一个信号 |
| 设计决策 | **用时间窗分开**：起音窗（约 10 ms）内归力度；**之后**的变化才归触后，且触后从 0 开始累计 |
| 若不做 | 按重一点会被算成"又重又揉" |
| 关联 | 实现层 I-06 |

### D-07 颤音的渐入时长

| 项 | 内容 |
|---|---|
| 设计决策 | 取 **100–300 ms，默认 200 ms**（真实歌唱颤音的渐入量级） |
| 修正记录 | 《31-演奏表情规格》原写 50 ms，**太短（像开关）**，已修正 |
| 重要 | 触后从 0 开始 ⇒ **先直音、后加颤**，这**恰好是自然乐器的行为**，**不要"优化"掉** |
| 关联 | 实现层 I-07 |

### D-08 滑音 vs 快速连弹如何区分

| 项 | 内容 |
|---|---|
| 现象 | 两种情形在**事件层面几乎相同**（旧音还在响时出现新音） |
| 设计决策 | 唯一依据是**手指是否离开面板**（MPR121 的状态位可给此信息） |
| 备选 | 若拿不到"手指在否"的信息，退化规则：**时间窗 + 位移连续性** |
| 关联 | 实现层 I-08 |

### D-09 电极间隙会造成瞬断

| 项 | 内容 |
|---|---|
| 现象 | 手指在键间移动时必然经过 3 mm 间隙 ⇒ 出现"短暂全松" |
| 若按"全松即抬手" | 滑音会变成**一串断音** |
| 设计决策 | **"全松"必须持续超过阈值（30–50 ms【待原型】）才算真的抬手** |
| 关联 | 实现层 I-09 |

### D-10 快速重复音与滑音争同一个阈值

| 项 | 内容 |
|---|---|
| 现象 | 全松阈值短 ⇒ 快速重复音跟得上但滑音易断；长 ⇒ 反之 |
| 设计决策 | **承认这是折中**；数值靠原型实测决定 |
| 候选 | 若折中不理想，可引入"相邻键连续经过"作为滑音的**加权证据**，而不单靠时间 |
| 关联 | 实现层 I-10 |

### D-11 泛音排中间掉格

| 项 | 内容 |
|---|---|
| 现象 | 与 D-09 同源：8 个键之间也有间隙 |
| 设计决策 | 泛音排**只需知道"经过了哪几格"**，不发声 ⇒ 可用更宽松的判据 |
| 关联 | 实现层 I-11 |

### D-12 多指同时按泛音排算哪个位置

| 项 | 内容 |
|---|---|
| 现象 | 两根手指同时落上，位置不唯一 |
| 设计决策 | **定死一条规则**（建议：取**最左**被按格；理由是滑动通常从一侧开始） |
| 待确认 | 是否改为"取首次落下的那一格"【待原型看手感】 |
| 关联 | 实现层 I-12 |

### D-13 亮度的目标谱形从哪来

| 项 | 内容 |
|---|---|
| 候选 | A 预设插值 / B 逐条缩放 / C 倾斜轴 |
| 设计决策 | **C 倾斜轴为主**（协议里 `0x5C TILT` = "谱形倾斜（低↔高连续轴）"**早已声明**），A 为补充：倾斜决定"怎么变"，预设决定"变到哪" |
| 否决 | **B 逐条缩放会变成音量变化**，不像亮度 ⇒ 不用 |
| 关联 | 实现层 I-13 |

### D-14 亮度只能缓慢推拉

| 项 | 内容 |
|---|---|
| 现象 | 逐声部谱形刷新走 `0x63`，有几十个周期延迟 |
| 设计决策 | 亮度**只做"缓慢推拉"**（手势级），**不做快速摆动**（音频级） |
| 理由 | 这是引擎刷新机制的真实上限，不是实现疏忽 |
| 关联 | 实现层 I-14 |

### D-15 泛音键的双重身份会打架

| 项 | 内容 |
|---|---|
| 现象 | 手指刚按下时，系统不知道你是"要点"还是"要滑" |
| 设计决策 | **点按加确认延迟 T**：稳定按住超过 T 且无位移 ⇒ 点按生效；期间有移动 ⇒ 判为滑动，**不触发泛音切换** |
| 代价 | 泛音键点按有 T 延迟（可接受：它是**设定**动作，不是演奏动作） |
| 关联 | 实现层 I-15 |

### D-16 力度/触后的"死区"与抖动

| 项 | 内容 |
|---|---|
| 现象 | 手指静止时读数仍有抖动，会被误判为"力度变化"或"触后" |
| 设计决策 | 设置**死区**：小于死区的变化不改变力度/触后 |
| 待定 | 死区大小取"噪声的 2–3 倍"【待原型量噪声后定】 |
| 关联 | 实现层 I-16 |

### D-17 表情的冻结条件

| 项 | 内容 |
|---|---|
| 设计决策 | **音域切换期间冻结表情**（音域是设定动作，切换时受力会污染表情） |
| 附加 | 抬手（note-off）后，该声部的表情值清零 |
| 关联 | 实现层 I-17 |

### D-18 逐声部 vs 全局的取舍

| 项 | 内容 |
|---|---|
| 决策 | **四维全部逐声部**（用户已定） |
| 理由 | 全局颤音在弹和弦时会一起颤，不自然 |
| 代价 | 资源约 +768（颤音相位）+256（表情寄存器）个触发器 |
| 关联 | 实现层 I-18 |

## 3. 设计层的待确认清单（需要你或原型来定）

| # | 待确认 | 由谁定 |
|---|---|---|
| 1 | 力度曲线形状 | 你的耳朵 |

| 3 | 全松阈值（D-09/D-10） | 原型实测 |
| 4 | 点按确认延迟 T（D-15） | 原型 + 手感 |
| 5 | 多指取哪一格（D-12） | 你的手感 |
| 6 | 颤音渐入 200 ms 是否合适（D-07） | 你的耳朵 |
| 7 | 死区大小（D-16） | 原型量噪声 |
