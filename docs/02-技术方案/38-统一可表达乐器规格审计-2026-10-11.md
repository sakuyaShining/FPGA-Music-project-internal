# 统一可表达电子乐器规格 V1.0：设计与实现衔接审计

日期：2026-10-11。状态：审计建议，未替代或冻结产品规格。

审计对象：本次用户提供的《统一可表达电子乐器：交互与演奏系统规格 V1.0》。原文件 SHA256：`091D4CCA2CC63D79F01E5AA007E21BFF32338C8F0B88A6EDD24D7B7A593BFBDC`。

代码身份：当前工作树 HEAD `fe326ad9505c94f46f9236bf7f9bfc3b5f1b9a12`。审计开始时工作树干净。本轮只增加审计记录、运行已有仿真，没有修改 RTL。

## 1. 审计结论与证据边界

总体产品分工可以保留，但尚不适合直接冻结为可执行的实现契约。主要缺口集中在：音符身份与资源回收、参数更新的隔离、事件可靠交付、实体触控的可观测能力，以及定量验收。

旧实现可以提供音频计算与部分控制基础；“兼容既有实现”必须说明兼容哪些层。旧的同音合并、满员抢占、加性塑谱、松手即标空闲等行为与新产品语义不同，不能继续作为新模式的正确性判据。

证据分三类：

- **本轮复现**：运行已有 `tb_padfast`，相邻释放/按下事件丢失仍存在。
- **源码确认**：按当前赋值与接口确认数据流；不等于已测量实际音频影响。
- **规格缺口**：存在多种合理实现，文档尚未选定；下文建议均不自动成为冻结决策。

本轮没有重跑全量回归、综合/PnR或实体传感器与音频测量。旧文档的通过数、资源占用和时序余量不能转写成本轮结果。

## 2. 冻结前必须解决的发现

### A01：音符身份接口与当前分配器不兼容（高，源码确认）

规格 §2.1/§2.4 要求同音多指独立。当前 `note_map.v:55` 附近事件只有 on/off、音号和力度；`:249` 按音号匹配已分配组，`:302` 在无候选时选择轮转抢占组。这既不能区分同音触点，也不满足满员拒绝新音的规则。

建议：音符接口至少携带来源、音符身份及其代次；音高只作为属性。触点复用或 Voice 回收后，旧代次的移动/释放必须被拒绝并计数。明确分配成功/拒绝的应答，不能把 FIFO 收到事件当作发声成功。拒绝落指后建议等该手指离开再重新申请，避免空出声部时无新动作却突然起音。

验收补项：两个同音触点独立释放；填满全部声部后追加落指；Voice 复用后注入旧释放；上位机与实体触点同音并存。

### A02：资源可用状态与声音结束状态仍未闭合（高，规格缺口及源码确认）

规格允许释放尾音继续存在，也允许 Impulse 在手指仍按住时结束。当前 `note_map.v:540` 附近收到释放就清 `gact`、将 `gtab` 设为 FREE；分配器没有来自引擎的完整声音结束反馈。后续新音可以覆盖尚在释放的槽。

建议分别保存 `owner_present`、`sound_active`、`voice_allocated`。V1 若不实施尾音抢占，就只回收真正结束的声音；可允许已经静音的 Impulse 归还 Voice，但触点保留“本次落指已消费”的身份，移动不重触发。此时对已结束音符的音高更新应定义为忽略或只更新逻辑状态。

声音结束建议以该 Voice 的所有合成分量归零为确定判据；效果器残响拥有独立生命周期，不阻止 Voice 回收。需要规定异常包络参数导致不能结束时的处理，以及独立的全音符停止命令。

### A03：现有谱刷新不能承接右手实时修饰（高，源码确认）

规格 R08 要求右手不改变音高、力度或包络。当前路径存在以下耦合：

- `note_map.v:489` 只保存最近事件的 `vel_cur`；`:510` 的刷新没有装载目标 Voice 的原力度，却在重算幅度时继续使用它。
- `:510` 只刷新 `gact=1` 的组，已松手尾音被跳过，与 R07/E07 及全局范围定义冲突。
- `:568` 附近刷新同时写频率、幅度、gate、包络参数；`:572` 将滑音初值写零。引擎 `tdm_engine.v:553` 又将每次装载消费接到音高偏移写使能。
- `note_map.v:446` 的释放路径使用未经原力度缩放的 `amp_src`，释放操作本身也不是单纯的生命周期更新。

这些数据流足以说明不能把现有 refresh 直接当 TIMBRE_UPDATE；实际声音变化大小仍需专项仿真和试听。

建议为音高、音色、生命周期分别定义写入权限或更新掩码；保存原力度及未乘修饰的基础参数，禁止从反复量化后的最终幅度反推。右手更新仅改变修饰/有效谱，不重写 pitch、gate 或包络状态。释放只改变驱动/阻尼状态。

验收补项：两种力度的声音一起刷新后仍保留力度差异；滑音中编辑谱不清除滑音；释放尾音可继续塑形；释放瞬间不重新缩放基础幅度。

### A04：相邻事件静默丢失仍可复现（高，本轮复现）

当前 `tdm_top.v:849` 用 `pp_ev_valid && !pp_pend` 接收事件；前一事件尚占挂起槽时，后一脉冲会被忽略。已有 37 号修复方案尚未在本工作树落实。

本轮使用回归脚本的 `compile_and_run` 运行原有 `tb_padfast.v`，结果：

```text
PASS  B-two-events-produced (2)
FAIL  B-both-events-acked got 1 exp 2
FAIL  B-note49-allocated got 0 exp 1
PASS  B-dropped-by-pending-slot (1)
RESULT padfast=FAIL fails=2
```

证据：`sim_build/regress/audit_20261011_padfast/audit_result.txt`。这是受控数字仿真，不是实体触控实测。运行器进程返回 0，不代表测试通过；结果以测试台 FAIL 为准。

建议补充端到端输入契约：最大同时触点、一次扫描可产生的事件数、最坏突发、每类事件服务时限、源端背压能力和溢出恢复。人手动作慢不能保证数字事件不紧邻；一次扫描可以同时产生多个边沿。

NOTE_ON/RELEASE 必须保持每个身份内的因果顺序。PITCH_UPDATE/TIMBRE_UPDATE 可以按同一身份合并为最新值，但不得跨越 RELEASE 或代次边界；不必为每次扫描发送 NOTE_HOLD。

另外，`event_hold.v:96` 在 valid 且队列满时每拍增加 overflow。对允许保持 valid 等待 ready 的接口，这应是“背压周期数”，不能直接称为丢事件数。应分别统计背压、明确拒绝/丢弃、过期身份和安全恢复。

### A05：预设版本、草稿提交和旧音符保留缺少统一规则（高，规格缺口）

规格 §5.3 只明确旧音符保留激发生命周期，没有定义基础谱、频率比、包络参数、映射和效果器是否也保留。当前 `note_map.v:353` 持续读取全局 preset；`tdm_top.v:523` 的谱数据是直接写入，尚没有完整草稿事务。

建议默认让音符在起音时绑定一份完整的发声参数版本；右手全局修饰继续作用于这些声音。基础音色 Apply 先影响新音符，主动更新旧音符作为独立功能。必须选定版本存储方式：逐声部快照，或带引用计数的预设库；两份缓冲在旧音符持续时连续 Apply，仍可能覆盖在用版本。

配置接口需要 BEGIN/写草稿/APPLY/提交应答，或等价的完整性与版本机制。定义同一边界的 Apply 与 Note On 顺序；释放事件始终按身份处理。上位机断线或只写一半不能提交。

“样本边界提交”需要说明原子范围：16 条谱、单个 Voice，还是全局配置。现有 `tdm_engine.v:338` 的逐槽消费不能自动证明所有声部在同一帧使用同一配置版本。

### A06：实体前端的能力要求与候选方案还没有闭环（高，规格缺口）

当前出货顶层 `tdm_ship.v:47` 附近是 16 路电极接口；`pad_pitch.v:29` 接收触摸位图并按离散键产生事件。这些接口不能证明连续多指坐标追踪已经实现。

规格应先明确左右手各自的最大触点数、最小可分辨间距、坐标误差、扫描周期、追踪失效边界及恢复策略。多指合并、交叉或遮挡时，如果观测不足，应采用明确拒绝/冻结/终止规则；不能仅凭稳定 ID 的目标推定传感器提供了足够信息。

同时明确 §9.3 中“FPGA 完成坐标计算”的硬性程度：只提供坐标的控制器与只提供原始电极观测的前端，对 FPGA 的职责不同。硬件选型必须核实可取得的数据类型。本轮没有对任何候选芯片重新做数据手册核验。

## 3. 应在第一轮实现前补齐的规则

### A07：右手编辑存在饱和、RESET、接管与丢踪四种边界（中）

除上一轮提出的 RESET 重锚定及同组接管规则外，还需规定：达到最大/最小修饰后继续滑动，反向时是否要走回超出的距离。建议增量式更新并同步位置参考，避免出现长段无响应行程。

短暂丢踪期间冻结最后可信值；恢复时重锚定位置，避免跨缺口跳变；超时后锁存并释放所有权。同组同时落指用稳定次序裁决，例如时间戳后接触点 ID。建议已有竞争触点需重新落指才能接管。

RESET 与移动在同一更新周期时，建议 RESET 优先，清目标值并重设仍有效触点的参考；明确复位只清演奏修饰，不能兼任停止所有音符。

### A08：乘性强调、补偿和定点精度尚不是完整算法（中）

建议写出 modifier 的范围、8×16 权重的范围、重叠组如何聚合、饱和顺序、乘积位宽、舍入规则，以及目标值到音频值的平滑方式。若仅允许强调已有成分，则 modifier 应非负；“减少”指回到零修饰，不能默认为可衰减到低于基础谱。

归一化必须满足零修饰严格恒等和零谱安全。若每次都强制等总能量，纯正弦音色的单分量 Boost 可能被完全抵消；应在默认音色的可操作反馈中说明。最大多音、多组强调的混音余量与效果器内部余量需要一起验证，不能只在单个泛音处饱和。

当前 `note_map.v:375` 使用加性叠加及触摸置满幅，会创造原本为零的分量，明确不满足新规格 R09。必须用新语义重建相应判据。

### A09：频率比与“16 条泛音”的含义缺了一层（中）

现有 `part_rom` 同时包含幅度、包络参数和 Q8 频率比，允许非整数比；新预设表只列 base_spectrum 幅度。需要明确 V1 的第 k 条是否固定为 k 倍基频，还是允许 16 个任意分量。若保留钟类非谐分量，应将频率比纳入预设，并说明右手映射针对“分量索引”还是“谐波阶次”。

抗混叠要在最终调制后的完整频率上判断。当前 `note_map.v:366` 先截成 24 位再在 `:435` 判断 Nyquist，且引擎 `tdm_engine.v:577` 之后还会做滑音/颤音调制。该路径不能证明连续演奏全范围的防混叠。

建议先以足够宽的数值计算实际频率，再进行边界处理；滑音跨越截止边界时平滑衰减分量。分量临时静音不能丢掉基础谱，向下滑回时应能恢复。此项为源码风险识别，本轮没有新增音频实测。

### A10：三种激发需要可验证的时间行为（中）

仅给 Continuous/Impulse/Hybrid 名称还不足以判 E01–E08。建议明确每种模式的最小参数集、释放策略和完成条件。当前包络以 gate 边沿触发；显式 RETRIGGER 需要独立命令，不能依赖同一 gate 再写 1。

Hybrid 应明确瞬态与持续成分是否能作用于同一频率分量、各自如何释放，以及 transient_mix 的极端值。若仅让不同分量使用不同包络，属于一种受限实现，不能默认等价于任意瞬态加持续模型。

不必立即增加 16 套复杂包络控制器；但应保留现有分量状态，先证明最小混合模型的行为和资源预算。

### A11：10 ms 上限必须保留，测量口径需要分层（中）

项目约束文档 `01-选题确认与约束条件.md:37` 将控制信号到音频输出 ≤10 ms 列为必须项。因此上一轮“改成待确认目标”的建议应撤回。未实测代表尚未验收，不改变要求。

建议分别记录物理动作到原始观测、观测确认、追踪/映射、队列等待、合成提交、I2S/DAC 输出的延迟，并给出总预算。明确系统验收起点与项目原约束的关系。

起音延迟测试应使用规定的短起音参考音色，或测量包络启动时刻；慢 Attack 音色越过听感阈值的时间不能直接作为控制处理延迟。滑音与音色响应还需要独立测量平滑带来的延迟及抖动。

### A12：配置模式、断线、启动与应急停止尚未覆盖（中）

建议配置模式进入时平滑释放实体触点拥有的音符、解除编辑所有权、保留修饰；退出后要求先检测到松手，再接受新落指，避免仍按着的配置动作变成演奏。若选择允许配置期间持续演奏，则需另写完整的输入路由规则。

为上位机键盘断线定义来源级释放/租约恢复，不能影响实体手指拥有的音符。普通 TIMBRE RESET 与 ALL_NOTES_OFF/紧急静音要分开；紧急静音是否清除效果器缓存也要明确。

“松手保持”不自然等于断电保存。V1 可默认修饰只在当前开机期间保留，基础预设的非易失保存需要另行说明。

## 4. 基线与验证口径修正

- 34 号文档表格写 46875 Hz、27 MHz ÷576，同时写 BckDiv=16；当前 `tdm_top.v:908` 实例参数为 DIV_BCK=16、BCK_PER_LRCK=32，按该 RTL 关系为 27 MHz ÷512 = 52734.375 Hz。规格中的历史记录更接近此源码，但板上实际时钟仍需测量。
- 35 号阶段文档仍绑定 `c5ec00a`、宣称事件通路完成；37 号文档及本轮判据已说明相邻事件问题未闭合。新设计不得沿用旧的“已完成”标记。
- 512 时隙全占满表示现有调度不能直接多塞串行工作，不等于控制计算或流水线扩展完全没有空间；应以具体访存端口、流水级、状态容量和 PnR 报告预算。
- 黄金参考应约束旧兼容模式及未改变的音频算术。新模式有意改变同音分配、尾音管理和塑谱行为，必须使用新预期，不能要求所有旧行为逐位不变。
- 本工作树未找到文档引用的 `sim_build/regress_result.txt`；本轮只对保存的 padfast 日志给出新的验证结论。

## 5. 建议的下一轮交付顺序

1. 形成状态与事件契约：身份/代次、分配应答、声音结束、满员拒绝、事件顺序及故障恢复。
2. 修复现有事件丢失，并建立每源输入突发的测试；同时完成实体前端最小可行性验证。
3. 实现逐音符 pitch/timbre/lifecycle 独立更新，保存原力度与预设版本；验证两个同音触点、两种力度、尾音和滑音组合。
4. 实现右手组所有权、保持、RESET、饱和反向与失踪恢复，再接连续实体手势。
5. 增加 Impulse 和最小 Hybrid，补齐数值边界、总延迟及资源证据。

规格冻结至少需要关闭 A01–A06 的设计决策，并为 A07–A12 给出明确默认行为与可测阈值。实现尚未完成可以保留为未验收项；规则本身不能继续用“建议”“原则上”同时容纳互相冲突的行为。
