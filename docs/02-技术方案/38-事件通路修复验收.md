# 事件通路修复验收（2026-10-08）

起点：`fe326ad`（RTL 同 `f4c53b5`）。当前候选的 RTL blob 绑定见 34 号规格 §5。

## 改动及根因

1. 原 `event_hold` 的寄存输出始终读旧读指针，连续出队会重复旧队头；
   `~empty | (ov_r & out_ready)` 在最后一次消费后仍报有效，导致空队继续出队。
   新增独立流式测试在原版 DEPTH=2/4/8 均 FAIL；改为消费后的指针预取并同步撤销有效位后 PASS。
2. 单槽挂起会丢紧邻脉冲，UART 则覆盖旧事件；改为每源 4 槽 FIFO。
3. 原清位条件未检查哪个源被选中，多源待处理会一起清除；仅选择且中央接受时出队。
4. 原轮转表达式不能正确跳过空源，且游标缺复位；保留轮转意图，修正扫描及初始化。
5. 丢弃原本不可读；通过既有 UART 回读的保留地址开放只读饱和计数及非零状态。
   中央 FIFO 是合规保持队头的生产者，背压不计为丢弃。

## 判据

- `tb_padfast`：真实 RC pad A/B/C/D，紧邻 off→on 及三连事件，检查产生数、确认数、顺序、分配和零溢出。
- `tb_evhold`：容量、丢弃、顺序、保持有效等待的生产者、计数饱和；修正旧测试台在采样沿驱动的竞争。
- `tb_evhold_stream`：DEPTH=2/4/8，连续消费、同拍进出、反压头稳定、指针回绕。
- `tb_event_sources`：源边界四源各三拍突发，逐源字段/顺序、轮转、关闭定序器后排空、跳空源；
  阻塞下每源 10 条收 4 丢 6；解码真实 TX 验证诊断地址/值、只读及复位。
  UART RX 与 RC 输入由原 `evmerge`/`padfast` 覆盖，本测试不冒充传感器或 UART RX 实测。
- 原 `evloss/evmerge/alloc/legato/pitchmod/tdm` 针对性测试全部通过：evloss 16 条、evmerge 28 条、
  alloc/legato PASS；pitch_mod Python 判据 G1/G1b/G2/V1/V2/C1 全部通过；TDM 逐位不符 0/2495。
- `regress_all.py --full` 已启动，当前待最终汇总。日志 `sim_build/event_repair/regress_full.log`。
  padfast 已提升为硬门禁；新增 37 evhold stream、38 event sources；30/34 明确标记 INFO。

## 限制

I²C v2 和混响 0xC0 仍按既有已知失败登记；连奏首版行为没有在本次改动。
