## 先看两个关键事实（影响后面所有判断）

### 事实 A：Gowin BSRAM 支持真双端口

来自官方 `UG285-1.3.7 Gowin存储器(BSRAM & SSRAM)用户指南`（原文已在本地）：

> 「个 BSRAM 具有独立的 A、B 两个端口，具有独立的时钟、地址、数据和控 制信号，可以独立的进行读写操作，且两个端口共享一块存储空间。」

**含义**：一块 BSRAM 可以**同时被两个声部独立查表**。这直接把"BRAM 端口不够"这个常见瓶颈砍掉一半。

Tang Nano 20K 的 GW2AR-18C：**46 块 BSRAM，共 828 Kb**（≈18Kb/块）。
一张 1024 点 × 16bit 波表 = 16 Kb ≈ 正好放一块。32 个声部要 32 个端口 → 只需 **16 块**（真双端口 ×2）。**46 块够用，还有余量做效果器延迟线。**

### 事实 B：时隙预算非常宽松

- 音频采样率 ≈ 46.875 kHz
- FPGA 内部可轻松跑 100 MHz
- → 每个采样周期有 **约 2100 个时钟周期**可用

**含义**：如果用"分时复用"（一个运算单元轮流服务多个声部），每个声部分到几个周期也绰绰有余。**振荡器数量的上限不是逻辑资源，而是我们愿意投入的控制复杂度。**

这两个事实合起来意味着：**32 复音只是起点，不是天花板。**

## 对赛题指标的影响

赛题指标 = 振荡器数 × 采样率。板子大**不直接加分**，但决定：
- **能不能跑加法合成**（每个分量 1 个振荡器，最吃资源）→ 决定指标上限
- 能不能同时装下 效果器 + HDMI 可视化 + 大量声部
- 不用为了省资源而牺牲音色

## 我的观察（供参考，非结论）

- Nano 20K 的 **48 个乘法器**是硬约束。全并行 32 声部，每个声部至少要 1 个乘法器做包络，就已经 32/48 了，插值、效果器再要乘法器 → **很紧**。

- → **D1 和 D2 强耦合。如果你倾向 TDM，Nano 20K 可能够用；如果倾向全并行，Mega 60K 会更舒服。**

# 决策 D2：引擎并行架构 ★ 最关键

## 背景

这是全项目的地基。它决定：振荡器上限、延迟特性、资源占用、以及**现场能不能讲清楚**。

## 三个选项

### 选项 A：全并行（每个声部一套独立硬件）

```
voice_0: [相位累加器][波表查表][包络乘法] ─┐
voice_1: [相位累加器][波表查表][包络乘法] ─┤
   ...                                      ├→ 混音求和
voice_31:[相位累加器][波表查表][包络乘法] ─┘
```
用 `generate for` 生成 N 份，**改一个参数就改声部数**。

| | |
|---|---|
| ✅ 优点 | 延迟 = **1 个采样周期**（最低）；无控制状态机；时序直观；**答辩最好讲**；每声部物理独立，绝无"是否算独立振荡器"的争议 |
| ❌ 代价 | 资源线性增长：N 个乘法器 + N 个 BRAM 读端口（真双端口下 N/2 块）；Nano 20K 的 48 乘法器会先撞墙 |
| 上限估算 | Nano 20K：约 **32 声部**（乘法器吃紧）；Mega 60K：约 **64~96 声部** |
| 赛题风险 | 无 |

### 选项 B：时分复用（TDM，1 套运算单元轮流服务 N 个声部）

```
        ┌──────────────────────────────┐
        │  运算单元（1 套）              │
时隙0 → │  相位累加 → 查表 → 包络乘     │──→ 写入该声部状态
时隙1 → │  （同一套硬件，换一份状态）    │
 ...    │                              │
时隙K → │                              │──→ 1 个采样周期输出一次混合结果
        └──────────────────────────────┘
   声部状态（相位/包络/频率）存在 BSRAM 或寄存器堆里
```

| | |
|---|---|
| ✅ 优点 | 资源**几乎不随声部数增长**（只增状态存储）；1~4 个乘法器就够；**振荡器上限极高**（时隙预算约 2100/周期，扣掉查表/乘法流水线，理论上限 200+ 声部） |
| ❌ 代价 | 需要控制状态机与状态存储（复杂度上升）；调试更抽象（要抓时序看时隙）；延迟 = N 个时隙（仍远小于 1ms） |
| ⚠️ 赛题风险 | **中等**。赛题定义："独立发声单元为包含**独立相位累加器、频率调控、包络控制**的完整振荡器"。TDM 下每个逻辑声部**确实有**独立的相位累加器状态、频率与包络——只是运算硬件分时复用。**符合定义**，但评委可能追问"共享硬件还算独立吗？" |
| 缓解 | ① 保留"测试模式"让频谱真的出现 N 个独立谱峰（物理事实胜于争论）；② 报告里主动说明架构并论证独立性；③ 必要时保留一个"全并行小规模模式"做对照演示 |

### 选项 C：混合（分组并行 + 组内 TDM）

例：8 组并行 × 每组 16 时隙 = 128 声部；或 4 组 × 8 = 32 声部。

| | |
|---|---|
| ✅ 优点 | 在资源、时序、复杂度间取平衡；延迟可控（=组内时隙数）；乘法器用量适中 |
| ❌ 代价 | 架构最复杂，两套机制都要调 |
| 赛题风险 | 与 B 类似但更弱（并行的组本身就是独立硬件） |

## 三者对比速览

| | 全并行 A | TDM B | 混合 C |
|---|---|---|---|
| 振荡器上限（Nano 20K） | ~32 | **200+** | ~64–128 |
| 乘法器占用 | N | 1–4 | 组数 |
| 延迟 | 最低 | 低（N 时隙） | 中 |
| 控制复杂度 | **低** | 高 | 中高 |
| 答辩难度 | **低** | 中（需论证） | 中 |
| 吞吐量指标潜力 | 中 | **高** | 高 |

## 我的观察（供参考，非结论）

- **全并行是"安全牌"**：一定做得出来，一定讲得清，但指标上限被 48 个乘法器锁死在 32 左右。
- **TDM 是"高天花板牌"**：指标能翻好几倍，但要能接受并守住"共享硬件是否算独立振荡器"这个论证责任，且调试更抽象。
- **折中思路**：先按全并行做出**能响、能弹的 8~16 声部**（对应学习路线的 P1/P2），**架构上预留声部数参数**；等你看过实机效果、也更熟悉 Verilog 之后，在 P4 阶段再决定要不要改 TDM 冲高指标。
  → 这个思路的好处：**决策可以推迟，且不用返工**（两者共用同一套"声部接口"）。
- 注意：D1 与此耦合 —— 若走全并行，Mega 60K 的 118 个乘法器很值；若走 TDM，Nano 20K 就够。

## 需要你回答

1. 选 **A / B / C**？
2. 或者采纳"**先全并行保底、P4 再评估是否上 TDM**"的推迟策略？

# 决策 D3：合成算法配比

## 背景

赛题的振荡器计数规则对不同算法**计数方式不同**，导致同样的资源投入，"指标产出效率"差别巨大：

> 单波表采样查表**只计 1 个**振荡器；**加法合成按运算分量统计**；**FM 按调制运算器统计**；**物理建模按并行弦/模态单元统计**。

## 四种算法对比

| 算法 | 一个"声部"产出几个振荡器 | 单振荡器资源成本 | 指标效率 | 音色特点 |
|---|---|---|---|---|
| **波表采样** | 1 个 | 中（相位器+查表+包络乘） | 中 | 万能，靠波表决定 |
| **加法合成** | **= 分量的个数**（如 16 分量 → 16 个） | 中高（每个分量要相位器+查表+累加） | **高**（计数×N） | 风琴、钟琴、拨弦；纯净 |
| **FM 调频** | **= 调制运算器个数**（4-op 算法 → 4 个？） | 中（每个 operator 一个相位器+查表） | 中高 | 电钢琴、贝斯、金属感；经典 DX7 味 |
| **物理建模** | **= 并行弦/模态单元数** | **低**（一条延迟线 + 滤波 + 衰减） | **最高** | 吉他/竖琴/拨弦，极其自然 |

## 我的观察（供参考，非结论）

- **性价比之王可能是"物理建模（Karplus-Strong）"**：一根弦的成本主要是一段 BSRAM 延迟线（几百点到几千点）。Nano 20K 的 828Kb 里，若每根弦用 1~2Kb 延迟线，能塞进**几十到上百根弦**，而每根弦**都计 1 个振荡器**。而且拨弦音色天然好听、演示讨喜。
- **加法合成计数最"赚"但最贵**：16 分量 = 16 个振荡器，但也要 16 套相位器+查表。适合只给 **2~4 个特色音色**用。
- **波表是主力**：音色覆盖广、成本可控，适合承担"复音数 ≥32"的基础指标。
- 一个可能的配比思路（仅示例，供你参考以扩大选项）：

| 角色 | 算法 | 声部数 | 振荡器数 |
|---|---|---|---|
| 复音主力 | 波表 | 32 | 32 |
| 拨弦音色 | 物理建模 | 8 根弦 | 8 |
| 特色音色 | 加法（每音 8 分量） | 2 | 16 |
| 电声音色 | FM（4 operator） | 2 | 8 |
| **合计** | | | **≈64** |

## 需要你回答

1. 你想**主推哪种音色风格**？（这决定算法配比）——例如：管风琴感 / 电子琴 / 拨弦民乐 / 合成器音色 / 都要
2. 是否接受"多算法混合"？（更复杂，但指标与音色都更好）

> 如果你暂时说不清音色偏好，也可以先选"波表为主 + 物理建模拨弦为特色"这个低风险组合，后面再加。

# 决策 D4：采样率与音频时钟

## 背景

赛题不指定采样率。它影响音质、时序余量、TDM 时隙预算。

## 选项对比

| | **A. 46.875 kHz** | **B. 48 kHz** | **C. 更高（96 kHz）** |
|---|---|---|---|
| 时钟来源 | 27 MHz 整数分频（已算好，**零附加复杂度**） | 需板载 **MS5351** 时钟芯片出精确 1.536 MHz | 同 B，需更高频 |
| BCK | 1.5 MHz | 1.536 MHz | 3.072 MHz |
| 音质 | 优于 CD（44.1k） | 标准 | 更好（但人耳增益有限） |
| 时序余量 | **最好**（时钟低） | 好 | 差（时钟高） |
| TDM 时隙预算（100MHz 内部钟） | **~2100/周期** | ~2083/周期 | ~1041/周期 |
| 对指标影响 | **不影响**（振荡器数×采样率，采样率×2 → 声部上限÷2，乘积持平） | 同 | 同 |
| 复杂度 | 低 | 中（要配 MS5351） | 中高 |

## 关键洞察

**采样率对最终指标（振荡器数 × 采样率）是"中性"的** —— 采样率翻倍，TDM 能塞的声部就减半，乘积不变。它主要影响：

- **音质**（46.875k 已足够，无需上 96k）
- **时序余量**（越低越好做）
- **实现复杂度**（46.875k 无需碰 MS5351）

→ 我倾向 **A**，理由是"零复杂度 + 时序余量最大 + 音质已达标"。但这是你的决定。

# 决策 D5：相位位宽 / 波表深度 / 插值

## 背景

这三项共同决定**音准精度**与**音色失真度**，也影响 BSRAM 占用。

## D5-1 相位累加器位宽

| 位宽 | 频率分辨率 @46.875kHz | 说明 |
|---|---|---|
| 20 bit | 0.045 Hz | 已远超需求（人耳分辨 <0.5Hz） |
| 24 bit | 0.0028 Hz | 常规选择 |
| **32 bit** | 0.000011 Hz | 教科书标准；TDM 下几乎免费（只有 1 套加法器） |

**关键**：若选 TDM（D2-B），位宽成本趋近于零 → 直接上 32 bit。
若选全并行，32 个 32bit 加法器 = 约 1024 个 FF，Nano 20K 的 15552 FF 里占 6.6% —— 也可接受。

## D5-2 波表深度

| 深度 | 单表大小(16bit) | 正弦 THD 量级 | BSRAM 占用（每份副本） |
|---|---|---|---|
| 256 | 4 Kb | 约 −48 dB（一般） | 1/4 块 |
| 512 | 8 Kb | 约 −54 dB | 1/2 块 |
| **1024** | 16 Kb | 约 −60 dB | 1 块 |
| 2048 | 32 Kb | 约 −66 dB | 2 块 |

> 若要**多个音色**，每个音色一份表 → 深度 × 音色数 才是总占用。真双端口下，2 个声部共用 1 份表。

## D5-3 是否插值

| | 无插值 | 线性插值 |
|---|---|---|
| 音质 | 有阶梯噪声，需更深表 | **可用 256 表达到接近 1024 无插值的质量** |
| 成本 | 0 | 每次查表多 1 次乘加（或移位近似） |
| 建议 | 表深 ≥1024 时可省 | 想省 BSRAM 又想好音质时用 |

## 我的观察（供参考，非结论）

- **最高效组合**：相位 32 bit + 波表 **1024 点 + 线性插值** + 多音色各一份表
  - BSRAM 占用：4 音色 × 16 Kb = 64 Kb（只占 828 Kb 的 8%），**非常宽裕**
  - 音质足够好，且给效果器延迟线留足空间
- **更省的组合**：相位 24 bit + 波表 256 点 + 线性插值 —— 占 4 Kb/音色，但需要更多插值逻辑

## 需要你回答

1. 相位位宽选多少？（20 / 24 / 32）
2. 波表深度？（256 / 512 / 1024 / 2048）
3. 要不要线性插值？

> 若你说"你定"，我按"32bit + 1024 + 插值"执行并记录理由。
