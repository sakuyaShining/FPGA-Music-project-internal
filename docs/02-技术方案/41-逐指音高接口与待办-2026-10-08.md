# 逐指位置 → 所属声部音高：接口增量与待办

日期：2026-10-08。此前交付检查点：8e8c5ce。本页区分可仿真的数字接口与真实触控演奏。

## 本次用户决定

- 左手位移直接控制音高，多指各自控制所属音符的表情。
- 保留往返手势控制自动颤音深度、速率的扩展需求；先实现直接跟手路径，往返自然产生手动颤音。
- 自动颤音辅助的算法、强度、进入与停止规则尚未冻结，本次不实现自动意图判断。
- 右手多指强调的增益、上限、新音继承保留修饰的规则仍待讨论。
- 音符使用默认音色预设，实体按钮控制预设；实体机提供保存修饰的编辑模式。
  每音符独立默认预设还是共用当前选中预设、保存目标槽以及断电保持介质，尚需明确。

## 已增加的实际代码

1. `finger_pitch.v`：显式触点 ID 与实际分配声部绑定，绑定时记录位置锚点；移动只更新该组的频率比例。
2. `note_map.v`：新增声部分配/释放通知，供上游确定绑定目标并撤销旧所有权；谱刷新不产生分配通知。
3. `tdm_engine.v`：新增可选逐组位置表达输入，复用已有相位增量比例乘法；每组第一泛音采样表达，后续泛音使用同一份快照。
4. `tdm_top.v`：通过 `FINGER_EXPR=1` 接通绑定模块与引擎。默认值为 0，以保持旧测试与当前板级输入兼容。
5. `tdm_ship.v`：新控制输入接零，没有新增板级引脚；当前出货包装未接连续触控传感器，不能称为实物逐指滑音已完成。

直接表达生效时，该组以触点位置为准，不叠加旧自动 portamento 或全局 LFO。
未绑定的组仍使用原调制路径。振荡器相位连续，位置移动不发送 note-on，不重置包络或修改基础音符编号。

## 接口合同与暂定映射

接口工作在 FPGA 主时钟域；上游必须完成 CDC、触点追踪及坐标标定。它不是 I²C 协议或新 UART 命令。

| 信号 | 含义 |
|---|---|
| `voice_valid/on/group/note` | 分配器正在提交组表更新的通知；不是全部 16 泛音已加载完成的确认 |
| `finger_valid` | 本拍执行一条表达命令，连续拍可接收命令 |
| `finger_cmd=0` | 将 `finger_id` 绑定到 `finger_group`；位置作为锚点 |
| `finger_cmd=1` | 更新该 ID 的绝对位置；更新命令不使用 group 字段 |
| `finger_cmd=2` | 撤销该 ID 所有权，保持尾音最后音高；不代替 note-off |
| `finger_position` | 有符号 12 位标定位置，暂定 256 单位对应一个八度 |

绑定必须等目标组 active 已有效。没有绑定、非法操作码、非活动组绑定不会改变表达；
本接口没有命令队列或接收确认，不可把任意乱序历史帧当作实时位置输入。
上游必须按时间顺序提供触点更新，完成触点离开/ID 重用处理，并避免把过期绑定命令送给已复用的组。
同拍的分配/释放通知优先于表达命令。

映射为 `ratio = 2^((position-anchor)/256)`，使用生成的 Q16 查表；当前限制为上下各一八度。
一位置单位约 4.6875 音分，这是数字接口的临时分辨率，不是已确定的面板毫米量程或最终手感。
回到锚点即回到基础音高。保持不动不自动归零；往返位置直接产生手动颤音。
传感器噪声、平滑、灵敏度与更细位置分辨率，需要实测后调整。

声部 note-off 撤销绑定，释放尾音保持最后表达；新 note-on（包括同音重触发和抢占）清除旧表达。
这些是本轮工程默认规则，仍需上板试听。触点解绑本身不改变发声方式。

## 验收范围

命令：`python tools/scripts/finger_pitch_check.py`。

- 单元：组 0 与 31 独立更新、锚点、正负位移、上下限、解绑、重绑、分配同拍竞态、非活动组拒绝、复位。
- 集成：真实 `tdm_top` 分配两个不同音符，再按通知绑定；验证 16 泛音相位增量的独立宽位乘法参考。
- 连续位置在组遍历途中更新，不将同一音符泛音拆成两代比例；验证 3584 个遍历拍，无重新起音。
- note-off 后重新分配，旧触点移动无法控制复用组。
- 实际装满 32 个声部后验证第 31 组的表达与全部泛音，再验证正在受控的第 0 组被抢占后旧所有者失效。

启用表达的独立综合探针已通过 Gowin synthesis（不修改原工程输出目录）；
Logic 17910/20736（87%）、Register 4932/15750（32%）、BSRAM 31/46（68%）、Latch 0。
探针是仿真/综合接口包装，不是经过板级引脚约束和 PnR 的出货顶层。
原有 pad_pitch 位宽警告和未接物理输入的 strip_ctrl 优化警告保留；新模块的 ROM 字宽及地址截断警告已修正。

日志在 `sim_build/finger_pitch/`。这些是数字输入仿真，不证明真实位置识别、两指交叉跟踪、压力、试听、10ms 延迟或新功能 PnR。
旧检查点的 PnR 数字不继承到当前源码。默认关闭表达的板级包装不代表已验证启用表达后的资源与时序。
