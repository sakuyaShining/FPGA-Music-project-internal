# 触控原型验证程序（四个问题）

**2026-10-10最新约束：只使用Tang Nano20K FPGA进行应用计算。以下PSoC固件/到货/接线步骤为历史计划，不能执行为当前原型路线。PSoC数量0，其他MCU及外部坐标/ID计算也不允许；新的原始测量前端、FPGA扫描与追踪须另建可验证实验方案。**


> 2026-10-10适用性标记：下文是旧MPR121实验方案，不是当前施工指令。当前使用PSoC双形态比较，见`project/touch-decision-20261010.md`；采购见24号清单。电容接触面积不等于压力，旧档数/100Hz结论不能签收真实力度、连续位置或整机10ms。

> 目的：在**画 PCB 之前**，用一个晚上的实验回答四个问题，它们直接决定"表情"能做到什么程度。
> 执行者：硬件组装的同学。**不需要等 FPGA 侧的 I²C 驱动完成**——本实验用独立工具读芯片。
> 标【对照数据手册】的寄存器地址与参数，请在动手前核对一遍。

## 1. 物料

| 物料 | 数量 | 说明 |
|---|---|---|
| 电容触摸控制器模块（MPR121 等） | 1 | 12 通道即可，不必用四片 |
| **USB 转 I²C 适配器**（CH341A 一类）或树莓派 | 1 | **关键**：让本实验不依赖 FPGA |
| 手工触点 | 5–6 个 | 铜箔贴在洞洞板上，或用现成的小铜片 |
| 细导线、烙铁 | — | 导线焊到铜箔上（铜箔胶带的胶面通常不导电） |
| 万用表 | 1 | 查通断 |
| 上拉电阻 4.7 kΩ | 2 | SDA/SCL 上拉 |

**接线**：适配器 SDA/SCL ↔ 模块 SDA/SCL（各加上拉）；模块 VCC/GND ↔ 适配器 3.3 V/GND；触点分别接到模块的通道输入。

## 2. 通用方法

1. 用适配器把模块初始化（上电、软复位、使能各通道）【对照数据手册】
2. 周期性读取**每个通道的滤波数据寄存器**（10 位，低字节在前）【对照数据手册】
3. 把读数与时间戳落到 CSV：`时间, 通道0, 通道1, ...`
4. 后续用 Python 直接算均值和极差

采样脚本建议写成可复用的：`tools/scripts/pad_probe.py`（本次实验用，不必进闸口）。

## 3. 四个问题

### 问题 1：轻碰 vs 实按，读数差几档

| 步骤 | 做法 |
|---|---|
| 1 | 手指**离开**模块，采 50 个样本（基线） |
| 2 | **指尖轻碰**该触点，采 50 个样本 |
| 3 | **指腹实按**，采 50 个样本 |
| 4 | **整根手指平贴**（尽量覆盖整个触点），采 50 个样本 |

**计算**：

```
动态范围 = 均值(整指) − 均值(指尖)
噪声     = 各手势 50 个样本极差的平均
可区分档数 ≈ 动态范围 ÷ 噪声
```

**判据**：

| 项 | 要求 |
|---|---|
| 可区分档数 | **≥ 4**（做 16 级力度的最低要求），≥ 8 更好 |
| 单调性 | 指尖 < 指腹 < 整指（顺序不能乱） |

**同时记录**：每种手势的原始均值（后面算档距要用）。

### 问题 2：同一力度重复十次，散多大

| 步骤 | 做法 |
|---|---|
| 1 | 用"指腹实按"这一种手势 |
| 2 | **完全抬手**，再按，重复 10 次 |
| 3 | 每次记录该通道稳定后的均值 |

**计算**：10 次的极差 ÷ 问题 1 得到的档距。

**判据**：

| 项 | 要求 |
|---|---|
| 重复性 | 极差 **< 1 个档距** |
| **基线恢复时间** | 记录数值（抬手到读数回到基线 ±噪声的时间） |

第二条同样重要：**恢复慢会导致快速重复音的第二下变轻**。

### 问题 3：相邻键被按，本键漂多少

| 步骤 | 情形 |
|---|---|
| 1 | 按住**紧邻**的触点，读本触点 |
| 2 | 按住**隔 1 个**的触点，读本触点 |
| 3 | 按住**隔 2 个**的触点，读本触点 |
| 4 | **两指同时**按相邻两个触点，读第三者的漂移 |

**计算**：漂移量 ÷ 档距，得到一张耦合衰减表。

**判据**：

| 项 | 要求 |
|---|---|
| 邻键漂移 | **< 半个档距** |
| 两指同时 | 不产生假的第三点触发 |

### 问题 4：全通道轮询一圈要多久

| 步骤 | 做法 |
|---|---|
| 1 | 连续读取全部 12 通道，记录一次完整轮询的耗时 |
| 2 | 若有 IRQ 引脚【对照数据手册】，测"触摸到 IRQ 拉低"的延迟 |
| 3 | 用逻辑分析仪看 I²C 时序，确认没有时钟拉伸导致的卡顿 |

**计算**：

```
单通道更新率 = 1 ÷ (一次完整轮询耗时)
估算四片（38 通道）下的等效更新率
```

**判据**：

| 用途 | 需要 |
|---|---|
| 音符开关 | ≥ 100 Hz |
| 力度（起音瞬间取一次） | **起音不能被漏掉**（所以 IRQ 很关键） |
| 键间滑动式滑音 | ≥ 100 Hz 足够（滑过 12 键约 200–400 ms，可得 20–40 个采样点） |
| 真正连续位置 | 需要远高于此，**不建议依赖** |

## 5. 结论如何映射到表情方案

| 实测结果 | 表情方案 |
|---|---|
| 档数 ≥ 4 且重复性 < 1 档 | **力度 + 触后都从按键本身来**（颤音深度挂在触后上） |
| 档数 < 4 或重复性差 | 力度用固定值；表情改由**显式通道**（拇指条/脚踏）提供 |
| 更新率 ≥ 100 Hz | 键间滑动式滑音可用 |
| 更新率偏低 | 滑音只做"键间跳变 + 引擎平滑"（引擎已支持） |
| **无 IRQ 引脚** | **架构要重算延迟预算**——可能必须换器件 |
