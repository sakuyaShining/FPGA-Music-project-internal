## 1.2 每一步的验收原则（三条，不可妥协）

1. **必须有可重复的仿真证据** —— 不能是"看起来对"
2. **必须有数值断言** —— 不是看波形"差不多"，是脚本比对出 0 差异 / 误差在阈值内
3. **必须有综合报告** —— 每步都要跑一次 PnR，记录资源与时序增量

## 1.3 "没板子怎么证明它工作"——统一答案

| 手段 | 说明 |
|---|---|
| **闭环自检** | 把输出重新解码回输入，逐位比对（I2S 用这招最强） |
| **Python 镜像** | 算法在 Python 里有一份逐位一致的模型 |
| **参数化测试台** | 同一份 tb 换参数跑多组，自动断言 |
| **综合报告** | 资源与时序是硬证据，不依赖板子 |

# 二、三条设计纪律（贯穿全部步骤）

这三条**不是额外工作量，是接口写法**。它们决定"天花板能不能接上来"。

## 纪律 1：振荡器单元无状态

```
接口 = "给我 inc，还你一个正弦样本"
相位存哪里，由外层决定：
  · 并行  → 寄存器数组
  · TDM   → BSRAM + 时隙调度
```
**理由**：当前 `osc_additive.v` 里 `phase[]` 与运算通路缠在一起。不改的话，
将来上 TDM 要重写引擎；改了，TDM 只是一次接线改动。

## 纪律 2：幅度来源可替换

```
引擎只管"取第 k 个泛音的幅度"，不管它从哪来
常量 → 寄存器 → 频谱包络发生器（三级替换，引擎一行不改）
```
**理由**：频谱参数化是预定的"天花板"，必须能加法式接入。

## 纪律 3：包络按"可时分复用的槽"设计

```
不要写："第 3 号声部的包络"（状态内嵌）
要写成：状态进 / 状态出，一次处理一个槽
```
**理由**：同纪律 1。

> **三条合起来是一件事：状态与运算分离，且输入可替换。**

## 步骤 2 · 时钟架构 + 时序约束（1.5 天）

### 为什么这步必须在前面
- **全项目目前一个 `.sdc` 都没有**——所有时序数字都是工具猜的，不可信
- I2S 需要 BCK，而 BCK 必须与采样率整数相关，否则有抖动
- TDM 决策（步骤 4 之后）需要知道 **108 MHz 到底收不收得住**

### 交付物
- `src/constr/osc_additive_top.sdc` —— 真正的时序约束
- `src/rtl/clk_gen.v` —— rPLL 例化 + 分频链
- `src/gowin/` 下的 rPLL IP（由 IP 向导生成）
- 时钟树说明文档

### 时钟链（已验证的推导）
```
27 MHz 晶振
  └─ rPLL ─→ 108 MHz      IDIV_SEL=0 / FBDIV_SEL=3 / ODIV_SEL=4
                          fVCO = 108 × 4 = 432 MHz ∈ [400, 1200] ✓
      ├─ ÷72   ─→ 1.5 MHz  = BCK（46875 × 32）
      └─ ÷2304 ─→ 46875 Hz = LRCK / 采样率
```
> rPLL 公式（已解开的悬案）：`fCLKOUT = fCLKIN × (FBDIV_SEL+1) / (IDIV_SEL+1)`

### 验收标准
1. 27 MHz 下当前设计 **slack ≥ 0**（真实约束，非工具猜测）
2. 108 MHz 尝试收敛，**给出明确的"能/不能"结论与 slack 数字**
3. 分频链仿真：BCK/LRCK 的频率与相位关系正确（LRCK 边沿与 BCK 计数对齐）
4. 复位同步：跨时钟域复位释放正确

### 无板证明方式
时序报告（报告 slack、关键路径）+ 分频链仿真波形

## 步骤 3 · I2S 发送器（2 天）

### ✅ 目标器件已确认：MAX98357A（I2S 输入 DAC + D 类功放）

出处：`src/constr/tangnano20k.cst` 第 49–53 行；`docs/02-技术方案/02-硬件bringup-TangNano20K音频通路.md`

| 项 | 结论 | 对我们的影响 |
|---|---|---|
| **需要 MCLK 吗** | ❌ **不需要** | 少一根时钟线，I2S 发送器可以很干净 |
| **需要 I2C 配置吗** | ❌ **不需要** | 省掉整个配置状态机 |
| 支持采样率 | 8 kHz – 96 kHz | 46875 Hz ✅ 在范围内 |
| BCK/LRCK 比 | 支持 32× | 1.5 MHz / 46875 = 32× ✅ |
| 声道 | **单声道**（D 类功放只有 1 路） | 立体声效果（合唱/混响宽度）需外接 DAC |
| 使能 | `PA_EN`（引脚 51）= SD_MODE，高电平有效 | 上电先拉高 |
| 音量 | 官方 README 标注 "A bit loud" | **调试时先压低幅度**，避免烧喇叭/扰民 |

> **这是最省事的一种情况**：免 MCLK、免 I2C。步骤 3 的估算从 2 天下调到 **1.5 天**。

### ⚠️ 但有一个必须查证的问题：**MAX98357A 的固定延迟**

MAX98357A 内部有数字处理（去加重、立体声混合），**存在固有的群延迟**。
M4 要求端到端延迟 ≤10 ms，**这个延迟必须算进去**。

- 待办：查 MAX98357A 数据手册的 propagation delay / group delay 规格
- 若延迟偏大，可考虑：提高采样率、或改用无内部处理的纯 DAC 模块
- **不影响本步实现**，但影响 M4 的最终数值是否达标

### 交付物
- `src/rtl/i2s_tx.v` —— I2S 发送器
- `src/sim/tb_i2s_tx.v` + **闭环解码脚本**
- 中文设计说明

### 验收标准
1. **闭环自检**：用脚本把 I2S 串行流**解码回样本**，与源样本**逐位一致**
2. 时序符合 I2S 标准：WS 在 BCK 下降沿变化、MSB 领先 WS 一个 BCK 周期、左右声道正确
3. 采样率精确 = 46875 Hz（无抖动）
4. 输出接饱和限幅后的 24 bit 样本，截取到 16/24 bit 的位对齐正确

### 无板证明方式
**闭环解码比对**——这是本计划里最强的证据形式：
串行流 → 解码 → 与源样本 0 差异，等于证明了整条输出通路

## 步骤 5 · RTL 内置测试模式（1 天）

### 交付物
- `src/rtl/test_mode.v` —— 测试音发生器 + LFSR 随机触发
- FFT 分析脚本

### 设计要点
赛题 F1/R3 原文要求「测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰」。

**加分设计（成本极低，专打 R3）**：
> 用 RTL 内置 **LFSR 随机触发**音符序列（音高、时刻、泛音数都随机）。
> 于是**预录在原理上不可能匹配**——你没法提前录一段你都不知道会响什么的音频。

### 验收标准
1. 设定 N 个泛音 → 频谱出现 **N 个独立谱峰**，峰位与理论值误差 < 半个 FFT 格
2. N 可运行时设定，逐个验证 N = 4/8/16/32
3. LFSR 序列可复现（固定种子 → 固定序列），便于复检
4. **A/B 独立性实验**：只改第 k 个泛音参数 → 只有第 k 个峰移动

### 无板证明方式
FFT 频谱图 + 峰位误差表 + 可复现的随机序列
