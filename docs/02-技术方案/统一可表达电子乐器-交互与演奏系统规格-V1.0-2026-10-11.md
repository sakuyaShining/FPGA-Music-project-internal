# 统一可表达电子乐器：交互与演奏系统规格 V1.0

**项目**：FPGA-Music-project  
**目标硬件**：Tang Nano 20K  
**日期**：2026-10-11  
**文档状态**：设计基准线候选，等待项目正式冻结  
**设计策略**：兼容既有实现，统一音乐语义，分阶段交付

---

## 0. 总体设计决策

### 0.1 产品定义

本项目是一台以 FPGA 为实时计算核心的多指可表达电子乐器。

它不以完整复制某一种传统乐器为唯一目标，而是希望通过统一的音符控制、激发机制、音色塑造及声音生成接口，表达多种传统乐器的典型演奏行为，并创造新的演奏方式。

**核心交互关系：**

- 左手负责音符的触发、释放、独立音高及连续音高变化。
- 右手负责泛音结构的实时塑造与状态保持。
- 乐器预设决定激发机制、基础音色、包络及演奏响应。
- FPGA 负责真实触控处理、音乐状态计算、声音合成及实体可视化。
- 上位机负责精细编辑、预设管理、测试和临时键盘演奏，不参与音频样本实时计算。

### 0.2 功能收敛

| 功能 | 本版决定 | 阶段 |
|---|---|---|
| 左手独立多指演奏 | 保留并完善 | V1 |
| 左手连续滑音、手动颤音 | 保留并完善 | V1 |
| 右手多触点泛音强调 | 保留并完善 | V1 |
| 右手松手保持 | 保留 | V1 |
| 全和弦音色修饰 | 默认方案 | V1 |
| 持续 / 瞬间 / 混合激发 | 统一为激发策略 | V1 |
| 基础谱、修饰状态、编辑草稿分离 | 保留 | V1 |
| 双 Part 独立音色 | 架构预留，后续启用 | V1.1 |
| 右手逐音符修饰 | 不进入当前产品需求 | 后续研究 |
| 加法合成以外的声音模型 | 统一接口，逐步扩展 | V2 |
| 真实乐器物理建模 | 独立后端研究 | 长期 |

**关键决定：V1 采用单一全局音色修饰范围，不为双 Part 提前增加完整的演奏交互复杂度。**

但数据结构可以保留 `part_id`，使未来的分区功能不必推翻音符状态管理。

### 0.3 设计的五个基本维度

任何一种可支持的乐器行为，都通过以下维度描述：

| 维度 | 定义 | 默认实现 |
|---|---|---|
| Excitation | 如何向声音系统输入能量 | 持续、瞬间、混合 |
| Generation | 如何产生振荡与共鸣 | TDM 加法合成 |
| Pitch | 音高如何确定与改变 | 左手多指连续控制 |
| Timbre | 泛音组成及其变化 | 基础谱 + 右手修饰 |
| Control | 动作如何绑定音符、分区及状态 | 独立身份、作用范围、锁存 |

这些维度具有统一接口，但不要求物理过程完全独立。未来物理建模后端可以包含激发器与共振器之间的反馈耦合。

## 1. 整体演奏架构

### 1.1 数据流

系统分为六层：

**第一层：物理输入层**

负责取得触点的原始观测，包括存在状态、位置、通道数据及测量质量信息。

**第二层：触点追踪层**

负责坐标估计、滤波、身份分配、移动追踪、离开判断及异常恢复。

**第三层：演奏语义层**

将连续触点轨迹转化成音符事件、音高更新、泛音修饰和控制命令。

**第四层：乐器状态层**

保存音符状态、音色预设、激发策略、右手修饰与配置状态。

**第五层：声音生成层**

根据当前乐器状态产生音频样本。第一版沿用 TDM 加法合成架构。

**第六层：输出与观察层**

包括音频效果、I2S 输出，以及 FPGA 端的演奏状态观察。

### 1.2 模块边界

建议在逻辑上保持以下模块：

| 模块 | 职责 |
|---|---|
| `touch_frontend` | 获取原始触控观测 |
| `touch_tracker` | 坐标、触点 ID、轨迹 |
| `left_controller` | 音符触发、释放、音高 |
| `right_controller` | 泛音目标选择、强调量与保持 |
| `voice_manager` | 音符身份、声部分配、生命周期 |
| `instrument_state` | 预设、激发策略、基础谱 |
| `timbre_manager` | 合成全局或分区泛音修饰 |
| `excitation_engine` | 产生激发与包络控制参数 |
| `synthesis_backend` | 音频生成，首版为 TDM |
| `performance_monitor` | 演奏事件、轨迹、状态观察 |

这些是**逻辑职责边界**，不是要求立即新增十个 RTL 文件。

现有 `note_map`、`tdm_engine`、`osc_env` 等模块可以通过明确接口逐步承担这些职责。是否拆分文件应由实际耦合度与测试边界决定。

## 2. 左手交互规格

### 2.1 基本目标

左手是一个**多指独立音符控制器**。

一个手指对应一个独立的演奏身份，该身份在整个触摸生命周期内保持稳定。

核心关系：

`finger_id → note_id → voice_id`

- `finger_id`：物理触点身份。
- `note_id`：一次音乐音符生命周期的身份。
- `voice_id`：实际执行声音计算的硬件逻辑声部。

三者不应直接视为同一概念。

一个音符即使已经脱离手指，也可能继续保留释放尾音，因此音符生命周期与触点生命周期必须解耦。

### 2.2 左手事件

| 动作 | 音乐事件 | 行为 |
|---|---|---|
| 有效落指 | `NOTE_ON` | 创建音符并启动激发 |
| 持续接触 | `NOTE_HOLD` | 保持音符身份 |
| 连续移动 | `PITCH_UPDATE` | 修改所属音符的音高 |
| 往返移动 | 连续 `PITCH_UPDATE` | 形成手动颤音 |
| 正常离开 | `NOTE_RELEASE` | 解除手指归属，按激发策略处理声音 |
| 重新落指 | 新 `NOTE_ON` | 创建新的演奏生命周期 |

**禁止将正常滑动错误解释为连续的 NOTE_ON。**

### 2.3 音高映射

默认采用基于触点位置的连续音高映射。

初次落指决定初始音高，之后同一手指的位置变化持续控制音高。

支持两类映射策略：

**Absolute Pitch：绝对位置模式**

触点的空间位置直接对应音高。适合连续音高演奏、滑奏及实验性乐器。

**Anchored Pitch：锚定音符模式**

初次落指确定一个基准音符，后续位移控制相对音高偏移。适合旋律演奏、传统音阶及受限音程滑音。

V1 优先保证 Absolute Pitch 的连续链路，同时在映射接口保留 Anchored Pitch 选择。

音高映射可以采用查找表或其他定点近似实现，但必须保证单调性、边界稳定性及足够的音准精度。

### 2.4 多指所有权规则

1. 不同有效手指具有独立音符身份。
2. 两个手指可以演奏相同音高，但仍应具有不同音符生命周期。
3. 手指交叉不自动交换音符所有权。
4. 手指短暂丢失时进入追踪宽限状态，不应立即创造新音符。
5. 超过追踪超时后解除绑定，防止永久卡音。
6. `finger_id` 被重新使用时，不得继承不属于它的旧音符。
7. 同一音符身份不得由两个硬件 Voice 同时无意执行。
8. 不足以判断身份的场景必须有确定的拒绝或恢复行为。

V1 默认不抢占仍被手指拥有的活动 Voice。声部耗尽时拒绝新音符并报告事件；未来可以研究安全的尾音声部回收策略。

### 2.5 左手其他表现能力

**滑音**直接来自位置变化。

**手动颤音**直接来自往返移动，其幅度与速度由用户动作形成，不强制启用 LFO。

**自动颤音**可作为未来可关闭的辅助效果，但不得覆盖手动滑音的基础语义。

**力度**必须与触摸位置分离。当前既有 RC 开关不能证明能够测量真实压力。V1 可以使用预设起音力度、上位机输入力度或经验证的传感数据，不得伪造压力连续性。

## 3. 右手交互规格

### 3.1 基本定位

右手是一个**多触点、可保持状态的泛音塑造控制器**。

V1 默认作用于所有正在发声的音符，包括仍具有可听释放尾音的声部。

右手不改变左手音符的：

- 音符身份与所有权；
- 基础音高；
- 左手产生的音高偏移；
- 原有力度状态；
- 激发和包络生命周期。

右手可以改变的是这些音符共享的泛音修饰参数。

### 3.2 三种音色数据

必须分开保存：

| 状态 | 含义 | 修改者 |
|---|---|---|
| Base Spectrum | 基础泛音配置 | 预设、配置模式、上位机 |
| Performance Modifier | 演奏修饰状态 | 右手实时交互 |
| Edit Draft | 尚未提交的编辑草稿 | 上位机或实体配置模式 |

**右手不直接覆盖 Base Spectrum。**

按下恢复操作，只清除当前演奏修饰，不破坏用户保存的基础配置。

编辑草稿需要明确执行 Apply，才成为新的正式配置。

### 3.3 泛音的控制粒度

合成核心保留 16 个独立泛音幅度参数。

演奏面不强制提供 16 个独立物理控制器，而是使用一个可配置的映射层：

`Touch Region → Harmonic Group → Harmonic Weights`

建议 V1 初始采用 8 个逻辑控制组：

| 控制组 | 初始映射 |
|---|---|
| G1 | 第 1 泛音 |
| G2 | 第 2 泛音 |
| G3 | 第 3 泛音 |
| G4 | 第 4 泛音 |
| G5 | 第 5～6 泛音 |
| G6 | 第 7～8 泛音 |
| G7 | 第 9～12 泛音 |
| G8 | 第 13～16 泛音 |

这是一份便于试听的默认映射，不是已经被证实最合理的声学分组。

逻辑上允许使用一张 8×16 映射表，使演奏控制组的数量与最终 16 条泛音的实际分配解耦。

电脑编辑器始终可以独立修改 16 条基础泛音。

### 3.4 泛音强调语义

右手默认执行 **Boost Existing Components**。

它强调已经存在的谱分量，而不是将原本为零的泛音直接创造出来。

建议采用乘性强调及饱和保护：

`effective[k] = normalize(base[k] × (1 + depth × modifier[k]))`

要求：

- `base[k] = 0` 时，该分量仍为零。
- 没有修饰时，应精确恢复基础谱。
- 对同一组的修饰可以增加，也可以减少到无修饰状态。
- 混音和音色修饰不得产生不可控的定点溢出。
- 在改变谱结构时尽量限制不必要的响度突变。
- 幅度归一化或补偿不能错误重写音符的力度与包络状态。

这里的 `normalize` 是待设计的有界幅度处理函数，不意味着必须将每一个音色强制归一到完全相同的感知响度。

### 3.5 右手连续控制手势

建议的最终控制面是多个可定位的泛音控制区。

如果传感前端能提供稳定的二维位置，则：

- 横向位置用于确定泛音控制组。
- 纵向位移用于增加或减少该组的修饰强度。
- 触摸建立后，控制组归属保持到该手指离开。
- 新触摸从该组当前保持值开始编辑。
- 松手后保留最后有效参数。

采用**相对位移控制**，避免手指刚刚落下就使原本保持的泛音幅度突然跳到另一个绝对值。

例如，某组当前强调强度为 40%：

- 手指落下，只选中该组。
- 向上移动，强调逐渐增加。
- 向下移动，强调逐渐减少。
- 松手，保留最终强度。

右手连续性来自可测量的触点位置，**不应把 RC 电极的读数直接当成已验证的真实按压力度**。

如果第一版实体面板只能提供二值触摸，可先通过离散步进编辑建立功能原型，但不能把这种替代操作认定为最终连续演奏已实现。

### 3.6 多触点组合规则

建议 V1 采用**每组单编辑所有权**。

- 多个手指可以同时编辑不同泛音组。
- 第一个接触某组的有效触点取得该组的编辑所有权。
- 后续触点如果同时尝试编辑该组，不改变当前所有者。
- 原所有者释放后，该组可由新的触点接管。
- 每个泛音组始终只有一个明确的当前写入来源。

这样不需要复杂的数值争用和时间顺序冲突处理。

### 3.7 松手保持规则

每组泛音修饰拥有自己的保持值。

| 事件 | 状态变化 |
|---|---|
| 手指落下 | 锁定控制组，载入当前保持值 |
| 手指移动 | 连续更新该组目标修饰 |
| 手指离开 | 锁存最后有效修饰 |
| 其他手指离开 | 不影响已锁存的其他组 |
| 所有右手手指离开 | 整体音色维持最后结果 |
| 新左手音符加入 | 自动继承当前全局修饰 |
| 触摸追踪异常终止 | 提交最后可信数值并释放编辑所有权 |
| RESET | 平滑清除指定范围的修饰 |

**重要：部分松手不清除已经修改的泛音。**

这使“松手保持”在单指、多指和部分释放情况下保持一致，而不需要特殊解释。

### 3.8 RESET 与保持控制

右手无需额外按下 HOLD 才能保持泛音。

保持是正常演奏语义。

RESET 则是明确的恢复命令：

- 短按：清除当前目标范围的演奏修饰。
- 恢复过程进行短时间平滑，避免声音突变。
- 不删除基础谱。
- 不修改已经保存的预设。

右手保持与左手音符持续必须是两种不同状态，避免把两者都称为 HOLD 而造成歧义。

## 4. 激发系统：统一持续、瞬间与混合

### 4.1 激发与音符所有权分离

乐器中必须明确区分：

**手指是否还在控制这个音符**

和

**这个音符是否还在发声**。

这两件事不总是同步。

例如钢琴型瞬间激发：

- 落指时激发声音。
- 手指按住时声音仍然可以自然衰减。
- 手指离开后，声音也可能继续有释放尾音。

因此一个 Voice 的完整生命周期不应仅由 `finger_active` 决定。

### 4.2 三种激发策略

| 模式 | Note On | 持续按住 | Note Release |
|---|---|---|---|
| Continuous | 开始起音 | 保持连续驱动 | 结束持续驱动，进入释放 |
| Impulse | 触发一次能量注入 | 自然衰减，不重复激发 | 根据阻尼策略处理剩余振动 |
| Hybrid | 同时启动瞬态和持续成分 | 瞬态衰减、持续成分保持 | 停止持续成分，处理剩余尾音 |

### 4.3 Continuous 模式

用于管风琴式、持续合成器式音色。

音符具有起音、维持、释放阶段。

只要左手维持触点所有权，持续激发条件保持有效。

左手移动持续改变该音符的音高，不重启包络。

右手可以在整个持续阶段实时改变音色。

### 4.4 Impulse 模式

用于钢琴式、钟琴式、拨弦式衰减行为。

Note On 触发一次能量输入。

随后声音根据衰减模型自动演化，而不需要每个时钟重新产生激发事件。

左手保持触摸时仍然可以修改音高，但不会重新注入激发能量。

Note Release 可以根据音色预设选择：

- Free Decay：允许声音自然衰减。
- Damped Release：加快已有振动的衰减。

默认由音色预设决定，不要求演奏者每次手动选择。

### 4.5 Hybrid 模式

Hybrid 不是简单地在持续与瞬间之间切换，而是允许两种成分同时存在。

例如：

- 按下时有一段明显的敲击瞬态。
- 随后保留持续发声的主体。
- 松开时持续主体结束。
- 瞬态与共鸣残留按各自规则衰减。

当前加法合成后端可以尝试通过不同泛音的包络组合近似实现。

未来物理建模后端则可以实现更接近真实振动系统的持续输入及自然衰减。

### 4.6 统一激发接口

建议至少定义：

- `NOTE_ON`
- `NOTE_RELEASE`
- `PITCH_UPDATE`
- `EXCITATION_UPDATE`
- `TIMBRE_UPDATE`
- `RETRIGGER`

其中 `RETRIGGER` 是显式的新激发命令，不能由普通滑音意外生成。

当前实体左手只需要提供落指、移动和离开。

不同激发模式的细节由 Instrument Preset 决定。

### 4.7 统一包络模型

建议逻辑上区分：

- 音符门控状态；
- 持续驱动状态；
- 瞬态包络；
- 释放与阻尼状态；
- 最终可听幅度。

在加法合成中，各泛音可以共享一部分包络，也可以通过配置获得不同的演化参数。

但 V1 不强制实现 16 条泛音各自完整独立的高复杂度包络。

第一阶段优先实现每声部统一的连续、瞬间、混合语义，再通过少量谱形随时间变化提升音色表现力。

## 5. 音色、激发与演奏的组合

### 5.1 Instrument Preset

一个乐器预设不应只是 16 个幅度值。

建议至少包括：

| 参数 | 用途 |
|---|---|
| `generator_type` | 声音生成后端 |
| `base_spectrum[16]` | 基础泛音结构 |
| `excitation_mode` | 持续、瞬间或混合 |
| `attack` / `decay` / `sustain` / `release` | 包络配置 |
| `transient_mix` | 混合激发的瞬态比例 |
| `pitch_mapping` | 左手音高映射方式 |
| `pitch_range` | 允许的音高范围 |
| `timbre_map` | 右手控制组到泛音的映射 |
| `timbre_depth` | 修饰强度上限 |
| `release_policy` | 释放后的衰减/阻尼行为 |
| `effect_parameters` | 效果器参数 |

这是概念性预设结构，不代表所有字段都必须立即占用独立寄存器。

### 5.2 典型乐器配置

| 乐器类型 | 激发 | 音高行为 | 音色行为 |
|---|---|---|---|
| 管风琴式 | Continuous | 以离散音符为主 | 稳定谱形、实时修饰 |
| 钢琴式 | Impulse | 起音后基本稳定 | 起音亮、随后衰减 |
| 拨弦式 | Impulse | 可连续推弦 | 高频分量逐渐减弱 |
| 弦乐式 | Continuous | 连续滑音与颤音 | 随驱动和时间变化 |
| 混合合成器 | Hybrid | 连续可调 | 多触点实时塑形 |

这些首先是可表达的演奏与声音行为，不保证现有加法合成已经能够准确复现对应真实乐器的声学特征。

### 5.3 演奏期间修改预设

应当区分修改基础预设与进行右手修饰。

默认规则：

- 右手修改实时生效。
- 上位机编辑先写入草稿。
- 正式 Apply 才切换基础配置。
- Apply 必须在确定的音频更新边界提交，防止半更新状态。
- 激发模式的大幅改变原则上对新触发音符生效；正在发声的旧音符保持其原有生命周期。
- 基础谱即时更新若要影响已有音符，必须具备明确的平滑策略。

## 6. 作用范围与未来双 Part

### 6.1 V1 默认规则

V1 使用一个 Global Timbre Modifier。

所有 Voice 根据当前基础音色与全局修饰计算有效泛音。

新音符、持续音符和仍然可听的释放尾音，都使用相同的全局修饰状态。

这是一种有意选择的管风琴式共享控制语义。

### 6.2 V1.1 双 Part

未来允许：

- Part A 拥有独立基础谱与修饰。
- Part B 拥有独立基础谱与修饰。
- 每个音符在起音时确定 `part_id`。
- 演奏者选择 ALL、A 或 B 作为右手控制范围。
- 进行滑音时不自动改变音符的 Part。
- 切换右手控制范围不重触发音符。

Part 的分配可以由演奏前设置的区域、预设或显式模式决定。

默认不要求演奏者在右手调整泛音之前，再从左手多个音符中选择一个目标。

### 6.3 不引入逐音符泛音编辑的原因

逐音符音色控制在计算架构上可以支持，但如果右手和左手物理分离，就需要额外确定右手动作指向哪个音符。

这会明显增加现场演奏的认知负担。

因此，逐音符实时泛音编辑不属于 V1 必须实现的能力。

现有每 Voice 独立相位、频率和包络状态继续保留，不因为全局音色控制而合并。

## 7. 实体交互与设备模式

### 7.1 两种主要模式

**Performance Mode：演奏模式**

默认启动状态。

左手演奏音符，右手塑造泛音。

所有音高与音色变化都对应确定的音乐行为。

**Configuration Mode：设定模式**

用于设置：

- 基础泛音谱；
- 乐器预设；
- 激发模式；
- 音高映射；
- 泛音组映射；
- 效果参数；
- 未来的 Part 分配。

配置动作不能因为普通演奏手势而误触发。

### 7.2 建议的实体控制命令

| 命令 | 职责 | V1 优先级 |
|---|---|---|
| PRESET | 切换乐器预设 | 必需 |
| RESET TIMBRE | 清除右手修饰 | 必需 |
| CONFIG | 进入/退出设定状态 | 必需 |
| SUSTAIN | 可选的音符保持控制 | 扩展 |
| PART SELECT | 选择全局或分区控制范围 | V1.1 |

这些是逻辑命令，不等于必须增加五个实体按钮。

具体使用已有板载按键、外接控制器还是专用控制面板，应在硬件方案确定后映射。

配置模式也不要求首版就支持脱离电脑进行全部 16 条泛音的精细编辑。

### 7.3 演奏状态反馈

最终实体设备至少应该让演奏者知道：

- 哪些音符当前被激活；
- 哪些触点已被系统接受；
- 当前使用哪个预设；
- 当前激发模式；
- 右手有哪些泛音组被修饰；
- 音色修饰是否保留；
- 是否发生声部分配拒绝或触点追踪错误。

更高级的波形、频谱和演奏轨迹显示可以逐步加入。

最终现场演奏不依赖电脑显示器提供关键状态反馈。

## 8. 事件、状态与异常处理

### 8.1 音符状态机

建议的逻辑状态包括：

`IDLE → ATTACK → ACTIVE → RELEASE → FINISHED`

Impulse 音符可以在进入 ACTIVE 后自行衰减至 FINISHED。

手指释放与声音进入 RELEASE 不一定是同一时刻发生的动作。

### 8.2 右手修饰状态机

每个控制组分别维护：

`INACTIVE → EDITING → LATCHED`

- INACTIVE：尚未编辑或修饰为零。
- EDITING：当前有触点正在修改。
- LATCHED：触点已离开，但参数保持。
- RESET：将目标值恢复为默认状态，完成后回到 INACTIVE。

状态机中的保持值和经平滑后的实际音频使用值可以不同。

### 8.3 时间连续性

任何改变实时音高或音色的参数，都需要明确处理：

- 传感噪声；
- 参数量化；
- 时钟域跨越；
- 事件突发；
- 延迟更新；
- 输出不连续。

原则上：

- 音高滤波优先保留快速滑奏与颤音能力；
- 泛音修饰采用短时平滑抑制突变；
- 包络转换避免无意的幅度阶跃；
- 预设切换使用确定的提交时机。

不在本文件中固定滤波系数和具体平滑时间。这些参数需要以真实面板实验和音频听感共同确定。

### 8.4 异常状态

必须覆盖：

- 触点短暂消失；
- 多指交叉；
- 触点 ID 重用；
- 同音多指；
- 连续滑音跨越音区边界；
- 右手控制组争用；
- 触控测量异常；
- 事件 FIFO 满；
- Voice 耗尽；
- 配置更新与音符释放同时发生；
- FPGA 控制参数跨时钟域传递。

系统不得声称无限输入速率下永不丢事件。

必须提供错误计数、状态观察和安全恢复机制，尤其不能让一次丢失的释放事件造成永久卡音。

## 9. FPGA 实现约束

### 9.1 保留既有声音核心

当前历史架构记录采用：

- Tang Nano 20K；
- TDM 加法合成；
- 32 逻辑声部；
- 每声部 16 条泛音；
- 512 个计算时隙；
- 27 MHz 时钟下约 52.734 kHz 的采样率。

这些是对应旧源码快照的实现记录。

本方案不要求直接修改采样率、扩大声部数或替换 TDM 算法。

是否保留全部数值，应由最新整合候选的源码身份、综合与回归结果确认。

### 9.2 激发扩展的资源边界

三种激发模式会增加状态管理复杂度。

尤其 Hybrid 可能需要额外的包络状态、乘加运算或参数访问。

当前 512 时隙已被 32×16 的调度配置占满，不能假设所有新增计算都能无代价插入同一条流水线。

必须分别统计：

- 每声部状态位数；
- 每声部/泛音的访存；
- 包络运算周期；
- 控制事件处理周期；
- FPGA DSP、LUT、FF、BSRAM 占用；
- 实际时序余量。

### 9.3 触控前端

触控前端尚未冻结。

所有实体前端候选必须满足：

1. 能输出后续音乐语义所需的观测。
2. FPGA 完成触点坐标、身份跟踪及应用计算。
3. 支持目标数量的同时触点。
4. 具备能够验证的最坏扫描与处理延迟。
5. 能区分真实移动与噪声。
6. 可以在 Tang Nano 20K 的引脚、资源与成本约束内运行。

若硬件只能提供二值触摸，则不得声称已经满足最终连续多指演奏目标。

## 11. 实现路线

### P0：设计与代码身份收敛

确定最新版源码身份、正式产品定义、有效决策、废弃提案和未决参数。

建立本文件与最新项目 `design`、`integration`、`validation` 记录的对应关系。

### P1：保证左手与音符生命周期

优先完成真实触点到独立音高控制的闭环。

将手指所有权与声音生命周期解耦，完成同音多指、ID 重用、移动与释放测试。

### P2：完成全局右手泛音塑造

先实现确定的修饰状态模型。

验证多组修饰、部分释放、松手保持、恢复及新音符继承。

连续手势以触控硬件实测结果为准。

### P3：统一三种激发策略

在现有加法合成后端实现 Continuous、Impulse、Hybrid 的基础语义。

验证包络、音符释放、滑音及泛音修饰的组合行为。

### P4：完整实体演奏

完成真实左右手输入、音频输出、关键状态反馈和端到端延迟测量。

### P5：扩展音色与演奏范围

按实际音乐需求加入双 Part、分区音色与高级演奏辅助。

### P6：扩展声音生成后端

在统一事件和演奏状态接口下研究 FM、拨弦、波导或其他物理建模。

不得让这些扩展阻碍当前乐器完成。

## 12. 设计冻结清单

### A. 建议现在冻结的内容

- 左手控制音符，右手控制泛音。
- 左手多指独立拥有音符。
- 连续移动不重新触发音符。
- 右手默认修改全局在奏音色。
- 右手多触点强调已有泛音。
- 右手松手保持，RESET 才撤销修饰。
- 基础谱、演奏修饰和编辑草稿相互分离。
- 持续、瞬间与混合统一为激发策略。
- 音符所有权与声音生命周期分离。
- 激发策略由乐器预设决定。
- 首版保留 TDM 加法合成。
- 所有应用级实时计算保留在 FPGA。

### B. 冻结接口，但不冻结物理参数

- 左右手触点事件格式；
- 连续位置与音高映射；
- 泛音组与 16 条泛音的对应；
- 泛音强调量计算；
- 多指身份追踪；
- 参数滤波与平滑；
- 触控扫描频率；
- 触点确认与丢失超时；
- 音符起音与释放时间常数。

### C. 暂不纳入 V1 的内容

- 逐音符右手泛音编辑；
- 必须依赖压力的音色表达；
- 超过两个 Part 的复杂编组；
- 全部传统乐器的精确物理模拟；
- 同时部署所有合成算法；
- 未经实测的高维连续传感功能。

## 13. 最终设计基线声明

本项目的核心不是复刻某一种传统乐器，而是实现一套具有明确演奏语义的可表达乐器系统。

**左手决定哪些音符存在，以及它们的音高如何变化。**

**右手决定这些音符具有怎样的泛音构成，并通过状态保持实现可持续的实时音色塑造。**

**乐器预设决定声音如何被激发、持续、衰减与释放。**

**声音生成后端负责将统一的演奏状态转化为实际音频。**

当前加法合成系统是这一架构的第一个实现，而不是整个架构的能力边界。

产品成功的第一标准是：演奏动作清晰、响应稳定、声音可控、状态可预测。

在此基础上逐步扩展新的激发器、共振器与声音生成模型，使更多传统乐器的演奏行为成为统一架构的不同配置，同时保留创造新乐器的可能性。

**最终原则：优先统一音乐语义，而不是统一所有乐器的内部物理算法。**
