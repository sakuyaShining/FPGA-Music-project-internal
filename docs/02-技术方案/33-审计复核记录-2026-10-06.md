## 一、I²S 标准对齐：**我方未能复现"错位"现象**，但也不能据此排除

### 1.1 新增的判据与产物

| 项 | 路径 |
|---|---|
| 测试台（标准接收器 + 旧模型同线对照） | `src/sim/tb_i2s_std.v` |
| 判据脚本 | `tools/scripts/i2s_std_check.py` |
| 复跑 | `iverilog -g2005 -o d/i2s.vvp -s tb_i2s_std src/rtl/audio_clk_en.v src/rtl/i2s_tx.v src/sim/tb_i2s_std.v && vvp d/i2s.vvp` 然后 `python tools/scripts/i2s_std_check.py --simdir d` |

### 1.2 实测结果（`i2s_tx.v`/`audio_clk_en.v` **未做任何改动**，即当前基线）

```
[I3] 激励覆盖：正 68 个 / 负 132 个（范围 -32768 .. 16930）
[I1] 标准接收器：滞后 2 字，不符 0 / 99  ← 逐位相等
[L1] 旧模型：同样滞后 2 字，不符 0 / 99
★★★ 通过（标准接收器逐位一致 + 正负覆盖）
```

两条独立接收模型（同一份位流并行解码）**都**得到"源样本逐位相等"。所以：
**当前基线 RTL 与"接收器按 bck 上升沿采样、WS 翻转即新字边界、每半周期 16 位"这个模型完全自洽。**

### 1.3 需要区分的两件事（这是复核的关键）

"符合标准"与"被某个特定接收模型接受"不是一回事。全部差异只可能来自**接收器的相位假设**：

| 接收器相位假设 | 结果 |
|---|---|
| 采样沿 = bck 上升沿；WS 翻转沿 = 新字 MSB；每半周期 16 位 | **逐位相等**（本测试台与既有 `04 i2s` 都是这一档） |
| 采样沿 = bck 上升沿；但字窗口相对 WS 再挪一个沿 | 会读出"整字移一位"或"末位/首位互换" |

**我方实测没有观察到"源 ×2"或"源 >>1"的签名**，`04 i2s` 门禁在未改动的 RTL 上也是 0/63。

### 1.4 结论与下一步（不夸大为"已排除"）

- **不能据此宣布 I²S 无缺陷**：本测试台的接收模型与 `tb_i2s_tx.v` 的模型在**采样沿与字边界**上假设相同，两者同源，共同的相位假设如果有错，两个模型会一起错。
- **也不能据此确认缺陷**：审计探针（`33-审计证据-2026-10-06/i2s_standard/probe.v`）在**复位后立即开累加**，其第一个字取自复位期位流，与源样本没有对应关系；该探针输出的是"整字移一位"的形状，属于**接收器相位**差异，不是数据位错误。
- **唯一的决定性证据在板上**：板卡到手后，用示波器同时看 **WS 与 SD 的相对相位**（S1 阶段"先验证标准 DAC 输出"正是为此）。
  - 若板上 WS 与 SD 的相位关系与本次仿真一致 ⇒ I²S 无需修改，撤销该阻断项；
  - 若不一致 ⇒ 按板上实测修 `i2s_tx.v`，并同步更新本测试台与 `tb_i2s_tx.v` 的接收模型。

## 二、声部释放回收：**审计结论成立**，我方已复核源码

`note_map.v` 全文对 `gtab` 的写只有两处（`grep -n "gtab\["`）：初始化（`:178`）与
note-on（`:493` `gtab[gsel_r] <= n_hold`）。**note-off 分支只清 `gact`，从不把 `gtab` 写回 `FREE`**，
而空闲搜索的唯一条件就是 `gtab[n] == FREE`。⇒ 一旦 32 组填满，空闲搜索永不命中，之后每个
note-on 都走 round-robin 抢占。

这一条**保留为阶段 3 的工作项**，且表述按审计意见改为"完善释放与回收生命周期"，
不是"修改分配优先级"。

## 三、事件丢失：**对 pad 路径不成立**（实测已复现为"通过"）；真实缺口在汇合点

### 3.1 审计主张与我方原判断都要修正

- 我方原说法"`pad_scan` 静默丢弃事件"是**错的**。`pad_scan.v` 用的是
  **8 位待发位图 + `note_busy` 反压**（`:243` `pend_eff_on = pend_on | edge_on_pulse`、
  `:286` `pend_on <= pend_eff_on & ~clr_on`、`:294/301` 只在 `!note_busy` 时发射）：
  它**不丢**，只是**推迟到 note_map 空**再发，每次发一个、发完清一位。
- `tdm_top.v:425` 那句"冲突时后到者被忽略"讲的是**汇合点的优先级 mux**
  （UART > 定序器 > pads > 排针），不是 pad 路径内部。

### 3.2 实测（`src/sim/tb_evloss.v`，DUT = 真实 `pad_scan` + 忙模型）

忙模型忠实模仿 `note_map`：收到有效事件后拉高 `busy` 约 20 拍再释放。
电极用 `tb_pad.v` 同款 RC 模型，`disch_time` 取它标定的 **30 = 松开 / 90 = 按下**。

```
8 键同时按下 → 同时松开
 实测事件序列 16 条：60/62/64/67/69/72/74/76 各一次 on，再一次 off
 E1 事件总数 = 16（无丢失）            PASS
 E2 8 个键都收到了 note-on             PASS
 E3 8 个 note-off 都发出（不挂音）      PASS
RESULT evloss=PASS
```

⇒ **"4 键、8 键同时按放不丢事件、不挂音"这一条，在 pad 路径上已经成立且有判据守着。**

> 过程记录（避免下次重走）：第一版我把 `disch_time` 写成 `0 / 4000`，远离标定区间，
> 结果 `state` 永远回不到 0、**一个 note-off 都没有** —— 看上去就是"挂音缺陷"。
> 换回标定值（30/90）后立刻 16/16 通过。**模型不在标定区间会造出假故障**，
> 这类结论必须先自己排除再谈 RTL。

### 3.3 真实缺口（比"pad 丢事件"窄，但确实存在）

| 源 | 是否受 `note_busy` 反压 | 忙期间到达会怎样 |
|---|---|---|
| pads（`pad_scan`） | ✅ 是 | 推迟发射，**不丢**（已实测） |
| UART `0x61` 写脉冲 | ❌ 否 | `wr_en` 单拍脉冲；note_map 忙时被忽略 ⇒ **该次写丢失** |
| 定序器 | ❌ 否 | 同样是单拍脉冲，忙时被忽略 |
| 排针 `ev_*` | ❌ 否 | 同上 |

⇒ **阶段 2 的"待处理与接收确认"应针对这三个源做**（至少在汇合点前加一级挂起/队列），
而不是去改已经正确的 `pad_scan`。这一条现在**尚无判据覆盖**，属于已知缺口。

## 四、本轮踩到的三个坑（写给下一次，避免重走）

1. **诊断必须先"开闸"再打印**。第一版把逐沿打印放在采集开闸之前，打出来的是复位期位流，
   于是"看起来像 RTL 坏了"。
2. **接收器必须在"填满本字的那一个采样沿"就把字输出**。写成"设标志、下一沿再填"会让第 16 位
   推迟一位，那个 bit0 变成下一个字的 MSB —— 实测症状是**每个字被输出两遍**。
3. **单声道设计每帧有两个声道槽**，接收器每个半周期吐一个字 ⇒ 日志里每个样本出现两次。
   这是**记录口径**，去重后才能与源逐字比对（判据脚本已内置该去重并注明）。
