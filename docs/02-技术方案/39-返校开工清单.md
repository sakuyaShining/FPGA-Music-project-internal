## 1. 返校后先确认物料与分工

- 确认板卡是否下单、预计到货与准确型号；盘点 USB 数据线、电脑、编程器驱动和可用测量工具。
- 按实际板卡版本核对音频输出连接器、是否有配套扬声器及其要求，未核对前不按旧清单接线。
- 板卡/音频负责人：供电、电脑识别、下载与基础输出。
- 输入原型负责人：候选资料、触点/面板与测量条件；暂不制作正式面板。
- 项目负责人：确定每轮测试使用的源码/配置/码流，记录结果与问题。可一人兼任，不要求额外队员。

## 2. 板卡到手后的第一轮

1. 不接自制面板，按板卡官方资料检查供电、USB 识别与下载连接。
2. 使用与准确板型匹配的官方简单例程验证下载/LED，再用官方音频例程验证输出硬件。只作硬件自检，不当作作品的实时合成证据。
3. 每步记录预期、实际现象和所用文件。失败时先解决该步，不连续换多份码流掩盖原因。
4. 我方代码上板前，先选定一个提交并完成全量回归、最新综合/PnR和引脚核对，生成绑定该提交的码流；不能拿旧 `.fs` 当成最新版。
5. 我方码流先验证串口正常 note-on/off、单音→和弦→释放与复位，再测 I²S/模拟输出。先固定配置、只用干声，随后扩展效果。

无板卡时仍可完成物料盘点、驱动准备与候选资料筛选；不能做出板级通过结论。

## 3. 输入原型的开工条件

先按 38 号文档筛选，不直接采购四片触控模块：

- 离散按键候选用于验证可靠起音/释放和延迟底线。
- 多点坐标候选用于验证左手连续音高表情；单指先通过，再测两指独立移动、分别抬起和身份稳定性。
- 原型前明确供电、I/O 电平、接口/IRQ、实际新数据周期、最大点数、所需驱动与测量参考时刻。
- 同时测能力、噪声/误触和完整控制到音频延迟；低延迟设置若失去稳定性也不算通过。
- 现有 `padmon` 仅覆盖既有 RC 遥测；外接 I²C 控制器需对应驱动与采集工具，不能假定插上可用。

## 4. 正式面板可以开始的判据

| 必须明确 | 交付给同学的证据 |
|---|---|
| 输入器件与交互边界 | 原型数据；支持几指、哪些手势、不可靠动作怎样处理 |
| 延迟与稳定性 | 单指/多指、起音/释放/移动、最终装配条件的记录，符合 ≤10 ms 要求 |
| 布局与接线 | 电极/控制位置、模块型号、电压、连接器位置/方向、线长与通断检查；区分封装脚号和排针脚位 |
| 软件与硬件匹配 | 同版驱动、引脚约束、源码 SHA、码流与配置 |
| 分段验收与恢复 | 每步操作、预期、故障检查位置和清音/复位方法 |

这些内容未齐全前，可做试验接线与小原型，不能宣布正式布局冻结。
