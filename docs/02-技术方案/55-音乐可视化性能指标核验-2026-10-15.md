# 音乐可视化性能指标核验

状态：本轮性能测量与缺口复现范围**已验证**；显示功能仍**部分实现**，全负载稳定20Hz与最终实体效果**待实现/待验证**。用户认可预览后要求核验刷新率等效果指标，本轮只新增性能测试/分析及文档，未改音乐引擎或可视化RTL。

## 1. 结论

首版是**20Hz局部图表更新方案**，原双音工作负载通过，不能签收为任何负载下稳定20fps，更不能把软件周期边界当作液晶同步换帧。本轮保守合法接口压力输入中，局部绘制最长**51.721ms**，超过50ms预算；连续两次绘制全部完成的间隔最大**80.862ms**。后者包含不同绘制量和不同完成相位，不等于屏幕完全没有像素更新80ms。

另外确认5ms短音可能没有留下音高轨迹；波形每50ms取约9.71ms片段而非连续覆盖；频谱满高柱自身回落到零约0.9秒。这些都会影响最终观感，不能只用平均刷新次数判断。

## 3. 新测试与结果身份

新文件位于`experiments/music_visualizer_20261015/metrics/`：

- `tb_render_budget.v`：直接给渲染器合法接口变化，4轮；波形相邻快照从32px满跨度变为31px跨度，使每列擦旧/画新合计达到最大63px；48柱从0跳到35px，页首状态同时变化，轨迹仍绘制。最大轮实际16455像素、306窗口、36276字节，1396455周期。
- 上述是**保守接口压力场景**。48个频带同时达到最大级别不代表有界真实PCM一定能产生该组合，不能说它就是所有真实音乐的实测最坏情况，也不能从未穷尽的输入反推万能上界。
- 同一测试在首周期后约2ms发出MIDI67按下，维持约5ms后松开；整个过程位于轨迹读取间隙，未显示bit28。持续的MIDI60始终显示bit18，证明轨迹绘制本身仍工作。
- `tb_analysis_timing.v`：实际PCM脉冲每512周期一次，记录4次FFT首/末样本/发布和2次波形请求/完成，核对1023个样本间隔、连续分析周期、忙时分析计数。
- `measure.py`：核对周期、字节/像素/窗口计数关系、短音轨迹和分析时间，输出`metrics-summary.json`，包含全部RTL、表、两份TB、检查器、日志与既有证据SHA-256。结果`audit=COMPLETE`，**all_stress_20hz_met=false**，不是功能目标PASS。

两份新TB用#5时钟加快周期逻辑仿真；渲染器测试缩短初始化等待并跳过静态整屏绘制，只测动态绘制。它们不是电气时序/冷启动测试，不替代54号27MHz/真实等待/SPI引脚模型证据。没有新综合或PnR，因为RTL完全未改；既有综合哈希仍相符。

复现新测试：

```powershell
python experiments/music_visualizer_20261015/metrics/measure.py
```

`--analyze-existing`复核已有编译/记录的新旧关系和计数，不重跑仿真。模块原验证入口`run_validation.py --check-existing`和备份审计本轮均通过；main192输入基线PASS。新增测试代码也属于需追踪输入，已单独绑定在指标摘要中，未覆盖产品基线快照。

## 4. 接下来的收口顺序

1. **待实现**：将波形擦旧/画新合并到覆盖两者的单一窗口，逐像素选背景/新波形，避免重叠区域重复传输；保持20Hz目标，建议动态绘制留出余量（例如≤40ms），随后重新做完整图像、压力与联合综合检查。这是优化建议，本轮未改RTL，不把估算收益当实测。
2. **待实现**：轨迹增加音符事件保持/待画点，保证已接受短音至少留下一个点；不延长真实音频时值、不阻塞引擎事件。波形若要覆盖每个短瞬态，改为连续min/max环形采集或峰值保持，而不是只提高计数器频率。
3. **讨论中**：频谱回落视觉时间、细颤音的放大视图与音域切换时历史标尺处理。可先比较更快回落（如200～400ms）的观感，不把这些显示候选误作音乐包络/表情语义更改。
4. **待实现/待验证**：真实引脚/供电/初始化确认后联合PnR、色条与三视图点屏；测实际图表更新、声音到屏幕变化的延迟分布、短音/和弦/滑音、撕裂、亮度与观看距离可读性，再签最终效果。

[ILI9341 v1.11手册](https://www.crystalfontz.com/controllers/uploaded/ILItek%20ILI9341%20v1.11.pdf)§18.3.4要求SPI写周期至少100ns，不能靠未核实超频来补性能；§10的TE信号可用于同步显存写入，但需先确认用户模块是否引出以及实际扫描参数。屏幕内部扫描与主机写入更新是两个指标，目前未读取/实测前者。

上述不足不能直接用第二块FPGA解决SPI带宽或漏采策略问题。本轮维持选型/制造暂停，无采购、下载或改动原引擎。

## 5. 更高刷新率的可行边界（2026-10-15后续问答）

用户询问是否因计算资源而已经无法提高刷新率。结论：**20Hz是当前调度目标，不是FPGA或这块屏的通用上限；局部更新仍有优化路径，全屏30/60fps则受当前SPI接口带宽硬约束。**本次仅核对代码、手册和传输预算，未改RTL，未执行新的仿真/综合/PnR/实屏测试；main192输入基线PASS。用户恢复硬件工作及57号录放需求继续有效，不延续上节较早的暂停指令。

19777/20736Logic（约95.4%）是空间利用率，不是CPU运行时间占用率。已有并行显示逻辑可在不同调度周期重复工作，20→30Hz不等于需要1.5倍Logic；但减少握手/改变缓冲/新增时钟或录放控制器可能增加面积，最终仍需联合综合和布局布线。

240×320×16=1,228,800bit=153,600byte/完整帧。只计像素、不计命令/握手/总线共用的理想值：

| SPI SCK候选 | 全帧像素传输时间 | 全屏理想上限 |
|---|---:|---:|
| 当前6.75MHz | 182.044ms | 5.493fps |
| 假设9MHz | 136.533ms | 7.324fps |
| 手册100ns写周期对应10MHz | 122.880ms | 8.138fps |

当前逐字节驱动整屏约219ms是已有仿真值，不能与上述纯载荷理想值混用。全屏30/60fps分别至少36.864/73.728Mbit/s有效像素带宽，现有手册合规SPI不满足。ILI9341 v1.11 §18.3.4还规定高/低脉宽各至少40ns、数据建立/保持各30ns；不能采用网上未核实的40/80MHz SPI超频作承诺。27MHz时钟下现有半周期2拍得到6.75MHz；改半周期1拍为13.5MHz且37ns脉宽，违反所用手册。9MHz/10MHz候选须另设计合适显示时钟和时序/跨域，不改变音乐采样时钟来迁就显示。

实际代码`mv_renderer.v`波形WE/WD仍分两次窗口擦旧/画新；`mv_spi_byte.v`逐字节HOLD/GAP、`mv_panel_driver.v`高低字节握手仍有空隙，均有优化候选。55号压力场景原63pixel/列（32+31），改为32pixel并集窗口的算式可少31×128=3968pixel，减少7936byte像素及128×11=1408byte窗口头，共9344byte；原36276byte可降至26932byte（约25.8%）。这是针对既有压力输入的理论数据量算式，不是优化实现或通用最坏上界；不相交波形区间等输入仍需重新测量。

26932byte在6.75MHz下仅线上时间约31.919ms，30Hz的33.333ms预算只剩约1.414ms给其他开销，不能据此宣布30Hz达标；假设9MHz时线上时间约23.940ms，也仍须计实际开销/共用总线/未来曲谱UI。建议先在保持音频隔离的前提下做并集擦画、窗口/字节连续发送和短音保持，验证稳定20Hz余量并以30Hz局部更新为下一档候选目标，不冻结30/60Hz承诺。

FFT目前约47.637Hz结果率，足以供应30Hz频谱显示的新数据；提高到60Hz显示并不自动产生60份新频谱，需区分波形/指示的刷新、FFT结果率与液晶内部扫描。短音事件保持和连续波形采集仍要修，单纯加快调度不保证所有瞬态可见。

若确需高刷新全屏内容，可研究现屏8080并口（须实物支持切换）或更高带宽屏幕；8位并口在保留CS/DC/RST且WR独立的示意下，比当前SPI多约7信号，需要重做18GPIO预算/真实引脚/资源。双板能增加逻辑与IO，但不能突破同一屏固定SPI链路的带宽。TE同步减少撕裂的候选也不能增加带宽，且当前模块是否引出仍未知。物理屏响应及扫描率须实测，传输完成率不等于无撕裂显示帧率。

下一步候选：备份后仅在隔离显示实验中优化并重跑完整图像/压力/音频隔离，联合综合/PnR再决定是否需要改屏接口。状态**讨论中/待实现**，本轮没有购买、更换屏幕、改引擎或改原理图。
