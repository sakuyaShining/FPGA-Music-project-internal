# 逐指力度与低延迟前端：需求及候选

> **低成本实现研究**：用户认为高额前端预算不可行，要求保留功能重新选型。完整功能要求保留，具体实现现新增《42-低成本自由测力平面-材料实验候选.md》的自制压阻阵列方向；本页厂家阵列为技术参照，未形成采购决定。

状态：选型研究与实验要求；尚无通过完整验收的采购型号。

用户最新要求：逐指力度是重要演奏表情，触控前端必须贴合多指连续演奏功能，同时低延迟重要，不希望以功能退让来解决选型。

因此，固定力度、全局力度、触摸面积代替真实受力，均不能作为满足逐指力度要求的最终方案。39 号文档中的普通电容屏、原始电容读数和单纯 RC 电极路线，应重新按本要求筛选。

## 1. 必须保留的功能与尚未冻结的指标

必须保留：

- 多个手指独立触发、移动和释放音符。
- 每个有效触点具有连续位置及对应的独立受力观测。
- 同音不同手指仍有独立身份与力度状态。
- 滑动不重触发；逐指力度变化不影响其他音符。
- 完整实体输入至音频输出延迟不超过 10ms，并包含传感、读出、滤波与输出。
- 最终演奏不依赖电脑进行实时控制计算或音频生成。

自由平面仍作为重点评估形态；独立滑条只有在用户接受其物理移动限制时才可转为最终方案。

以下数字仍待用户需求、厂家资料和实测共同确定：最大同时触点数、有效面积、最小可分辨指间距、位置误差、轻触阈值、最大可用力、力度重复性、串扰上限与滤波时间。

“至少五指”可作为左手候选设计尺度，不在本文件中自动冻结。力度建议同时考虑起音表达和持续触后：起音值可由规定的初始短窗口计算，持续受力另存为表达量；窗口不能无限延长而破坏延迟。

## 2. 推荐优先评估的架构

```text
二维力敏阵列
    ↓
受控扫描＋多点串扰处理的模拟读出＋外部 ADC
    ↓
FPGA：时间标记的原始力分布帧
    ↓
标定、接触区域分离、位置估计、逐指力估计、身份追踪
    ↓
NOTE_ON / PITCH_UPDATE / EXCITATION_UPDATE / NOTE_RELEASE
    ↓
独立音符状态、包络/激发、TDM 合成、I2S 输出
```

这是一条符合“FPGA 进行应用级位置与身份计算”的研究路径，不是已经证明能在目标面积、力度和延迟下工作的成套方案。

原始力分布同时提供位置和受力依据，避免分别叠加触摸与单块全局测力后，无法把总力分配给各根手指。力估计必须基于实际装配的标定；阵列读数、每单元压力和整个触点的力不能无条件视为同一个量。

若另选已计算触点位置与逐指力的控制模块，需要单独裁定其计算职责；不能默认这与原始数据在 FPGA 内处理等价。

## 3. 候选与目前不能下结论的部分

| 候选方向 | 已核实的相关能力 | 缺失证据 | 当前定位 |
|---|---|---|---|
| Sensitronics ThruMode MatrixArray | 厂家提供 10×16 力敏单元，约 50.8×76.2mm，有原始扫描教程 | 轻触手感、五指可分辨性、快速低串扰读出、交期 | 小型力阵列评估对象，不是最终左手面板 |
| Sensitronics ShuntMode MatrixArray | 厂家提供 16×16 单元，约 101.6×101.6mm | 标准受力范围较偏重；轻触与多点读出未证实 | 仅在灵敏度适配得到证据后考虑 |
| Uneo / Tekscan 薄膜力阵列 | 厂家公开力阵列/压力分布技术和集成方向 | 具体型号、原始接口、全帧速率、尺寸、轻触范围、价格交期 | 进一步核资料与报价的方向 |
| 普通 GT911 电容面板 | 多点坐标 | 没有合格的逐指真实力数据 | 单独使用不能满足完整要求 |
| AD7147 / MPR121 / Trill 等电容读出 | 电极/触摸观测 | 触摸面积与真实力的区分 | 单独使用不能满足完整要求 |

Sensitronics ThruMode 标称受力范围为 0.25–12.5lb，且有特定加载面积条件；不能把这个数直接视为单个指尖的可用范围或轻触起音阈值。标准尺寸也不一定能容纳自然的五指演奏。

厂家基本分压扫描教程明确说明多点加载会影响其他单元读数，不能照搬后宣称逐指力度独立。应核查电流读出、驱动方式及串扰补偿的完整方案。算法不能恢复原始观测中已经丢失的信息。

Sensel Morph 文档可以作为位置与逐指力功能的参考，但其供货、FPGA 直连接口、原始帧解码和实际全链路延迟均未核验，因此不列入直接下单清单。

## 4. 阵列、接口与延迟的纸面预算

以下均为用于筛选的假设，不是厂家承诺或已测结果。先以 16×16、16 位存储、500 完整帧/秒建立预算：

- 每帧 256 个单元，512 字节。
- 每秒 128,000 次有效单元测量；过采样、切换建立时间、丢弃转换会增加实际转换次数。
- 原始净数据 256,000 字节/秒，即 2.048 Mbit/s；接口还需加入帧头、校验和事务开销。
- 400kHz I2C 逐字节传这 512 字节，仅数据及 ACK 就需约 11.52ms，不适合这种全帧原始数据路径。
- 双帧缓存＋基线＋一份处理图，按四份 16 位图计算共 2,048 字节。标定表、标签、身份与队列另计；实际 BSRAM 占用依组织方式和综合映射决定。

1MSPS ADC 可为纸面预算提供转换速度余量，但不能直接保证扫描完成速度。TI ADS7953 是 16 通道、12 位、SPI、最高 1MSPS 的器件候选；它尚不是本项目选定的 ADC。其通道建立、输入驱动、参考电压、时钟和实际板级接口仍需核验。

- [TI ADS7953 官方规格](https://www.ti.com/product/ADS7953)

若最终扩大至假设的 24×40 阵列，同样按 500 帧/秒计算，将需要 480,000 次有效单元测量/秒及 7.68Mbit/s 净原始传输；不能将小阵列实验直接当作大阵列的时序证明。

### 总延迟候选分配

| 环节 | 候选最坏预算 |
|---|---:|
| 受力响应、扫描相位、形成可用帧及读出 | 4ms |
| 接触判断、位置/力计算、必要滤波 | 2ms |
| 音乐状态与参数提交 | 1ms |
| 音频序列输出及 DAC | 1ms |
| 集成余量 | 2ms |
| 合计 | 10ms |

500Hz 的帧周期是 2ms，不代表物理动作最多 2ms 后就能被完整帧消费者看到。动作可能恰好发生在对应单元扫描之后；若统一等帧结束，最坏相位可能接近两个帧周期。还要验证模拟建立、滤波和输出延迟。

因此询价必须明确“满阵列、目标同时触点条件下的完整帧速率与最坏延迟”，拒绝仅以传感材料响应时间、单通道速度或平均延迟替代。

## 5. 原型必须通过的核心实验

1. **轻触与逐指力**：在最终候选覆盖层下，轻触、加力、减力能稳定区分；固定接触位置和角度，记录力读数及重复性。
2. **双指独立性**：A 指保持固定载荷，B 指从轻至重变化；A 的估计力与位置不能出现超出冻结阈值的联动。用固定加载工具辅助隔离手指自身动作。
3. **滑动同时加力**：记录位置和力，两者不能互相错误解释；滑动不重新触发。
4. **多指与邻近**：测试目标触点数、同排同列、邻近和接触合并；冻结最小间距与无法分离时的行为。
5. **释放及保持**：局部释放不改变其他指的身份和力；长时间保持检查漂移与错误基线归零。
6. **端到端时序**：从物理接触/力变化到数字帧、语义事件、音频输出分别记录时间；以规定的参考包络验证 ≤10ms。

先用小阵列执行相同类型的测试，是分阶段验证方法；不能据此降低最终触点数、尺寸、力度或延迟需求。

## 7. 演奏状态接口的新增要求

每个触点记录至少需要关联身份、位置、力观测、质量和时间戳。起音力度与持续力度分别保存；持续力度可通过已有 EXCITATION_UPDATE 接口或等价的逐音符表达更新传递。

用户加力不是新 NOTE_ON。释放不能重算或覆盖原力度；右手全局音色更新不能覆盖左手逐指力表达。需要根据激发策略明确：Continuous 可用持续力控制驱动，Impulse 默认由起音力度决定初始能量，Hybrid 的两部分需明确分配规则。这些音乐映射属于候选决策，不能由传感器型号自动决定。

目前真实力阵列、读出电路和 FPGA 算法仍存在实现与交期风险。尚不能保证完整功能将在 11 月 4 日前完成；遇到不满足指标的候选，应报告差距并更换候选，不能自行用固定力度或面积估计标记为已完成。
