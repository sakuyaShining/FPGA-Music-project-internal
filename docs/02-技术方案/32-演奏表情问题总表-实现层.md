## 1c. 力度→亮度 + 独立亮度轴：最终形态（2026-10-06 收尾）

| 项 | 内容 |
|---|---|
| **力度→音色** | `vel_wtab.hex` 查表（16×16，9 位权重），`vel_shape.v` 取权重 |
| **力度灵敏度** | `0x6E VEL_SENS`：只缩放"相对恒等的偏差"，**0x00 = 关**、0x80 = 一等一（= 与只用表逐位相同）、0xC0+ = 511（约 2 倍） |
| **独立亮度轴** | `0x5C TILT` → `tilt_wtab.hex`（16 档），**恒等点 = 0x70**；`reg_bank` 默认值必须是 0x70 |
| **插入位置** | 亮度轴作用在**预设谱合成之后、力度乘法之前**（`amp_src → amp_tilt → vel_shape → amp_mul`）。放在力度乘法之后会变成"改音量"（32 号 D-13 明确否决） |
| **开关唯一性（重要）** | 力度维的开关**只有 0x6E 一个**。旧实现另有一个 `feat_on = (tilt_gain!=0)` 的总门，而 `0x6D` 换成查表后已不参与运算 ⇒ 出现"写了 0x6E 却什么都不发生"的死门。已删除，并把 0x6B/0x6C/0x6D 一律降级为"历史字段、不参与运算" |
| **判据（都在门禁里）** | 单元 `13 vel shape` **V1–V9**（新增 V9：灵敏度只缩放偏差）；端到端 `14 vel timbre` **J1–J4**（力度→音色）+ **L1–L6**（亮度轴单调/恒等点/最暗不静音/动态范围/跨预设/可复现） |
| **试听链路** | `python tools/scripts/vel_audition.py` 一条命令：编译 → 跑仿真 → 导 4 个 wav → 出 `audition_report.txt`（含谱心与高次占比对照） |

### 两条"仿真绿但功能假"的实测教训（都是本次踩到的）

1. **`$readmemh` 数组开小了会静默装错**：`tilt_wtab.hex` 有 256 个词（16 行 × 16 列），
   而数组声明成 `[0:15]` 时 iverilog 只报一句
   `WARNING: Too many words in the file for the requested range [0:15]`，
   然后**把前 48 项装进去、其余留 X**。症状不是报错，而是"亮度轴的恒等点被夹到下限、
   看起来还能跑"。现在按**文件词数**开数组（`[0:255]`），并让测试台在开跑前打印
   `tilt_rom[112..127]` 自检。
2. **同一件事在四处各写一遍**：运行目录缺 hex 已经栽过三次；本次把数据文件收成
   唯一入口 `copy_data()`，并让**缺表直接让闸口红**（原来 `if os.path.isfile()` 静默跳过，
   下游拿到 X 只报一句莫名其妙的 `invalid literal for int()`）。

### 一个"指标会骗人"的教训（写进报告用得上）

**谱心（spectral centroid）不适合单独当"亮度"的判据。** 本功能在低力度会**砍掉高次泛音**
（条数机制），高次一没，重心被拉回低处 ⇒ 出现"逐条比较确实更亮、谱心却更低"的矛盾：

| v=14 | 264Hz | 791Hz | 1301Hz | 2092Hz | 3146Hz | 4184Hz | 谱心 |
|---|---|---|---|---|---|---|---|
| 功能关 | 1.000 | 0.650 | 0.402 | 0.351 | 0.224 | 0.199 | 1666 Hz |
| 功能开 | 1.000 | **0.710** | **0.475** | **0.460** | **0.339** | （被砍） | **1601 Hz** |

逐峰比较是变亮的，谱心却更低。**正确的主指标是"高次能量占比"**（谐波 k≥3 的能量 / 总能量），
它单调且与听感一致。所以 `vel_audition.py` 用占比当主判据、谱心只作旁证并注明差异原因。
——这类"指标方向本身错了"的坑，若不写下来，下一次还会用谱心去判亮度。

| 项 | 内容 |
|---|---|

## 1b. 力度->音色：实现形态的最终决定（2026-10-06）

| 项 | 决定 |
|---|---|
| 实现形态 | **查表**（`src/rtl/vel_shape.v` + `vel_wtab.hex`），不是公式 |
| 表结构 | 16 档力度 × 16 条泛音，每项 9 位权重（256 = 1.0 倍）= 256 项 |
| 为什么换 | ① 表达力：公式只能「倾斜 + 门限置零」；表可写任意谱形（奇次优先、凹陷）② 时序：原公式含 `/15` 除法，实测把 slack 打到 **+4.488 ns**（低于 5 ns 阈值，被闸口判红）；查表版 **+15.229 ns**，关键路径已不在 `u_vshape` 内 |
| 生成方式 | `tools/scripts/gen_vel_wtab.py`（初值由原公式生成 ⇒ 行为逐位不变） |
| 开关 | `0x6D` 非 0 = 打开；默认 0 = 恒等（判据 V8 守着） |
| 判据 | 单元 `13 vel shape`（V1–V8）+ 端到端 `14 vel timbre`（J1–J4，穿 `tdm_top`）——**均已纳入门禁** |

**两条只在综合侧显形的教训（仿真看不见）**：

1. **正弦表缺表假绿**：门禁从 `sim_build/_hex/` 拷贝，而该目录从未被创建 ⇒ `$readmemh` 失败、音频全 X；`09 regctl` 长期靠残留旧产物「通过」。
2. **ROM 位宽不匹配**：`vel_wtab.hex` 每项 3 个十六进制位（12 位），而存储器声明 9 位 ⇒ 综合报 `WARN (EX2526)`，**板上 ROM 装不进去**。仿真完全正常。改为 12 位声明后消除。

→ **结论：综合日志是「仿真看不见的那一半」，每次改 RTL 必须查。**

## 4. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| I²C 模拟量不可用 | I-01/02/03/16 全部退化 | 已备兜底：固定力度 + 长按渐入（D-05） |
| 采样率不足 | I-08/10 退化 | 只做 legato，不做滑动 |
| **无 IRQ 引脚** | 延迟预算重算 | **架构级风险**，见《28》第 4 节 |
| 逐声部资源超预期 | 占用 > 70% | 闸口自动判红；届时只保留颤音逐声部，亮度回全局 |
| 同一信号两处判定（I-06） | 力度/触后不一致 | **单点判定**，一处产生两个量 |
| **新寄存器默认值写错** | 上电音色被静默改掉（既有音频证据全失效） | `0x5C` 默认 **0x70**（恒等点）而不是 0；每加一个寄存器都要问"0 是不是恒等？" |
| **`$readmemh` 数组开小** | 表只装一半 + 其余 X，**不报错**、看起来还能跑 | 数组按**文件词数**开；测试台开跑前打印表内容自检 |
| **运行期数据表缺文件** | $readmemh 失败 ⇒ 音频全 X ⇒ 判据抛异常 | 数据文件收成唯一入口 `copy_data()`，**缺表直接让闸口红**；判据脚本遇 X 给可读结论 |
| **指标方向本身错误** | 用谱心判亮度，会把"砍高次"读成"变暗" | 亮度主指标 = 高次能量占比；指标与听感冲突时先怀疑指标 |
