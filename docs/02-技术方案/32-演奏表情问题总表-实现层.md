# 演奏表情问题总表 —— 实现层

> 2026-10-05 · 配套：`32-演奏表情问题总表-设计层.md`、`32-演奏表情问题总表.json`
> 本文件只记**落到哪个模块、需要什么信号、怎么证明它对、代价多少**。
> 编号 `I-xx` 与设计层的 `D-xx` **一一对应**（I-01 ↔ D-01，依此类推）。

## 0. 现状盘点（哪些已经有了）

| 能力 | 现状 | 位置 |
|---|---|---|
| 力度通路 | **已有**：`ev_vel` 4→8 位，`amp = (p_amp × vel8) >> 8` | `tdm_top` / `note_map` / `tdm_engine` |
| 滑音 | **已有且运行时可控**：`CTRL[2]` → `pmod_cfg[0]` → `pitch_mod.glide_en`（应用处门控） | `tdm_top:288/294`、`pitch_mod:182` |
| 滑音速率 | **已有**：`GLIDE_STEP`（`0x35–0x36`） | `pitch_mod` |
| 滑音初值 | **已有**：`note_map` 的 `gq`（`tdm_top` 把 `GLIDE_EN` 显式设为 `1'b1`） | `note_map:753` |
| 颤音 | **已有但是全局**：`VIB_INC` / `VIB_DEPTH`，单一 LFO 相位 | `pitch_mod` |
| 逐声部谱形刷新 | **已有**：`0x63 SPEC_REFRESH` + 谱 RAM 16×8 | `tdm_top:619`、`note_map` |
| 亮度轴 | **未实现**：协议已声明 `0x5C TILT` | — |
| 输入层模拟量 | **没有**：现在只有离散触摸位图 | `pad_pitch` |

**⇒ 真正要写的 RTL 只有三块**：逐声部颤音、`0x5C` 亮度通路、输入层"模拟量→表情"映射。

## 1. 逐条实现

### I-01 相对映射与标定（↔ D-01）

| 项 | 内容 |
|---|---|
| 落点 | 输入层新模块 `expr_map.v` |
| 需要信号 | 每通道 10 位模拟值（I²C 提供）【待原型确认可用性】 |
| 做法 | 保存"最轻/最重"两端读数；线性插值到 0..15 |
| 寄存器 | 新增 `CAL_LO` / `CAL_HI`（每通道一个？还是全局？**建议全局**，省寄存器） |
| 判据 | `E2-D1-a`：给定两端读数，中间值插值正确（表驱动） |

### I-02 起音窗取峰值（↔ D-02）

| 项 | 内容 |
|---|---|
| 落点 | `expr_map.v` |
| 做法 | note-on 时刻起计时 **约 10 ms**（27 MHz ≈ 270000 拍），窗口内跟踪最大值并锁存 |
| 寄存器 | `ATK_WIN`（单位拍，默认 270000） |
| 资源 | 每通道一个比较器 + 一个保持寄存器（38 通道 ⇒ 约 38×10 位）；**但可以复用**：只有"正在起音"的通道需要 ⇒ 用 32 个声部级寄存器即可 ✓ |
| 判据 | `E2-D1-b`：窗内峰值被正确取到（注入一段上升信号，验证取的是峰值不是首值） |

### I-03 力度同时作用于音量与音色（↔ D-03）

| 项 | 内容 |
|---|---|
| 落点 | `tdm_engine` 的声部增益与**谱形缩放** |
| 做法 | 音量：已有 ✓；音色：把力度映射为"亮度偏移"，叠加到谱形倾斜量上 |
| 依赖 | **需要 I-13 的倾斜通路先在位** ✗（所以 I-03 应排在 I-13 之后） |
| 判据 | `E2-D1-c`：同一音高、不同力度 ⇒ 谱心**单调**升高（复用 `12 f1` 的谱分析工具） |

### I-04 力度曲线（↔ D-04）

| 项 | 内容 |
|---|---|
| 落点 | `expr_map.v`（可选加曲线 ROM） |
| 做法 | 4 位索引 → 曲线值；曲线可由寄存器选择（0=线性 / 1=对数 / 2=分段） |
| 判据 | `E2-D1-d`：曲线选择生效，且线性档与理论值逐点一致 |

### I-05 触发方式的兜底（↔ D-05）

| 项 | 内容 |
|---|---|
| 落点 | 输入层（模式寄存器位） |
| 做法 | 三选一：触后 / 长按渐入 / 专用轴；由 `PERF_CTRL` 位选择 |
| 判据 | `E2-D2-a`：三种模式下，颤音深度的**来源**正确（触后=面积变化；长按=计时） |

### I-06 力度与触后的时间窗分离（↔ D-06）

| 项 | 内容 |
|---|---|
| 落点 | `expr_map.v`（一个状态机：`起音窗 → 触后阶段`） |
| 做法 | 起音窗内 → 更新力度；窗口结束后 → 只更新触后，且触后基准 = 窗口结束时的值 |
| 风险 | 同一信号走两个用途，**必须单点判定**，否则两处逻辑会不一致 ✗ |
| 判据 | `E2-X2`：重按（快速大变化）⇒ 力度大、**颤音深度不变** |

### I-07 颤音渐入的平滑（↔ D-07）

| 项 | 内容 |
|---|---|
| 落点 | `pitch_mod`（每声部深度平滑） |
| 做法 | 每声部一个平滑计数器，深度按 **约 200 ms** 线性趋近目标 |
| 寄存器 | `VIB_IN_MS`（默认 200） |
| 注意 | 触后从 0 起 ⇒ 天然"先直音后加颤" ✓，**不要改动这个起点的语义** ✗ |
| 判据 | `E2-D2-b`：触后给满 ⇒ 深度在设定时间内单调到达，不超调 |

### I-08 手指在否的判定（↔ D-08）

| 项 | 内容 |
|---|---|
| 落点 | 输入层（I²C 状态位，**不是**滤波数据） |
| 做法 | 滑动判定需要"手指从未离开面板"这一事实 |
| 依赖 | **MPR121 的状态位**（芯片自带）✓；若拿不到 ⇒ 退化规则 |
| 判据 | `E2-D3-a`：滑动一次经过 5 个键 ⇒ **note-on 数量 = 0**，音高连续变化 |

### I-09 全松去抖（↔ D-09）

| 项 | 内容 |
|---|---|
| 落点 | 输入层（`pad_pitch` 之前的一级，或并入 `slide_det`） |
| 做法 | "无任何键被按"必须持续 **T_release** 才算抬手；否则视为跨越间隙 |
| 寄存器 | `REL_MS`（默认 30–50，待原型） |
| 判据 | `E2-X3`：注入"按A→空10ms→按B" ⇒ 判定为**同一次滑动**（不产生 note-off/on 对） |

### I-10 阈值折中与加权证据（↔ D-10）

| 项 | 内容 |
|---|---|
| 落点 | `slide_det.v` |
| 做法 | 主判据 = 时间窗；可选增强 = "相邻键连续经过"计数 |
| 参数 | `SLIDE_WIN`（滑动时间窗，默认 50 ms，待原型） |
| 判据 | `E2-X4`：快速重复音（间隔 > 窗口）判为**两个独立音**；连续滑过判为**一次滑音** |

### I-11 泛音排的宽松判据（↔ D-11）

| 项 | 内容 |
|---|---|
| 落点 | `slide_det.v`（复用同一模块，参数不同） |
| 做法 | 泛音排不发声 ⇒ 不产生 note 事件，只需位置序列 |
| 判据 | `E2-D4-a`：滑过 H1→H8 ⇒ 位置序列单调递增，无跳变丢失 |

### I-12 多指的取位规则（↔ D-12）

| 项 | 内容 |
|---|---|
| 落点 | `slide_det.v` |
| 做法 | 取**最左**被按格（可配置为"首个落下的格"） |
| 判据 | `E2-D4-b`：同时按 H2/H5 ⇒ 位置 = 2（按选定规则） |

### I-13 亮度倾斜通路（↔ D-13）

| 项 | 内容 |
|---|---|
| 落点 | **新增 `0x5C TILT`**（协议已声明）+ `note_map` 的谱形写入路径 |
| 做法 | 倾斜值 → 对 16 条泛音幅度做**逐条加权**（低频减/高频增），写入谱 RAM 后触发 `0x63` 刷新 |
| 为何不逐条缩放 | 那会变成音量变化，不像亮度 ✗ |
| 预设补充 | 可保留 2–4 个预设谱，倾斜在预设之间插值 |
| 判据 | `E2-D4-c`：倾斜 0 → 255 ⇒ 谱心**单调**上升 |

### I-14 刷新延迟的边界（↔ D-14）

| 项 | 内容 |
|---|---|
| 落点 | 说明性约束（不是新逻辑） |
| 做法 | 记录逐声部刷新的实际延迟，作为"亮度速率上限"的依据 |
| 判据 | `E2-D4-d`：以不同速率推拉倾斜 ⇒ 超过上限时行为**可预测**（不崩、不静音） |

### I-15 点按确认延迟（↔ D-15）

| 项 | 内容 |
|---|---|
| 落点 | 输入层（泛音排专用） |
| 做法 | 稳定按住 > T（默认 150 ms）且无跨格移动 ⇒ 点按生效；期间有移动 ⇒ 判滑动 |
| 寄存器 | `TAP_MS` |
| 判据 | `E2-X5`：快速滑过 H1→H4 ⇒ **不改变泛音掩码**；稳定按住 H3 ⇒ 掩码更新 |

### I-16 死区（↔ D-16）

| 项 | 内容 |
|---|---|
| 落点 | `expr_map.v` |
| 做法 | 阈值 = 噪声 × 2–3（原型量得后定值） |
| 寄存器 | `DEAD_ZONE` |
| 判据 | `E2-X6`：注入噪声级抖动 ⇒ 力度/触后**不变化** |

### I-17 表情冻结与清零（↔ D-17）

| 项 | 内容 |
|---|---|
| 落点 | `expr_map.v` + 声部表情寄存器 |
| 做法 | 音域切换期间冻结更新；note-off 时清该声部表情 |
| 判据 | `E2-X7`：切换音域时，正在响的音的颤音深度**不变** |

### I-18 逐声部资源（↔ D-18）

| 项 | 内容 |
|---|---|
| 逐声部颤音相位 | 32 × 24 位 ≈ **768 个触发器** |
| 声部表情寄存器 | 32 × 8 位 = **256 个触发器**（可含力度/触后/亮度） |
| 合计 | 约 **1024 个触发器**（当前 3569 ⇒ 约 +29%） |
| 逻辑占用实测 | 接入 vel_shape 后 **71%**（14683/20736）；DSP 8.75 → 10.75 |
| **时序实测（更正）** | **+16.479 → +11.872 ns（代价 4.6 ns）** —— 不是原先预估的 <1 ns ✗；中途含除法的版本曾跌到 **+4.488 ns**（被闸口判红），去掉 /15 后恢复 |
| 判据 | **闸口自动判**：`check_timing.py`（slack ≥ 5 ns）+ 占用 ≤ 70% |

## 2. 实施顺序（按依赖排）

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | **I-13 亮度倾斜通路** | 最独立、风险最小；且 I-03 依赖它 |
| 2 | I-18 逐声部颤音相位 + 表情寄存器 | E2 颤音维的核心短板 |
| 3 | I-06/I-07 时间窗分离 + 渐入平滑 | 与 2 同批 |
| 4 | I-03 力度→音色 | 依赖 1 |
| 5 | I-01/I-02/I-04/I-16 输入层映射 | 依赖 I²C 原型结果 ✗ |
| 6 | I-08/I-09/I-10/I-11/I-12/I-15 滑动检测 | 依赖 I²C 原型结果 ✗ |
| 7 | I-05/I-14/I-17 兜底与冻结 | 收尾 |

**⇒ 第 1–4 项不依赖硬件原型** ✓✓，假期内就能做完；第 5–6 项等原型。

## 4. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| I²C 模拟量不可用 | I-01/02/03/16 全部退化 | 已备兜底：固定力度 + 长按渐入（D-05） |
| 采样率不足 | I-08/10 退化 | 只做 legato，不做滑动 |
| **无 IRQ 引脚** | 延迟预算重算 | **架构级风险**，见《28》第 4 节 |
| 逐声部资源超预期 | 占用 > 70% | 闸口自动判红；届时只保留颤音逐声部，亮度回全局 |
| 同一信号两处判定（I-06） | 力度/触后不一致 | **单点判定**，一处产生两个量 |
