# 乐器形态建议（还在摸索阶段的决策指南）

> 现状：已报名、手上有 **Tang Nano 20K**、乐器形态未定、距提交截止 47 天。

---

## 一、核心决策原则：**先做引擎，后做外形**

理由有三条，都很实在：

1. **分数在引擎里，不在外形里。** 赛题的核心评分依据是
   > 吞吐量 = 「同时活跃可闻独立振荡器总数 × 实际音频输出采样率」

   这是纯引擎指标。外形再炫，振荡器只有 4 个，分数就上不去。
2. **引擎与形态无关。** I2S 发送器、振荡器、ADSR、混音、效果器——换成任何形态都得做，一行都省不掉。先做这些，零返工。
3. **形态晚定反而更准。** 等引擎跑起来、你真的"弹"过之后，才知道自己需要几个键、要不要连续音高、力度手感如何。现在拍板容易返工。

**结论：P1/P2 阶段（约 4 周）专注引擎，形态放到 P3 再定。** 但要在引擎里预留一个**稳定的演奏事件接口**，让外形可插拔：

```verilog
// 演奏事件接口（前端形态无关）
// 任何前端（按键/触摸/手势/吹奏）只需产生这些事件
note_on   : (note_id[7:0], velocity[7:0])   // 起音：音高 + 力度
note_off  : (note_id[7:0])                  // 释音
pitch_bend: (signed [15:0])                 // 滑音（连续音高偏移）
modulate  : (intensity[7:0])                // 颤音/调制深度
timbre_sel: (timbre_id[3:0])                // 音色切换
```

只要接口不变，前端从"两个板载按键"换成"13 键触摸板"再换成"手势传感器"，引擎一行都不用改。

## 二、三种形态对比（按 Tang Nano 20K 的实际条件评估）

| | **A. 触摸键盘式** | **B. 触摸滑条 + 无接触** | **C. 纯手势/空气琴** |
|---|---|---|---|
| 音高维度 | 离散键位（12~13 键） | **连续**（滑音天生） | 连续（手的位置） |
| 力度维度 | FSR 压力片 / 接触面积 | 接触面积或触发速度 | 手到传感器的距离/速度 |
| 可达维度数 | 2~3 维 | **3 维**（音高/力度/表情） | 2~3 维 |
| 器件成本 | 极低（TTP223 几毛/个） | 低（自制铜箔 + 少量元件） | 中（ToF/超声/红外阵列） |
| 硬件难度 | ★☆☆ 简单 | ★★☆ 需调电容前端 | ★★★ 需标定与环境鲁棒性 |
| 演示观感 | 像电子琴，**和弦演示最直观** | 有辨识度，滑音很出彩 | **最抓眼球**，赛题原文点名 |
| 现场风险 | 低 | 中 | **高**（灯光/反射/噪声干扰） |
| 对复音展示 | **最好**（按和弦即证明 ≥4~32 复音） | 一般（连续音高难按和弦） | 一般 |
| 建议角色 | **保底主力** | **表情维度增强** | 可选彩蛋 |

**关键约束**：Nano 20K **没有 ADC**。所以模拟量力度不能直接采：
- 方案 1：外接 I2C ADC（ADS1115 等）——增加器件与协议工作量；
- 方案 2（推荐）：**RC 充放电时间测量法**——用一个数字 IO 先放电、再充电、数到阈值翻转所需的时钟数，即得电阻/电容值。纯数字逻辑，FPGA 极其擅长，**零额外器件**。这也是"用 FPGA 做交互"的技术亮点，写进报告很好看。

## 三、推荐路线：**A 保底 + B 增强 + C 彩蛋**

```
P3 阶段落地形态：
  ├─ 主力：8~13 键电容触摸键盘（TTP223 或自制焊盘）    → 音高 + 触发   [第 1、2 维]
  ├─ 增强：1 条电容/电阻触摸滑条                       → 滑音、颤音    [第 3 维]
  └─ 彩蛋：1~2 路红外/超声无接触通道                   → 力度/音量     [+ 赛题点名的"手势"]
```

这样能同时拿到：
- **基础要求**：≥2 个独立可控演奏维度 ✓
- **拓展 2**：≥3 维演奏表情调控（力度 + 滑音 + 颤音）✓
- **赛题原文点名的"无接触手势"** ✓
- 和弦演示能力（复音展示最有力的证据）✓

## 四、战略提示：注意"振荡器"是怎么计数的

赛题原文对计数的定义，直接决定了怎么做最划算：

> 独立发声单元为包含独立相位累加器、频率调控、包络控制的完整振荡器；单波表采样查表不计多谐波数量，仅计单个振荡器；**加法合成按运算分量统计、FM 按调制运算器统计、物理建模按并行弦/模态单元统计**。

也就是说，**加法合成的每一个分量都算一个振荡器**。于是：

| 做法 | 振荡器数 | 吞吐量（fs = 46.875 kHz） |
|---|---|---|
| 4 复音 × 波表（基础要求） | 4 | 0.19 M osc·Hz |
| 32 复音 × 波表（拓展 1） | 32 | 1.5 M osc·Hz |
| 8 复音 × 每音 16 加法分量 | **128** | **6.0 M osc·Hz** |
| 32 复音 × 波表 + 2 个富音色用 32 分量加法 | 32 + 64 = 96 | 4.5 M osc·Hz |

**建议**：基础架构用**波表法**（每个 voice 成本低，先把 32 复音稳稳做出来），再挑 **2~4 个"特色音色"用加法合成**（例如风琴、钟声）——既有真实音色差异（满足"≥2 种音色"），又大幅拉高吞吐量指标，同时完全符合计数规则。

⚠️ 前提是资源放得下。Nano 20K 只有 48 个乘法器和 20736 LUT4，128 个相位累加器+查表在 46.875 kHz 下需要时分复用；Mega 60K（118 DSP / 59904 LUT4）会宽裕得多。**所以"能不能上 Mega 60K"会实质影响我们能冲多高。**
