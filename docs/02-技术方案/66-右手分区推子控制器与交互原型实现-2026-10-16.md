# 右手分区推子控制器与交互原型实现 · 2026-10-16

对应N-04/N-05/N-06的输入控制阶段。用户授权检查已有代码并推进实现，本轮交付可综合RTL、可操作预览和实际验证；**控制器在隔离数字范围已验证**，完整右手产品路径仍**部分实现/待实现/待验证**。

## 1. 用户决定与原型设置

已确认竖直推子左右分侧、同侧两个触点取最近者、两侧各一个则取高度算术中点、松手保持。用户进一步明确每根推子有自己的分区，B不能因距离近而抢A区手指，作用范围可调。旧相对位移/落指单组独占不再是默认方案。

当前原型将分区作为硬边界，在区内按横向距离取最近，半径可调；坐标/区宽/组数均可替换。用户尚未回答后续“范围只能在本区调，还是允许显式扩展邻区”的问题，故这仍是原型设置，不能因实现已存在当作额外用户决定。最近距离按横向计算也作为明确列出的原型解释，不冒称用户已单独选择该距离度量。

8组、800×480、5点及100px区宽为实例，不冻结最终组数、音色映射或屏幕型号。松手保持/全和弦修饰/RESET平滑目标不变。

实现细则：分区为半开区间，交界归右侧；等距以较小触点ID决定，避免报告顺序引起抖动；轴线上触点同时占两侧，因此直接跟随该点；中点加宽求和，取整误差≤0.5px再限幅。多触点两侧均有候选时各侧先取最近。以上技术细则可调整，尚无声音听感验收。

完整可信触点报告由上游驱动提供，本控制器不代替传感器扫描、I²C报文、坐标校准、触点ID追踪或时钟域处理；无效报告不能直接当成抬手。输出是**推子目标像素位置**，不是音频增益，也没有改写正式基础谱/编辑草稿/EEPROM。恢复接口即时发布目标，声音侧平滑仍待接合。

## 4. 实际验证与发现

- 11项独立行为单元测试通过，覆盖同侧取近/报告重排、双侧各取最近后中点、越区隔离、区边界、部分/全部抬手、轴线上触点、等距ID、半径边界、中点溢出/限幅、非法分区与重复ID。
- 1/8/16根推子各620帧，固定面板封装另620帧，共2480帧RTL对参考；含定向例与固定种子随机位置、数量、顺序和范围。控制测试额外验证输入受理后变化不污染快照、发布原子性、错误配置拒绝、恢复/复位抢占不出现旧帧延迟提交。
- 浏览器模型以同2480组输入核对参考通过，不将它与RTL相加宣称4960种独立场景。
- 独立Chrome临时上下文11项UI检查通过，含浏览器真正多触点输入/移动、松手保持、放大半径仍不跨区、390px窄窗口无横向溢出、无运行错误。只验证原型，不是实物触屏。
- 首次浏览器原型逐触点处理抬手，复现同时双指抬起产生单指中间目标；已改为完整触摸报告并在浏览器显示帧合并事件，新增强断言后通过。FPGA接口从开始即以完整报告原子处理。不能把浏览器显示帧策略说成硬件必须等待屏幕画完。
- 默认8推子×5触点受理到提交49周期，27MHz名义换算1.815µs。仅为数字控制器，不含感测、I²C、音频或光学时延，不能当成整机10ms通过。

运行记录与来源指纹在`evidence/validation.json`、`ui-validation.json`及`delivery.json`。普通浏览器控制工具初始化失败后，UI验证用本机已有Chrome的独立测试上下文完成，未接管用户浏览器配置、未下载/安装软件。
