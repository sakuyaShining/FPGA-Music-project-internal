# 什么才叫好作品 —— 评审逻辑与高分画像

> 目的：在动手写代码之前，先搞清楚**这个竞赛到底奖励什么样的作品**。
> 方法：官方明示的评分维度 + 1442 件历届获奖作品（2024/2025）的定量分析。
> 数据来源：官网 `/competition/awardInfo/search` 接口全量拉取（作品名称+奖项+学校），落盘于
> `refs/_site-archive/history-lists/获奖作品-2024-2025.csv`
> 分析日期：2026-09-18

---

# 第一部分　评分规则的三层结构

这个竞赛的"得分"不是单一公式，而是**三层叠加**：

```
第 1 层  组委会层   资格审查 → 初赛线上评审 → 决赛现场评审
        （决定你能不能进场、能不能进决赛）
                    ↓
第 2 层  厂商赛题层  高云选题二的评分规则
        （决定你在该赛道内的相对排名）
                    ↓
第 3 层  现场层      FPGA基础编程考核 + 作品演示 + 专家提问
        （决定最终奖项等级）
```

**关键**：三层都过关才拿得到好名次。很多队伍第 2 层做得漂亮，栽在第 1 层（报告/视频太糙）或第 3 层（讲不清/演示翻车）。

# 第二部分　官方明示的评价维度（原文）

## 2.1 资格审查看 6 项

> 「主要根据参赛队伍信息提交**完整度**、项目**创新性**、**科学性**、**工程可行性**、**设计难度**以及 **FPGA 平台适用度**等因素判定。」

（来源：`refs/official-notices/news_53.txt`）

逐项翻译成人话：

| 维度 | 评委在问什么 |
|---|---|
| 提交完整度 | 东西交齐了吗？报告结构完整吗？ |
| 项目创新性 | 别人做过了吗？有新意吗？ |
| 科学性 | 技术路线合理吗？有理论依据吗？ |
| 工程可行性 | 做得出来吗？是纸上谈兵吗？ |
| 设计难度 | 太简单了没意思 |
| **FPGA 平台适用度** | **这个事为什么非得用 FPGA？** ← 最关键的一条 |

## 2.2 决赛评审看 3 项

> 「专家组将根据参赛作品**完整度**、**专业性**、**创新性**等标准进行评审」

（来源同上）

## 2.3 决赛还有一道硬门槛

> 「决赛评审期间将安排 **FPGA 基础编程设计能力考核**，通过测试的参赛队伍将获得决赛评奖资格。」

→ 意思：技术再炫，基础题做不出来，**没有评奖资格**。

## 2.4 高云选题二的评分规则（第 2 层）

> 系统吞吐量指标 = 「**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**」，过采样不叠加加分。

外加振荡器计数规则（详见 `01-选题确认与约束条件.md` 第 2.3 节）。

## 2.5 参考：高云给另一道选题的权重表（暴露了它的评分习惯）

高云选题三（具身智能机器人）给出了明确权重：

| 项目 | 占比 |
|---|---|
| FPGA 实时感知与控制 | **40%** |
| 系统稳定性 | 25% |
| 自主导航能力 | 20% |
| 创新设计 | 10% |
| AI 扩展功能 | 5% |

→ **读出来的信号**：高云最看重"**FPGA 真的在干活**"（40%），其次是"**稳不稳**"（25%），创新只占 10%。选题二虽未给权重表，但倾向大概率一致。

# 第三部分　奖项现实（历届数据）

## 3.1 奖项规模

| 年份 | 一等奖 | 二等奖 | 三等奖 | 合计 |
|---|---|---|---|---|
| 2024 | 100 | 194 | 395 | 689 |
| 2025 | 100 | 193 | 460 | 753 |

**另有**（不在上述统计内）：5 个企业杯（AMD杯 / 紫光同创杯 / 安路科技杯 / **高云杯** / 易灵思创新杯）、最佳创意奖 ≤3、最佳工程奖 ≤3。

## 3.2 几个重要事实

1. **一等奖固定 100 个**两年不变（赛题指南写"≤100"，实际正好 100）。→ 一等奖是稀缺资源，竞争激烈。
2. **二等奖 ~193 个**（指南写"≤200"）。→ 相对可及。
3. **三等奖 395→460 个**，是最大的池子。→ **只要作品完整、合规，拿到奖项的概率不低。**
4. 2025 年获奖 753 支 vs 晋级决赛现场 305 支 —— 两个数字对不上（获奖数 > 现场数）。推测三等奖中包含未到现场的队伍，但**官方未解释，此处存疑，不作为决策依据**。

# 第四部分　从 1442 件获奖作品反推「高分画像」

## 4.1 主题热度与一等命中

| 主题 | 获奖总数 | 其中一等奖 | 一等率 |
|---|---|---|---|
| 视觉 / 图像处理 | 298 | 43 | 14% |
| 信号分析 / 测试仪器 | 191 | 25 | 13% |
| 通信 / 无线电 / 以太网 | 146 | 18 | 12% |
| AI / 神经网络 / HLS 加速 | 99 | 21 | 21% |
| **音频 / 语音 / 声音** | **84** | **14** | **17%** |
| 工业 / 检测 / 农业 | 76 | 8 | 11% |
| 医疗 / 内窥 / 影像诊断 | 52 | 13 | **25%** |
| 机器人 / 运动控制 | 32 | 11 | **34%** |
| 密码 / 安全 | 7 | 2 | 29% |
| 游戏 / 娱乐 / 显示 | 30 | 3 | **10%** ← 最低 |

**读数**：
- **游戏/娱乐类一等率最低（10%）** → 纯好玩但"没用"的作品不受待见
- **机器人、医疗类一等率最高** → 有明确现实价值 + FPGA 不可替代
- **音频类 17%，高于平均** → 我们选的方向不吃亏

## 4.2 一等奖作品的命名规律（2025，n=100）

| 特征 | 占比 |
|---|---|
| 名称含"**系统**" | **40%** |
| 含"智能/AI/神经/深度学习" | 28% |
| 含"基于 FPGA/基于 XX" | 27% |
| 含**具体应用场景词**（医疗/内窥/工业/检测/安防/驾驶/通信/会议/录音/识别/诊断/导航） | 26% |
| 含"装置/仪" | 8% |
| 含"平台" | 4% |

作品名称平均 **11.4 字**。

**读数**：一等奖作品绝大多数是 **"面向某个明确场景的 XXXX 系统"**。名字里带着"这个系统是干嘛用的"。

## 4.3 一个极强的规律：**命题式赛题占比巨大**

同一个作品名反复出现，说明它来自企业命题：

- 2024：「**高精度音频处理和效果生成系统**」出现在南京大学、西安石油大学、南京邮电大学、西安电子科技大学、电子科技大学（横跨一/二/三等奖）
- 2025：「**智能信号分析与测试系统**」系列出现 10+ 次
- 2025：「**L1 算子优化 / HLS 加速器内核设计**」系列出现 7+ 次（对应 AMD 命题式基础赛道）

**读数**：**走企业命题是主流且行之有效的路径**，命题赛题里同样能出一等奖。我们选高云选题二，走的就是这条主流路。

## 4.4 高频"高分题材"观察

1. **医疗内窥/影像**（52 件，13 个一等奖）—— 异常集中。故事性强 + 对实时性要求高 + FPGA 不可替代
2. **信号分析/测试仪器**（191 件）—— FPGA 的"高速采集+实时处理"本职
3. **调试器/协议分析仪** —— 2025 高云赛道就出了多个一等奖（ACG525 调试器、多协议高速调试器）
4. **AI 加速/算子** —— 2025 热点，一等率 21%
5. **无线通信/SDR** —— 高云赛道 2025 多个一等奖

## 4.5 反面样本（教训）

名单里也能看到**没有说服力**的作品名：
- 「FPGA基础能力」「FPGA设计」「FPGA」「命题式作品」「命题式FPGA设能力专项」→ 这些是**命题式基础赛道的考核作品**，只有编号式命名，本身不是创意作品
- 大量"XX系统"但看不出应用场景的命名

**读数**：如果作品的"用途"无法从名字里读出来，说明**你可能自己也没想清楚它的应用价值**。

# 第六部分　结论：「好作品」的定义

## 6.1 一句话定义

> **好作品 = 一件"完整、可演示、有真实应用场景、且 FPGA 在其中承担不可替代核心作用"的系统级作品。**

## 6.2 六个判据（按重要性排序）

| # | 判据 | 依据 |
|---|---|---|
| 1 | **完整度**：端到端跑通，不是单模块验证 | 决赛评审第一项是"作品完整度" |
| 2 | **FPGA 不可替代性**：这事非 FPGA 不可 | 资格审查看"FPGA 平台适用度"；高云选题四明写"体现 FPGA 的性能和非替代性" |
| 3 | **应用场景清晰**：能说清"给谁用、解决什么问题" | 26% 一等奖名称含具体场景词 |
| 4 | **可现场演示 + 有量化指标** | 决赛要"作品介绍及演示、专家提问" |
| 5 | **专业性**：工程规范、报告完整、可复现 | 决赛评审第二项 |
| 6 | **创新性** | 决赛评审第三项；但在高云的权重习惯里占比最低（10%） |

## 6.3 明确的陷阱（别踩）

| 陷阱 | 为什么致命 |
|---|---|
| 只做单模块验证，没有端到端闭环 | 完整度直接失分 |
| FPGA 只当接口板/转接板，核心算法在 CPU/PC | 违反"FPGA 平台适用度" |
| 无法现场演示，或演示不稳定 | 决赛现场翻车 |
| 拿不出量化指标 | 专业性失分，专家提问答不上来 |
| 只"好玩"没有应用价值 | 游戏/娱乐类一等率最低（10%） |
| 基础编程考核过不了 | **直接失去评奖资格** |

## 6.4 从结论反推：我们要做成什么样

把高云选题二做成一等奖作品，需要**在赛题要求之上再加一层包装**：

| 赛题要求（底线） | 一等奖要求（加一层） |
|---|---|
| 一个能发声的合成引擎 | **一台完整的电子乐器**，有名字、有形态、有演奏方式 |
| 复音 ≥4、延迟 ≤10ms | **可量化、可现场实测**的性能数字（含对比基线） |
| 满足 ≥2 维交互 | **3 维以上演奏表情**，且演奏体验说得通 |
| 通过 I2S 输出 | **可听、可看、可互动**的完整演示（含频谱/波形可视化） |
| 无预录 PCM | **能自证**（测试模式 + RTL 讲解） |

**关键包装点**（从高分作品学来的）：
1. **给它一个应用场景故事** —— 例如"面向音乐教育的低成本 FPGA 电子乐器"、"面向无障碍演奏的触控乐器"
2. **给一个产品化的名字** —— 参考获奖命名风格：「XX 系统 / 装置」，11 字左右，含场景词
3. **把"FPGA 为什么不可替代"写成一段核心论述** —— 并行振荡器、确定性低延迟、硬件效果器实时性
4. **准备一份量化指标表** —— 复音数、延迟、吞吐量、资源占用、THD/信噪比
5. **现场演示脚本要排练** —— 因为决赛有专家提问环节

# 第七部分　对我们的行动含义

## 7.1 立即影响

- **第 3 层（现场）现在就要纳入设计**：作品的"可演示性"和"可讲解性"应在架构阶段就考虑，而不是最后补
- **第 2 层（赛题评分）指向明确**：振荡器数 × 采样率 —— 这决定我们架构决策（见 `06-架构决策清单-第1批.md`）
- **第 1 层（报告/视频）是初赛生死线**：从开发第一天就要留存素材（照片、数据、截图）

## 7.2 需要补充的信息

- [ ] 组委会是否公布过**评审细则原文**（目前只有定性维度）
- [ ] 高云选题二是否发布**评分权重表**（选题三有，选题二没有）
- [ ] 初赛的**淘汰率**（有多少队伍报名 vs 多少晋级）
- [ ] 往届**优秀作品文集**是否有公开版本（竞赛背景提到计划出版）

## 7.3 存疑事项（不做决策依据）

- 2025 获奖 753 支 vs 决赛现场 305 支，数字不一致，原因未知
- 企业杯（含高云杯）的具体归属，从 PDF 文本推断，可能有偏差
