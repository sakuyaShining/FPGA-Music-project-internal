# 四个关键维度：强制 / 自由 / 过拟合 / FPGA与Agent 的发挥空间

> 目的：在你形成直觉之前，先把**客观边界与客观机会**铺开。
> 本文档**不替你定方向**，只负责把"题目给了多少空间、空间在哪、陷阱在哪"讲清楚。
> 依据：赛题原文（`refs/candidate-guides/gaoyun.txt` 第 242-302 行）+ 1442 件历届获奖作品 + 官方文档

# 维度一　题目**强制**的东西（不可协商）

按"强制强度"分三级。**红线级碰了就废，硬指标级不达标就失格，形式级是必须存在的构件。**

## 1.1 红线级（合规性，碰了直接废）

| # | 强制内容 | 原文 |
|---|---|---|
| R1 | **严禁播放预录 PCM 音频** | 「严禁直接播放预录 PCM 音频、预置推流及整段录音触发」 |
| R2 | **所有音频必须逐音、逐样本实时生成** | 「所有输出音频均由 FPGA 根据实时演奏指令逐音、逐样本实时生成」 |
| R3 | **必须能自证无预录** | 「可通过 RTL 代码佐证纯硬件实时合成通路，验证无预录音频播放行为」 |

→ 这三条是一体的：**不能用录音，且必须能证明没用录音。**

## 1.2 硬指标级（不达标 = 不合格）

| # | 强制内容 | 数值 |
|---|---|---|
| M1 | 演奏**独立可控维度** | **≥2** |
| M2 | 完整音频通路 | **全部基于 FPGA HDL**（不能有软核/MCU 参与发声） |
| M3 | 输出接口 | **必须经 I2S → DAC** |
| M4 | **控制信号到音频输出总延迟** | **≤10 ms** |
| M5 | 基础**复音数** | **≥4**（四路及以上独立声部并发） |
| M6 | 单音**实时变调** | 必须支持 |
| M7 | **ADSR 包络**调控 | 必须支持 |
| M8 | **多声部实时混音** | 必须支持 |
| M9 | 交互形态 | 必须**自研**（不能买成品乐器） |

## 1.3 形式级（必须存在的构件）

| # | 强制内容 | 说明 |
|---|---|---|
| F1 | **测试模式** | 现场必须能"输出多路不同频率音频，频谱可观测对应数量独立谱峰" |
| F2 | **振荡器必须完整** | 「独立发声单元为包含**独立相位累加器、频率调控、包络控制**的完整振荡器」 |
| F3 | 输入指令类型 | 要能识别「选音、和弦、触发、拨弦」等演奏指令 |
| F4 | 适配板卡 | Sipeed Tang 系列（Nano 20K / Primer 25K / Mega 60K / 138K） |

## 1.4 强制清单里藏着的"自由度"

**注意一个关键措辞**：

> 「系统依托电容触摸、光电感应、压力检测、无接触手势等**任意自研交互方案**」
> 「采用波表采样、加法合成、FM 调频或物理建模等**任意合规算法**」

→ **题目强制的是"达到什么效果"，不是"用什么手段"。** 交互方式、合成算法、产品形态、音色风格、UI 呈现——**全部自由**。

# 维度二　**可自由设计**的东西（发挥空间在哪）

我按"自由度 × 对得分的影响"排列。

## 2.1 完全自由（题目零约束）

| 领域 | 自由度 | 对得分的影响 |
|---|---|---|
| **产品定位与应用场景** | 100% 自由 | ⭐⭐⭐⭐⭐ 决定"创新性"与"完整度" |
| **作品形态与外观** | 100% 自由 | ⭐⭐⭐⭐ 决定现场观感 |
| **交互传感器方案** | 自由（"任意自研方案"） | ⭐⭐⭐⭐ 决定 M1 与 E2 |
| **合成算法组合** | 自由（"任意合规算法"） | ⭐⭐⭐⭐⭐ **直接决定吞吐量指标** |
| **音色设计** | 100% 自由 | ⭐⭐⭐ 影响演示效果 |
| **表演曲目与演示脚本** | 100% 自由 | ⭐⭐⭐⭐ 决定现场印象 |
| **可视化形式** | 自由（赛题只列了 4 种"包含"式举例） | ⭐⭐⭐ 兼作合规自证 |
| **额外功能** | 自由（蓝牙、App、脱机曲目…） | ⭐⭐ 加分但吃时间 |

## 2.2 半自由（有边界，边界内自由）

| 领域 | 边界 | 边界内自由度 |
|---|---|---|
| 板卡 | 限 Sipeed Tang 四款 | 选哪款、是否自制扩展板 |
| 采样率 | 题未规定 | 完全自主（但受时钟硬件制约） |
| 复音数 | ≥4 底线 | 4 ~ 200+，自己定 |
| 延迟 | ≤10ms 上限 | 越低越好，可冲 ≤5ms |
| 精度（位宽/表深） | 题未规定 | 完全自主 |
| 效果器 | 题"包含"混响/延迟/合唱 | 也可以做别的（失真、移调、环形调制…） |

## 2.3 一个常被忽略的自由度：**"乐器"这个词本身**

赛题标题叫「电子乐器引擎」，但正文只说"**构建低延迟、高实时性、高表现力的纯硬件实时电子乐器系统**"。

**没有规定必须长成传统乐器的样子。** 这可能是一台：
- 传统键盘琴
- 触摸条 / 无接触空气琴
- 打击垫 / 手碟式
- 吹奏式
- **甚至是一种全新的演奏交互**（赛题鼓励"任意自研交互方案"）

→ **这是最大的自由空间，也是最需要你自己有感觉的地方。**

## 2.4 补充：自由度与风险成正比

| 自由度高的地方 | 附带的风险 |
|---|---|
| 自研交互 | 传感器调试不稳定 → 现场翻车 |
| 自研算法 | 实现难度大 → 做不完 |
| 全新形态 | 评委不理解 → 演示说服力要求高 |
| 额外功能（App/蓝牙） | 吃时间 → 挤占核心 |

→ **自由度不是"越多做越好"，而是"你愿意为哪些自由承担风险"。**

# 维度三　**最容易过拟合**的地方（陷阱在哪）

> "过拟合"在这里指：**把作品过度贴合赛题的某个表层特征，而丢掉了作品的本质价值。**

我先给一个**反直觉的实测数据**：

## 3.1 先说数据：命题式作品并没有优势

| 类别 | 数量 | 一等奖 | 一等率 |
|---|---|---|---|
| 全部作品 | 1442 | 200 | 13.9% |
| **纯命题/抽象命名**（FPGA基础能力、命题式…） | 109 | 14 | **12.8%** |
| 具体场景+系统命名 | 641 | 86 | 13.4% |
| 通用功能命名 | 27 | 4 | 14.8% |

→ **一等率几乎持平。** "照着命题做、把名字取成赛题名"**不会带来优势**。2024 年那一大批「FPGA基础能力」一等奖，是因为那是**命题式基础赛道的考核科目**，不是创意作品。

## 3.2 五个具体的过拟合陷阱

### 陷阱 1：把"振荡器数 × 采样率"当成唯一目标 ★ 最危险

**为什么危险**：这是评分依据之一，但**不是全部**。
- 它只服务第 2 层（厂商评分）
- 第 1 层（报告/初赛）和第 3 层（现场演示/答辩）不看这个
- 如果为了堆振荡器数而牺牲**稳定性、可演示性、音色可听性**，就是典型的过拟合

**具体表现**：
- 堆到 200 个振荡器，但现场一放就爆音/时序违例
- 振荡器很多，但"同时活跃**可闻**"的没几个（规则强调"可闻"）
- 频谱峰挤在一起，数不出来（那现场自证就失败）

**平衡点**：指标要冲，但**必须服从"现场能稳定演示、频谱能数清峰"**。

### 陷阱 2：只做赛题列的算法/功能，不做产品

**具体表现**：
- 赛题提到"混响、延迟、合唱"，就只做这三个
- 赛题提到"蓝牙 + App"，就硬塞一个蓝牙模块
- 结果是一个"功能清单的堆砌"，而不是一件完整的乐器

**为什么扣分**：判据是"完整、可演示、有真实应用场景"。"功能齐全"≠"是个好乐器"。

### 陷阱 3：把交互做成"能过测试"而不是"能演奏"

**具体表现**：
- 两个按键 = "2 个独立可控维度"，技术上达标
- 但演奏起来毫无音乐性，演示时只能"滴滴"两下

**为什么扣分**：赛题要求"**适配乐器演奏场景**"、"交互逻辑灵敏稳定"。演示时如果弹不出一段像样的东西，第 3 层会失分。

### 陷阱 4：追求参数漂亮，忽略"可闻"

**具体表现**：
- 采样率飙高（96kHz），但"过采样不叠加加分"
- 位宽堆到 32 位，但听不出区别
- THD 指标很好看，但音色寡淡无趣

**关键提醒**：规则原文「**同时活跃可闻**」——"可闻"是限定词。听不出来的东西不算数。

### 陷阱 5：照着赛题原文写报告

**具体表现**：
- 报告标题就是「基于 FPGA 的实时多音色合成电子乐器引擎」
- 章节照抄赛题的基础要求/拓展要求
- 全文都在"证明我满足了要求"，而不是"讲清楚我做了一个什么东西"

**为什么扣分**：一等奖作品名平均 11.4 字，带具体场景词。**"证明合规"是底线，"讲清价值"才是拿分点。**

## 3.3 过拟合的镜像风险：**欠拟合**

反向的陷阱也一样致命：

| 表现 | 后果 |
|---|---|
| 做了个很酷的东西，但**没满足 ≥2 维交互** | 不合格 |
| 音色很好，但**复音只有 2** | 不合格 |
| 演示很炫，但**拿不出振荡器数 × 采样率** | 指标分丢了 |
| 能发声，但**没有测试模式** | 现场自证失败 |

→ **正确姿势：先把强制项全部做实（防欠拟合），再在自由空间里做出个性和价值（防过拟合）。**

# 维度四　最值得发挥 **FPGA** 与 **Agent** 的地方

## 4.1 FPGA 的"不可替代性"在哪（这是 40% 权重的来源）

回忆 `02-什么才叫好作品`：高云给另一道题的权重是「**FPGA 实时感知与控制 40%**」。
资格审查看「**FPGA 平台适用度**」。
高云选题四明写：「体现 FPGA 的性能和**非替代性**（不使用 MCU）」。

**所以核心问题：这件事为什么非 FPGA 不可？**

### 四个真正的 FPGA 优势点（我们的赛题能兑现的）

| # | FPGA 优势 | 在我们的赛题里体现为 | 能不能量化 |
|---|---|---|---|
| **1** | **大规模并行** | N 个振荡器**同时**运算，互不干扰。CPU 只能串行或靠多核（几个核） | ✅ 振荡器数、吞吐量 |
| **2** | **确定性时序** | 延迟**固定可预测**，不抖动。CPU 有中断、调度、缓存导致的抖动 | ✅ P99 抖动、延迟分布 |
| **3** | **单周期级流水线** | 每个时钟都产出样本，无"软件串行运算滞后" | ✅ 延迟、采样率 |
| **4** | **数据流架构** | 信号就是流经硬件，无需访存往返 | ✅ 资源占用、能效 |

### 一个极有说服力的论证结构（建议用于报告/答辩）

> **对比论证**：同样做 32 复音合成，在 CPU 上会怎样？
> - CPU：需要分时调度 32 个声部，音频回调里做 32 次运算 → 延迟受缓冲区大小限制（通常 5-20ms），且受系统负载影响抖动
> - FPGA：32 套并行硬件，每个采样周期所有声部**同时**运算完 → 延迟 = 固定流水线级数，**抖动为 0**
>
> **这就是为什么必须用 FPGA。**

**这个对比如果能实测出来（CPU vs FPGA 同任务延迟对比），会是非常强的加分点。**

### 反面：哪些做法会毁掉"FPGA 不可替代性"

| ❌ 做法 | 为什么致命 |
|---|---|
| 用软核 CPU 跑合成算法 | 直接违反 M2（必须纯 FPGA HDL） |
| FPGA 只做 I2S 接口，合成在外部芯片 | 变成"接口板" |
| 大量逻辑用现成 IP 拼接，没有自研设计 | 设计难度失分 |
| 把 PCM 存在 ROM 里播放 | 踩红线 R1 |

## 4.2 Agent 的发挥空间在哪

> 先澄清：**"Agent"在你的项目里有两个完全不同的含义**，别混。
> - **(a) 你的开发助手**（就是我）—— 帮助扩大设计空间、执行操作
> - **(b) 作品内的智能体**（如果有）—— 属于作品功能
>
> 下面分别讲。

### (a) 开发过程里的 Agent 协作 —— **今年赛制明确鼓励**

**证据链**：

| 来源 | 原文 |
|---|---|
| AMD 2026 指南 | 新增「**RTL/HLS 本地智能体设计赛道**」；3.3 自主选题**权重含「大模型协作与技能包 15 分」**；要求提交「体现大模型协作过程的交互记录（提示词、模型回答、自我纠错轨迹）」，并**须提交可复用技能包** |
| 复旦微 2026 指南 | 「鼓励学生可以自由发散地利用合适的 **Agent 工具与大模型**进行选题、方案制定、算法实现以及高效开发」；**额外义务**：「作品成果中需要细化具体在什么环节中使用了何种 AI 工具及其在整体工作量中的占比情况」 |
| AMD 3.3 | 「须提炼可复用技能包随作品提交」；**通用 PYNQ Skill 单独加分** |

→ **今年组委会层面明确把"如何用 AI/Agent 做工程"纳入了评分视野**，至少 AMD 和复旦微都写了。

**⚠️ 但我们不能盲目套用**：高云选题二的评分规则里**没有**提到 Agent 协作。
- 不能假设高云会因此加分
- 但可以在报告中**主动体现**（作为工程方法论的加分项），成本很低

**可操作的 Agent 协作点**（低成本、高可见度）：

| 环节 | 怎么用 Agent | 产出物 |
|---|---|---|
| 选题调研 | 抓官网数据、对比历年题目 | 情报文档（我们已在做） |
| 架构权衡 | 列选项、算代价、做敏感性分析 | 决策记录 |
| RTL 编写 | 生成骨架、写 testbench、逐行注释 | 代码 + 注释 |
| 调试 | 分析时序报告、定位违例 | 调试日志 |
| 测试 | 生成测试向量、自动化仿真 | 测试脚本 |
| 文档 | 报告结构化、图表生成 | 报告草稿 |
| **沉淀** | **把踩过的坑写成可复用技能包** | **`skill/` 目录** ← 这是 AMD 明确加分的形态 |

**建议**：从现在开始**记录协作日志**（`notes/agent-collaboration-log.md`），记录：什么问题、怎么问的、Agent 给了什么、我采纳/否决了什么、为什么。
- 成本：每天 5 分钟
- 收益：如果高云也看这个，是加分；如果不看，至少是"工程方法论"的体现，且**顺便帮你自己复盘**

### (b) 作品内的"智能" —— 要谨慎

**可选方向**：
- 智能调音（自动识别音准偏差）
- 自适应音色（根据演奏力度自动配比泛音）
- 演奏辅助（和弦推荐、节奏纠错）

**⚠️ 重大警告**：
1. **必须仍满足 M2** —— 完整音频通路全部基于 FPGA HDL。任何"智能"如果是软核跑的，只能在不碰发声通路的前提下做
2. **会稀释精力** —— 47 天很紧，智能功能很容易变成"做了个半成品"
3. **可能引发质疑** —— 如果智能部分跑在软核上，评委会问"这还算纯硬件合成吗？"

→ **建议：作品内的"智能"放到最后，作为锦上添花；不要作为必做项。**

## 4.3 一个真正的机会点：**把"不可替代性"做成可测量的对比**

结合你的示波器条件，一个很有说服力的实验：

```
实验：同一段旋律（比如 8 音同时发声）
  ├─ 用 PC/手机上的软件合成器播放，示波器测「触发→出声」延迟
  └─ 用我们的 FPGA 乐器演奏，同样测延迟
对比：延迟数值 + 抖动分布（P50/P95/P99）
```

**这个对比一旦做出来，就是"FPGA 为什么不可替代"的硬证据**，直接服务 40% 那个权重维度。

而且它**成本很低**（软件合成器现成，示波器你有）。

| | 内容 | 你的行动 |
|---|---|---|
| **强制** | 3 红线 + 9 硬指标 + 4 形式项 | 全部落实，一条不能少 |
| **自由** | 定位/形态/交互/算法/音色/演示/可视化 | **在自由处做选择，并承担对应风险** |

| **Agent 发挥** | 开发协作（今年赛制鼓励）+ 记录技能包 | 从今天起记协作日志，成本 5 分钟/天 |

# 六、这些信息对你定 D0（产品定位）的意义

看完上面四节，D0 要考虑的就清晰了：

1. **强制项不构成约束** —— 定位怎么选都不影响合规（除了别踩红线）
2. **自由度最大的就是定位与形态** —— 题目完全没限制
3. **过拟合的第一个陷阱就是"唯指标论"** —— 所以定位不能只为堆指标服务，要"是件真东西"
4. **FPGA 不可替代性需要通过"对比"来证明** —— 所以定位最好选一个"CPU 做不好"的场景
   - 例：超低延迟演奏（CPU 音频缓冲做不到）✅
   - 例：几十个声部同时（CPU 算不过来）✅
   - 例：单纯的"播放音乐"（手机就能做）❌

**一句话检验标准**：
> **如果这个作品用一台普通电脑/手机就能做出来，那 D0 选错了。**
