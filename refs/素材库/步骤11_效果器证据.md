## 二、实现要点

### 1) 并联湿声支路 + 零延迟旁路（纪律 D2）

```
引擎 sample_out ─┬──────────────────────────→ 干声（零延迟组合直通）
                 └→ fx_delay → 湿声 ×1/2^n ──┘
                            ↑
              两个效果都关时：顶层 mux 让音频【完全绕开】fx_delay
```

顶层那一行是本次最重要的设计决定：

```verilog
wire signed [23:0] audio = fx_active ? fx_out : sample;   // fx_active = dly_en|cho_en
```

⇒ 旁路时音频与"没有效果器"**逐位相同**（已用 2000 样本验证），
所以**加效果器没有动到任何既有证据**（R0、延迟、I2S 闭环全部照旧）。

### 2) 一块 BSRAM 支持两个抽头：用"每样本 512 拍"分时

延迟与合唱各要一个抽头，而 BSRAM 一个端口一次只能读一个地址。
好在每样本有 **512 拍**，于是用一个小状态机把两次读、一次写摊开：

```
st1 读延迟抽头 → st2 读合唱抽头 → st3 写回（干声 + 反馈×抽头）+ 混合 + 输出
```

⇒ 不需要双口存储器，线缓冲只占 8 块 BSRAM。

### 3) 合唱 = 被 LFO 推着走的延迟抽头

```
cho_delay = CHO_BASE(1024) + lfo_off,   lfo_off ∈ [-depth, +depth]
```
回声到达时间缓慢起伏 = 音高轻微抖动，这正是合唱效果的定义。

### 4) 寄存器映射（新增）

```
0x40      FX_CTRL   [0]干声 [1]延迟 [2]合唱 [5:3]湿声右移(增益 1/2^n)
0x41-42   DELAY_LEN 延迟抽头（小端 16 位，样本）     默认 2048 ≈ 39 ms
0x43      FEEDBACK  延迟反馈（Q8）                    默认 0x60 (0.375)
0x44-45   CHORUS_RATE  合唱 LFO 频率字（小端 16 位）  默认 430 ≈ 1.35 Hz
0x46-47   CHORUS_DEPTH 合唱深度（小端 16 位，样本）   默认 64 ≈ 1.2 ms
默认 FX_CTRL = 0x01（仅干声）→ 上电与"没有效果器"完全一样
```

## 四、过程中踩的三个坑（都值得记）

### 1) 综合器把整个 fx_delay 当【黑盒】丢掉
```
ERROR (EX3934): Loop count limit of 2000 exceeded  (fx_delay.v:64)
Module 'fx_delay' remains a black box due to errors in its contents
```
原因是仿真用的**存储器初始化循环有 8192 项**，超过 GowinSynthesis 的 2000 次上限。
**最危险的地方在于**：综合"继续跑完了"，资源报告看起来跟没加效果器时差不多
（Logic 9175，数字没变）—— 如果只看数字，会得出"效果器几乎不花钱"的错误结论。

修法：初值只给仿真（编译时 `-DSIM_INIT`），综合路径里根本没有这个块
（硬件上 BSRAM 本来就是上电为 0）。
> **教训：综合报错要看全 —— "生成码流成功"不等于"你的模块在里面"。**

### 2) 未初始化的线缓冲在仿真里是 x
第一版输出**全是 0**（判据里"检出回声 0 个"）。原因不是逻辑，而是仿真里 BSRAM 没初值
→ 抽头读出 x → 一路污染到输出。加上 `-DSIM_INIT` 的初值块后正常。
（这与 `tdm_engine` 里那段初始化是同一个理由。）

### 3) 合唱的测试台两次"测错"
- **冲激太窄**：合唱抽头地址每样本移动 0.3~1.3 个样本，**单样本冲激会被跳过**
  （实测 10 次里有 4 次"找不到回声"）→ 改成 4 样本宽的短促发。
- **注入步长的两条约束**（都是被实测逼出来的）：
  ① 不能与 LFO 周期成简单整数比 —— 用过 97，而 97×4=388≈390，
     采样相位几乎原地打转（混叠），测得的调制极差只有 73/128；
  ② 必须大于调制范围本身（2×depth=128）—— 用过 37，搜索窗会先撞到
     上一个冲激的回声，出现 954 这种"低于理论下限"的假值。
  最终用 **137**（≈4 个周期、12 次注入）才测出 981~1059 的正确结果。
> **教训：验证效果器的测试台本身也需要设计 —— 采样步长、激励宽度都会改变结论。**

## 六、混响（第二轮加上的第三件）

### 为什么不用经典 Schroeder（4 梳状 + 2 全通）
每条独立延迟线都要自己的 BSRAM 读写口，4+2 ≈ 12~16 块，而本项目 BSRAM 已用 17/46。
这里改成**共用同一条线缓冲的 8 个近间距抽头 + 阻尼反馈**：
依然得到"密集、缓慢衰减的尾巴"，代价只是每样本多 8 个读周期（每样本有 512 拍，够）。

```
8 个抽头（743/806/870/939/1008/1068/1140/1229）→ 求和 → ÷8 取平均 → 一阶低通（阻尼）
                                                    ↓ × rev_fb
                                       写回线缓冲（与延迟反馈、干声相加）
```

新增寄存器：`FX_CTRL[6]`=混响使能、`0x48`=REV_FB（Q8，默认 0xC0=0.75）、`0x49`=REV_DAMP（默认 3）。

### ★ 踩到的坑：环路增益按"抽头之和"算 → 自激
第一版反馈用的是 8 个抽头的**和** × 0.75 —— 和里已经含了 8 份能量，
环路增益 = 8×0.75 = **6 > 1**，实测能量分段 **1.25e7 → 2.5e11 一路涨上去**（自激）。
改成**先 ÷8 取平均再反馈**，环路增益 = 0.75，稳定，RT60 ≈ 0.5 s。

### ★ 踩到的坑：把"多抽头读"改成"单读口"导致抽头静默错位
为了省 BSRAM，试过把 10 处 `line[地址]` 读改成"一个地址寄存器 + 一个同步读数据"。
结果**每个抽头都错一格**：延迟回声间距实测 **1742**（设定 2048），
而且把 `dly_len` 改成 512/1024/3000 **都还是 1742** —— 说明根本不是 `dly_len` 在起作用，
而是读到了混响抽头 RT2=1741 的地址。

那次实验还顺带撞到综合器的两个脾气（都已记进注释）：
- 读数据写成组合 `wire` 再在别的 always 块里锁存 → **DFF 37465 超过器件上限 15750**；
- 改成规范单口 RAM 模板后 BSRAM 从 100% 回落到 29%，但功能已经错位了。

**结论**：把"多抽头"改成"单读口"必须先严格算清地址/数据的流水相位，
否则功能会**静默错位**（判据能抓到，但代价是两轮返工）。本轮选择保留"每状态显式读"的版本
—— 功能全部通过，用资源换正确性。

## 七、代价（含本轮资源优化）

混响加进来后 BSRAM 一度冲到 **46/46 = 100%**（工具按读地址把 RAM 复制了多份）。
把线缓冲从 4096 样本缩到 **2048 样本（≈39 ms）** 后回落：

| 项 | 加混响前 | 加混响后（未优化） | **优化后（最终）** |
|---|---|---|---|
| Logic | 12384（60%） | 15951（77%） | **12514（61%）** |
| BSRAM | 13/46（29%） | 46/46（**100%**） | **29/46（64%）** |
| DSP | 8.75（37%） | 8.75（37%） | 8.75（37%） |
| SETUP slack | +4.217 | +2.433 | **+2.228** |
| HOLD slack | +0.205 | +0.220 | +0.228 |

**代价**：延迟最长 39 ms（原来是 78 ms）。合唱（19 ms）与房间混响都不受影响；
要更长的延迟就得把线缓冲加回 4096（BSRAM 会回到 100%，不可行）或换更省的存储方案。
**这条限制要如实写进报告。**
