# 步骤 5（RTL 内置测试模式）证据留档  2026-09-30

## 它解决赛题的哪两条
- **F1**：「支持测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰」
- **R3**：「现场需自证无预录音频播放行为」

## 核心思路：让每个泛音占一个独立的频率格
正常演奏时一个声部的 8 个泛音是同一条谐波列（f, 2f, 3f...）。
测试模式下把它们拆开，让 **32 个泛音各占一个等间隔频率格**：

    泛音序号 i (0..31) → 频率 = (i+1) × 400 Hz
    400, 800, 1200, ..., 12800 Hz   （全部在 Nyquist 23.4 kHz 以内）

于是**频谱上出现的峰数就是振荡器数** —— 评委可以一个一个数。
这比"我说我有 32 个振荡器"强得多：数字可以在频谱仪上直接验。

## 验收结果（全部通过）

| 项 | 方法 | 结果 |
|---|---|---|
| **T1 谱峰计数** | 32 泛音等幅 → FFT 数峰 | **恰好 32 个独立峰** |
| | 峰位比对 | 401 / 801 / 1202 / ... / 12800 Hz，与期望(400×(i+1))最大偏差 **2.75 Hz**（FFT 分辨率 5.72 Hz） |
| **T2 随机自证** | LFSR 开关泛音，取两个时间窗 | 32 个频率格里 **16 个不同** → 频谱随时间随机变化 |

## 两种子模式
| TEST_SEL | 模式 | 用途 |
|---|---|---|
| 0 | 正常演奏 | 默认 |
| 1 | 固定谱峰 | 现场数峰，验证振荡器数 |
| 2 | 随机自证 | LFSR 随机开关泛音，每 ~50 ms 一变 |

**种子取自一个不受复位清零的自由计数器** → 每次上电/复位时刻不同，序列起点就不同。
现场可以当场复位一次给评委看："峰变了，预录做不到这个。"

## 资源代价（TEST_SEL=2 最坏情况）
| | 正常(TEST_SEL=0) | 测试模式(TEST_SEL=2) |
|---|---|---|
| Logic | 8048 (39%) | **8829 (43%)** |
| Register | 2182 (14%) | **2260 (15%)** |
| BSRAM | 32/46 | 32/46（不变） |
| DSP | 24/24 | 24/24（不变） |
→ 测试模式只增加 781 逻辑 + 78 寄存器。

## ★ 一个必须如实记录的已知限制
**目前 TEST_SEL 是顶层常量（localparam），不是运行时开关。**
后果：当 TEST_SEL=0 时，综合器会把 test_mode 整个优化掉（实测资源与加它之前完全一致）。
- 现场演示需要改一个字 + 重新综合（约 1 分钟）+ 重新下载
- **步骤 6 会把它变成寄存器位**，届时可以现场切换

之所以现在不做成引脚：Nano 20K 只有两个按钮（S1 复位 / S2 演奏），
不愿意为此引入悬空引脚（悬空输入会让测试模式随机触发，比不能切换更糟）。

## 为什么测试模式不旁路引擎
它仍然走完整通路：相位累加器 → 查表 → 乘幅度 → 包络 → 加法树 → 混音 → I2S，
测试模式只是【换了一组频率与幅度参数】。
本测试台刻意把 env_en 设为 1（包络不旁路），确保测试模式也经过包络级。
