## 四、★ 这一步抓出的三个真 bug（含闸口为何漏掉）

### bug 1：顶层输出**永久为 x**
- **现象**：`tb_audio` 里 150000 个样本**全是 x**，而 `sample`（引擎输出）是 0 ✓
- **定位**：最小复现 `tb_fxinit` — **直接例化** `fx_delay` 时 `line[0]=0` ✓，
  经 `tdm_top` 例化时 `line[0]=x` ✗
- **机制**：复位释放后**第一个样本**引擎还没进入定态（仿真里是 x），被写进线缓冲；
  只要有混响反馈，这个 x 就**每样本被回写**，~2048 样本内扩散到整条线
- **修法**：加**上电冲刷**（参数 `FLUSH_LEN`：顶层 2048 = 整条线；模块级测试台 64，
  以免打乱它自己的激励时刻）。硬件上这也是标准做法（避开上电未定态/直流冲击），代价 39 ms 启动静默

### bug 2：`DELAY_LEN` 默认值放不进地址位宽
- 默认 2048，而线缓冲 `AW=11` ⇒ `2^11 = 2048` ⇒ 低 11 位截断成 **0** ⇒ 抽头读到**刚写入的样本** ✗
- **修法**：默认改 **1500**（≈28 ms）

### bug 3：★★ **干湿混音的无符号加法 ⇒ 输出 +50% 直流、49% 削顶**
- **现象**：`audio_check` 报"直流 4233525（满量程 50.5%）、削顶 73989" ✗
- **定位过程**：先怀疑效果器符号扩展（`rev_fbv[16:0]` 位选 ⇒ 无符号 ✗，确有此病、已修），
  但直流**几乎没变** ✗；最终定位到混音那一行：
  ```verilog
  // ✗ concat 是【无符号】⇒ 整个加法按无符号做 ⇒ 负的干声被【零扩展】成大正数
  wire signed [25:0] mix_sum = (dry_en ? $signed(din) : 26'sd0) + {{2{wet_s[23]}}, wet_s};
  ```
  **修法**：先把符号扩展结果落到 signed wire 上再相加 ✓
- **为什么闸口 27 套全绿却没抓到**：
  ① 旁路测试用 FX 全关 ⇒ 这条路径根本没被走 ✗；
  ② `fx_check` 只看**回声位置与能量**，对直流/削顶是盲的 ✗；
  ③ **所有既有测试用的都是正冲激** ✗ —— 负半周从来没被激励过 ✗✗
- **补救**：新增 `tb_fxinit` 的**负样本单元测试**：`din=−1000000 → dout=−1000000` ✓
  （修之前会变成大正数）。**建议把"负样本"与"无直流"两条纳入闸口**（已登记 D9/D10）

**修完后**：直流 **4,233,525 → 32,593（0.389%）**、削顶 **73,989 → 0**、峰值 **8.39e6 → 944,593** ✓
**闸口 `regress_all.py` 仍 11/11 全绿** ✓、`fx_check` 全过 ✓

## 五、⚠️ 判据 B（音高识别）**尚未成立** —— 如实记录

这一条我**不能算通过**，理由要写清楚：

| 事 | 结果 |
|---|---|
| HPS 判据（对数域谐波积） | **6 / 7**，失败的是**第二个音**（与第一个同为 E4），被判成低八度 ✗ |
| 第一轮（修 bug 之前） | 同一判据给 **7 / 7** ⇒ 说明它的结果会**随信号细节翻转**，本身不稳 |
| 我用自相关复核 | 给出 +89 / +70 / −177 音分等**互相矛盾**的值 ✗ |
| 自相关工具本身 | **也不可靠**：干声段里它把 C4 测成 65.75 Hz ✗ —— 因为包络衰减让自相关在长滞后仍有大值，而我的取峰没有做重叠归一化 ✗ |

**结论（诚实版）**：
> 现有音频**是干净可听的**（直流 0.39%、削顶 0、非零 100% 这些简单判据可信 ✓），
> 但**"逐音音高正确"这条我还没有可信的证据** —— 判据工具（HPS 与自相关）都还没做对。
> 在此之前，不要说"音高已逐音验证通过"。

**要修成什么样才算数**（下次做）：
1. **判据专用渲染**：`CTRL=0x00`（关滑音）+ `FX_CTRL=0x01`（**只干声、关混响**）
   —— 混响余韵会把前一音叠进测音窗，这是本次误判的主因之一；
2. **归一化自相关**（按重叠长度归一）或**倒谱**，而不是取全局最大峰；
3. 判据要求：每个音的基频与十二平均律的偏差 **< 25 音分**，且**不允许八度歧义**
   （若候选是期望音的一半/两倍，直接判失败 ✗）。

**顺带一个真实的设计发现**（已登记 D11）：滑音是**按时隙**而非按声部的 ——
时隙复用时 `gq` 初值对着该时隙残留的旧音高算，所以旋律里会听到"从上一个占用该时隙的音滑过来"。
演奏单音连奏时这是想要的 portamento ✓，但会干扰逐音判据 ⇒ 演示/判据里都先写 `CTRL=0x00`。

## 六、这套东西证明了什么、没证明什么

| | 结论 |
|---|---|
| ✅ 证明了 | 整条链（**真实 UART 协议帧 → 寄存器 → 曲谱 RAM → 定序器 → 音色映射 → TDM 引擎 → 效果器 → 输出**）在仿真里跑通，且**无直流、无削顶**（音高判据尚未成立，见第五节） |
| ✅ 证明了 | 上位机的操作序列是**逐帧可复现**的，且与仿真用的是同一串字节 ⇒ 上板时"操作"这一环没有未知量 |
| ❌ 没证明 | **板上行为**（时钟/复位/DAC/UART 电平）—— 仍然只能上板才知道 |
| ❌ 没证明 | 听感质量（我只能给客观数字 + 让你耳朵判断） |

**所以"能跑"的准确说法**：*"数字层面已全绿且有音频为证；板级只剩上电验证。"*
不要说成"已经能跑"——板子还没上过电。
