## 二、实现要点（三句话）

1. **插入点只有一行**（`tdm_engine.v`）：
   ```
   ph_n = ph1 + eff_inc + ((eff_inc × poff) >> 16)
   ```
   `poff` = 每音符的有符号 Q2.16 **音高比**偏移。因为 `inc` 里已含泛音比，
   所以**所有泛音同比移动** —— 这才是"音高在滑"，而不是"音色在扭"。

2. **两个来源、一个乘法**：`poff = gq[note] + vib_q`
   - `gq`：滑音偏移，note_on 时初值 = `(inc_旧 − inc_新)/inc_新`，之后
     `|gq| -= max(1,(|gq|×m)>>k)` **指数衰减到 0**（复用包络那套移位衰减，**零 DSP**）。
   - `vib_q`：全局三角 LFO × 深度（Q16），控制速率。
   - 初值不用除法器：`note_map` 用 **128 项倒数 ROM**（`recip_inc.hex`）乘一次即可。
     实测 MIDI 60→74：gq0 = **−36343** = 2^(−14/12)−1 的 Q16 表示，**精确吻合**。

3. **默认关，且关闭时逐位不变**（保护门）：`GLIDE_EN=0 且 VIB_EN=0` → `poff ≡ 0`
   → `ph_n` 与原来的 `ph1 + eff_inc` 逐位相同。R0 回归因此必须原样通过。

### 为什么 `gq` 必须走装载待生效区（不是设计洁癖，是实测逼出来的）

**这个坑有正反两副面孔，两次都被判据抓出来了。**

**第一副（128 档发现）："旧 inc × 新 gq"**

第一版让 `note_map` 直接写 `gq`。实测在滑音起点出现**1 个样本的相位增量异常**：

```
实测序列（组 0 的 slot 0 相位增量）：
  112367  112367  112367  [50053]  112417  112467 ...
                            ↑ 旧 inc × 新 gq = 112367 + ((112367×−36343)>>16)
```

即"新 gq 已到、新 inc 还没生效"的**混代样本** —— 与本项目栽过的
"累加窗口横跨两代状态"是同一类错误。修法：把 `gq` 并入装载待生效区
（`pgq_mem`，+1 块 BSRAM），在**装载被消费的那一拍**与 inc/amp/gate/epar 一起生效。

**第二副（512 档发现）："新 inc × 旧 gq"**

上面修完后，128 档全绿，但 512 档（16 号组）又出现 1 个异常样本：
实测 **179788 = 纯新 inc、无调制**，而镜像期望 71348（= 新 inc × 旧音高比）。
成因不同：`gq` 表是**寄存器组**，在第 N 拍写入、第 N+1 拍才读得到；
而 inc 走的是**待生效区直通**（`eff_inc = consume ? pi1 : inc1`），第 N 拍就生效。
两者差一拍，于是在消费那一拍配错。

修法（与 inc/amp/gate 完全对称的**一次选择**）：

```verilog
wire signed [QW-1:0] gq_eff = (gw_en === 1'b1) ? gw_val : gq[rd_note];
```

即"正在消费装载的那个时隙，用待生效值"，同时照旧写回寄存器供后续样本使用。
修后 512 档 G1 **0/6048**、G2 **16.00000~16.00021**，128 档仍全绿。

> **教训（值得写进报告）**：一个"边界对齐"的修复必须**覆盖同一组参数的所有成员**。
> 只把 `gq` 放进待生效区、却让它在读口上比 inc 晚一拍，等于把混代问题从
> 一副面孔换成了另一副。**判据必须是"逐样本比对"，而不是"看起来对"。**

## 三、过程中修掉的两个真 bug + 一个附带发现

### 1. LFO 三角波写错（两处）
- 错法一：`lfo_t = ph[23] ? (127-u) : (u-128)`，其中 `u = ph[23:16]`。
  `ph[23]=1` 时 `u` 已经是 128..255，再算 `127-u` 得到的还是负半周
  → **三角波根本没越过零点**。
- 错法二：三元表达式两个分支一个有符号一个无符号 → 整体判为无符号，负半周当大正数。
- 症状：`vib_q` 恒正、均值 ≈ +1450（应 ≈ 0），频偏呈 +25..+50 音分。
- 修法：两半都用段内 7 位 `u7 = ph[22:16]`，且乘法两个操作数都显式 `$signed`。

### 2. `sample_en` 自锁（测试台）
`wire sample_en = (pc == 0)` 又拿 `sample_en` 去清零 `pc` → `pc` 永远停在 0、
`sample_en` 永远为高 → 引擎的 `sc` 每拍被清零，**两个引擎都不推进**，数据全 0。
更隐蔽的是：中间还写过 `pc == NSLOT[6:0]` —— **对 128 做位选得 0，不是 127**。
现在测试台自带自检：**`sample_en` 周期必须 = 128 拍**（那两次错误时它分别是 1）。

### 3. ★ 附带发现：`note_inc.hex` 的采样率与顶层不匹配（会毁掉现场演示）

`note_inc` 里的数字直接含采样率：`inc = f × 2^24 / fs`。

| 用途 | 采样率 | MIDI 69（A4）的 inc |
|---|---|---|
| 原表（`note_map_gen.py` 默认） | 39062.5 Hz（5 MHz / 128，仿真时间基准） | 188979 |
| **`tdm_top` 实际**（27 MHz/18/32） | **46875 Hz** | **157482** |

两者差 **1.2 倍 = 3.16 个半音** —— 上板后 **A4 听起来是 528 Hz**，
而综合、时序、I2S 全部正常，**没有任何工具会报这个错**。
已修：`note_map_gen.py` 增加 `--fs`，并分别生成
`sim_build/*`（39062.5，给 tb）与 `src/gowin/tdm_synth/`（**46875，给上板**）两份。
