## ★★ 本步挖出的三个真问题（都已修，是本次最有价值的产出）★★

### 问题 1：没被写过的寄存器会被综合器【常量折叠】，测试模式被悄悄优化掉
顶层原先只有"演示序列器"在写音高寄存器，CTRL / MIX / ADSR 从来没被写过。
综合器据此认定它们恒等于初值 → 测试模式位恒为 0 → 整个 test_mode 被优化掉。
**症状极具欺骗性：编译成功、资源"正常"，但现场根本无法切换测试模式。**
修法：接上 UART，让写端口真正活着。
> 通用教训：寄存器表只要有一个字节永远不被写，那块逻辑就有被吃掉的风险。

### 问题 2：包络参数从常量变成寄存器 → 综合直接失败
把 a_inc / s_lvl / d_inc / r_inc / cutoff / d_k / d_m / r_k / r_m 全做成寄存器后：

    逻辑 8047 → 26226（超出器件上限 20736）→ 编译失败
    其中 ALU 10162 个

原因：包络要实例化 4 声部 × 8 泛音 = **32 份**。
d_k 变成寄存器后 `lvl >> d_k` 从【常量移位】变成【变量移位】，
`d_step * d_m` 从常量乘变成变量乘 —— 等于凭空造出
32 个 16 位桶形移位器 + 32 个变量乘法器 + 上百个加减/比较器。

即使把形状参数改回常量、只留电平参数为寄存器，逻辑仍达 19462（94%），
且出现时序违例（42.1 ns 路径 vs 37.0 ns 周期）。

**最终划定的边界（有依据的取舍，不是偷懒）：**
| 参数 | 形式 | 理由 |
|---|---|---|
| 音高 inc | **运行时寄存器** | M6 实时变调必需 |
| 幅度 amp | **运行时寄存器** | 「多音色」必需（幅度谱就是音色） |
| 包络全部参数 | 编译期常量 | 属于音色设计，不随演奏变化；做成寄存器要复制 32 份，得不偿失 |

### 问题 3：关键路径穿过"测试模式多路器"，时序违例 −5.1 ns
路径：`u_reg/mem[0]`（CTRL 的测试模式位）→ 32 路 inc/amp 二选一
→ 包络乘法 → 加法树 → 饱和，**全挤在一个时钟周期内，共 42.1 ns**，
而 27 MHz 周期只有 37.0 ns。

修法：给测试模式多路器加一级流水。
代价：写寄存器到听到声音多一拍（46875 Hz 下约 21 µs），完全不可感。
结果：关键路径降到 **24.76 ns**，slack **+12.3 ns**。
