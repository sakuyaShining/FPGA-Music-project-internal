# 设计增量空间实测 + 泛音控制方向的竞争力评估（2026-09-30）

## 一、★ 实测：TDM 之后天花板不但没被封死，反而抬高了 16 倍

| | 全并行 | **TDM** |
|---|---|---|
| 配置 | 4 声部 × 8 泛音 = 32 振荡器 | **NSLOT = 512 振荡器** |
| Logic | 13362 / 20736（65%） | **1979 / 20736（10%）** |
| Register | 4459 / 15750（29%） | **163 / 15750（2%）** |
| BSRAM | 32 / 46（70%） | **3 / 46（7%）** |
| DSP | 24 / 24（**100%**） | **2 / 24（9%）** |
| 关键路径 | 24.76 ns | 24.44 ns（周期 37.04 ns，slack **+12.6 ns**） |
| **吞吐量** | 32 × 46875 = **1 500 000** | 512 × 46875 = **24 000 000**（16×） |

### 约束变了：从"器件资源"变成"每样本的时钟拍数"

| 架构 | 真正的天花板由什么决定 |
|---|---|
| 全并行 | **DSP 100%、BSRAM 70%** → 约 5 声部 = 40 振荡器，且几乎没有余量做功能 |
| TDM | **27 MHz ÷ 46875 Hz = 每样本 576 拍**（减去流水线 4 拍 → 572）<br>→ 512 时隙，**而器件还剩 90%** |

### 继续抬高的路径（都还空着）
- **27 MHz → 108 MHz**（rPLL 预留）：2304 拍/样本 → 2048 时隙 → **96 000 000 osc·Hz**
  - 那时的资源：状态 2048 × 77 位 ≈ 8.6 块 BSRAM ✓ 仍然宽裕
- 或者多放几套运算核（每套约 2000 逻辑）做"并行 × 时分"混合

**结论：器件资源不再是瓶颈。** 90% 的逻辑、93% 的 BSRAM、91% 的 DSP 可以用来做**功能**，
而不是用来堆振荡器。

## 二、★★ 一个差点酿成大错的坑：综合器把整个引擎"优化没了"

第一次综合 TDM 时得到 **25 LUT / 0 BSRAM / 0 DSP**，而且 **编译成功**。
看起来像"TDM 极省资源"，实际是：

```
WARN (EX3988) : Cannot open file 'sine256.hex'
WARN (NL0002) : The module "tdm_engine" ... is swept in optimizing
WARN (NL0002) : The module "i2s_tx"    ... is swept in optimizing
```

`$readmemh` 找不到文件 → 正弦表为空 → 输出恒 0 → 整条链路被判定为常量而全部删除。

- **触发条件**：综合器是从【工程目录】找 `sine256.hex` 的，不是从当前工作目录。
  仿真器则是从【运行目录】找。两边都要放一份。
- **危险性**：它只报 WARNING，**编译照样"成功"**。
  如果不核对资源数字的合理性，就会把"设计消失了"当成"设计很省"。
- **教训：资源数字必须与预期量级对得上。**
  25 LUT 对一个 512 时隙的引擎显然不合理 —— 这个"不合理感"是最后的防线。

## 三、"控制泛音结构"这个方向的竞争力（诚实评估）

### 现状：平庸
8 个泛音 + 运行时幅度控制 = **拉杆风琴（Hammond，1935）**。
评委一眼能认出这是加法合成的标准做法。**它不构成差异化。**

### 但有一个升级点，而且 TDM 恰好把它变成几乎免费

> **每个泛音独立的包络（尤其是独立衰减率）＝ 模态合成（modal synthesis）＝ 物理建模**

- 模态合成就是"每个模式有**独立频率 + 独立幅度 + 独立阻尼**的加法合成"
- 钟、马林巴、钢琴、玻璃 —— 都是模态行为
- 这是有分量的方向，不是教科书

**关键对比**：

| | 每泛音独立包络 |
|---|---|
| 全并行 | **做不到**。实测：32 份包络 + 运行时参数 = 26226 逻辑 > 20736 上限，综合直接失败 |
| **TDM** | **几乎免费**。包络只有【一份】，参数从时隙状态存储里读 |

**所以：方向本身平庸，但 TDM 解锁的升级让它变得不平庸 —— 而且现在很便宜。**

## 四、一个音由几个维度的输入决定

### 当前（全并行）—— 只有 2 个维度是"每个音独立"的

| # | 维度 | 粒度 | 每音独立？ |
|---|---|---|---|
| 1 | 音高 | 每声部 24 位 `inc` | ✅ |
| 2 | 泛音幅度谱 | 每泛音 8 位 × 8 | ✅ |
| 3 | 包络时间（A/D/S/R） | **全局共享 10 个参数** | ❌ |
| 4 | 门 / 力度 | 每声部 1 位 | ✅ |
| 5 | 混音增益 | 全局 | ❌ |

**严格说：一个音现在只由「音高 + 8 个泛音幅度 + 门」决定，包络是全局的。**

### TDM 之后可以变成 7 个维度

| # | 维度 | 粒度 | 来源 |
|---|---|---|---|
| 1 | 音高 | **每泛音**独立 `inc` | TDM |
| 2 | 泛音幅度 | 每泛音 | 已有 |
| 3 | **泛音衰减 / 包络** | **每泛音独立** | ★ 新（= 模态合成） |
| 4 | **泛音频率比**（非整数比 → 钟 / 金属） | 每泛音失谐 | ★ 新 |
| 5 | 门 / 力度 | 每声部 | 已有 |
| 6 | 混音 / 声像 | 全局 | 已有 |
| 7 | 起始相位（瞬态塑形） | 每泛音 | 可选 |

**每音参数量级**：当前约 89 位；TDM 后约 8 × (24+8+16) = 384 位（8 个泛音各自独立）。

## 五、必须如实说明的风险

1. **TDM 的逐位一致【尚未达成】**。黄金参考测试目前对不上，
   最后一次尝试还因为测试台在采集前卡住而没拿到新数据。
   **在逐位一致成立之前，TDM 不能算可交付。**
2. 综合器"静默删除模块"这类问题（第二节）本质上是**验证盲区**，
   需要靠"资源数字是否合理"来兜底。
