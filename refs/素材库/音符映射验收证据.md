# 音符映射验收证据（note_map）

> 2026-10-01 · **"从引擎到乐器"的最后一块 FPGA 逻辑：把 MIDI 音符号变成正确频率的声音。**

## 结论

**音符事件 → 正确的 12 平均律频率 → 4 音复音累加 → 释放，全部验证通过。**

```
【逐段验证】D5 不是任何其他音的整数倍，可无歧义区分
  时刻   应在奏          检出基音        结论
  0.15s   [60]             [60]             ✓
  0.35s   [60, 64]         [60, 64]         ✓
  0.55s   [60, 64, 67]     [60, 64, 67]     ✓
  0.75s   [60, 64, 67, 74] [60, 64, 67, 74] ✓
  0.95s   [60, 64, 67, 74] [60, 64, 67, 74] ✓
总结论: ★★★ 全部时段基音逐一命中
```

实测基频 vs 12 平均律期望（误差 < 0.5%，在 FFT 分辨率之内）：

| 音 | 期望 | 实测 |
|---|---|---|
| C4 (60) | 261.63 Hz | 262.3 Hz |
| E4 (64) | 329.63 Hz | 329.0 Hz |
| G4 (67) | 392.00 Hz | 391.0 Hz |
| D5 (74) | 587.33 Hz | 587.3 Hz |

## 设计

| 决策 | 选择 | 理由 |
|---|---|---|
| **时隙分配** | 固定分组：音符组 `g` 占 `[g*P, g*P+P-1]` | 确定、可验证、时隙归属无歧义 —— 正好满足赛题"频谱可观测对应数量独立谱峰"的现场验证要求 |
| **音高 → inc** | **128 项 MIDI 音符号 ROM** | 128×24 = 3 Kbit，**精确无近似**（现场算 `2^((n-69)/12)` 需要指数运算） |
| **泛音比** | **Q8 定点**，`inc_partial = (inc_note × ratio_q8) >> 8` | 谐波用整数比（256/512/768…）**精确**；非谐（钟 2.76、马林巴 4.0）也能表 |
| **复音管理** | 已奏同音优先 → 空闲组 → round-robin 抢占 | 重触发不占新组；满了抢最老的 |
| **门控** | 开 → 该组 P 个时隙写 `gate=1`；关 → 写 `gate=0` | 走已验证的 `load_*` 通路，**自动获得样本边界对齐语义**；关是走释放段而不是硬停 |

**为什么泛音比必须用乘法而不是查表**：
泛音比是"每音色一份"、音符是"每次演奏一个"，两者的乘积无法预先查表
（128 音 × 16 泛音 × 4 音色 = 8192 项）。一个共享乘法器在装载时算，一个音符只需 P 次。

## 复现

```powershell
mkdir sim_build\notemap -Force
copy sim_build\additive\sine256.hex sim_build\notemap\
python tools\scripts\note_map_gen.py gen --outdir sim_build\notemap

iverilog -g2005 -o sim_build\notemap\nm.vvp -s tb_note_map `
  src\rtl\osc_core.v src\rtl\osc_env.v src\rtl\tdm_engine.v `
  src\rtl\note_map.v src\sim\tb_note_map.v

cd sim_build\notemap ; vvp nm.vvp        # 约 70 秒
```

**运行目录必须有三张表**：`sine256.hex` / `note_inc.hex` / `preset_part.hex`
—— `$readmemh` 找不到时**不报错**，只是表全为 0、输出静音。

## 踩过的坑（都值得记）

### 1. **位域重叠 —— 与 `preset.hex` 那次是同一个错误**

```
word = (rq8 << 24) | (amp << 16) | epar      # ✗ amp[23:16] 与 epar[23:0] 重叠
```
`16 + 8 + 24 = 48` 位，不是 40。实测第一行读回 `ratio_q8 = 0x0100FA`（应为 `0x0100`），**整表报废**。
这次是**核对了数值**才发现的（不是靠猜）。

### 2. **测试用例选错：C5 与 C4 的二次谐波同频**

第一版第四个音用 **C5 (523.26 Hz)** —— 而 **C4 的二次谐波也是 523.26 Hz**，
FFT **无法区分**"C5 的基频"和"C4 的二次谐波"。

症状看起来像"**第四个音在 0.15 s 就提前响了**"，很容易误判成音符映射有 bug。
改用 **D5 (587.33 Hz)**（不是 C4/E4/G4 的任何整数倍）后无歧义。

> **这是测试用例的设计问题，不是合成的问题。** 教训：验证多音复音时，
> 选用的音必须**互不为整数倍关系**，否则谐波会伪装成额外的音。

### 3. 硬超时按拍数而不是仿真时间

1.10 s 音频 = 42968 样本 × 128 拍 × 200 ns ≈ **1.1 s 仿真时间**，
第一版写 `#20_000_000`（20 ms）—— 差了 55 倍，仿真必然超时。

### 4. `g_cur * P` 的位宽溢出

`g_cur`(7 位) `* P`(16) 若在 7 位上下文里求值会溢出（32×16=512 需要 10 位）。
与 `osc_core` 的 `prod4 <= (a*b) >>> 16` 栽的是同一件事。
改为显式加宽的中间量，**不依赖 Verilog 的上下文宽度推断**。
