# TDM 音色示范 —— 每泛音独立包络到底改变了什么

> 4 个音色预设的 WAV 与量化对比。**这是"构造泛音结构"从"静态频谱"走向"频谱随时间演化"的第一次可听证据。**

---

## 一、怎么跑

```powershell
# 1) 生成预设表（音色定义在 Python 里，改数字即可，不用碰 RTL）
python tools\scripts\tdm_demo.py gen --out sim_build\demo\preset.hex

# 2) 编译示范测试台
iverilog -g2005 -o sim_build\demo\demo.vvp -s tb_tdm_demo `
  src\rtl\osc_core.v src\rtl\osc_env.v src\rtl\osc_additive.v src\rtl\mixer.v `
  src\rtl\synth_top.v src\rtl\tdm_engine.v src\sim\tb_tdm_demo.v

# 3) 跑 4 个音色（每个 0.8 s）
cd sim_build\demo
foreach ($i in 0..3) { vvp demo.vvp +IDX=$i ; cp demo_out.txt demo_out_$i.txt }

# 4) 渲染 WAV + 频谱演化分析
python tools\scripts\tdm_demo.py render --prefix sim_build\demo\demo_out --outdir sim_build\demo
```

> `sine256.hex` 必须放在运行目录（`sim_build\demo\`），否则 `$readmemh` 打不开、
> 输出会全 0 而不报错。

## 二、时间基准

| | 值 |
|---|---|
| clk | 2.5 MHz（周期 400 ns） |
| NSLOT | 64（4 音色 × 16 泛音） |
| 采样率 | **39062.5 Hz**（真实音频率，WAV 可直接播放） |
| 时长 | 0.8 s / 音色 |

用真实音频采样率而不是抽象值，是为了**输出能直接听**，不需要重采样或时间缩放。

## 三、结果

### 幅度包络（RMS，归一化到 t=0）

| 音色 | 0-100ms | 100-200 | 200-300 | 300-400 | 400-500 | 500-600 |
|---|---|---|---|---|---|---|
| org | 1.00 | 0.99 | 0.99 | 0.99 | 0.99 | 0.99 |
| piano | 1.00 | 0.88 | 0.75 | 0.62 | 0.50 | 0.39 |
| bell | 1.00 | 0.74 | 0.58 | 0.45 | 0.32 | 0.20 |
| marimba | 1.00 | 0.30 | 0.09 | 0.00 | 0.00 | 0.00 |

### 频谱随时间演化（高频能量 1500–15000 Hz 占总能量比例）

| 音色 | t=50ms | t=250ms | t=450ms | 判读 |
|---|---|---|---|---|
| **org** | 18.0% | 18.0% | 18.0% | **完全静止** ← 对照组 |
| piano | 10.0% | 5.4% | 5.2% | 变暗 |
| bell | 5.1% | 2.9% | 3.1% | 变暗 |
| marimba | 3.6% | 3.2% | 0.0% | 高频消失 |

**风琴那一行是刻意留的对照组**：它代表"只有每泛音音高 + 幅度"能做到的上限
（即 Hammond 拉杆风琴，1935）—— 频谱在时间上**完全不动**。
其余三个音色的频谱都在随时间变化，靠的就是**每泛音独立的衰减速率与衰减终点**。

## 四、四个预设的定义（`tools/scripts/tdm_demo.py` 的 `PRESETS`）

每个泛音给四样东西：`(频率比, 幅度, d_k, s_lvl)`

| 预设 | 频率比 | 衰减 | 说明 |
|---|---|---|---|
| **org** | 谐波 1..16 | `d_k=20`，`s_lvl=30000` | 几乎不衰减、衰减到高电平后保持 |
| **piano** | 谐波 1..16 | `d_k` 从 17 递减到 10，`s_lvl` 递减 | 高次泛音先死，频谱变暗 |
| **bell** | **非谐** 1, 2.76, 5.40, 8.93, 13.34… | `d_k` 从 15 递减到 6，`s_lvl=0` | 金属体振动模式；衰减到静音 |
| **marimba** | 1, 4, 9.2, 16… | `d_k` 从 13 递减，`s_lvl=0` | 木条的 1:4 特征 |

`τ ≈ 2^d_k / 3` 个样本；**`d_k` 每减 1，时间常数减半**。

## 五、为什么这一条只有 TDM 做得出来

| | 全并行 | TDM |
|---|---|---|
| 每泛音独立相位 | ✅ | ✅ |
| 每泛音独立幅度 | ✅ | ✅ |
| **每泛音独立衰减** | ❌ 逻辑 8047→**26226，超 20736 上限，综合失败** | ✅ **+105 LUT，零额外 BSRAM** |

原因：全并行要给 32 套包络各配一套变量移位器；TDM 的包络**只例化一套**（时分复用），
参数只是多几个存储字段（每时隙 23 位）。

## 六、踩过的坑（都值得记）

1. **位域重叠**：`word = (inc<<24) | (amp<<16) | epar` —— `amp` 占 `[23:16]` 而
   `epar` 占 `[23:0]`，**两者重叠**，幅度高位漏进了 `s_lvl`。
   实测症状：`epar_mem` 读回 `0x5C006F`（应为 `0x00006F`），于是 `s_lvl=47104`，
   **包络早早停在 SUS，四个音色听起来一模一样**。
   正确布局：`inc 24 + amp 8 + epar 24 = 56 位`。
2. **分析窗口越界**：取 700 ms 窗口（27343+4096 > 31250 样本）→ FFT 长度不足 → `nan`。
3. **`sine256.hex` 不在运行目录** → `$readmemh` 失败但**不报错**，输出全 0。
4. **第 1 个样本是 X**（流水线未建立）→ 直接 `int()` 会把脚本打断，
   而崩掉会让人误以为"设计坏了"。
