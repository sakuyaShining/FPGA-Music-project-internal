## 一、结论

| 项 | 判据 | 结果 |
|---|---|---|
| **E3 音色切换** | 写 `PRESET` 寄存器后，该音 16 个泛音的幅度**逐个等于** `preset_part.hex` 对应行 | **4 个预设全部 16 / 16** ✓ |
| **E2 颤音深度** | 写 `VIB_DEPTH` = 0 / 1000 / 2000 → 实测频偏 = 0 / 26.2 / 52.0 音分 | **0.00 / 26.31 / 52.64 音分**，且都**越过零点** ✓ |
| **E2 滑音时间** | 写 `GLIDE_M_K` = (m3,k13) 与 (m3,k10) → 衰减时间常数 τ = 2^k/m | τ 实测 **2806**（理论 2731）与 **343**（理论 341），**比值 8.19 ≈ 8** ✓ |
| **E2 滑音轨迹** | 与 Python 镜像逐样本比对 | **0 / 1399 不符**（两档都是）✓ |
| 回归 | R0（调制关）/ 128 档 / 512 档 / 顶层 I2S 闭环 | **0/2495**、全过、全过、**0/201** ✓ |

滑音初值 gq0 = **−55216**（= −3200 音分 = −32 个半音，正是 MIDI 40 → 72 的音程）✓ 公式精确。

## 二、实现要点

### 1) 寄存器映射（`tdm_top.v`）

```
0x00      CTRL      [0]测试模式 [1]颤音开 [2]滑音开 [3]音色源(0=引脚 1=寄存器)
0x30-32   VIB_INC   LFO 频率字（小端 24 位）= f × 2^24 / fs
0x33-34   VIB_DEPTH 颤音深度（小端 16 位，Q16）
0x35      GLIDE_M_K [1:0]m  [6:2]k（与 R_M_K / D_M_K 同一套编码）
0x37      PRESET    [1:0]音色
```

- **协议复用**：`uart_rx`（115200 8N1，两字节一帧：先地址后数据）+ `reg_bank`（256×8）
  与全并行版完全一致 —— 上位机脚本不用改。
- **开机自举**：复位释放后由一个小序列器经**真实写端口**写入 8 个默认值。
  这既给出确定默认值，又避免"某字节永不被写 → 被综合器常量折叠"的老问题
  （教训记在 `uart_rx.v` 顶部）。
- **默认值与加这条通路之前完全一致**：演奏档、滑音开、颤音关、音色走引脚
  ⇒ 测试模式的 512 个谱峰不会被颤音抹开（R3 现场自证要求）。

### 2) 参数总线（`pmod_cfg`，49 位）

```
{ lfo_inc[23:0], vib_depth[15:0], glide_k[4:0], glide_m[1:0], vib_en, glide_en }
```

打成一根总线的理由：`tdm_engine` 在 **8 个测试台**里被实例化，
打包后每个测试台只需多接一行 `.pmod_cfg(49'd0)`（= 两开关全关 = `poff ≡ 0` = 逐位不变）。

### 3) 开关放在"应用"处门控

`gq` 的衰减与装载**照常进行**，只有 `poff = (glide_en ? gq : 0) + (vib_en ? vib : 0)`
处门控 —— 这样关掉再打开不会残留旧偏移（否则滑音关掉后 gq 会永久卡住）。

## 三、过程中抓到的三个坑（都值得记）

### 1) ★ 越界取位返回 x（最难查的一个）

```verilog
wire [3:2] cfg_glide_m = pmod_cfg[3:2];   // ✗ 声明成源位段
...
.glide_m(cfg_glide_m[1:0])                // ✗ 对 [3:2] 取 [1:0] = 越界 → x
```

后果极其隐蔽：`glide_m` 变 x → 衰减里的 `mmul` 变 x → 但**只有负数 gq 才显形**
（gq=0 的项被 `mag <= CUT` 恒真掩盖），表现为"滑音一开始，那一组的相位就全变 x"。
定位过程：先排除引擎数据通路（单独诊断 `poff` 正常），再逐拍追踪到
"装载写入正确 → 下一个 `sample_en` 衰减 → x"，最后用**独立的 30 行递推复现**
证明递推本身没错，才回头怀疑例化时的位宽。

**规矩**：切片声明一律写 `[目标位宽-1:0]`，不要照抄源位段。

### 2) ★★ 三元表达式混有符号/无符号 → 负值被零扩展

```verilog
// ✗ 一条分支 signed、一条无符号 → 整个表达式判为无符号
poff_sum = (glide_en ? $signed(gq_eff) : {QW{1'b0}}) + (...)
```

实测症状：`gq = -36343` 时 `poff_sum = 225801`（= 2^18 − 36343，即无符号重解释），
于是被上游限幅夹成 **+131071**，音高高了两个八度。
修法：先把选择结果落到 **signed wire** 再做加法。

> **这是本项目第二次栽在同一件事上** —— 第一次在 LFO 三角波那里，
> 当时还把教训写进了注释，然后 30 行之后又犯。**同一个陷阱会以不同面目重复出现**，
> 所以"逐样本比对"这种判据不是形式主义。

### 3) "编译通过"不等于"重建过"

后台任务里用 PowerShell 的函数 + 数组展开调用 `iverilog`，它**打印了成功但没重建 vvp**
（`pm.vvp` 时间戳 2:36 vs RTL 2:45）。于是"改完还是老结果"，白查了一轮。

**规矩**：每次改完 RTL，先核对 `vvp` 与 `.v` 的时间戳再下结论。

## 四、代价：运行时可控不是免费的

| 项 | 加参数通道前 | **加之后** | 增量 |
|---|---|---|---|
| Logic | 8874 / 20736（43%） | **14766 / 20736（72%）** | **+5892** |
| Register | 1313（9%） | 1454（10%） | +141 |
| BSRAM | 9 / 46（20%） | 9 / 46（20%） | 0 |
| DSP | 6.25 / 24（27%） | **6.75 / 24（29%）** | +0.5 |
| 告警 | 仅 PR1014 | **仅 PR1014** | 无新增 |
| SETUP | slack +12.220 | slack **+11.838** | −0.4 ns |
| HOLD | slack +0.201 | slack **+0.205** | 持平 |

### 归因实验：+5892 LUT 几乎全部来自"变量移位"

`glide_k` 从编译期常量变成运行时端口后，每音符衰减回路里的
`mmul >> glide_k` 从**常量移位（免费连线）**变成 **19 位变量移位器**，
32 份实例 + m 选择 ≈ 5270 LUT。

验证方法：把那一行临时改回常量移位再综合 ——
**Logic 14766（72%）→ 9497（46%）**，LUT 12267 → 6997（**−5270**）✓ 归因确凿。

### 优化方案（下一步，预计回收 ~5000 LUT）

样本周期 **576 拍**、时隙只有 **512** 个 ⇒ 每个样本末尾有 **64 拍空闲**。
把衰减从"每样本 32 路并行"改成**分时复用**：

```
在空闲窗口（sc ≥ NSLOT）里，每拍算一个 entry 的衰减
  → 只需要 1 个变量移位器（~165 LUT）而不是 32 个
  → 每个 entry 仍然每样本恰好衰减一次 ⇒ 轨迹【逐位不变】
```

要点：**窗口必须排在所有时隙访问之后**（即 sc ≥ NSLOT），
否则同一周期内"先读后写"的顺序会让一部分组的 gq 早/晚一个样本生效。
测试台这边需要把周期改成 `NSLOT + 64`（现在 tb 用的是 `period == NSLOT`，
没有空闲窗口），才能与真实设计的结构一致。

## 五、复现

```powershell
# 编译（注意：必须确认 vvp 时间戳是新于 .v 的）
iverilog -g2005 -o sim_build\latency\rc.vvp -s tb_reg_ctl `
  src\rtl\audio_clk_en.v src\rtl\osc_env.v src\rtl\i2s_tx.v src\rtl\tdm_engine.v `
  src\rtl\pitch_mod.v src\rtl\note_map.v src\rtl\reg_bank.v src\rtl\uart_rx.v `
  src\rtl\tdm_top.v src\sim\tb_reg_ctl.v

cd sim_build\latency
vvp rc.vvp +test=0     # E3 音色切换（4 个预设 × 16 泛音）
vvp rc.vvp +test=1     # E2 颤音深度（三档）
vvp rc.vvp +test=2     # E2 滑音时间 (m=3,k=13)
vvp rc.vvp +test=3     # E2 滑音时间 (m=3,k=10)

python tools\scripts\reg_ctl_check.py --simdir sim_build\latency

# 四套回归（每套都必须绿）
#   R0：tb_tdm_equiv + tdm_compare.py        → 黄金参考 0/2495
#   128 档：tb_pitch_mod + pitch_mod_check.py
#   512 档：tb_pitch_mod512 + pitch_mod512_check.py
#   顶层：tb_tdm_top（I2S 闭环 0/201）
```

运行目录需要 `sine256.hex / note_inc.hex / preset_part.hex / recip_inc.hex`
（且必须是 `--fs 46875` 生成的那份）。

**UART 写入方式**（上板/上位机）：波特率 115200 8N1，先发地址字节、再发数据字节。
例：把颤音深度设为 2000（0x07D0）→ 发 `33 D0`、`34 07`；
开启颤音并选寄存器音色 → 向 `0x00` 写 `0x0E`。
