    时钟：27MHz → audio_clk_en → bck 1.5MHz / lrck 46875Hz / sample_en

## 闭环自检（无板条件下最强的证据形式）
方法：测试台内置一个 I2S 接收模型 —— 在 bck 上升沿采样 sd，
      用 WS 边沿同步声道起点，每 16 位拼成一个 16bit 字。
结果：128 个字全部导出，与源样本【逐位一致】（跳过前 2 个未同步字后 0 处差异）。
      同时验证：左右声道完全相同、帧间步进恒为 +37（无丢位、无错位）。

## 过程中踩的两个坑（都已修，见 RTL 注释）
1. 「1 bit 延迟」的正确做法：发送方踩 bck 下降沿、接收方踩上升沿，
   那半个周期的错开【本身就构成】延迟。曾试过把装载推迟一个 bck_en，
   结果整帧错位一位（解码值 = 源值 >> 1，幅度减半）。
2. 测试台里用「帧配对」逻辑很脆弱（依赖左右声道事件的先后顺序），
   改成导出原始字流、由 Python 对齐比对，既简单又不会因为测试台自己的 bug 误判 DUT。
