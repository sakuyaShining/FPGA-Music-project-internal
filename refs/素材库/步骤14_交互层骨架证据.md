## 二、设计：为什么把"核心"和"传感器"拆开

```
   具体传感器                设备无关核心                   引擎（已有，一行没改）
 ┌──────────────┐        ┌──────────────────┐        ┌─────────────────────┐
 │ 超声/触摸/编码器 │ 通用测量总线  │   perf_ctrl.v    │ 动作总线 │ tdm_top 的 ev_* 端口 │
 │  → 解码模块   │ ─────► │ 维度1→音高        │ ─────► │ note_map → 32 声部   │
 │ （几十行 RTL） │ m1/m2/pads │ 维度2→力度        │ act_*  │ → 引擎 → I2S         │
 └──────────────┘        │ 触发/门控/锁存     │        └─────────────────────┘
                         └──────────────────┘
```

通用测量总线只有三样东西：

| 信号 | 含义 | 谁能驱动 |
|---|---|---|
| `m1_raw[15:0]` + `m1_vld` | 维度1（选音）：一个数 + "新测量到了" | 测距值、编码器计数、触摸键序号…… |
| `m2_raw[15:0]` + `m2_vld` | 维度2（力度） | 第二次测量、挥速、压力值…… |
| `pads[3:0]` | 触发（按下持续 / 松手收声） | 按键、触摸模块、霍尔、干簧管…… |

**映射全程不用除法**（沿用本项目一贯做法）：
```
note = note_lo + ((m1_raw − m1_lo) >> m1_shift)      上限 127
vel  = (m2_raw >> m2_shift)                          上限 15
```
好处：逻辑省，而且**判据能独立复算期望值**（脚本就是这么比的）。

### 两种演奏手感，各自对应 M9 的一个词
- **按住触发**（触摸键/按键）→ note-on 后**按住持续**，松手才收声 = 「选音」+「触发」
- **挥手拨弦**（m1 变化率超阈值）→ note-on + **固定门长后自动收声**，
  力度 = 挥速 = 「拨弦」+「力度感应」

## 三、★ 判据（这一步的重点）

**M1 的原文判据是"现场演示可分别操控"，所以核心必须是交叉测试** ——
只证明"两个都能变"是不够的，必须证明**动一个、另一个不动**：

| 判据 | 内容 | 结果 |
|---|---|---|
| **P1** | 只动维度1（选音）→ 音高变、**力度恒定** | 音高 **[60..67] 严格递增**，力度集合 **[15] 唯一** ✓ |
| **P2** | 只动维度2（力度）→ 力度变、**音高恒定** | 力度 **[0..15] 严格递增**，音高集合 **[63] 唯一** ✓ |
| **P3** | **锁存**：按住期间把两个维度都改掉，正在响的音不许变 | 全程只有 **(63,15)** 与重按后的 **(70,0)** 两种组合 ✓ |
| **P4** | 拨弦/力度感应：三档挥速 → 力度单调 | 挥 64/160/320 → 力度 **[4, 10, 15]** 精确 ✓ |
| **P5** | **集成**：传感器仿真器 → 核心 → `ev_*` → **真引擎** | 引擎 group0 的相位增量 = `note_inc[74]` = **186856 逐位相符** ✓ |
| **P6** | 松手收声：每次 note-on 都有配对 note-off | 2 对 2 ✓ |

### 附带量出一个重要数字（补 E5 的缺口）
E5 文档里写明"本测量**不包含控制侧**"（传感器采样/按键去抖）。这一步把那段补上了：

```
动作开始于样本 6  →  引擎组 0 起振于样本 7
控制侧延迟 = 1 个样本 = 18.96 µs
```

⇒ 整链（动作 → DAC 输入端样本）≈ 18.96 µs + 103.96 µs = **0.123 ms**，
对 5 ms 预算余量仍有 **40×** ✓

## 四、过程中踩的坑（都值得记）

### 1) ★ 又在"采样节拍"里看窄脉冲（第三次了）
集成测试第一版把传感器接线写在"每样本一次"的循环里：
```verilog
for (...) begin @(posedge clk); i_m1v <= sim_m1v; while (!sample_en) @(posedge clk); ... end
```
`sim_m1v` 只有**一个时钟宽**，而样本周期 512 拍 —— 撞上的概率 1/512 ✗
结果 **20000 个样本里一个事件都没有**，看起来像"设计不出声"。
改成独立 `always` 块**每时钟连续接线**后立刻正常。
> 同一个坑在 `tb_seq`（`ev_valid`）栽过一次，这是第二次。
> **规矩：任何窄脉冲的跨模块连接，必须用连续的 always 块，不能放在按节拍推进的循环里。**

### 2) 变化率触发被"起手复位"污染
每次挥完要把基准值移回去重新起手，而**移回去本身就是一次大挥** ✗
→ 每次多出一个假触发（实测力度序列 4/4/10/10/15）。
修法：复位期间**关掉变化率触发**，只对真正那一挥计数 → 得到精确的 **[4,10,15]**。

### 3) 锁存语义：真实乐器不会"拨完再改音高"
第一版没有锁存：按住不放时转动维度1，**已经响着的音会跟着换音高** ✗
（判据 P3 直接抓住：出现了一堆不该有的 (音高,力度) 组合）。
修法：触发瞬间把音高/力度写进 `held_note/held_vel`，收声也用这一对 ✓

## 五、器件未定也不耽误：将来怎么接（下一步）

上板只差两件事：

| 步骤 | 内容 | 说明 |
|---|---|---|
| **1b** | 把 `perf_ctrl` 例化进 `tdm_top`，加"事件源仲裁"（本地传感器 / E7 定序器 / UART 三选一） | 这样现场可切换演示模式 |
| **1b** | 加"**虚拟传感器**"寄存器：由上位机通过 UART 写 `m1/m2/pads` | ⇒ **不买任何器件也能上板验证整条链路**（还能顺手变成 E8 的手机 App 入口） |
| **2** | 选定器件后写一个解码模块（`sensor_range.v` / `sensor_touch.v` / `sensor_enc.v`） | 输出仍是同一条测量总线，核心与判据**一个字都不用改** |
| **3** | 上板 bring-up + 现场演示 | M1/M9 才算真正达成 |

**候选器件（等用户定）**：
- 超声波/红外测距 → 距离=选音、挥速=力度（`TRIG=48`、`ECHO=77`，正好用掉仅剩的两根排针）
- TTP223 触摸模块 → 触发/选音（3.3V、自带消抖、1 根线一个键）
- 旋转编码器 EC11 → 选音/参数（2 根线）
- ⚠️ **模拟量（电位器/FSR/压电片）本芯片没有 ADC**，要么外挂 ADC，要么用"数字 IO + RC 充放电计时"
