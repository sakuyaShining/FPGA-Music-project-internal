# E5 延迟证据：控制信号 → 音频输出（实测拍数 + 确定性论证）

> 2026-10-02 · 赛题拓展要求 E5：「将演奏延迟压缩至 **≤5 ms** 且实现**确定性无抖动延迟**」
> 方法：在仿真里**逐拍量出来**（不是架构推算），并证明它对事件到达时刻的依赖是**闭式可预测**的。
> 测试台：`src/sim/tb_latency.v`；判据脚本：`tools/scripts/latency_check.py`；原始数据：`原始测量.txt`
>
> ⚠️ **本文件是 2026-10-02 第二轮重测的结果**（时钟链 ÷18 → ÷16，每样本 576 → **512 拍**，
> fs 46875 → **52734.375 Hz**）。改时钟链的原因见
> `refs/素材库/步骤10_出货配置修正与LUT回收.md`。

---

## 一、结论

| 指标 | 实测值 |
|---|---|
| 端到端最坏（音符事件 → **DAC 输入端**解出的样本） | **2807 拍 = 103.96 µs = 0.104 ms** |
| 引擎侧最坏（音符事件 → `sample_out` 首次非零） | **2052 拍 = 76.00 µs** |
| **对 ≤5 ms 的余量** | **48×** |
| 对基础项 M4（≤10 ms）的余量 | **96×** |
| 抖动 | **0**（同一相位重复测量逐拍完全一致） |

**结论：内核侧（引擎 + 输出通路）的延迟是 0.1 ms 量级，把 5 ms 预算用掉了 2%。**
剩下 4.9 ms 全部留给控制侧（按键去抖 / 传感器采样 / 上位机往返），余量非常宽。

## 二、为什么会"确定"——两条依赖都是闭式的

### 1) 对"事件落在样本周期内的位置"的依赖（相位项）

控制事件是异步的，装载必须等到下一个样本边界附近才生效，所以延迟必然含一个相位项。
实测扫 7 个相位，**每个相位跑两遍**：

```
相位    0 拍：t_smp = 1156   t_pin = 2006      ← 两遍完全相同
相位   96 拍：t_smp = 1060   t_pin = 1910
相位  192 拍：t_smp =  964   t_pin = 1814
相位  288 拍：t_smp =  868   t_pin = 1718
相位  384 拍：t_smp =  772   t_pin = 1622
相位  480 拍：t_smp =  676   t_pin = 1526
相位  560 拍：t_smp = 1172   t_pin = 2022      ← 含 +1 周期项（见下）
```

模型（**误差 0 拍**）：

```
t(phase) = t0 − phase + 576 × [ phase + 18 > 511 ]
```

**那个 511 是本次实测挖出来的一个真实细节**：装载"待生效"的奇偶翻转点在
`sc = NSLOT−1 = 511`，比样本边界（`sc` 归零）**早 64 拍** ——
因为 **NSLOT = 512 < 每样本 576 拍**。
所以事件若晚于 `511 − 18 = 493` 拍到达，写进去的那一代就要多等一个周期。
相位 560 的实测值 1172 = 1156 − 560 + 576 **精确吻合**。

> 这正是"确定性"的含义：不是"抖动很小"，而是**可以写成一个闭式公式**。

### 2) 对"音符落在哪个组号"的依赖（组号项）

组号决定该组的时隙在本样本周期里被访问的早晚，实测（相位固定 0）：

```
组  0 → t_load = 1086 拍      组 16 → t_load = 830 拍
组  4 → t_load =  574 拍      组 20 → t_load = 894 拍
组  8 → t_load =  702 拍      组 24 → t_load = 958 拍
组 12 → t_load =  766 拍      组 28 → t_load = 1022 拍
                              组 31 → t_load = 1070 拍
```

范围 **574 ~ 1070 拍（18.4 µs）**，同样是可复现的确定量。
（0 号组偏晚，是因为 `slot_addr = sc + LAT`：slot 0 在本周期要到 `sc ≈ 508` 才被访问。）

## 三、判据（`latency_check.py`，全部通过）

| 判据 | 内容 | 结果 |
|---|---|---|
| **L1** 可复现性 | 同一相位跑两遍，逐拍一致 | **8 / 8 组一致** ✓ |
| **L2** 相位闭式 | `t = t0 − phase + 576·[phase+18>511]` | **误差 0 拍** ✓ |
| **L3** 硬上限 | t_pin ≤ 0.2 ms，并给出相对 5 ms/10 ms 的余量 | 0.0749 ms，**67× / 134×** ✓ |
| **L4** 组号依赖有界 | 跨度 ≤ 1 个样本周期 + 固定项 | 496 拍 ✓ |

## 四、"零抖动"的结构性论证（比数字更有分量）

内核这条路径上**不存在**任何抖动来源：

| 抖动来源 | 本设计 |
|---|---|
| 时钟 | 27 MHz 晶振直连，**无 PLL**；BCK/LRCK 全是**整数分频**（÷18、÷32） |
| 调度 | **静态时分复用**：每个时隙每个样本周期恰好被访问一次，无仲裁、无抢占队列 |
| 软件 | **没有 CPU / 软核 / 中断**参与发声（合规红线 R1/R2 也依赖这一点） |
| 缓存 | 无 cache、无 DMA、无总线竞争 |

⇒ 延迟不是"测出来很小"，而是"**由结构决定、不可能抖动**"。
上面 L1/L2 的实测（两遍完全一致 + 闭式吻合）是这一结论的实验corroboration。

## 五、五件必须如实说明的事

1. **本测量不包含控制侧**：传感器采样、按键去抖、USB/UART 往返都在交互层，
   那部分要在**上板后用示波器**测（`docs/01-竞赛情报/01-选题确认与约束条件.md`
   第三节已记录学校有示波器）。内核侧只占 0.075 ms，因此控制侧预算 4.9 ms，非常宽。
2. **MAX98357A 自身的群延迟未计入**：它的数据手册 propagation/group delay 要加上，
   这是"声学端到端"的最后一截（此前已列为风险项）。
3. **测量口径**：`t_pin` 是"I2S 串行流里解出左声道 16 位"的时刻，
   即 DAC 输入端的数字时刻；不是喇叭出声时刻。
4. **仿真时间基准是真实的**：本测试台用 **27 MHz 真时钟**（37.037 ns），
   不是加速过的仿真时间基准 —— 所以拍数可以直接换算成 µs。
5. **本测试台自己踩过两个坑，都值得记**：
   - 判"非零"不能用 `!== 0`（`x !== 0` 为真，上电 x 会在第 1 拍误触发），
     必须用 `>0` / `<0` 这类**在 x 上求值为假**的比较；
   - 引擎的时隙存储**没有复位分支**（设计上依赖"BSRAM 上电为 0"），
     所以**不能在仿真中途拉复位来隔离多次测量** —— 必须每个相位一次冷启动。
     第一版就因为这两点，6 次测量里有 5 次得到 `t_smp = 1 拍` 的假值。

## 六、复现

```powershell
iverilog -g2005 -o sim_build\latency\lat.vvp -s tb_latency `
  src\rtl\audio_clk_en.v src\rtl\osc_env.v src\rtl\i2s_tx.v src\rtl\tdm_engine.v `
  src\rtl\pitch_mod.v src\rtl\note_map.v src\rtl\tdm_top.v src\sim\tb_latency.v

cd sim_build\latency
# 相位扫描（每个相位一次冷启动；跑两遍可验可复现性）
vvp lat.vvp +phase=0     # 再试 96/192/288/384/480/560
# 组号扫描（用预填音把被测音挤到指定组；只信 t_load）
vvp lat.vvp +phase=0 +prefill=16

python tools\scripts\latency_check.py --file refs\素材库\步骤8_延迟证据\原始测量.txt
```

运行目录需要 `sine256.hex / note_inc.hex / preset_part.hex / recip_inc.hex`
（**且必须是 `--fs 46875` 生成的那份**，否则频率不对 —— 见表情调制证据里的采样率血案）。
