## 二、E7 怎么做到"脱机"

```
曲谱（RTL 里的 case 表）
      ↓
节拍累加器 ──进位──→ 步进器 ──→ note-on / note-off 事件 ──→ note_map → 引擎 → I2S
   ↑                                                              │
tempo_inc（寄存器）                                     LED 指引（6 个板载 LED）
```

- **曲谱烧在 RTL 里**（`case` 表，15 步"小星星"），不依赖任何外部事件、不依赖上位机 —— 上电写一个寄存器就自己弹完。
  ★ 用 `case` 而不是 `$readmemh`：本项目吃过"hex 文件没加载成功却静默继续"的亏。
- **节拍不动除法**：沿用本项目一贯做法，上位机把 BPM 换算成"每样本前进多少拍（Q24）"：
  ```
  tempo_inc = (BPM / 60) × 2^24 / fs
  ```
  定序器只做**加法 + 看进位**。BPM=120、fs=52734.375 时 `tempo_inc = 636`（实测拍率 1.9996 拍/秒，误差 0.02%）。
- **事件源二选一**：`seq_en ? 曲谱事件 : 外部演奏事件`，默认 `seq_en = 0`
  ⇒ 与加定序器之前**完全一致**，既有证据全部继续有效。

## 三、E6 的 LED 指引：顺便修掉一个**极性 bug**

### LED 怎么显示
```
[5] = 拍点闪（每个拍点拉高约 40 ms）
[4:0] = 当前应弹音高的低 5 位   ← 演奏者照二进制编号按键，就是"脱机曲目指引"
定序器关时：[4:0] = 在奏声部数（原有行为）
测试模式：6 个全亮
```

### ★ 极性修正
官方 `blink_leds` 的 cst 注释写得很明确：

```
// 6 mono LEDs -- COMMON ANODE, so a LOW output lights them.
```

而原来的代码是

```verilog
assign led = test_mode ? 6'b111111 : {1'b0, active[4:0]};   // ✗ 用 1 点亮
```

**上板会全反**：测试档全灭、在奏声部反而灭、空闲声部常亮。
现在改成 `assign led = ~led_bits;` 并写了注释。
> 这一条**只能在板上最终确认**（无板时以官方 cst 注释为准，已如实标注）。

## 四、过程中的三个坑

### 1) `ev_valid` 只持续一个时钟 → 事件一条都没记到
测试台原来只在 `sample_en` 那一拍去看 `ev_valid`，结果 **9 条事件丢光**，
而拍点与 LED 全对 —— 很容易误判成"定序器不发事件"。
改成独立 `always` 块**连续监视** + 样本计数器打时间戳。

### 2) 节拍累加器被事件状态机"卡住"（★ 设计缺陷，已修）
第一版把 `acc <= acc + tempo_inc` 放在状态机的**空闲分支**里，
于是每次换音的那 2 拍**不计时**，每一步的拍点都往后漂 2~3 个样本：

```
实测拍间隔 13192 样本，理论 13187（慢档）
```

听感上无所谓，但"时间戳 vs 曲谱"这条判据就永远差几个样本。
**修法：把计时与记账解耦** —— 累加器每样本都推进，拍点用 `beat_pend` 挂起交给状态机消费（不丢拍）。
修完拍间隔中位数 **13190 / 1319，比值 10.00** ✓

### 3) 判据自己写错两次
- **模型相位错一拍**：RTL 是"第 0 步持续到**第一个**拍点"，我的模型等到第二个拍点才换步
  → 所有时间戳整齐地差一拍（"对了 90% 却全错"）。
- **去重不一致**：曲谱里有连续同音（60,60 / 67,67），实测侧按"值变化"提取，
  期望侧却拿未去重的曲谱比 → 假报 3/5 不符。两侧都去重后 0 不符。

> 这一轮再次说明：**判据脚本本身也要当作被测对象**，报错时先怀疑模型。
