> 2026-10-02 · 赛题拓展要求 E8：「蓝牙 ＋ 手机 App 智能联动」
> **内核能收下的只有 FPGA 侧这一半**：串口收发协议、曲谱下载、寄存器回读。
> 蓝牙模块与手机 App 必须依赖外部件，**内核收不下**（本文最后如实写清）。
> 新增模块：`src/rtl/uart_tx.v`；接线：`tdm_top.v`（`uart_tx_pin` = 引脚 69）
> 测试台：`src/sim/tb_e8.v`（**在测试台里自带一个独立的串口接收机**，把"上位机那一段"搬进仿真）

## 一、结论

| 判据 | 结果 |
|---|---|
| **回读协议** 上位机写 `0x60 = 地址` → FPGA 在 TX 上回【地址】【数据】两字节 | 独立解码器收到 **`0x33` `0xD0`**，与写入值一致 ✓ |

## 二、协议（与写入帧完全对称，上位机好写）

```
写寄存器：  [地址][数据]                       （沿用原有 2 字节帧）
读寄存器：  发 [0x60][地址]  →  FPGA 回 [地址][数据]
下载曲谱：  发 [0x72][起始索引]
           发 [0x70][音高] [0x71][拍数]        ← 写完拍数索引自动 +1，可连续流式下载
           发 [0x73][步数]
           发 [0x50][0x05]                     ← 使能 + 用下载曲谱（bit2 = 曲谱来源）
```

新增寄存器：

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x60 | RB_ADDR | 写一个地址即触发回读（返回该地址的值） |
| 0x70 | SCORE_NOTE | 曲谱音高（写当前索引处） |
| 0x71 | SCORE_BEATS | 曲谱拍数（写当前索引处，然后索引 +1） |
| 0x72 | SCORE_IDX | 曲谱写入索引 |
| 0x73 | SCORE_LEN | 下载曲谱的步数 |
| SEQ_CTRL[2] | — | 0 = 内置曲谱，1 = 下载曲谱 |

`uart_tx.v`：115200 8N1、LSB 先发，`DIV = 27e6/115200 = 234`（整数，无累积误差）；
`tx_start` 一个时钟脉冲启动，`done` 一个时钟脉冲收尾（级联两个字节靠它）。

## 三、过程中的四个坑

### 1) ★ 写曲谱用了"寄存器旧值"
第一版把 `ram_note` 接的是 `R[0x70]`（寄存器输出），而 `reg_bank` 的寄存器是**同步更新**的
—— 在写使能那一拍它还是**上一次写入的旧值** ✗，于是整条曲谱错位一位。
改成直接用进来的字节 `wr_data` 就对。
> 教训：**写端口要用"进来的数据"，不要用"已经落到寄存器里的数据"**。这是"同一拍读旧值"的又一个变体。

### 2) 第 0 步永远不响
定序器只在**拍点**换步，而刚使能时它停在"等第一个拍点"的状态 —— 那一刻正好换到第 1 步，
**第 0 步的音永远不会被弹出来**（实测漏掉 62）。
加一个 `started` 标志：使能后先把第 0 步弹出来 ✓。

### 3) 模块加端口 → 直连它的测试台全变 x
给 `song_seq` 加了曲谱下载端口后，`tb_seq`（**直接例化**该模块的测试台）没连新端口，
Verilog 里悬空输入是 **z**，而 `use_ram ? ... : ...` 遇到 z 会整体变 x ✗
—— 实测表现为"该档一条事件都没有"。顶层是自动连的，所以只有模块级测试台会中这一枪。
> 教训：**加端口后要搜一遍所有直连该模块的测试台。**

### 4) 加一级流水后，另一个测试台的激励窗口不够宽了
给事件路径加寄存器（见下节时序问题）后，`tb_latency` 的"预填音"全部丢失
（`t_load=-1`），看上去像设计回归。实际是激励窗口太窄：预填事件只保持了 8 拍。
放宽到 64 拍 + 200 拍稳定时间后，数值与改动前**逐个一致**（574/638/766/1006 拍）✓
> 教训：**判据突然失败时，先分清"设计变了"还是"激励窗口不够"。**

## 四、时序：加完 E8 后余量被吃掉了，已抢救

| 阶段 | Logic | SETUP slack |
|---|---|---|
| 加 E8 前 | 10255（50%） | **+12.044 ns** |
| 加 E8 后（未处理） | 12101（59%） | **+0.105 ns** ✗ |
| 加事件流水后 | 12223（59%） | **+1.208 ns** ✓ |

关键路径是 `u_reg/mem[80]`（SEQ_CTRL）→ 事件源 mux → `note_map` 的时隙分配网络，
也就是"**一个寄存器直接串进 note_map 的组合分配逻辑**"。
在中间加一级寄存器（事件打一拍）就切断了这条路：寄存器→mux→寄存器 变短，
而"寄存器→note_map"这条本来就余量充足。

代价：音符事件晚 **1 个时钟 = 37 ns**（相对 5 ms 预算可忽略）。
E5 重测后延迟仍是 **2807 拍 = 0.104 ms**（这一拍被"装载必须对齐样本边界"吸收了，
所以端到端数字没变）✓

> 试过把寄存器堆从 256 收到 128 来省 LUT，但 `reg_bank.v` 里有并行设计遗留的
> 256 项初值，综合直接报 `EX3784 Index 128 is out of range` —— 回退。
> **余量提示**：Logic 已到 59%，再加功能前要先看时序（这一轮的教训）。

## 六、复现

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\scripts\build_sims.ps1
cd sim_build\e8
vvp e8.vvp +test=0     # 寄存器回读（应回 0x33 0xD0）
vvp e8.vvp +test=1     # 曲谱下载后演奏（应依次 62 64 65 67）
```

**上板怎么用**：用任意串口工具（115200 8N1）按上面的帧格式发两字节即可；
回读时先发 `60 <地址>`，再从 TX 收两个字节。
